# FEELM 문서 개선 — 측정 결과

2026-09-12 / **제한된 파일럿 완료** / 원본: `FEELM-standalone` / 작업: `FEELM-docs-efficiency`

**현재 연구를 설명할 때 읽는 문서 묶음은 로컬 토크나이저 기준 74.1% 줄었다. 동일 Astra/ultra로 수행한 두 차수의 소규모 비교에서는 개선 조건의 실제 총 토큰이 각각 11.6%, 11.0% 적었다.**
계정 전체 사용량·월 비용·누적 순절감의 실적은 아니다. 엄격한 답변 포함 기준도 완전히 통과하지 못했다.

## 무엇을 바꿨나

- 현재 결론과 과거 진행 기록을 분리하고, 문서 첫 화면이 최신 연구를 안내하도록 수정했다.
- 공통 AI 규칙과 작업별 필수 상세 규칙을 나눴다. 독립 검토·계약·보안·외부 게시 권한은 유지했다.
- 사람용 실험 요약 양식, 내부 용어·표·반복 설명을 줄이는 작성 규칙, 폴더·브랜치 지도를 추가했다.
- 원본 실험 수치·config·검토 봉인·실패 기록과 원본 worktree의 기존 파일은 보존했다.

## 결과와 품질

| 측정 | 기존 | 개선 | 관측 감소 |
| --- | ---: | ---: | ---: |
| 봉인된 읽기 묶음의 로컬 토큰 | 14,069 | 3,647 | 74.1% |
| 1차 실제 총 토큰 | 66,613 | 58,894 | 11.6% |
| 2차 실제 총 토큰 | 66,652 | 59,353 | 11.0% |
| 1·2차 모두 포함한 실제 총 토큰 | 133,265 | 118,247 | 11.3% |

| 같은 5문항의 엄격한 포함 기준 | 기존 | 개선 |
| --- | ---: | ---: |
| 1차 | 3/5 | 3/5 |
| 2차 최종 독립 판정 | 2/5 | 4/5 |

2차 개선 답변은 Qwen 판정 기준이 **사전에 고정**됐다는 설명을 빠뜨렸다. 기존 답변에는 데이터 이름과 응답 시간 검증도 명확하지 않았다.
채점자의 2차 초안은 Q1을 두 조건에 다르게 적용해 일관성 재검토 후 수정했다. [원답변과 모든 판정](grading.json)을 보존한다. 5/5 통과나 동등 품질을 입증했다고 쓰지 않는다.

1차 누락을 본 뒤 두 조건 모두 출력 요구를 명확히 하고 900자 한도를 1,400자로 바꿨다. [변경 이유와 종료 조건](protocol-amendment.md)을 먼저 기록했고, 1차 결과를 버리지 않았다. 두 차수는 같은 설정의 독립 반복 표본이 아니다.

## 측정 범위

- 현재 연구 인계라는 **한 과업의 5개 확인 항목**이다. 다섯 독립 과업이나 통계적 검정이 아니다.
- 두 조건 모두 AGENTS, 현재 연구, 같은 hybrid345 선정 근거를 읽었다. 파일·질문·해시는 [manifest](manifest.json)에 고정했다.
- 로컬 수치는 tiktoken 0.14.0 / `o200k_base`로 UTF-8·LF 문서 묶음을 센 값이다. Astra 내부 토크나이저라고 가정하지 않았다. 모델별 실제 요청에는 역할·도구 등 추가 입력이 있다. [공식 토큰 계산 설명](https://developers.openai.com/api/docs/guides/token-counting)
- 실제 비교는 매번 새 대화, Astra/ultra, 문서 읽기 1회와 답변으로 제한했다. 각 실행에 하위 에이전트·재시도는 없다. 입력+출력을 합산했고 추론·캐시는 부분집합으로 기록했다.
- 2차 캐시 입력은 두 조건 모두 53,376이었다. 입력은 65,269→58,202, 출력은 1,383→1,151, 그중 추론은 558→391이었다. 1차 캐시 상태는 달랐다. 표본·실행 순서·캐시·생성 변동 때문에 효과를 일반화하지 않는다.
- 각 조건을 번갈아 무작위 실행한 다수의 짝비교가 아니다. 같은 순서로 시작한 두 비동기 실행의 관측값이다.
- 측정 묶음은 봉인했다. 이후 현행 요약의 재현 명령 안내 오류와 기록 문서의 상태 설명을 고쳤지만 측정 묶음은 바꾸지 않았다. 정책·질문에 대한 정답은 그대로다.

## 초기 비용과 지금 주장할 수 있는 범위

정리·도구 제작·검토·두 차수 파일럿을 포함한 [초기 사용량 스냅샷](setup-usage-snapshot.json)은 **최소 5,090,144토큰**이다. 대부분은 반복된 캐시 입력이며 실제 청구액이 아니다. 보고서 마무리 이후 사용량은 이 스냅샷에 포함되지 않았다.
따라서 초기 작업량까지 회수한 **누적 순절감은 아직 입증되지 않았다**. 문서 준비 비용은 한 번 들고, 같은 작업을 반복할 때의 절감은 향후 별도로 누적해 확인해야 한다.

발표에는 다음처럼 범위를 함께 쓴다.

> FEELM의 현재 상태와 연구 이력을 분리하고 필요한 문서만 읽도록 개선해, 지정한 인계 문서 묶음의 토큰을 74.1% 줄였다. 같은 Astra/ultra를 사용한 제한된 인계 파일럿에서 총 토큰은 약 11% 적었고, 보완한 요청의 엄격한 답변 포함 기준은 2/5에서 4/5로 개선됐다. 초기 정리 비용 회수와 전체 업무 효과는 추가 측정이 필요하다.

## 다시 계산하기

저장소 루트에서 실행한다. 모델 API를 호출하지 않으며 제품 의존성과 분리된 가상환경을 쓴다.

```powershell
py -3 -m venv .codex-tmp/ai-efficiency/venv
.codex-tmp/ai-efficiency/venv/Scripts/python.exe -m pip install -r scripts/requirements-ai-efficiency.txt
.codex-tmp/ai-efficiency/venv/Scripts/python.exe scripts/measure_ai_efficiency.py bundle --manifest docs/ai-workflow/efficiency/manifest.json --output .codex-tmp/ai-efficiency/recount.json
py -3 scripts/measure_ai_efficiency.py usage --rollout docs/ai-workflow/efficiency/usage-m2.jsonl --output .codex-tmp/ai-efficiency/recount-usage.json
py -3 -m unittest discover -s scripts -p test_measure_ai_efficiency.py -v
```

`usage-*.jsonl`에는 사용량·모델·도구 횟수 등만 남겼다. 비밀값·원본 채팅·추론 내용은 내보내지 않았다. 답변은 `answer-*.txt`에 따로 보존한다.
새 비교는 동일 repo·데이터·질문·완료 기준·모델·추론을 고정하고 작업 단위로 순서를 무작위화한다. 실패·재시도·모든 자식 사용량을 포함하며, 결과가 나쁘다고 제거하지 않는다. 모델 가격 변경 효과는 문서 효과와 별도로 비교한다.
