## 4. 핵심 데이터 후보

### 원천 데이터

- `User`: 서비스 사용자. 인증된 정규화 이메일과 고유 닉네임을 포함하며 MovieLens 사용자와 ID 공간을 반드시 분리한다.
- `EmailVerification`: 회원가입 이메일 소유 확인 토큰·상태·만료 정보.
- `SocialIdentity`: `(provider, providerUserId)`로 식별하는 소셜 로그인 수단. 한 식별자는 한 `User`에만 귀속하며, 소셜 신규 가입 시 새 `User`와 함께 생성한다. 기존 User에는 로그인 후 설정에서 연결한다.
- `UserBlock`: 차단한 사용자와 차단된 사용자의 방향성 있는 관계.
- `UserProfileSettings`, `UserNotificationSettings`, `UserPrivacySettings`: 프로필·알림·공개 설정.
- `OttProvider`, `UserOttSubscription`: OTT 제공자와 사용자 구독 설정.
- `Movie`: 제목, 국가, 개봉연도, 장르, 태그, 줄거리, 감독, 배우 등의 카탈로그.
- `MovieOttOffer`: 영화별 OTT 제공 여부와 외부 링크.
- `OnboardingPreference`: 온보딩의 좋아요/싫어요 입력. 일반 `Rating`과 의미가 다르다.
- `Rating`: 감상 확인 후 나중에 입력할 수 있는 정수 1~5 만족도. 수정·삭제를 허용하며 삭제 시 파생 Frame·Popcorn도 삭제한다.
- `WatchIntent`: OTT 링크 클릭에서 시작한 감상 확인 상태와 시각.
- `ViewingRecord`: 실제 감상을 확인한 사실. Rating 없이도 존재할 수 있다.
- `Party`, `PartyMember`, `PartyInvitation`: 최대 4명의 파티, 구성원, 닉네임 기반 앱 내 초대·수락 상태.

### 파생 데이터 또는 읽기 모델

- `Frame`: 현재 Rating이 있는 감상 영화의 시각화·조회 단위. Rating 생성 후 만들고 Rating 삭제 시 제거한다.
- `Film`: 한 사용자의 프레임 모음. 별도 테이블보다 조회 모델일 수 있다.
- `Popcorn`: 프레임과 1:1인 취향 시각화 단위.
- `TasteProfile`: 장르·국가·시대·감독 등 요소별 집계와 사용자 벡터.
- `TasteKeyword`: 취향 분석 수치를 3~5개 키워드로 변환한 결과.
- `PopcornFlavor`: 데이터 분석 후 확정할 8개 팝콘 맛과 장르 매핑.
- `FlavorAggregate`: 팝콘 맛별 수량과 평균 평점. 수량과 선호도는 별도 값이다.
- `RecommendationCandidate`: 배치가 생성한 사용자별 Top-N 후보(원문 기준 500편).
- `RecommendationResult`, `RecommendationReason`: 노출용 추천과 XAI 근거.
- `PartyTasteAnalysis`, `PartyRecommendation`: 구성원별 예측을 집계한 파티 결과.

### 2차 MVP 데이터

- `TasteReport`, `ReportShare`, `ReportExport`: 반기 리포트, 서버 저장 외부 공유 링크, PNG 리포트의 객체 메타데이터. 바이너리는 비공개 S3 호환 객체 스토리지에 저장한다.
- `ShortReview`
- `TrendSnapshot`

### 확장 기능 데이터

- `UserRankingSnapshot`
- `BadgeProgress`, `BadgeAward`
- `CommunityPost`, `CommunityComment`

## 5. 반드시 지켜야 할 불변식

1. `MovieLensUserId`와 `ServiceUserId`를 같은 식별자로 취급하지 않는다.
2. 온보딩의 좋아요/싫어요는 일반 5단계 `Rating`과 구분해 저장하거나 명시적으로 매핑한다.
3. OTT 링크 클릭만으로 감상 완료, 프레임, 팝콘 또는 취향 집계를 생성하지 않는다.
4. 감상 확인 후 Rating은 나중에 남길 수 있다. 이 상태는 `WATCHED_UNRATED`이고, 최초 Rating 저장 후 `RATED`가 된다.
5. Rating은 정수 1~5이며 같은 영화의 평가는 수정·삭제할 수 있다. 재감상을 별도 기록 단위로 관리하지 않는다.
6. 프레임과 팝콘은 최초 Rating 저장 후 함께 생성되며 1:1로 대응한다.
7. Rating을 삭제하면 해당 Frame·Popcorn을 삭제하고 취향 집계에서 제거한다. `ViewingRecord`는 `WATCHED_UNRATED`로 유지한다.
8. Film은 사용자의 전체 Frame 모음이다.
9. 프레임이 없는 팝콘은 존재할 수 없다.
10. 팝콘 맛별 수량은 감상량이고, 맛별 평균 평점은 선호도다. 두 지표를 섞지 않는다.
11. 만료된 감상 확인은 추천·취향 신호로 사용하지 않는다.
12. `발견`은 새로운 맛의 영화를 실제로 평가 완료했을 때만 성립한다.
13. 온보딩 미선택 카드는 저장하지 않고 건너뛴 뒤 새 후보를 제공한다.
14. 정규화 이메일과 닉네임은 전체 사용자에서 유일해야 한다. 이메일 일치만으로 계정을 자동 통합하지 않는다.
15. 파티는 `Party`로 명명하며 `Group` 용어와 혼용하지 않고 최대 인원은 4명이다.
16. 활성 파티의 인원 구성이 바뀌면 기존 파티를 종료하며, 차단 관계의 사용자는 서로 검색·초대할 수 없고 영화 상세의 평가·한줄평을 포함한 작성자 콘텐츠를 볼 수 없다.
17. 구독하지 않은 OTT에서만 제공되는 영화도 추천 후보에서 제외하지 않는다.
18. 기본 추천 3개는 개인 맞춤 2개와 발견 1개로 구성한다. 발견 후보가 없으면 개인 맞춤 3개로 채우고 각 결과의 유형을 표시한다.
19. `ViewingRecord`가 있는 영화는 Rating 삭제 여부와 무관하게 개인·발견 추천 후보에서 제외한다.
20. Rating 등 추천 입력이 바뀌지 않으면 기본 추천 3개와 결과 버전을 유지하고 단순 재조회로 교체하지 않는다.
21. 리포트 공유 링크는 서버에 저장하며 외부 사용자를 대상으로 하고 생성 후 1개월 뒤 만료한다.
22. 리포트 파일은 PNG로 생성해 비공개 S3 호환 객체 스토리지에 저장하고 DB에는 메타데이터만 저장한다.
23. 영화 검색·상세는 비회원에게 공개한다. 사용자 프로필 데이터는 소유자가 공개한 경우에만 비회원에게 공개한다.
24. `관심없음` 제외 정책은 재검토 중이며 세 추천이 모두 마음에 들지 않을 때의 후속 동작은 확정 전까지 구현 계약에 넣지 않는다.
25. 추천 서비스 장애가 영화 조회·감상 평가 기능을 막지 않아야 한다.

## 6. 상태 흐름

### 감상 확인

```text
OTT_LINK_CLICKED
    ├─ 2일 경과 → CONFIRMATION_PENDING
    │                 ├─ 감상함 → WATCHED_UNRATED
    │                 │            └─ 나중에 Rating 1~5 입력 → RATED
    │                 │                                      ├─ Frame 생성
    │                 │                                      ├─ Popcorn 생성
    │                 │                                      ├─ 취향 집계 갱신
    │                 │                                      ├─ Rating 수정 → 파생 데이터 갱신
    │                 │                                      └─ Rating 삭제 → WATCHED_UNRATED로 복귀
    │                 │                                                         ├─ Frame·Popcorn 삭제
    │                 │                                                         ├─ 취향 집계에서 제거
    │                 │                                                         └─ ViewingRecord 유지 및 추천 제외
    │                 ├─ 감상하지 않음 → 상태 미정
    │                 └─ 클릭 후 7일 무응답 → EXPIRED
    └─ 반복 클릭 처리 → 미정
```

용어 표에는 확인 시점이 `2~3일 후`, FR-18에는 `2일 후`로 적혀 있어 확정이 필요하다.

### 추천 생성

```text
평가·감상 이벤트
    → 사용자 벡터 fold-in/집계
    → Spark 후보 Top-500 생성
    → 온라인 필터·재정렬
        ├─ ViewingRecord가 있는 감상 영화 제외 — Rating 삭제 후에도 제외
        └─ 미구독 OTT 작품은 제외하지 않음
    → 기본 3개 구성: 개인 맞춤 2 + 발견 1
        └─ 발견 후보 없음 → 개인 맞춤 3
    → XAI 근거 결합
    → 각 결과에 개인 맞춤/발견 유형과 resultVersion을 포함해 저장
    → Rating 등 추천 입력 변경 전까지 같은 3개 유지
```

세 추천이 모두 마음에 들지 않을 때 무변경 종료, `다른 추천 보기`, `관심없음` 중 어떤 후속 동작을 제공할지는 아직 결정하지 않았다.

### 파티 추천

```text
Party 생성(RECRUITING) → 닉네임 회원 조회 → 앱 내 초대(만료 없음) → 수락 — 최대 4명
    → 결과 생성 시 ACTIVE 및 구성 고정
    → 멤버별 예상 선호도 계산
    → 평균 만족도 + 최저 만족도 - 편차 페널티
    → Party Top-N + 공통점·차이점
    → 가입·탈퇴·강퇴·차단·회원 탈퇴로 구성 변경 → ENDED
```

점수식과 파티장 권한·위임 정책은 아직 없다. 종료된 파티 결과는 이력 조회용으로 보존하되 새 구성에는 재사용하지 않는다.

## 7. API와 내부 처리의 경계

- 공개 API 대상: 이메일 인증·구글·카카오·네이버 인증과 계정 연결, 닉네임·사용자 설정·차단, 비회원 영화 검색·상세, 추천 조회, OTT 클릭 기록, 감상 확인·지연 평가, 필름·취향 조회, 파티 초대·수락·종료, 반기 취향 리포트·외부 공유·다운로드, 공개 프로필·평가·필름·팝콘 조회·비교, 한줄평, 트렌드.
- 내부 비동기 처리: ALS 학습, 임베딩, 후보 생성, 취향 집계, 만료 처리, 캐시 갱신, 반기 리포트·트렌드 생성.
- 조회 모델 권장: Film, Popcorn Bucket, 추천 결과는 여러 원천 데이터를 합친 읽기 전용 응답으로 설계할 수 있다.
