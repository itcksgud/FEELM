## 4. 핵심 데이터 후보

### 원천 데이터

- `User`: 서비스 사용자. 닉네임을 포함하며 MovieLens 사용자와 ID 공간을 반드시 분리한다.
- `SocialIdentity`: 구글·카카오·네이버 계정과 서비스 사용자의 연결 정보.
- `UserProfileSettings`, `UserNotificationSettings`, `UserPrivacySettings`: 프로필·알림·공개 설정.
- `OttProvider`, `UserOttSubscription`: OTT 제공자와 사용자 구독 설정.
- `Movie`: 제목, 국가, 개봉연도, 장르, 태그, 줄거리, 감독, 배우 등의 카탈로그.
- `MovieOttOffer`: 영화별 OTT 제공 여부와 외부 링크.
- `OnboardingPreference`: 온보딩의 좋아요/싫어요 입력. 일반 `Rating`과 의미가 다르다.
- `Rating`: 감상 확인 후 나중에 입력할 수 있는 정수 1~5 만족도. 수정·삭제를 허용한다.
- `WatchIntent`: OTT 링크 클릭에서 시작한 감상 확인 상태와 시각.
- `ViewingRecord`: 실제 감상을 확인한 사실. Rating 없이도 존재할 수 있다.
- `Party`, `PartyMember`, `PartyInvitation`: 최대 4명의 파티, 구성원, 닉네임 기반 앱 내 초대·수락 상태.

### 파생 데이터 또는 읽기 모델

- `Frame`: 완료된 감상 1건의 시각화·조회 단위. `ViewingRecord`와 같은 원천을 공유할 가능성이 높다.
- `Film`: 한 사용자의 프레임 모음. 별도 테이블보다 조회 모델일 수 있다.
- `Popcorn`: 프레임과 1:1인 취향 시각화 단위.
- `TasteProfile`: 장르·국가·시대·감독 등 요소별 집계와 사용자 벡터.
- `TasteKeyword`: 취향 분석 수치를 3~5개 키워드로 변환한 결과.
- `PopcornFlavor`: 데이터 분석 후 확정할 8개 팝콘 맛과 장르 매핑.
- `FlavorAggregate`: 팝콘 맛별 수량과 평균 평점. 수량과 선호도는 별도 값이다.
- `RecommendationCandidate`: 배치가 생성한 사용자별 Top-N 후보(원문 기준 500편).
- `RecommendationResult`, `RecommendationReason`: 노출용 추천과 XAI 근거.
- `PartyTasteAnalysis`, `PartyRecommendation`: 구성원별 예측을 집계한 파티 결과.

### 2차 MVP 데이터

- `TasteReport`, `ReportShare`, `ReportExport`: 반기 리포트, 서버 저장 외부 공유 링크, 휴대폰 다운로드 결과.
- `ShortReview`
- `TrendSnapshot`

### 확장 기능 데이터

- `UserRankingSnapshot`
- `BadgeProgress`, `BadgeAward`
- `CommunityPost`, `CommunityComment`

## 5. 반드시 지켜야 할 불변식

1. `MovieLensUserId`와 `ServiceUserId`를 같은 식별자로 취급하지 않는다.
2. 온보딩의 좋아요/싫어요는 일반 5단계 `Rating`과 구분해 저장하거나 명시적으로 매핑한다.
3. OTT 링크 클릭만으로 감상 완료, 프레임, 팝콘 또는 취향 집계를 생성하지 않는다.
4. 감상 확인 후 Rating은 나중에 남길 수 있으며, Rating이 없는 `ViewingRecord`는 프레임·팝콘·취향 집계를 생성하지 않는다.
5. Rating은 정수 1~5이며 같은 영화의 평가는 수정·삭제할 수 있다. 재감상을 별도 기록 단위로 관리하지 않는다.
6. 프레임과 팝콘은 Rating까지 완료된 감상에서 함께 생성되며 1:1로 대응한다.
7. Film은 사용자의 전체 Frame 모음이다.
8. 프레임이 없는 팝콘은 존재할 수 없다.
9. 팝콘 맛별 수량은 감상량이고, 맛별 평균 평점은 선호도다. 두 지표를 섞지 않는다.
10. 만료된 감상 확인은 추천·취향 신호로 사용하지 않는다.
11. `발견`은 새로운 맛의 영화를 실제로 평가 완료했을 때만 성립한다.
12. 파티는 `Party`로 명명하며 `Group` 용어와 혼용하지 않고 최대 인원은 4명이다.
13. 구독하지 않은 OTT에서만 제공되는 영화도 추천 후보에서 제외하지 않는다.
14. 기본 추천 3개는 개인 맞춤 2개와 발견 1개로 구성한다. 발견 후보가 없으면 개인 맞춤 3개로 채우고 각 결과의 유형을 표시한다.
15. 리포트 공유 링크는 서버에 저장하며 외부 사용자를 대상으로 하고 생성 후 1개월 뒤 만료한다.
16. `관심없음` 기능과 추천 피드백 저장은 현재 범위에 포함하지 않는다.
17. 추천 서비스 장애가 영화 조회·감상 평가 기능을 막지 않아야 한다.

## 6. 상태 흐름

### 감상 확인

```text
OTT_LINK_CLICKED
    ├─ 2일 경과 → CONFIRMATION_PENDING
    │                 ├─ 감상함 → WATCHED_CONFIRMED
    │                 │            └─ 나중에 Rating 1~5 입력 → RATED_COMPLETED
    │                 │                                      ├─ Frame 생성
    │                 │                                      ├─ Popcorn 생성
    │                 │                                      ├─ 취향 집계 갱신
    │                 │                                      ├─ Rating 수정 → 파생 데이터 갱신
    │                 │                                      └─ Rating 삭제 → WATCHED_CONFIRMED로 복귀
    │                 │                                                         └─ 파생 데이터 처리 정책 미정
    │                 ├─ 감상하지 않음 → 상태 미정
    │                 └─ 클릭 후 7일 무응답 → EXPIRED
    └─ 반복 클릭 처리 → 미정
```

용어 표에는 확인 시점이 `2~3일 후`, FR-18에는 `2일 후`로 적혀 있어 확정이 필요하다.

### 추천 생성

```text
평가·감상 이벤트
    → 사용자 벡터 fold-in/집계
    → Spark 후보 Top-500 생성
    → 온라인 필터·재정렬 — 미구독 OTT 작품은 제외하지 않음
    → 기본 3개 구성: 개인 맞춤 2 + 발견 1
        └─ 발견 후보 없음 → 개인 맞춤 3
    → XAI 근거 결합
    → 각 결과에 개인 맞춤/발견 유형을 포함해 API 응답 및 캐시
```

### 파티 추천

```text
Party 생성 → 닉네임 회원 조회 → 앱 내 초대 → 수락 — 최대 4명
    → 멤버별 예상 선호도 계산
    → 평균 만족도 + 최저 만족도 - 편차 페널티
    → Party Top-N + 공통점·차이점
```

점수식, 초대 만료, 파티 종료·나가기·위임, 멤버 변경에 따른 재계산 정책은 아직 없다.

## 7. API와 내부 처리의 경계

- 공개 API 대상: 이메일·구글·카카오·네이버 인증, 닉네임·사용자 설정, 영화 검색·상세, 추천 조회, OTT 클릭 기록, 감상 확인·지연 평가, 필름·취향 조회, 파티 초대·수락, 반기 취향 리포트·외부 공유·다운로드, 공개 프로필·필름·팝콘 조회·비교, 한줄평, 트렌드.
- 내부 비동기 처리: ALS 학습, 임베딩, 후보 생성, 취향 집계, 만료 처리, 캐시 갱신, 반기 리포트·트렌드 생성.
- 조회 모델 권장: Film, Popcorn Bucket, 추천 결과는 여러 원천 데이터를 합친 읽기 전용 응답으로 설계할 수 있다.
