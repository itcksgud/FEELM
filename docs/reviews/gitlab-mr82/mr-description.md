## 배경과 병합 후 동작

이 MR은 **전처리가 끝난 데이터를 후속 ALS 작업이 받아도 되는지 검사하는 단계**를 추가합니다. 모델 학습 전 준비 작업을 119번에서 분리한 것이며, 학습·평가·모델 저장은 이번 업무에 포함되지 않습니다.

118번 전처리에는 허용 범위·단위를 벗어난 평점을 제외하고 사용자·영화별 최신 평점을 남긴 뒤 Parquet을 생성하는 로직이 있습니다. 이번 검사는 그 산출물을 읽어 약속한 형식이 유지되는지 확인합니다. 여기서 다시 평점을 보정하거나 중복을 정리하지 않고, 문제가 발견되면 실행을 실패시킵니다. 이는 코드의 처리 규칙을 설명한 것이며, 실제 MovieLens 원본에서 비정상 평점이 발견됐다는 보고는 아닙니다.

입력 루트 아래의 `ratings/`와 `service-movie-id-map/`을 읽습니다. 정상 입력이면 각 데이터의 건수를 출력하고 종료합니다. 후속 코드에서 호출하면 필요한 컬럼을 선택한 두 DataFrame과 건수를 받습니다. `--output-uri`를 지정해도 이 진입점은 결과 파일을 만들지 않습니다.

## 입력에 따라 실제로 달라지는 동작

| 들어온 데이터 | 현재 동작 | 리뷰에서 알아야 할 결과 |
| --- | --- | --- |
| 118번 규격의 정상 Parquet | 검사 후 건수 출력, 정상 종료 | 학습을 완료했다는 뜻은 아닙니다. |
| 허용 단위를 벗어난 평점(테스트에서 인위적으로 넣은 4.2점), 0 이하 ID, 필수 값 누락 | 실행 실패 | 문제가 있는 행만 버리고 계속 진행하지 않습니다. 평점 허용 범위는 0.5~5.0이며 단위는 0.5점입니다. |
| 같은 사용자·영화의 평점이 두 행 | 실행 실패 | 최신 평점을 고르는 책임은 앞선 전처리에 있습니다. |
| 필수 컬럼 누락 또는 타입 불일치 | 실행 실패 | 예를 들어 `rating`은 float여야 하며 double을 자동 변환하지 않습니다. 추가 컬럼은 허용하지만 반환 대상에서는 제외합니다. |
| 서비스 영화와 연결되지 않은 MovieLens 영화의 평점 | 평점 데이터에 보존 | 우리 서비스의 현재 카탈로그가 학습 입력을 제한하지 않습니다. |
| MovieLens에 없는 서비스 영화 | ID가 NULL이고 상태가 `SERVICE_ONLY_CONTENT_BASED`이면 보존 | 이 영화의 추천은 후속 콘텐츠 기반 처리 범위입니다. 이번 MR이 추천을 생성하지는 않습니다. |
| TMDb 연결이 모호한 서비스 영화 | ID가 NULL이고 상태가 `TMDB_ID_AMBIGUOUS`이면 보존 | 코드가 임의로 MovieLens ID를 선택하지 않습니다. |
| 빈 데이터 또는 `MATCHED` 서비스 영화가 0편 | 실행 실패 | MovieLens 평점 자체가 정상이어도, 서비스와 연결된 영화가 하나도 없으면 이 진입점을 사용할 수 없습니다. |

매핑에서는 서비스 영화 ID와 TMDb ID가 각각 유일해야 합니다. `MATCHED` 상태는 양의 MovieLens 영화 ID가 필요하고, 나머지 허용 상태는 MovieLens 영화 ID가 NULL이어야 합니다. 구현 근거는 [inputs.py](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E106/-/blob/aa5857fe8ec34ef563077f2f879be24db794b386/pipeline/spark/batch/train/inputs.py)입니다.

4.2와 6.0은 [test_rejects_invalid_ratings](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E106/-/blob/aa5857fe8ec34ef563077f2f879be24db794b386/pipeline/spark/tests/batch/test_als_inputs.py)가 정상 fixture의 평점 하나를 바꿔 넣는 값입니다. 각각 허용 단위와 범위를 벗어난 입력을 거부하는지 검사합니다. 테스트 통과는 이런 입력의 거부 동작을 증명하며, 실제 원본에 해당 값이 존재하거나 이런 검사가 얼마나 자주 필요한지는 증명하지 않습니다.

## 이미 정해진 범위와 이번 리뷰에서 확인할 선택

**입력 검증까지만 구현하는 범위와 미매핑 평점 보존은 267번 Jira에 명시돼 있습니다.** 미매핑 평점을 보존하는 목적은 학습 신호를 유지하는 것입니다. 기존 MR은 서비스에 노출할 ALS 후보를 후속 단계에서 `MATCHED` 매핑으로 제한한다고 설명합니다. 다만 평점을 더 보존했을 때 추천 품질이 얼마나 개선되는지는 아직 검증하지 않았습니다.

이번에 확인할 선택은 **서비스와 연결된 영화가 0편일 때 입력 단계 전체를 실패시킬 것인가**입니다. [현재 코드는 실패시킵니다](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E106/-/blob/aa5857fe8ec34ef563077f2f879be24db794b386/pipeline/spark/batch/train/inputs.py#L153). 그 결과 서비스 매핑 준비가 안 된 상태에서 MovieLens만 먼저 처리하는 것도 막힙니다.

서비스 연계 준비까지 확인하는 진입점이 목적이라면 이 조건을 유지할 수 있습니다. 서비스 매핑 준비와 무관하게 학습을 먼저 진행해야 한다면, 이 조건을 어느 단계에서 적용할지 조정해야 합니다. **실패 조건의 존재는 재현했지만, 이를 선택한 배경은 확인한 Jira·MR·README에 명시돼 있지 않습니다.** 구현 오류로 단정하기보다 작성자의 설명과 팀의 운영 순서를 확인할 부분입니다.

이상 행을 자동 보정하지 않고 전체 실패시키는 동작도 운영자가 알아야 합니다. 이는 118번의 정제 결과에 문제가 있음을 드러내지만, 일부 정상 데이터만으로 계속 진행하는 실행 방식은 지원하지 않습니다.

## 실행 설정의 의미

입력 경로와 seed, 분할 비율, 선호 평점 기준, 후보 수, ALS 비교 설정을 받습니다. 목표 우선순위는 CLI → 환경변수 → 기본값입니다. **현재 코드에는 아래 ‘남은 수정 사항’의 우선순위 오류가 있습니다.**

기본값은 seed 42, train/validation/test 비율 0.8/0.1/0.1, 선호 기준 4.0점, 후보 수 500입니다. ALS 비교 설정 4종도 제공하지만, 이 실행에서는 읽고 유효성을 확인할 뿐 분할이나 학습에 적용하지 않습니다. 이 기본값을 최종 모델 성능이 검증된 설정으로 승인하는 MR은 아닙니다. 전체 옵션과 실행 예시는 [pipeline/README.md](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E106/-/blob/aa5857fe8ec34ef563077f2f879be24db794b386/pipeline/README.md)에 있습니다.

## 검증 결과와 그 의미

Spark 4.1.3 / Python 3.10.12 / Java 21 컨테이너에서 다음을 독립적으로 확인했습니다.

| 검증 | 결과 | 확인한 범위 |
| --- | --- | --- |

| Ruff 정적 검사·포맷 검사, CLI 도움말 | 통과 | 코드 검사와 옵션 노출 |
| 118번 코드로 CSV fixture 전처리 → Parquet 저장 → 이번 MR CLI 실행 | **정상 종료: `ratings=2, service_movies=3, matched_service_movies=1`** | 작은 데이터에서 두 작업의 컬럼·타입·읽기 연계 |
| 위 실행에 `--output-uri` 추가 | 출력 파일 없음 | 검증 전용 진입점이라는 설명과 일치 |
| 빈 입력·잘못된 ID·double 평점·중복 서비스 ID·MATCHED 0편 입력 | 예상한 오류로 실패 | 본문에 설명한 거부 동작 |

기존 MR에 적힌 전처리 연계 결과를 재현했습니다. 다만 이 실행은 실제 PostgreSQL export와 MovieLens 32M 전체 데이터를 사용하지 않았습니다. 전체 데이터의 실행시간·메모리·매핑 건수, 추천 품질은 119번 통합 검증에서 확인할 범위입니다.

[GitLab 파이프라인 #181122](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E106/-/pipelines/181122)은 성공했지만, 실행 Job은 `backend-mr-test` 하나입니다. Spark 코드의 검증 근거는 위의 별도 실행 결과입니다.

검증 성공은 입력 전체의 의미적 정합성까지 보장하지 않습니다. 예를 들어 epoch와 UTC 시각이 같은 순간을 나타내는지, `MATCHED` 영화 ID가 평점 데이터에 실제로 등장하는지는 현재 검사하지 않습니다. 이런 검사가 이번 완료 조건에 포함된다고 단정하지 않으며, 후속 코드가 ‘검증 완료’만으로 이 성질까지 가정해서는 안 됩니다.

## 남은 수정 사항

현재 커밋에서 다음 두 문제를 재현했습니다. 설정 검증의 동작을 바로잡고 회귀 테스트를 추가하는 것을 승인 전 수정 사항으로 제안합니다.

1. **정상 CLI 값으로 잘못된 환경변수를 덮어쓸 수 없습니다.** `RECOMMENDATION_ALS_SEED=invalid`인 환경에서 `--seed 11`을 줘도 실패합니다. CLI를 읽기 전에 환경변수를 숫자로 바꾸기 때문입니다. 최종 사용할 값을 선택한 뒤 변환해야 합니다. [코드 위치](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E106/-/blob/aa5857fe8ec34ef563077f2f879be24db794b386/pipeline/spark/batch/train/settings.py#L84)
2. **ALS 정규화 값으로 NaN과 무한대를 허용합니다.** `--als-config 64:nan:10`과 `64:inf:10`이 통과합니다. 유한한 수인지 검사해야 합니다. 이번 진입점은 학습하지 않으므로 학습 실패를 재현한 것은 아니며, 잘못된 설정을 유효하다고 반환하는 문제를 확인했습니다. [코드 위치](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E106/-/blob/aa5857fe8ec34ef563077f2f879be24db794b386/pipeline/spark/batch/train/settings.py#L38)

## 영향 범위와 후속 작업

ALS 실행용 환경변수를 추가합니다. API, DB 스키마, 의존성·lock 파일과 배포 설정 변경은 없습니다. 기존 MR에는 267번을 먼저 병합하고 118번이 같은 산출물 계약을 유지하며, 계약 변경은 두 담당자가 조율하는 순서가 기록돼 있습니다.

후속 업무는 268번 시간순 데이터 분할, 269번 ALS 학습·모델 저장, 270번 후보 생성·평가, 119번 전체 데이터 통합 검증입니다. 이 MR의 승인은 해당 기능이나 추천 품질의 완료 승인을 포함하지 않습니다.
