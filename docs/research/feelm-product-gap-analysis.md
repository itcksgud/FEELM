# FEELM 제품 빈틈 및 경쟁 서비스 분석

- 팀: KOONGYA STUDIO
- 프로젝트: FEELM
- 작성일: 2026-08-28
- 문서 상태: 발표 작성 전 제품 검증용 초안
- 원칙: 외부 자료로 확인된 문제, 이용자 리뷰에서 관찰한 가설, FEELM 문서에서 발견한
  빈틈을 구분한다.

## 1. 결론

현재 FEELM의 핵심 문제는 다음과 같이 좁힐 수 있다.

> OTT마다 시청·평가 기록이 분리되어 사용자가 서비스를 옮길 때 취향 정보가 이어지지
> 않는다. 사용자는 각 OTT의 전체 카탈로그가 아니라 **자신이 만족할 영화가 어디에 더
> 많은지** 알기 어렵다.

개인 추천, 별점·한줄평, 취향 분석, 리포트, OTT 필터, 추천 이유는 이미 왓챠피디아,
JustWatch, Letterboxd, 각 OTT가 상당 부분 제공한다. 따라서 이 기능들을 묶었다는 사실만으로는
사용자가 기존 기록을 버리고 FEELM으로 이동할 이유가 부족하다.

따라서 FEELM의 우선 가치는 다음 두 단계를 연결하는 것이다.

1. 특정 OTT가 아니라 사용자에게 귀속되는 영화 감상·평가 기록을 유지한다.
2. 누적된 취향과 OTT별 현재 카탈로그를 비교해 **내가 만족할 영화가 많은 OTT와 구독
   조합**을 추천한다.

이는 `구독한 OTT 안에서 무엇을 볼지` 추천하는 기존 흐름보다 앞선 `어떤 OTT를 구독할지`
결정을 돕는 가치다. 파티 추천은 이후 `우리 파티가 함께 만족할 영화가 많은 OTT와 작품`을
찾는 확장으로 둔다. 단, 왓챠피디아도 OTT와 독립된 기록을 제공하므로 **통합 기록 자체는
차별점이 아니다. 통합 기록을 중립적인 OTT 선택으로 연결하는 것이 핵심 가설**이다.

아무 데이터도 없는 최초 사용자의 콜드 스타트는 해결할 수 없다. FEELM이 해결할 수 있는
것은 사용자가 직접 FEELM에 기록을 축적한 이후 OTT를 바꿔도 취향이 초기화되지 않는
`서비스 전환 콜드 스타트`다. 이 가치와 OTT 추천 효과는 아직 사용자 검증이 필요하다.

않는다. 키워드 집계도 하나의 리뷰가 여러 주제에 중복 포함될 수 있다.

## 3. 기존 OTT 이용자의 불편

### 3.1 확인된 주요 불편

| 불편 | 근거 | FEELM이 해결 가능한 정도 |
| --- | --- | --- |
| 구독료 부담 | 국내 OTT 이용자 3,000명 조사에서 42.5%가 가장 불편한 점으로 구독료 부담을 선택했다.[^1] | 중간. 가격을 낮출 수는 없지만 취향 적합 영화 수와 구독료를 함께 비교해 불필요한 구독 결정을 줄일 수 있다. |
| 특정 콘텐츠 때문에 서비스 이동·추가 구독 | 같은 조사에서 이동·추가 구독 의향자의 52.8%가 특정 콘텐츠를 이유로 들었다.[^1] | 높음 후보. 미감상 취향 적합 영화와 OTT별 카탈로그를 연결하면 이동·추가 구독 판단을 직접 도울 수 있다. |
| OTT 사이에서 이어지지 않는 시청·취향 기록 | Netflix는 프로필별 시청 활동과 평가를 자체 계정에 보존하고 CSV 또는 개인정보 사본으로 제공한다.[^17] Disney+도 사용자 활동·재생 데이터를 자체 서비스 운영에 사용한다고 명시한다.[^18] 비교한 공식 문서에서는 이 기록을 다른 OTT 추천으로 자동 전달하는 기능을 확인하지 못했다. | 중간~높음. 사용자가 FEELM에 직접 기록하면 이후 OTT를 바꿔도 하나의 취향 기록을 유지할 수 있다. 과거 기록의 자동 복구는 불가능하고 가져오기 지원 범위에 따라 달라진다. |
| 여러 서비스 사이의 탐색과 선택 | Accenture의 11개국 6,000명 조사에서 복수 스트리밍 서비스 이용자의 60%가 탐색 경험에 불편을 느꼈고, 44%가 볼거리를 찾는 데 6분 이상 썼다.[^2] | 중간. 세 편 압축과 제공처 필터가 선택을 도울 수 있으나 효과 검증이 필요하다. |
| 원하는 콘텐츠의 서비스별 편차 | 국내 2024년 조사에서 원하는 콘텐츠가 많다고 응답한 비율은 Netflix 61.1%, TVING 59.2%, Wavve 54.2%, Coupang Play 32.7%였다.[^3] | 중간~높음. 콘텐츠 공급 자체는 바꾸지 못하지만 개인별로 원하는 영화가 많은 서비스를 비교할 수 있다. |
| 추천이 현재 상황을 충분히 반영하지 못함 | 영화 선택과 평가는 기분, 시간, 동행자 같은 맥락에 따라 달라질 수 있다는 영화 추천 연구가 있다.[^4] | 현재 낮음. FEELM 개인 추천에는 현재 기분·러닝타임·지금 함께 보는 사람 같은 세션 맥락이 없다. |

### 3.2 OTT 문제에 관한 정직한 판단

- FEELM은 구독료 자체를 낮추거나 콘텐츠 독점을 없애지 못한다. 대신 사용자의 취향에 맞는
  미감상 영화와 가격을 함께 비교해 **어디에 비용을 지불할지** 판단하게 할 수 있다.
- FEELM이 개입할 수 있는 영역은 **OTT 구독 선택과 구독 후 영화 선택 과정**이다.
- 제공처 통합 검색과 필터도 이미 JustWatch가 무료로 제공한다. JustWatch는 이용 중인
  서비스, 구독·무료·대여·구매 조건을 필터링하고 개인 추천까지 제공한다.[^5]
- 따라서 `어디서 볼 수 있는지 알려준다`는 FEELM의 차별점이 아니라 기본 요건이다.
- `모든 OTT의 기록을 자동으로 가져온다`고 주장해서도 안 된다. Netflix처럼 사용자가
  내려받을 수 있는 데이터는 가져오기 후보가 될 수 있지만, 공개된 일괄 연동 수단이 없는
  서비스의 과거 기록은 사용자가 다시 확인하거나 FEELM에서 새로 쌓아야 한다.
- 최초 콜드 스타트는 피할 수 없다. 차별화 가설은 **한 번 FEELM에 쌓은 기록이 OTT 전환과
  관계없이 유지되고, 그 기록이 다음 구독 결정에 사용된다는 것**이다.

## 4. 왓챠피디아의 현재 경쟁력

공식 앱 설명을 기준으로 왓챠피디아는 다음을 이미 제공한다.[^6]

- 영화·시리즈·책·웹툰 별점과 감상 기록
- 7.5억 개 별점 데이터 기반 예상 별점과 추천
- 구독 중인 OTT와 관심 태그 기반 탐색
- 월말 결산과 취향 분석
- 팔로우 사용자의 평가·기록 피드와 매거진
- 한줄평부터 긴 감상까지의 기록

과거 공식 소개 자료에는 영화 상세의 `내가 좋아할 이유`도 제시되어 있다.[^7] 따라서
`추천 이유를 보여준다` 역시 FEELM만의 기능이라고 주장하기 어렵다.

2026년 8월 28일 확인한 앱 마켓 지표는 다음과 같다.

| 플랫폼 | 표시 평점 | 평가·리뷰 규모 | 해석 |
| --- | --- | --- | --- |
| Apple App Store | 4.6/5 | 약 2.2만 평가 | iOS에서는 전반적 만족도가 높다. |
| Google Play | 3.6/5 | 약 3.91만 리뷰 | Android에서는 상대적으로 낮지만 플랫폼·버전 차이가 있어 제품 전체 만족도로 단정할 수 없다. |

즉 왓챠피디아는 광범위하게 실패한 경쟁자가 아니다. 장기 이용자와 누적 기록을 가진 강한
선행 서비스이며, FEELM은 명확한 전환 이익이나 데이터 이관 수단 없이 정면 경쟁하기 어렵다.

공식 앱 설명에서 왓챠피디아는 사용자가 이미 구독 중인 OTT와 관심 태그를 설정해 콘텐츠를
탐색한다고 안내한다.[^6] 취향을 기준으로 `어떤 OTT를 새로 구독·유지·해지할지` 순위를
제공한다는 설명은 확인되지 않았다. 다만 왓챠피디아도 누적 평가와 제공처 정보를 보유하므로
기술적으로 구현할 수 없다고 단정해서는 안 된다. FEELM은 특정 OTT에 종속되지 않은 비교,
개인별 산출 근거, 가격 대비 추가 가치까지 실제 제품으로 증명해야 한다.

## 5. 왓챠피디아 리뷰에서 관찰한 불편

### 5.1 조사 방법

- Apple 공식 고객 리뷰 RSS의 최근 페이지를 조회했다.[^8]
- 10페이지를 조회하고 ID로 중복 제거한 결과 450개 리뷰가 남았다.
- 2025년 이후 리뷰는 149개, 2026년 리뷰는 50개였다.
- 2026년 50개 리뷰의 평균 별점은 4.38점이며 1~2점 리뷰는 4개였다.
- 아래 수치는 사전에 정한 키워드가 들어간 리뷰 수다. 감성 분석이나 모집단 추정치가 아니다.

### 5.2 2026년 리뷰에서 반복된 주제

| 재감상·N차 관람·중복 기록 | 13 | 같은 영화를 여러 번 본 날짜와 당시 감상을 각각 남기고 싶다는 요구가 반복됐다. | **FEELM도 현재 해결하지 못한다.** Rating과 ViewingRecord가 사용자·영화별 하나다. |

| 추천·예상 별점 | 4 | 추천을 긍정적으로 평가한 리뷰와 예상 별점을 숨기고 싶다는 리뷰가 함께 있었다. | 추천은 이미 경쟁력이 높은 영역이며 예측값 표시 여부도 사용자가 통제할 필요가 있다. |
| 오류·성능 | 3 | 앱 실행, 국가 설정, 알림 표시 오류가 있었다. | 구현 품질의 기본 요건이지 차별점은 아니다. |

Google Play의 2026년 공개 리뷰에서는 일본 콘텐츠의 인물·감상 가능 제공처 정보가
부정확하거나 업데이트되지 않는다는 의견과 콘텐츠 종류별 공개 범위를 나누고 싶다는 의견도
확인됐다.[^9] 이는 메타데이터 최신성과 세분화된 공개 정책을 검증해야 한다는 가설로만 사용한다.

### 5.3 리뷰에서 바로 가져오면 안 되는 결론

- 재감상 요구가 반복됐다고 해서 모든 사용자의 최우선 문제라고 말할 수는 없다.
- 높은 별점 리뷰 안의 기능 요청이 많으므로 이는 이탈 이유보다 충성 사용자의 개선 요구일
  가능성이 크다.
- 왓챠피디아의 빈틈을 그대로 모두 구현하면 FEELM의 범위만 커지고 핵심 차별점은 흐려진다.

| OTT 제공처 필터 | 자기 서비스만 표시 | 구독 OTT 설정 | JustWatch의 핵심 기능 | 구독 정보 기준 정렬·외부 연결 | 낮음 |

| 취향 기반 OTT 구독 선택 | 자기 카탈로그 안에서 추천 | 구독 OTT 설정 후 탐색 | JustWatch는 선택한 제공처 기반 추천 | 현재 요구사항에 없음 | **높음 후보. 개인별 OTT 순위·증분 가치·가격 효율을 구현하고 검증해야 함** |

| 여러 사람의 취향 결합 | 개인 프로필 중심 | 공식 핵심 기능에서 확인 안 됨 | 공유 목록은 있으나 비교 서비스 문서에서 파티 추천은 확인 안 됨 | 최대 4명 파티 추천·팝콘 보기 | **높은 확장 가치. 개인 OTT 선택 모델 검증 후 파티 단위로 확장** |

## 7. FEELM과 왓챠피디아의 객관적 비교

아래 평점은 구현 품질 점수가 아니라 FEELM은 현재 문서의 제품 준비도, 왓챠피디아는 공개된
기능·이용 지표·초기 성장 자료를 5점 척도로 비교한 것이다. 왓챠피디아의 내부 요구사항과
데이터 계약은 공개되지 않았으므로 해당 항목을 임의로 추정하지 않는다.

| 평가 항목 | FEELM | 왓챠피디아 | 비교 판단 |
| --- | ---: | ---: | --- |
| 문제의 외부 근거 | 4/5 | 5/5 | FEELM은 구독료·콘텐츠 이동 문제의 조사 근거는 있으나 목표 사용자를 직접 검증하지 않았다. 왓챠피디아는 누적 가입자와 평가 행동으로 기록·추천 수요를 실제 시장에서 확인했다.[^21] |
| 차별화 명확성 | 4/5 | 4/5 | FEELM은 `누적 취향에 따른 OTT 구독 선택`이 선명하지만 아직 가설이다. 왓챠피디아는 예상 별점과 개인화 추천으로 초기 차별화를 만들었고 대규모 데이터 우위를 축적했지만, 현재는 유사 기능이 많다. |
| 요구사항·데이터 계약 | 2/5 | 평가 불가 | FEELM API·ERD에는 OTT별 적합도, 증분 가치, 가격과 카탈로그 시점이 없다. 왓챠피디아 내부 계약은 공개 자료로 평가할 수 없다. |
| 데이터 준비도 | 3/5 | 5/5 | FEELM은 MovieLens·Tag Genome·TMDb 기반이 있으나 실제 국내 사용자와 최신 요금·카탈로그 보정이 필요하다. 왓챠피디아는 공식 자료 기준 7.5억 개 이상의 누적 별점을 보유한다.[^21] |
| 초기 사용자 획득 가능성 | 2/5 | 4/5 | FEELM은 첫 결과 전 입력 부담과 이관 부재가 남는다. 초기 왓챠는 영화 검색 노출과 모바일 접근성을 확보하고, 짧은 별점 입력 뒤 예상 별점이라는 즉시 보상을 제공했다.[^19][^20] |
| 반복 사용 동기 | 2/5 | 4/5 | FEELM의 OTT 변경은 저빈도 행동이다. 왓챠피디아는 영화 탐색 전 예상 별점, 감상 후 평가·기록, 피드, 월간 결산을 한 루프로 연결했다.[^6][^22] 공식 미디어킷은 주간 12.2회 방문을 제시하지만 자체 광고 자료라는 한계가 있다.[^21] |
| 해결 효과 검증 | 1/5 | 3/5 | FEELM은 OTT 선택·감상 만족 실험이 없다. 왓챠피디아는 장기간의 실제 이용과 대규모 평가 축적은 확인되지만, 추천이 선택 시간이나 감상 만족을 얼마나 개선했는지 보여주는 공개 대조 실험은 확인하지 못했다. |

### 7.1 왓챠피디아는 콜드 스타트를 없애지 않고 입력을 활성화했다

초기 왓챠는 모바일에서 약 20편, 웹에서 약 30편의 별점을 먼저 받아 추천을 시작했다.[^19]
아무 데이터 없이 개인 취향을 알아낸 것이 아니라 사용자가 직접 입력하게 했다. 대신 입력
직후 아직 보지 않은 영화의 예상 별점과 개인 추천을 보여줘 `평가 노동`을 `내 취향을 맞혀
보는 테스트`로 바꿨다.

2013년 모바일 앱 출시 당시 공개 수치는 회원 약 14만 명, 별점 약 1,014만 개였다.[^20]
단순 계산하면 회원당 평균 약 72개로, 가입 이후 평가 행동까지 활성화됐음을 보여준다. 다만
이 평균은 사용자별 분포와 잔존율을 설명하지 않으므로 모든 가입자가 활발했다고 해석해서는
안 된다.

초기 획득과 활성화 구조는 다음과 같이 정리할 수 있다.

1. 영화 검색 결과에 왓챠 평균 별점을 노출해 서비스 밖의 검색 수요를 유입시켰다.[^20]
2. 모바일 앱으로 영화관과 일상에서 검색·평가할 수 있게 접근성을 높였다.[^20]
3. 익숙한 영화 20~30편을 빠르게 평가하게 했다.[^19]
4. 예상 별점과 추천으로 즉시 정확도를 체험하게 했다.
5. 더 평가할수록 추천이 정교해진다는 보상으로 추가 입력을 유도했다.[^19]

### 7.2 왓챠피디아는 추천보다 넓은 반복 루프를 만들었다

왓챠피디아는 한 번 추천받고 끝나는 도구가 아니라 영화 감상 전후에 모두 사용할 이유를
만들었다.

> 작품 검색·예상 별점 확인 → 감상 → 별점·한줄평 기록 → 취향 갱신 → 다음 작품 탐색

현재 공식 설명에는 예상 별점, 맞춤 추천, 개인 아카이브, 팔로우 피드와 매거진이 포함돼
있다.[^6] 월 3편 이상을 기록하면 월간 감상 통계와 이용자 경향을 보여주는 결산도 제공한다.[^22]
누적 기록은 추천 품질뿐 아니라 개인 영화 아카이브가 되므로, 사용자는 새 영화를 고를 때와
본 영화를 남길 때 모두 돌아올 수 있다.

FEELM에 필요한 대응은 콜드 스타트 제거가 아니다. 일정 수의 영화를 평가한 직후 `내 취향
영화가 가장 많은 OTT`, OTT별 미감상 적합 영화와 대표 근거를 공개해 초기 입력의 보상을
분명히 해야 한다. 반복 사용은 저빈도인 OTT 구독 진단을 `오늘 볼 영화 → 감상 기록 → 취향과
OTT 순위 갱신 → 결제 전 재진단`과 연결해야 한다.

**잠정 종합 판단: FEELM의 문제와 차별화 가설은 선명해졌지만, 왓챠피디아가 이미 증명한
`입력 직후의 보상`과 `감상 전후의 반복 루프`가 없다. 현재 명세는 이전 제품 중심에 머물러
있고 최초 데이터 입력·반복 사용·해결 효과는 여전히 초기 단계다.**

## 8. FEELM의 핵심 빈틈

### P0 — 발표 전에 결정하거나 검증할 항목

#### 8.1 목표 사용자와 한 문장 문제를 새 핵심에 맞춰 검증해야 한다

우선 목표 사용자는 영화를 주로 보고, 현재 구독을 유지하거나 다른 OTT로 옮길 때 자신의
취향에 맞는 영화가 어디에 많은지 판단하기 어려운 사람이다.

검증할 후보 문장:

> OTT를 바꿀 때마다 서비스 안의 시청·취향 정보는 이어지지 않는다. FEELM은 사용자가 직접
> 쌓은 영화 기록을 OTT와 독립적으로 유지하고, 아직 보지 않은 취향 적합 영화가 많은 OTT와
> 구독 조합을 추천한다.

프로젝트가 영화만 다루므로 `OTT 전체 만족도`를 예측한다고 표현하면 안 된다. 드라마,
스포츠, 키즈 콘텐츠, 화질, 광고, 동시 접속도 구독 선택에 영향을 준다. 결과에는 반드시
`영화 취향 기준`이라는 범위와 카탈로그 기준일을 표시한다.

#### 8.2 OTT 추천 점수와 결과 계약이 없다

현재 요구사항·OpenAPI·ERD에는 다음 핵심 값이 없다.

- 사용자별 미감상 영화의 예상 선호도와 신뢰도
- `취향 적합 영화`로 셀 최소 기준 또는 사용자별 보정 기준
- OTT별 취향 적합 영화 수와 예상 만족도
- 현재 구독 서비스와 겹치지 않는 증분 영화 수
- 특정 OTT에서만 볼 수 있는 취향 적합 영화 수
- 요금제별 가격, 광고·화질 등 비교 범위와 가격 대비 가치
- 카탈로그 지역·기준일·마지막 동기화 시각
- 추천된 OTT와 산출 근거, 모델·카탈로그 버전

단순히 영화 수가 많은 OTT가 1위가 되면 개인화가 아니다. 이미 본 작품과 낮은 예상 선호
작품을 제외하고, 현재 구독과의 중복·다양성·가격을 함께 고려하는 점수 계약이 필요하다.

#### 8.3 최초 콜드 스타트와 서비스 전환 콜드 스타트를 구분해야 한다

아무 기록도 없는 최초 사용자의 취향을 정확히 알아내는 것은 불가능하다. 인기작이나
온보딩 선택은 임시 추천일 뿐 콜드 스타트의 해결이 아니다. 따라서 `차차 찾아갈래요` 이후의
결과에는 데이터 부족과 낮은 신뢰도를 그대로 표시해야 한다.

반면 사용자가 FEELM에 기록을 쌓은 이후에는 OTT를 바꾸더라도 같은 취향 정보를 계속 사용할
수 있다. 이것이 FEELM이 해결하려는 `서비스 전환 콜드 스타트`다. Netflix 시청 활동 CSV나
개인정보 사본은 과거 기록 가져오기의 후보지만[^17], 다른 OTT까지 자동 동기화한다고 약속할
근거는 없다. 가져오지 못한 기록은 사용자가 FEELM에서 직접 확인해야 한다.

필요한 결정:

- 무평가·저평가 사용자에게 표시할 데이터 부족 상태와 추천 신뢰도
- 최소 평가 수 이전에는 OTT 순위를 제공할지, 참고 결과만 제공할지
- 감상 여부와 좋아함·싫어함을 구분하는 입력 방식
- Netflix CSV의 작품명·시리즈·프로필을 FEELM 영화 ID로 매핑하는 기준
- 가져오기 실패·중복·오매핑의 확인 및 되돌리기 방식

#### 8.4 파티 추천의 공정성 규칙이 부족하다

OpenAPI 응답에는 평균 만족도, 최저 만족도, 편차 페널티가 존재한다. 그러나 다음 계약은
명확하지 않다.

- 세 값을 어떤 가중치와 순서로 결합하는가
- 한 명에게 평가 데이터가 거의 없을 때 어떻게 처리하는가
- 파티원 중 한 명이라도 이미 본 영화는 제외하는가
- 파티원들이 구독한 OTT의 교집합과 합집합 중 무엇을 사용하는가
- 최저 만족도를 어디까지 보장하거나 설명하는가
- 파티원이 특정 후보를 거절했을 때 파티 전체 추천에서 어떻게 반영하는가

파티는 개인 OTT 선택 모델이 검증된 뒤 `우리 파티가 함께 만족할 영화가 많은 OTT와 작품`을
찾는 확장으로 둔다. 공정성 규칙은 화면 애니메이션보다 먼저 확정돼야 한다.

#### 8.5 `관심없음`이 너무 많은 의미를 한 상태로 합친다

현재 `관심없음`은 영화를 이후 추천에서 제외한다. 하지만 사용자가 후보를 넘기는 이유는
취향 불일치뿐 아니라 `지금 기분과 안 맞음`, `러닝타임이 김`, `이미 봄`, `해당 OTT가 없음`,
`다음에 보고 싶음`일 수 있다.

최소한 다음 상태를 분리할지 검증해야 한다.

- 관심없음: 장기적인 부정 취향 신호
- 지금은 아님: 현재 세션에서만 제외
- 이미 봤음: 감상 이력 확인 또는 평가 유도
- 보고싶어요: 저장 후 나중에 다시 확인

#### 8.6 세 편과 2:1 비율에는 아직 근거가 없다

선택 과부하는 항상 선택지가 적을수록 줄어드는 단순한 효과가 아니다. 메타분석에서는
과제 난이도, 선호 불확실성, 선택지 복잡도에 따라 효과가 달라졌고, 다른 메타분석의 평균
효과는 거의 0에 가까웠다.[^14]

따라서 `3편이 최적`이라고 발표하지 말고 다음을 비교해야 한다.

- 3편 대 6편 또는 스크롤 목록
- 선택 완료율과 선택 시간
- 후보의 매력도·다양성·선택 확신도
- 추가 추천 요청률과 관심없음 비율

### P1 — MVP 계약에 추가 검토할 항목

#### 8.7 재감상 구조가 없다

현재 `rating(user_id, movie_id)`와 `viewing_history(user_id, movie_id)`가 각각 UNIQUE다.
따라서 여러 감상 날짜, 회차별 감상평, 재감상 횟수를 저장할 수 없다. 왓챠피디아 최신
리뷰에서 가장 반복된 요구와 동일한 빈틈이다.

권장 방향은 현재 대표 Rating과 여러 개의 ViewingEvent를 분리하는 것이다.

#### 8.8 팝콘 맛이 실제 취향을 지나치게 단순화할 수 있다

- 한 영화는 여러 장르를 가지지만 현재 문서는 대표 맛 하나를 산출한다.
- `Documentary·War·Western`처럼 성격이 다른 장르가 한 맛에 묶여 있다.
- 감상 수와 단순 평균만으로는 1편에 5점을 준 취향과 20편에 평균 4점을 준 취향의 신뢰도를
  구분하기 어렵다.
- `새로운 맛`의 임계치가 아직 미확정이다.

팝콘은 재미있는 시각 언어지만 분석 정확성을 증명하지 못하면 장식으로 보일 수 있다.
다중 장르 가중치, 최소 표본 수, 신뢰도 또는 보정 평균, 사용자 이해도 테스트가 필요하다.

#### 8.9 반기 리포트는 피드백 주기가 너무 길 수 있다

왓챠피디아는 월말 결산을 제공한다. FEELM은 더 상세한 반기 리포트를 계획하지만 신규 사용자가
가치를 느끼기까지 최대 6개월이 걸릴 수 있다.

가벼운 실시간·월간 팝콘 변화와 상세 반기 리포트를 분리하는 방안을 검토한다.

#### 8.10 기록 가져오기·내보내기가 없다

왓챠피디아나 Letterboxd 장기 사용자는 기존 기록 자체가 전환 비용이다. Letterboxd는 CSV
가져오기·내보내기와 IMDb 이관을 공식 지원한다. Netflix는 프로필별 시청 활동 CSV와 개인
데이터 사본을 제공한다.[^17] FEELM은 데이터 이관이 없어 이미 영화를 많이 본 사용자의
과거 감상 여부를 다시 입력하게 한다. 가져오기와 내보내기는 편의 기능을 넘어 `OTT가 바뀌어도
기록은 사용자에게 남는다`는 핵심 가치의 신뢰 조건이다.

#### 8.11 개인정보 수집 목적과 공개 단위가 불명확하다

- 닉네임 외 나이와 성별이 회원가입 필수다.
- MovieLens 32M에는 인구통계가 없고 현재 추천 계약도 나이·성별을 어떻게 사용하는지
  설명하지 않는다.
- 사용 목적이 없다면 가입 마찰과 관리 범위만 늘어난다.
- 프로필·팝콘 공개와 영화별 점수·한줄평 공개가 사용자가 기대하는 단위로 분리되는지
  확인해야 한다.

나이·성별을 필수로 유지하려면 사용자 가치와 모델 사용 목적을 설명하고, 그렇지 않으면
선택값 또는 미수집을 검토한다.

#### 8.12 OTT 제공처·가격 데이터의 정확성 운영이 없다

TMDb의 제공처 데이터는 국가별 필터가 가능하며 JustWatch 기반 데이터다.[^15] FEELM은 다음을
정해야 한다.

- 대한민국 지역을 항상 명시하는가
- 마지막 동기화 시각과 갱신 주기
- 제공 종료·잘못된 링크 신고 및 수정 경로
- JustWatch 출처 표기 조건
- 정보가 없거나 서로 충돌할 때의 화면 처리
- OTT별 요금제·가격·광고·화질 정보를 어느 출처와 주기로 갱신하는가
- 작품 제공처와 가격 정보의 기준일이 다를 때 어떻게 경고하는가

#### 8.13 추천 설명이 문자열 하나에 머문다

OpenAPI의 설명은 문자열이다. XAI를 주장하려면 최소한 다음 구조가 필요하다.

- 근거 유형: 장르·태그·감독·배우·유사 사용자·OTT 증분 가치·파티 합의
- 근거가 된 사용자 행동 또는 영화
- 요인별 기여도나 우선순위
- 모델·입력 버전과 설명 생성 버전
- 설명과 실제 추천 점수가 불일치하지 않는 검증

### P2 — 핵심 검증 뒤로 미룰 항목

- 상영관 매출 랭킹
- 탐험 배지
- 오늘의 영화
- 범용 커뮤니티
- 복잡한 공유 카드 확장

이 기능들은 재미와 체류를 늘릴 수 있지만 파티 선택과 탐험 추천이 유효한지 검증하기 전에
추가하면 핵심 가설을 흐릴 가능성이 크다.

## 9. 데이터와 기술에 대한 객관적 평가

### 9.1 강점

- MovieLens 32M의 3,200만 평가와 Tag Genome은 추천 실험과 분산 처리 학습에 충분히 크다.
- TMDb ID 매핑률을 확인해 메타데이터 보강 경로를 준비했다.
- 서비스 사용자와 MovieLens 사용자를 분리하고 fold-in하는 데이터 정책은 타당하다.
- 추천 결과·이유·피드백·모델 버전을 보존하는 계약은 평가 재현성에 유리하다.
- OTT와 독립된 Film·Frame 기록은 사용자가 서비스를 옮겨도 동일한 취향 모델을 유지하는
  기반이 될 수 있다.

### 9.2 한계

- MovieLens 32M은 1995~2023년 MovieLens 이용자 행동이며 한국 FEELM 사용자의 대표 표본이
  아니다.
- 포함 사용자는 모두 최소 20편을 평가했고 인구통계 정보가 없다. 신규 사용자와 국내
  세그먼트의 품질·공정성을 이 데이터만으로 확인할 수 없다.[^13]
- MovieLens에서 높은 오프라인 정확도가 실제 서비스 우수성을 보장하지 않는다는 연구가
  있다. 상호작용 생성 맥락과 사용자의 영화 지식이 실제 서비스와 다르기 때문이다.[^16]
- MovieLens 32M은 비상업 연구용 조건이 있으므로 수익 서비스로 발전할 경우 별도 허가
  검토가 필요하다.[^13]
- TMDb 제공처 정보만으로는 요금제, 가격, 광고, 화질과 같은 구독 조건을 계산할 수 없다.
  대한민국 카탈로그와 가격의 별도 출처·갱신 주기·기준일이 필요하다.
- `시청함`만으로는 만족도를 알 수 없다. OTT 기록을 가져오더라도 사용자가 좋음·싫어함을
  평가하지 않은 작품에는 시청 완료 여부와 취향 신호를 구분하는 정책이 필요하다.
- 자동 연동이 없는 OTT의 과거 기록은 FEELM이 복구할 수 없다. 직접 기록이 핵심 입력이라면
  입력 부담과 누락 편향을 제품 평가에 포함해야 한다.
- HDFS·Spark는 SSAFY 빅데이터 목표에는 맞지만 현재 서비스 트래픽에 필요한지 별개의
  문제다. 단일 머신 대비 데이터 규모·노드 수·처리 시간의 실험으로 정당화해야 한다.

## 10. 발표 전에 수행할 최소 검증

### 10.1 사용자 인터뷰

다음 조건의 사용자를 분리해서 확인한다.

- 혼자 영화를 주로 고르는 사용자
- OTT 하나만 구독한 사용자와 여러 개를 구독한 사용자
- 최근 OTT를 추가·해지·이동한 사용자
- OTT를 옮긴 뒤 추천이 처음부터 다시 시작된다고 느낀 사용자
- 왓챠피디아·Letterboxd 장기 기록 사용자
- 연인·친구·가족과 함께 고르는 사용자

핵심 질문:

1. 최근 OTT를 구독·유지·해지한 실제 과정을 처음부터 끝까지 설명해 달라.
2. 가격 외에 어떤 영화나 카탈로그 정보가 결정에 영향을 주었는가.
3. 다른 OTT에서 본 기록이나 취향이 새 OTT 추천에 반영되지 않아 불편했던 실제 사례가
   있는가.
4. `내 취향 영화가 가장 많은 OTT` 결과를 받는다면 어떤 근거를 확인해야 믿겠는가.
5. 과거 기록을 자동으로 가져올 수 없다면 FEELM에 직접 감상·평가를 쌓을 의향이 있는가.
6. OTT를 결정한 이후에도 FEELM을 다시 사용할 순간은 언제인가.
7. 다른 사람과 볼 때 누구의 취향과 구독 서비스가 어떻게 반영돼야 하는가.

### 10.2 프로토타입 비교

| 실험 | 비교 | 핵심 지표 |
| --- | --- | --- |
| OTT 선택 | 인기·전체 영화 수 순위 대 개인 취향 적합 OTT 순위 | 선택 변경률, 결정 시간, 확신도, 설명 이해도 |
| 결과 단위 | 적합 작품 수만 표시 대 예상 만족도·독점·중복·가격 효율 표시 | 신뢰도, 유용한 근거 선택률, 과잉 확신 |
| 기록 입력 | 직접 10편 평가 대 Netflix CSV 가져오기 후 추가 평가 | 완료율, 소요 시간, 매핑 오류율, 첫 결과 수용도 |
| 반복 가치 | 구독 시점 진단만 제공 대 구독 진단+오늘 볼 영화+카탈로그 변화 제공 | 재방문 의향, 알림 허용률, 월간 사용 빈도 |
| 후보 수 | 3편 대 6편·스크롤 | 선택 시간, 완료율, 확신도, 추가 추천률 |
| 추천 구성 | 취향 3편 대 취향 2+탐험 1 | 선택률, 만족도, 새 장르 수용도 |
| 파티 방식 | 각자 목록 공유 대 FEELM 파티 추천 | 합의 시간, 최저 개인 만족도, 대화 횟수 |
| 팝콘 표현 | 일반 장르 차트 대 팝콘 8종 | 이해 정확도, 재미, 신뢰도 |
| 피드백 | 관심없음 하나 대 이유 분리 | 잘못된 영구 제외율, 후속 추천 만족도 |

### 10.3 성공 기준 예시

구체적인 수치는 사용자 실험 설계에서 확정하되 최소한 다음 방향을 측정한다.

- 인기순·전체 작품 수보다 개인 취향 기반 OTT 순위가 선택 확신도를 높이는가
- 추천된 OTT의 상위 근거 영화를 실제로 보고 만족하는가
- 기존 구독과 겹치지 않는 취향 적합 영화 수가 추가·해지 판단에 영향을 주는가
- 직접 기록 또는 가져오기 과정의 완료율이 제품 사용이 가능한 수준인가
- 구독 결정 이후 오늘 볼 영화와 카탈로그 변화가 반복 사용으로 이어지는가
- 기존 방식보다 영화 선택 시간이 줄어드는가
- 선택하지 못하고 종료하는 비율이 줄어드는가
- 파티원 중 만족도가 가장 낮은 사람의 점수가 개선되는가
- 탐험 후보가 단순히 무시되지 않고 실제 선택·감상으로 이어지는가
- 추천 설명이 선택 확신도를 높이는가

## 11. 발표 방향에 대한 권고

지금 단계에서 발표의 중심을 `기존 OTT 추천이 나쁘다`에 두면 반박받기 쉽다. 기존 OTT는
자기 카탈로그 안에서 추천을 최적화한다. FEELM은 그보다 앞선 구독 선택 문제를 다음처럼
좁혀야 한다.

> OTT를 바꾸면 이전 서비스에서 쌓인 시청·취향 정보는 새 서비스의 추천으로 이어지지
> 않는다. FEELM은 사용자가 직접 쌓은 영화 기록을 특정 OTT가 아닌 개인에게 남기고,
> 누적된 취향과 각 OTT의 현재 영화 카탈로그를 비교해 내가 만족할 영화가 많은 OTT를
> 알려준다. 구독 후에는 그 안에서 오늘 볼 영화까지 추천한다.

범위는 `영화 취향 기준`이다. `왓챠피디아가 기술적으로 절대 할 수 없다`, `모든 OTT 기록을
자동으로 가져온다`, `구독 만족도를 완전히 예측한다`고 주장하지 않는다. 사용자 인터뷰와
프로토타입에서 OTT 선택 시간·확신도와 실제 감상 만족이 개선되는지 확인한 뒤 발표 주장으로
승격한다. 파티는 동일한 모델을 `우리 파티가 함께 만족할 영화가 많은 OTT와 작품`으로
확장하는 후속 가치로 설명한다.
