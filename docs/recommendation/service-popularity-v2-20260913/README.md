# 추천 재설계 v2 — 대중성을 후보와 개인 예측에 함께 반영

상태: **DRAFT · 로컬 재설계** · 2026-09-13. 새 학습·서비스 적용은 아직 수행하지 않았다.

**GBT에 TMDB와 KOBIS를 서로 다른 정보로 넣고, 사용자가 각 정보에 어떻게 반응했는지와
그 근거 편수까지 함께 학습한다. 한쪽 정보가 없어도 다른 쪽을 사용할 수 있게 만든다.
ALS는 평점 기반 점수를 유지하되, 새 GBT의 정보를 결합 단계에서 다시 덮어버리는지도 비교한다.**

이 문서가 대중성 처리의 최신 설계다. 이전 v1의 **KOBIS 후보에도 TMDB Q 필수**, **Q20+KOBIS5
고정 배분**, **후보만 바꾸고 최종 예측기는 그대로 사용**하는 안을 대체한다.
이전 문서·실험·감사 봉인은 당시 기록으로 보존한다.

## 1. 기존 방식에서 실제로 놓친 부분

| 현재 구성 | 확인한 사실 | 수정할 점 |
| --- | --- | --- |
| GBT | 230개 특징 중 30개가 TMDB 평점·투표 수·popularity 및 사용자 반응 | KOBIS와 새 결측 상황까지 포함해 새 특징 버전으로 재학습 필요 |
| TMDB 평점 처리 | 투표수가 적으면 학습 영화 기준 평균 쪽으로 축소하는 처리가 이미 있음 | 투표1개·10점을 그대로 강한 평가로 쓰는 모델이라고 설명하면 안 됨 |
| 자료 없음 처리 | 숫자와 present 플래그는 있지만, 선정 나무는 후보의 present 3열을 분기에 사용하지 않음 | 결측을 입력할 수 있다는 것과 결측을 잘 학습했다는 것을 구분 |
| ALS | 사용자 평점으로 만든 영화 factor와 fold-in을 사용. TMDB·KOBIS 직접 입력 없음 | 외부 관객 수를 ALS 입력 별점이나 학습 평가 수로 대체하지 않음 |
| ALS+GBT | 영화의 ML 학습 평가가 많으면 기존 shrink100은 ALS에 큰 비중 | 새 대중성 정보를 반영한 GBT가 묻히지 않는지 결합을 별도로 확인 |

실제 GBT의 분기 3,713개 중 1,022개가 대중 지표 30열을 사용했다. 이것은 **분기 횟수**이지
중요도나 인과 기여율이 아니다. 기존 카탈로그에 투표 수·popularity 결측이 없었던 점도
새 결측 처리를 검증해야 하는 이유다. [코드·모델 현물 감사](../../../outputs/recommendation-evidence/popularity-redesign-20260913/model-feature-audit.md).

## 2. GBT가 받을 정보

‘대중성’이라는 이름 아래 다음을 하나의 원점수로 합치지 않는다.

| 입력 | 무엇을 뜻하는가 | 사용자에게서 함께 계산할 정보 |
| --- | --- | --- |
| TMDB 보정 평균평점 | 투표 근거를 고려한 대중의 평가 | 대중평가가 높은 영화에 이 사용자도 높은 별점을 주었는가 |
| TMDB 투표 수 | 해당 플랫폼에 평가 기록이 많이 남았는가 | 많이 평가된 영화와 덜 평가된 영화에 대한 반응 차이 |
| TMDB popularity | TMDB가 제공하는 별도 인기 지표 | 이 지표 수준에 따른 사용자의 반응 |
| KOBIS 누적 관객 | 한국 극장에서 얼마나 관람되었는가 | 국내 흥행 영화의 관객 규모에 따른 사용자의 반응 |
| 자료 존재·근거 편수 | 위 계산을 얼마나 믿고 사용할 수 있는가 | 해당 출처가 있는 이력 0편·1편·여러 편을 구분 |

예를 들어 **KOBIS 관객은 많고 TMDB 평점은 없는 영화**는 ‘평가가 낮은 영화’가 아니다.
새 GBT는 `한국 흥행은 관측됨 / TMDB 평가는 모름`을 구분해서 받는다.
반대로 TMDB에서 충분히 평가된 OTT 영화는 KOBIS 기록이 없다고 관객0인 영화로 취급하지 않는다.

**높은 지표가 있다는 사실은 살리되, 높은 지표를 모든 사용자의 높은 예상 별점으로 강제하지 않는다.**
흥행작을 덜 좋아하는 사람도 있고, 흥행은 높지만 대중평점은 낮은 영화도 있기 때문이다.
각 출처의 값과 사용자 반응을 함께 넣어 GBT가 그 조합을 학습하게 한다.

## 3. ‘더 높은 쪽을 쓴다’는 어디에 적용하는가

| 단계 | v2 처리 |
| --- | --- |
| 후보 선정 | TMDB 목록이나 KOBIS 목록 중 **어느 한쪽에서 앞선 영화**가 후보로 올라올 수 있게 합침 |
| 개인 예측 | 두 출처를 별도 특징으로 보존. 관객·투표·평균별점 중 원값 최댓값을 넣지 않음 |
| 최종 정렬 | 새 GBT와 검증한 ALS 결합 점수로 정렬. 외부 인기 보너스를 다시 더하지 않음 |
| 둘 다 없음 | 대중성 모름으로 표시. 영화 콘텐츠·사용자 반응을 사용할 수 있으면 개인 예측 대상 유지 |

후보 목록은 각 출처 내 순위 중 앞선 순위를 사용한다. 예를 들어 TMDB 순위가 없지만 KOBIS
그룹 내 2위라면 ‘2위 근거’로 후보에 참여한다. **순위는 후보 공급 규칙이며 출처가 다른
평점·관객 수를 같은 만족도로 환산했다는 뜻은 아니다.** 정확한 동률·결측 규칙은 상세 설계에 있다.

## 4. 전체 추천 흐름

```text
TMDB + KOBIS 수집·영화 연결
 → 실제 값 / 조회 실패 / 자료 범위 밖 / 연결 모호를 구분
 → 영화 콘텐츠 + 출처별 대중 지표 + 사용자 반응·근거량 생성
 → 새 GBT로 개인 예상 별점 계산
 → ALS 계산 가능한 경우에만 검증된 비중으로 결합
 → 두 편 제공, 요청할 때마다 다음 두 편
```

맞춤은 전체 적격 서비스 카탈로그에서 개인 점수를 계산한다. 두 대중 자료가 모두 없다는
이유만으로 영화를 제외하지 않는다. 다만 영화 정보 자체가 없어 GBT 입력을 만들 수 없는
경우는 별도의 데이터 연결 문제로 처리한다.

발견은 기존 **8맛×맛당128그룹**, 덜 본 그룹 조건, 사용자와 그룹의 콘텐츠 비교를 유지한다.
그룹별 Q20+KOBIS5 대신 **두 출처의 앞선 순위로 최대25편**, 그룹 순서대로 최대100편을
모은 뒤 새 개인 예측기로 정렬한다. 두 대중 출처에 모두 없는 영화도 콘텐츠 순위 목록을
보조로 사용해 대중 후보가 부족할 때 채울 수 있다. 별도의 콘텐츠 배분 비율을 만들지는 않는다.

실제 별점 K10 전환, 최신 원본 H10, 실제 별점0.5 단위, 온보딩과 감상량 분리,
2편씩 페이지·버전·중복 처리는 기존 운영안을 유지한다. 이 숫자의 최적성을 새로 입증한 것은 아니다.

## 5. ALS 결합도 다시 확인한다

ALS 자체에 KOBIS 관객 수를 넣지는 않는다. 영화 factor가 없으면 여전히 ALS 점수는 없다.
MovieLens 평가로 학습한 ALS에 관측·활동량 편향이 있을 수 있으므로 평가 수를 곧바로
‘2026 한국 사용자에게 맞는 신뢰도’로 해석하지 않는다.

```text
GBT 단독:       P = 새 GBT의 보정 점수
ALS 결합 가능:  P = w × 보정 ALS + (1−w) × 새 GBT의 보정 점수
               w = α × n_ML_train / (n_ML_train+100)
ALS 미지원:     P = 새 GBT의 보정 점수
```

α는 사용자·국적별 임의 보너스가 아니라 선정용 자료에서 고를 **서비스 전체 공통 값 하나**다.
후보는 0·0.25·0.5·1로 제한한다. 0이면 GBT 단독, 1이면 기존 지원량 결합이다.
새 GBT를 학습했으므로 기존 GBT 보정 계수는 그대로 붙이지 않는다.

## 6. 실험은 어디까지 할 것인가

모델 종류를 다시 늘리는 비교가 아니다. **같은 Spark GBT 설정으로 입력의 기여를 분리**한다.

| 비교 | 바꾸는 것 | 확인할 질문 |
| --- | --- | --- |
| B0 | 기존 GBT 재사용, 공통 보정 자료로 점수 보정 | 현재 기준 |
| B1 | 결측 상황을 학습한 TMDB GBT | 기존 모델의 새 결측 문제를 줄이는가 |
| B2 | B1에 KOBIS 영화 지표 추가 | 한국 흥행 정보 자체가 도움이 되는가 |
| B3 | B2에 KOBIS 사용자 반응·근거량 추가 | 같은 흥행 지표도 사용자마다 다르게 해석하는 것이 도움이 되는가 |

**새 학습 최대3회**, 우선 같은 seed·나무 수·깊이 등으로 제한한다. 학습된 기존 나무에
열만 덧붙이는 방식은 아니다. 먼저 GBT 단독으로 비교하고, 남긴 GBT에 대해서만 ALS 비중을
선정한다. 후보 변경의 효과도 같은 모델을 고정해서 따로 비교한다.

기존 GBT와 ALS도 새 모델과 **같은 보정용 사용자**로 점수 보정을 맞춘다. 기존 보정 계수에
선정용 사용자의 정답이 들어가 있는 상태로 새 모델과 비교하지 않는다. 원 모델 학습을 다시 한다는 뜻은 아니다.

현재 KOBIS는 국적별 흥행 상위200편씩이라 저관객 비교군이 없고, 서비스 연결은371편
약0.156%다. **이 표본만으로 전체 영화에 적용할 새 GBT를 채택하지 않는다.** 먼저 KOBIS 순위와
독립적으로 고른 영화 목록의 관객 자료·결측 원인을 확인하도록 수집·중단 조건까지 설계했다.
수집 전에도 고정 평가 자료에 필요한 사용자·영화가 존재하는지 확인한다. 검증할 자료가 부족하면
KOBIS 모델 채택을 보류하고 후보 활용 설계와 TMDB 결측 개선까지만 남긴다.
