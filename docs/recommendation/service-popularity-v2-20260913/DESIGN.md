# 대중성 v2 상세 설계와 제한된 검증 계획

상태: **DRAFT · 설계 단계** · 2026-09-13. [읽기용 요약](README.md).
기존 산출물에 새 열을 붙여 실행할 수 있는 배포 설정이 아니다. 실행 코드·새 데이터 manifest의
독립 사전 검토가 완료되어야 실험할 수 있다. 이 문서 작성에서는 수집·학습을 시작하지 않는다.

## 1. 변경 범위와 목표

질문은 ‘인기만 높이면 좋아지는가’가 아니라 다음 세 가지다.

1. TMDB 대중 지표가 없을 때 기존 GBT가 낮은 수치와 결측을 구분해 예측할 수 있는가?
2. 한국 흥행 정보 자체와 이에 대한 개인별 반응이 예측에 추가로 도움이 되는가?
3. 후보를 넓혀도 최종 GBT·ALS 결합이 그 영화를 다시 부당하게 배제하지 않는가?

v1의 후보 TMDB Q 필수 조건·20:5 배분·예측기 불변 안을 대체한다. K10/H10, 실제 별점0.5
단위, 모델 입력과 전체 감상 이력 분리, 8×128 고정 분류·기준 그룹 대표, 그룹 경험량 조건,
2편 페이지와 입력 버전 우선 규칙은 [기존 운영안](../service-final-20260913/POLICY-DETAILS.md)을 유지한다.
v1의 `Q25` 실험 또는 `shrink100` 결과를 새 후보/새 GBT의 검증 결과라고 인용하지 않는다.

## 3. 원천 상태: 모름과 낮음을 구분

다음 상태는 원천 테이블·검증 로그에 보존한다. 수집 실패 이유나 수집 배치 ID를 사용자 취향
특징으로 넣지는 않는다. 모델은 검증된 수치·유효성·이력 근거량을 받는다.

| 상태 | 숫자 처리 | 의미 |
| --- | --- | --- |
| OBSERVED_POSITIVE | 실제 양수와 valid1 | 관측된 규모 또는 평점 |
| OBSERVED_ZERO | 공식 범위에서 명시된 실제0, valid1 | 해당 범위의 실제0. 평점은 투표0이면 유효 평균 없음 |
| NOT_IN_RANKED_EXTRACT | NULL, valid0 | Top200 추출본 밖. 관객0·상영 없음으로 해석 불가 |
| NOT_COLLECTED / FETCH_FAILED | NULL, valid0 | 미조회 또는 조회 실패 |
| ID_UNRESOLVED / AMBIGUOUS | NULL, valid0 | 동명·재개봉·영화 연결 미확정 |
| NOT_FOUND_IN_QUERIED_SCOPE | NULL, valid0 | 조사한 범위에서 찾지 못함. 전체 생애 관객0이 아님 |
| INVALID | NULL, valid0 | 범위·형식·일관성 검사 실패 |

TMDB 메타데이터 존재와 TMDB 평점 존재, KOBIS 관객 존재는 독립 플래그다.
TMDB 평균은 0<R≤10이고 투표 수가 양수인 경우만 유효하다. 투표 수·popularity는 검증된
0을 유효 값으로 유지한다. 두 대중 자료가 없어도 기본 영화 특징이 있으면 개인 예측 대상이다.
영화 자체의 ID·개봉·필수 속성이 없어 입력을 만들 수 없으면 MODEL_INPUT_UNAVAILABLE로 구분한다.

Spark 입력에서 필요한 숫자 대체0은 계산용 placeholder다. 반드시 valid와 함께 기록하며,
저장 원천 NULL을 관객0이나 실제 별점0으로 바꾸지 않는다. mask를 둔다고 무감점이 수학적으로
보장되는 것은 아니므로 실제 결측·가림 평가에서 예측 이동을 확인한다.

## 4. 새 GBT의 특징 계약

### 4.1 기존 정보와 새 영화 정보

기존 콘텐츠·장르·국가·인물 관계·별점 반응·지원량200열을 유지한다. TMDB 대중30열도
기존 뜻을 유지하되, 결측을 포함하는 학습 자료로 다시 학습한다. 기존 modelVersion과 새
featureVersion을 혼합하지 않는다. 실제 열 순서·길이는 실행 전 명세에 고정한다.

| 대중 채널 | 값의 변환 | 별도 정보 |
| --- | --- | --- |
| TMDB 평가 | 유효할 때 `(v×R + m×C_train)/(v+m)/10` | valid. 투표 근거는 기존 투표 채널·평점 축소에 반영 |
| TMDB 투표 | 기존 `clip(log1p(v)/log1p(100000),0,1)` | valid |
| TMDB popularity | 기존 `clip(log1p(p)/log1p(1000),0,1)` | valid |
| KOBIS 관객 | `log1p(audience) / q99(log1p(audience_train_valid))`를0~1 clipping | valid, 원래 log값 범위 초과 플래그 |

이번 대조는 B0~B3 모두 기존 TMDB 스냅샷과 학습 영화에서 산출한 C_train·m을 고정한다.
기존 값은 `C_train=6.173088067675869`, `m=48`이다. 가림 증강 전에 고정한다.
TMDB 재수집·prior 변경 효과를 결측 학습 효과에 섞지 않는다. KOBIS의 정규화도
학습 역할의 유효 영화만 사용하고 선정·확인 집합에는 고정 변환을 적용한다. 정규화 분모0이면
해당 모델 학습 준비 실패다. 두 변환값이 같은 숫자라고 같은 실제 인기라는 뜻은 아니다.

KOBIS 매출은 감사 자료로 보존하되 이번 첫 비교에는 추가하지 않는다. 관객과 매출을 동시에
넣어 중복 설명하거나 다른 변수를 한꺼번에 늘리지 않기 위해서다. 한국 제작국 자체는 기존
콘텐츠 특징으로 남기며 국적 가산점을 따로 더하지 않는다.

조회 시각·범위·매핑 신뢰도는 운영 검증에 사용한다. 단일 스냅샷밖에 없는 현재 자료로 최근
증가율·유행 변화·당시 관객 수를 만들어 넣지 않는다. 영화별 조회 시각이 모르면 스냅샷 생성일을
개별 조회일처럼 채우지 않는다.

### 4.2 사용자 반응: TMDB 기존 정의와 KOBIS 추가 정의

서비스와 주 평가에서는 원본 최신 H10 실제 별점을 먼저 고른 뒤 영화에 연결한다.
학습에서는 기존 원행의 cap0/1/5/10/30과 엄격 과거 이력을 그대로 사용하며 KOBIS만 따로
10편으로 자르지 않는다. 이하 H는 그 행에서 선택한 원본 이력 편수다. 온보딩 추정 별점은 사용하지 않는다.
TMDB 기존24개 반응 열은 현재 코드의 수식·순서·매핑 후 실제 입력 k를 쓰는 분모까지 유지한다.
명시적인 m·부분 이력 별점 평균·response_estimable 열을 TMDB에 새로 더하지 않는다.
아래 표와 수식은 **KOBIS에만 추가할 12개 반응 열**이다.

| KOBIS 사용자 특징 | 뜻 |
| --- | --- |
| m_s / 원본 선택 편수 | 이 출처로 설명 가능한 평가 이력 비율 |
| m_s 및 `m_s/(m_s+5)` | 반응 계산의 실제 근거와 축소 계수 |
| 값의 평균·분산 | 사용자가 평가한 영화들의 대중 지표 범위 |
| 해당 이력 별점의 평균·사용자 전체 평균과 차이 | 이 출처로 관측되는 영화를 상대적으로 좋아했는가 |
| 지표와 실제 별점의 축소 공분산 | 지표가 높은 쪽에 높은 별점을 줬는가 |
| 후보 값−이력 평균, 그 차이×공분산 | 이 후보의 지표가 해당 사용자에게 어떤 방향인가 |
| 이력 존재·반응 추정 가능 | 근거 없음과 반응0을 구분 |

KOBIS m은 유효한 서로 다른 영화 수다. 실제0도 유효 관측이면 포함하고 미기록은 제외한다.
KOBIS 비율의 분모 H는 매핑 전 선택한 원본 이력 편수다. 기존 TMDB 비율의 분모와 다르므로
출처 간 이 비율을 같은 의미의 수치처럼 직접 비교하지 않는다.

특징 순서는 실행 코드에서도 다음과 같이 고정한다(0부터 시작하는 열 번호).

- B0/B1: 기존 RH230, x0~229. 새 TMDB 열 없음.
- B2: x230=`kobis_z`, x231=`kobis_valid`, x232=`kobis_log_above_train_p99`. 총233열.
- B3: B2 뒤 x233~244에 `m/H`, `m`, `m/(m+5)`, `zbar`, `var_z`, `ybar`,
  `ybar−original_ybar`, `cov`, `delta`, `response_cross`, `history_present`, `response_estimable`. 총245열.

`m`은 실제 편수(학습0~30, 서비스/주 평가0~10), `var_z=Σ(z−zbar)²/m`이고 `original_ybar`는
매핑 전 원본 H의 실제 별점/5 평균이다. H=0이면 이 비율·평균을 계산용0으로 둔다.
학습의 cap0행은 기존대로 보존하지만 서비스에서 빈 입력의 개인화 경로를 실행하지는 않는다.
후보 KOBIS 값이 결측이면 x230~232는0이며 x231이 결측을 표시한다.

KOBIS 반응의 구체식은 다음과 같다. z는 변환된 관객 수, y=r/5다.

```text
zbar = 유효 이력 z의 평균
ybar = 유효 이력 y의 평균
cov = Σ (z−zbar)(y−ybar) / (m+5)
delta = 후보 z−zbar              (후보 valid이고 m>0일 때)
response_cross = delta×cov
```

m<2 또는 지표 분산≤1e−8이면 cov와 response_cross는0, `response_estimable=0`으로 둔다.
후보가 결측이면 delta·교차를0, candidate_valid=0으로 둔다. m=0이면 평균·분산·부분 별점 평균과 전체 평균의 차이도 계산용0이고
history_present=0이다. ‘근거가 없으므로 이 사용자는 흥행작을 싫어함’으로 바꾸지 않는다.
cov는 통제된 인과효과가 아니다. 좋아한 장르·감독과 흥행 규모가 겹칠 수 있으며 그 결합은
GBT가 학습하고, 특징 추가 대조로 유용성을 평가한다.

### 4.3 높은 쪽의 활용과 반대 근거

평점·관객·투표의 원값 max나 단순 평균을 모델 입력의 유일한 대중성 값으로 사용하지 않는다.
특히 관객이 많지만 대중평점이 낮다는 **반대 근거를 지우지 않는다**. 별도 채널과 사용자
반응이 있으므로 높은 관객 값이든 높은 대중평가든 사용할 수 있다. 높은 인기일수록 모든
사용자의 예측이 올라가야 한다는 단조 제약도 두지 않는다.

현재 범위에는 출처값의 추가 max 특징을 넣는 별도 학습 실험을 만들지 않는다. 강한 한쪽
근거를 후보에 살리는 규칙과, 서로 다른 출처의 효과를 개인별로 학습하는 구조로 목적을 충족한다.

## 5. 후보 규칙과 최종 점수

### 5.1 출처별 앞선 순위로 후보 공급

공통 카탈로그·필터·기시청·관심없음·세션 노출 제외를 먼저 적용한다. 개인화 발견에서는
GKT 콘텐츠 벡터와 고정 그룹 할당이 필요하나 **TMDB Q 유효 여부는 공통 자격이 아니다**.

각 적격 그룹 g에서 개인 제외 이후 다음 목록을 만든다.

- T: 유효 TMDB Q 내림차순 → 투표 수 내림차순 → service ID. 후보용 Q는 v1의 C/m을 유지한다.
- K: 검증된 양수 KOBIS 누적 관객 내림차순 → service ID. TMDB Q는 필요하지 않다.
- C: 사용자 콘텐츠 방향과의 내적 내림차순 → service ID. T/K 모두 없는 영화도 포함한다.

T/K의 순위는 각 그룹의 현재 유효 목록 안에서1부터 센다. 대중 후보의 점수는
`best_rank = min(rank_T, rank_K)`이며 없는 출처는 무한대로 계산한다. 동률은 service ID다.
양쪽에 있다는 이유로 보너스를 두 번 주지 않는다. 이 순위는 한정된 목록에서의 후보 공급
편의를 위한 값으로, 현재 Top200 KOBIS와 TMDB 전체의 동일 백분위·동일 품질을 주장하지 않는다.

대중 best_rank 목록에서 **그룹당 최대25편을 먼저 확보**한다. 25편에 못 미치면 C 목록을
앞에서부터 읽어 이미 포함한 영화를 건너뛰고 부족분을 채운다. KOBIS/TMDB의 고정20:5 몫이나
대중/콘텐츠의 새 배분 비율은 없다. 한쪽 출처만 있으면 그 순위를 사용한다. 두 출처가 모두
없는 영화는 이 부족분 보충 경로에 참여할 수 있지만 매 그룹에서 노출 몫을 보장하지는 않는다.

그룹을 사용자·그룹 평균 대표의 내적순으로 방문해 합계100편까지 모은다. 개인 예측기로
Top10을 만든 뒤2편씩 제공한다. 더 필요한 경우 같은 세션의 노출만 제외하고 다음 후보를
계산한다. 전체 감상량·분모는 노출 때문에 바뀌지 않는다.

맞춤의 K≥10 경로는 전체 적격 카탈로그를 점수화하므로 출처별 후보 제한을 새로 걸지 않는다.
대중 자료가 없는 영화도 콘텐츠 입력이 가능하면 점수를 계산한다. 이는 누락 자료를 높은
평가라고 추정한다는 뜻이 아니다.

### 5.2 K<10과 입력 부족

유효 콘텐츠 방향이 있으면 동일 그룹 방문·대중 우선/콘텐츠 부족분 보충으로 초기 추천한다. 개인 예상 별점은
표시하지 않는다. 콘텐츠 방향이 없으면 전역 T/K 목록에서 best_rank로 대중 후보를 고른다.
이때 두 출처도 모두 없는 영화는 개인화 없이 임의로 높은 순위에 넣지 않는다. 목록 소진은
사실대로 알리고 검색·추가 평가 입력으로 연결한다.

영화 메타데이터가 없어서 GBT 입력 자체를 만들 수 없는 항목은 ‘대중 지표 결측’ 실험과
구분한다. KOBIS 기록만으로 현재 GKT 분류·영화 표시·GBT230을 자동 생성할 수 있다고 가정하지 않는다.

### 5.3 GBT와 ALS 결합

기존 ALS factor·fold-in은 비교 기준으로 고정한다. ALS에 KOBIS 관객을 평점처럼 추가하거나,
TMDB 투표·KOBIS 관객으로 n_ML_train을 바꾸지 않는다. B0·B1~B3·ALS의 affine 점수 보정은
모두 같은 보정용45명에서 각 모델에 따로 적합한다. 이전90명 보정 계수는 역사적 참고값으로 보존한다.

```text
ALS 미지원이면: P = cal_new_GBT
지원되면:      w = α × n_ML_train/(n_ML_train+100)
               P = w×cal_ALS + (1−w)×cal_new_GBT
```

먼저 GBT 단독 B0~B3으로 특징의 기여를 판정한다. 선정한 GBT 하나에만 α∈{0,0.25,0.5,1}을
선정용 사용자에서 비교해 공통 α 하나를 정한다. 영화 국적·결측 조합별 α를 각각 최적화하지 않는다.
순위는 clipping 전, 별점 오차·표시는0.5~5 clipping이다. 미지원 ALS 값을0으로 만들어 곱하지 않는다.

## 6. 데이터 준비: Top200에서 바로 학습하지 않는다

현재 KOBIS371연결은 서비스237,817편의 약0.156%이며 한국·외국 각각 높은 관객 영화만 있다.
연결된 ML 평가 행수가 많더라도 많은 외국 인기 영화 평가가 반복되는 구조다. 저관객·극장
미관측과 국내 흥행의 차이를 이 표본으로 일반화할 수 없다. 과거 mixed yearly/lifetime 자료는 재사용하지 않는다.

### 먼저 고정할 수집 프레임

아래 최대1,200편은 **수집 가능성과 결측 구조를 확인할 진단 표본**이며 전체 학습용 데이터가 아니다.
먼저 기존 학습·보정·선정·확인의 목표 영화와 원본 H10을 메타데이터에 연결해, 선정/확인에서
KR 등 판정 대상의 최대 가능한 사용자·영화·평가 행수를 센다. 관객 값을 알기 전에도 확정할 수
있는 상한이 아래 하한에 못 미치면 B2/B3의 채택 비교는 수집 전에 중단한다. 목표나 사용자를
바꿔 분모를 채우지 않는다. 수집 프레임과 고정 역할의 교집합 수도 별도 보고한다.

KOBIS 조회·매칭 결과를 보기 전에 서비스 카탈로그에서 영화 목록을 고정한다.

| 축 | 층 |
| --- | --- |
| 제작국 | KR 포함 / 미포함 |
| TMDB 개봉연대 | 2004이전 / 2004~2019 / 2020~2023 / 2024이후 |
| TMDB 평가 관측 | 유효평균 없음 / 유효평균 있고 투표1~20 / 유효평균 있고 투표21이상 |

기록하고 억지로 KR미포함·옛 영화로 넣지 않는다. 이 표본은 균형 진단용이며 전체 카탈로그
비율을 추정할 때 원래 층 크기 가중치를 따로 사용한다. 기존 Top200은 비교·연결 검증용으로 보존한다.

수집은 선택 영화의 확인 가능한 공식 KOBIS 영화코드와 **같은 누적 집계 범위**를 확인하는
방법이어야 한다. 일별Top10에서 찾지 못했다고0으로 만들지 않는다. 기간별·연도별 관객 합계와
전체 누적을 섞지 않는다. 구체 조회/내보내기 방식·범위·요청 상한은 수집 실행 코드의 사전 검토에서
고정하며, 원 HTML/CSV·조회조건·시각·ID매핑·해시를 남긴다. 이 문서에서 조회를 실행하지 않는다.

### 준비도 판정과 중단

1. 선택한 모든 영화가 관측·실제0·미관측·실패·모호 중 하나로 설명되어야 한다. 미해결 매핑은 모델 값으로 쓰지 않는다.
2. 학습·선정·확인 역할별로 한국/외국 및 관객 구간(0,1~10만,10만초과~100만,100만초과)의 영화 수·평가 행수·사용자 수를 확인한다. 관측 없는 경우는 별도 행이다.
3. KOBIS 사용자 반응은 이력 유효 m=0,1,2~4,5이상으로 보고한다. 유효 입력과 목표 영화 양쪽의 지지도를 확인한다.
4. B2/B3의 사전 핵심 구간인 KR, KOBIS 저관객(1~100만), KOBIS 관측/TMDB평가 결측에서 선정·확인 각각 최소30사용자·30목표영화·200평가행이 없으면 해당 구간은 판단 불가다. B3은 추가로 m≥2이고 지표 분산>1e−8인 반응 추정 가능 사용자도 선정·확인 각각 최소30명이어야 한다.
5. 상한 점검 또는 한 번의 고정 프레임 진단·품질 재검증에서 핵심 구간이 부족하면 B2/B3의 전체 서비스 채택 판정은 진행하지 않는다. 결과를 본 뒤 인기 영화나 평가가 많은 사용자로 채워 기준을 낮추지 않는다.

이 최소 분모는 검정력을 보장하는 숫자가 아니라 소수 영화·소수 사용자만으로 채택하는 것을
막는 사전 하한이다. 부족한 구간을 0점이나 PASS로 쓰지 않는다. B1 결측 내성 개선은 KOBIS
모델 채택과 별도로 판단할 수 있다. 더 큰 데이터 수집을 자동으로 무한 반복하지 않는다.
준비도 미충족이면 종료 산출물은 **KOBIS 후보 활용 설계 + 가능한 범위의 B1 검증 + B2/B3 판단 불가 근거**다.
KOBIS 특징을 넣은 GBT가 좋다고 선언하거나 현재 모델에 그 열을 즉시 연결하지 않는다.

## 7. 학습·선정·확인 역할

기존 train 사용자·영화 역할 및 입력 상한·영화 cold 차단 목록을 유지한다. 기준 manifest를
실행 전에 재검증하고 새 KOBIS 연결 때문에 split이나 평가 후보를 옮기지 않는다.
기존270명 개발 사용자 중90명 보정 풀은 사용자 ID의 고정 해시순으로45명 보정/45명 선정으로
나누고, 기존180명은 확인으로 유지한다. 이는 **이미 사용했던 개발 자료 재검토**이며 새로운
블라인드 최종 test라고 부르지 않는다. H10 및 해당 원본 역할의 공통 행에서 비교한다.

실제 별점이 목표다. 입력 이력은 목표 timestamp보다 엄격히 이전인 것만 쓰고 목표 영화의
평가 자체를 제외한다. 서비스 사용자는 MovieLens 학습 사용자와 ID 공간이 다르다.
영화별 최신 TMDB/KOBIS 값은 과거 목표 시점의 정보가 아니다. 과거 스냅샷을 확보하지 못하면
‘현재 자료와 과거 선호의 개발 비교’까지만 허용하고 시간순 미래 예측·2026 한국 성능이라고 말하지 않는다.

메타데이터 정규화·평균 prior는 학습 영화만으로 적합한다. 모든 GBT 및 ALS의 이번 비교용
보정은45명 보정에서만, 모델 선택과 α 선택은45명 선정에서만 수행한다. 이전90명 보정을
그대로 쓰면 선정45명의 정답을 이미 사용한 비교가 되므로 주 비교에서 금지한다.
B0의 기존 나무 재사용과 affine 재보정은 구분하고 `B0_commoncal`로 기록한다. 이전 보정의
`B0_legacy`·`ALS_legacy`는 별도 참고 표에만 둔다. 재보정은 새 GBT/ALS 학습 횟수에 포함하지 않는다.
ALS 보정은 같은45명 중 ALS가 실제 계산 가능한 목표만 쓰며, 보정 적합 불가이면 결합 선정은
진행하지 않는다. 180명 확인 결과로 α·후보 비율·학습 설정을 다시 바꾸지 않는다.
구간별 최소 분모가45명 선정 풀에서 충족되지 않으면 INSUFFICIENT로 종료한다.

## 8. 최대3회 학습과 결측 내성

실행 여부를 다음 순서로 정하며, 이미 판단 불가로 끝난 조건의 비싼 학습을 자동 시작하지 않는다.

| 단계 | 실행 전 조건 | 미충족 시 |
| --- | --- | --- |
| B1 | 기존 입력/역할/원본230열 확인, 결측 파생 검사, 자원 사전 점검 | B0 보존, 원인 기록 |
| B2 | B1 준비 조건 + KOBIS 영화 정보의 원천/정규화/핵심 구간 지지도 | B2/B3 학습 없이 INSUFFICIENT |
| B3 | B2 준비 조건 + 선정/확인의 사용자 반응 추정 가능 지지도 | B3 학습 없이 INSUFFICIENT, B2까지만 판단 |
| α | 선정된 모델이 실제 통과한 해당 범위의 안전 조건 + 공통 ALS 보정 가능 | 기존 기준 결과 보존, 검증되지 않은 새 비중 채택 안 함 |

B1/B0가 남으면 α 선정에 KOBIS 반응/저관객 지지도를 추가 조건으로 붙이지 않는다.

| ID | 학습 입력 | 새 학습 |
| --- | --- | ---: |
| B0 | 기존 RH230·GBT120_s339, 공통45명에서 affine 재보정 | 0 |
| B1 | 기존 콘텐츠/반응 + TMDB대중30열, 아래 결측 증강 | 1 |
| B2 | B1 + KOBIS 영화 값/valid/범위 플래그 | 1 |
| B3 | B2 + KOBIS 사용자 반응·근거 블록 | 1 |

기존 Spark GBT의 나무 수120·깊이·bin·stepSize 등 하이퍼파라미터를 유지하고 seed339로
제한한다. **기존 학습된 나무의 분기를 고정한다는 뜻이 아니다.** 같은 원본 목표 행·사용자·영화·
순서·row weight·결측 seed를 사용한다. 컬럼과 학습된 분기만 해당 특징 조건에 따라 달라진다.

결측 증강은 원본 목표별 네 view를 만들고 합계 weight1을 유지한다(각0.25).
기존 약499만 원행을 네 배로 펼치면 약1,999만 학습행이다. 최대3회라는 이유만으로 가벼운
실험이라고 부르지 않는다. 실행 전에 원행/view/가중치 manifest, 특징 생성 용량·임시 디스크·
peak 메모리 추정과 제한된 변환 점검을 수행한다. 여기서 성능을 보고 설정을 선택하지 않는다.
기존 Spark4.1.3 고정 이미지·4CPU·컨테이너12GiB·driver8GiB·프로세스90분 상한을 유지하고,
학습은 순차로 최대3회(총270분 상한)다. 초과·OOM은 미완료로 기록하고 자동 자원 증설·행 축소·
재시도하지 않는다. 4view 동일행을 weight로 접는 최적화도 Spark binning/분기 표본수에 영향을
줄 수 있으므로 동등성을 확인하지 않은 채 적용하지 않는다. 데이터 준비·검산 시간은 별도다.

| view | 처리 |
| --- | --- |
| V0 | 관측 상태 그대로 |
| V1 | 고정 해시로 고른 영화20%의 TMDB 대중3채널 가림 |
| V2 | 같은 영화20%의 KOBIS 채널 가림 |
| V3 | 같은 영화20%의 두 출처 대중 채널 가림 |

가림은 **영화 단위**로 결정하며 그 view의 모든 사용자 이력과 후보에서 같은 영화에 같은
mask를 적용한다. 목표 별점을 보고 고르지 않는다. TMDB 장르·인물 등 콘텐츠 자체까지
가리는 실험과는 다르다. 원래 없는 값을 만드는 것이 아니라 있던 수치와 모든 파생 반응을
함께 가린다. valid·평균·cov·m·delta를 전부 다시 계산해 숨긴 정보가 반응 특징에 남지 않게 한다.
정답 별점은 바꾸지 않는다. B1에서 KOBIS view가 동일해지는 경우도 원본 목표의 총 가중치는1이다.

원본과 증강 view는 분할 간 이동하지 않는다. 모델 간 비교는 동일한 가림 파일을 사용한다.
평가용 가림은 학습용과 별도 해시 namespace(`train_mask`/`eval_mask`, seed339)로 고정한
20% 영화에 같은 네 view를 적용한다. 모델마다 다시 뽑지 않는다. 전체 점수와 실제로 후보 또는
이력이 가려진 목표의 점수를 구분해, 영향을 받지 않은 다수 행이 결측 변화를 가리지 않게 한다.
임의 가림 성능은 내성 점검이다. **실제 Top200 밖·극장 미관측·연결 모호의 결측을 무작위
가림으로 대표했다고 주장하지 않는다.** 실행 전 합성 검사에서 실제0/결측, 후보·이력 mask,
목표 제외, m=0/1, 가중치 합계, 입력 열 순서와 유한값을 검증한다.

## 9. 무엇을 어떻게 채점하는가

### A. 개인 예측의 기여 — 같은 관측 목표, GBT 단독

계획 대조는 B1−B0, B2−B1, B3−B2의3개다. 사용자별 평균을 동일 가중한 macro MSE가
주 지표이며 MAE·행 micro MSE·영화별 macro MSE도 보고한다. 전체 평균만으로 한국·저관객
구간의 악화를 숨기지 않는다.

ALS는 계산 가능한 같은 warm 목표에서 별도 기준선으로 표시한다. ALS 미지원 목표에서는
미지원 건수를 보이고 점수를0이나 인기점수로 채워 직접 비교하지 않는다.

### B. ALS 결합 — 고른 GBT를 고정

선정용 GBT 선택은 macro MSE 최소를 기본으로 하되, 아래 상위 추천/핵심 구간 안전 조건을
통과하는 것만 남긴다.1% 이내 차이면 더 적은 특징의 모델을 우선한다. 고른 하나에서만
α4개를 비교하며 같은 안전 조건 안에서 macro MSE 최소,1% 이내 동률이면 작은 α를 선택한다.
이 규칙은 영화별로 점수가 높은 모델을 사후 선택하는 oracle이 아니다.
같은 열 수·동률이면 기존 B0를 우선하고, 유효한 개선 후보가 없으면 B0를 유지한다.
KOBIS 준비도 실패로 B2/B3을 학습하지 않았다는 이유로 B1을 자동 채택하지 않는다.

### C. 후보 정책 — 고른 GBT·α를 고정

같은 영화 카탈로그·사용자·그룹·B100 조건에서 (기존 Q25), (v1 Q20+KOBIS5),
(v2 best-rank 우선+콘텐츠 부족분 보충)를 비교한다. 새 학습은 없다. 후보수·실제 계산 가능한 비율,
T/K/양쪽/둘다없음 구성, 한국·최근작 공급, 고유 영화 수·최대 영화 점유율, 비용을 측정한다.
최종 후보에 관측 별점이 없으면 UNKNOWN이다. 이를 실패·성공으로 채우지 않는다.
공통 시작 집합은 콘텐츠 입력과 그룹 할당이 가능한 같은 카탈로그다. 이후 Q 필수 등의 자격
차이는 정책 자체의 차이로 기록한다. 정책별 최종 후보가 다른 상태의 MSE를 같은 목표 MSE처럼
비교하지 않는다. 공통 관측 목표의 예측 비교는 A에서 하고, C는 공급·노출과 관측 가능 범위를 본다.

### 지표와 판정 한계

| 보는 범위 | 지표 |
| --- | --- |
| 같은 관측 영화 | macro MSE·MAE, micro/영화 macro 오차, 예측값 보정 |
| 같은 관측 후보 순위 | NDCG@2/4/6/10, Top2 평균 별점,2점 이하 비율, 각 추가2편 |
| 서비스 카탈로그 | 후보 공급·점수화 지원·UNKNOWN·중복·노출 집중도·출처/국가/연대 구성 |
| 결측 | 실제 출처4조합과 별도 가림4조합, 원본 대비 예측 이동·상위 노출 변화 |
| 개인 대중성 반응 | 이력 근거 m별 성능, 많이 알려진/덜 알려진 영화에 대한 이력 반응별 오차·노출 |

실제 출처4조합의 TMDB 기준은 **유효 평균평점 존재**, KOBIS 기준은 **검증된 관객 값 존재**다.
TMDB 투표 수·popularity의 유효 여부는 별도 열로 보고한다. ‘TMDB 평가 결측’과 ‘TMDB 전체
메타데이터 없음’을 합치지 않는다. 실제 결측 조합과 인위적인 채널 가림 view도 별도 표다.

사용자와 영화가 여러 행에 반복되므로 행 독립 표준오차를 쓰지 않는다. 동일 목표의 모델 간
차이에 사용자와 영화 군집을 고려한 paired bootstrap을 사용하고 실제 재표집 코드는 별도
사전 검토한다. 최소 분모와 신뢰구간을 같이 보고한다.

선정 안전 조건은 **NDCG@2 감소0.01 이내, Top2 저평점 비율 증가2%p 이내,
핵심 구간 MSE 악화5% 이내**로 사전에 둔다. B1~B3의 공통 기준은 B0_commoncal,
ALS α 비교의 기준은 선택한 GBT 단독(α=0)이다. 특징별 B2−B1·B3−B2 대조는 별도 보고한다.

- B1: 전체와 warm/ALS미지원 구간의 오차·상위 추천, TMDB 가림 내성을 본다. KOBIS 지지도를 B1 채택 조건으로 쓰지 않는다.
- B2/B3: 위 조건에 더해 §6의 KR·KOBIS 저관객·KOBIS 관측/TMDB평가 결측, 유효 반응 m 구간을 적용한다. 준비도 미달이면 채택 판단 불가다.
- B1의 자연 TMDB 결측 구간이 최소30사용자·30목표영화·200행 미만이면 해당 구간은 판단 불가다. 가림 평가가 좋아도 실제 결측 일반화가 검증되었다고 하지 않는다. B1의 전체 개발 비교 결과와 이 한계는 따로 보고한다.

통계적 비열등을 말하려면 해당 방향의95% 신뢰
구간까지 한계 안에 있어야 한다. 점 추정만 충족하면 탐색 후보이며 검증된 채택이라고 하지 않는다.
세 특징 대조의 우위 주장은 Holm 보정을 적용한다. 한 seed이므로 모델군 전체의 확실한 우위로 확대하지 않는다.

관측 후보 순위와 실제 카탈로그 순위를 섞지 않는다. 실제 UNKNOWN이 많으면 서비스 만족도
판정은 불가능하다. 한국 제작국이나 ML 평가량을 가산해 좋은 점수가 나오도록 평가 정답을 수정하지 않는다.

## 10. 갱신과 배포 경계

| 변화 | 처리 |
| --- | --- |
| 실제 별점 변경 | 같은 snapshot으로 사용자별 출처 반응·m·GBT입력·ALSfold-in 재계산 |
| TMDB/KOBIS 값 갱신 | 후보 영화 값뿐 아니라 사용자가 평가한 이력 영화의 출처값·반응 통계도 함께 갱신 |
| 새 데이터로 원천 상태 변경 | 새 catalogVersion에서 valid·후보·사용자 반응 모두 다시 계산 |
| 새 특징 또는 새 GBT | featureVersion/modelVersion/calibrationVersion 변경, 새 학습·예측 parity 검증 |
| 실패·미완성 갱신 | 마지막 정상 snapshot 유지. 부분 값과 이전 사용자 특징을 섞어 게시하지 않음 |

사용자 반응 특징을 만들 때 후보와 이력 모두 같은 외부 데이터 스냅샷을 사용한다. 새로운
관객 값과 예전 평균·공분산을 섞으면 같은 모델이라도 의미가 어긋난다. 모델이 갱신되지 않았더라도
외부 스냅샷이 바뀌면 관련 사용자 추천은 다시 계산한다. 군집 중심·기준 그룹 대표는 그대로 둔다.

새 feature schema를 기존 GBT120_s339에 로드하지 않는다. B0는 재현·비교 기준으로 보존한다.
현재 모델의 소스 미지원 문제를 해결했다고 말하려면 B1~B3 중 선택 모델의 실제 결측 내성,
동일 새 모델의 배치/서비스 예측 parity, 빈 이력, ALS 미지원,2편 페이지까지 연결 검증이 필요하다.

## 11. 참고한 연구와 적용 범위

- [DropoutNet, NeurIPS2017](https://papers.nips.cc/paper_files/paper/2017/hash/dbd22ba3bd0df8f385bdac3e9f8be207-Abstract.html)은 cold-start 입력 부재를 학습에서 다루는 접근을 제시한다. 여기서는 ‘결측 상황을 학습과 평가에 포함한다’는 방향만 참고했다. GBT의 본 설계나20% mask의 효과를 그 논문이 검증한 것은 아니다.
- [Popularity bias와 사용자별 calibration 연구](https://arxiv.org/abs/2008.09273)는 사용자 집단별 인기 선호와 추천의 불일치를 다룬다. 높은 대중성을 모두에게 강제 가산하지 않고 사용자별 반응·노출을 함께 보려는 근거다. 이 설계가 인과적 편향 보정을 달성했다는 뜻은 아니다.
- [Spark GBTRegressor 공식 문서](https://spark.apache.org/docs/latest/api/python/reference/api/pyspark.ml.regression.GBTRegressor.html)는 특징 벡터와 가중치를 받는 회귀 모델의 계약이다. 재현에는 기존 프로젝트의 고정 runtime/하이퍼파라미터를 유지한다.
