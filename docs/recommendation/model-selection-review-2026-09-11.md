# 추천 모델을 무엇으로 결정할 것인가

2026-09-11 · 로컬 실험 회고와 논문 검토. 추가 학습·서비스 채택·외부 게시를 실행한 문서가 아니다.

**내 제안은 FM 계열을 주모델 후보로 두고, ALS 보조는 추가 이득이 확인될 때만 남기는 것이다.**
다만 현재 FM이나 고정 비율 FM+ALS를 MSE만 보고 그대로 채택할 근거는 부족하다.
이제 필요한 일은 정보를 계속 추가하는 대규모 비교보다, **2편씩 보여줄 때의 품질·전체 후보의 이상 노출·혼합 점수의 일관성**을 확인하는 제한된 마무리 검증이다.

K-means·분류 기반 맞춤/발견 정책은 보류한다. 처음 2편, 요청할 때마다 추가 2편을 현재 기준으로 삼는다.
장르·감독 같은 원래 영화 정보를 입력에서 없애는 뜻은 아니다. 과거 맞춤 2+발견 1 실험은 완료 이력으로 보존한다.

**우선 바로잡을 점**

“결국 모든 모델이 ALS를 못 이겼다”는 지금까지의 결과를 정확하게 요약하지 못한다.
REC047의 입력 30편 조건에서는 ALS가 평균 MSE·MAE·선호순서 정확도 모두 앞섰다.
최근 조건에서는 FM과 혼합이 별점 예측 오차에서 더 낮은 값도 냈다.
그러나 입력량, 학습 영화, 학습 평점 수, 콘텐츠 특징, 평가 후보가 달라졌으므로 두 실험의 원수치를 연결해 모델 역전이라고 해석할 수 없다.
REC047 내부에서도 입력 10편까지 ALS가 모든 지표에서 이긴 것은 아니다.

또한 FM도 MovieLens 별점을 정답으로 학습했다. ALS는 사용자-영화 평가 관계에서 벡터를 만들고,
현재 FM은 영화 정보와 사용자가 입력한 별점의 반응·근거량으로 별점을 예측한다.
둘 다 평가 데이터에서 배운 모델이며, “데이터를 쓴 ALS와 학습 없이 정보만 쓰는 모델”의 비교가 아니다.
현재 FM은 사용자 ID 대신 이력에서 계산한 특징을 사용하므로 새 사용자의 입력도 처리할 수 있다.
입력 0에서는 개인 취향을 구분할 근거가 없다. 고정 연구 영화축 밖의 새 영화 연결은 별도 구현 확인이 필요하다.

**MSE만으로 고르면 왜 안 되는가**

같은 최근 실험의 입력 상한 10편·개인 입력이 있는 사용자 결과다.
혼합은 ALS 지원 시 `0.75 × FM + 0.25 × ALS`, 미지원 시 FM을 그대로 사용한다.

| 지표 | FM 기준 S | FM+ALS 0.25 | 숫자가 말하는 것 |
|---|---:|---:|---|
| 사용자 평균 MSE ↓, 186명 | 0.690512 | **0.665264** | 혼합이 관측 별점을 평균적으로 더 가깝게 예측 |
| 관측 후보 Top2 NDCG ↑, 176명 | **0.847138** | 0.840536 | 앞의 2편 순위 점수는 FM이 높음 |
| 그 2편의 실제 평균별점 ↑ | **3.867898** | 3.830966 | 혼합에서 선택한 2편의 평균별점 하락 |
| 그 2편 중 2점 이하 비율 ↓ | **5.3977%** | 6.5341% | 혼합에서 낮은 별점 영화 비율 증가 |

각 행 안에서는 두 모델의 사용자·후보·정답이 같다. MSE와 Top2는 필요한 관측 편수가 달라 분모가 다르다.
이는 기존 개발 결과의 기술통계이며, 이 표 자체가 새로운 통계적 우월성 검정은 아니다.
관측 후보란 그 사용자가 실제로 나중에 평가한 영화들이며, 모든 서비스 영화의 만족도를 뜻하지 않는다.

실험마다 질문이 다르므로 원수치를 한 모델 순위표에 합치지 않는다.
초기의 개인 상대선호 점수, 별점 MSE, 선호순서 정확도, NDCG도 서로 다른 평가다.
최근 FM 특징은 230개이고 ALS 학습도 영화 평점 차단 때문에 499만 행으로 달라졌다.
ALS 출력과의 일치도는 참고 지표이며, 실제 사용자 별점에 대한 품질보다 우선하는 목표가 아니다.

**잘못된 판단과 아직 남은 검증을 구분해야 한다**

1. **관측 후보의 좋은 점수만으로 전체 추천을 통과시키면 안 된다.** 현재 S는 개인 입력 186명의 전체 후보 Top2 372슬롯 중 342슬롯이 TMDB 투표 1개·10점 영화였고, 전체 372슬롯의 실제 별점은 UNKNOWN이었다. 372슬롯에 노출된 영화는 13편뿐이었다. UNKNOWN이라서 나쁜 영화라는 뜻은 아니다. 적은 근거의 극단값에 노출이 집중되는 동작과 만족도 미검증을 따로 문제로 봐야 한다. [노출 원본](../../outputs/recommendation-evidence/combination340/catalog-diagnostics.csv)
2. **점수를 그냥 섞어도 같은 기준이 된다는 가정은 검증이 필요하다.** 같은 별점 단위라도 FM과 ALS가 평균적으로 높게/낮게 예측하는 정도가 다를 수 있다. 혼합 0.25의 지원 영화 내부 NDCG는 소폭 높아졌지만, 전체 관측 후보 NDCG는 낮아졌다. 지원·미지원 영화 사이의 순위 변화와 점수 오차를 확인해야 한다. 이것만으로 점수 보정 문제가 원인이라고 확정하지 않는다.
3. **고정 설정의 패배를 모델군의 한계로 해석하면 안 된다.** 최근 모델은 조건당 한 번, FM은 기존 반복 수·정규화 등을 이어 썼다. 실행·수식 재현은 검증했지만 충분한 최적화·수렴을 입증한 것은 아니다. 반대로 수렴하지 않았다고 확인된 것도 아니다. 학습 입력 0 비중은 B 82.34%, 이력 수정 H 21.04%로 달랐으며 H의 개선 미확정이 B의 서비스 적합성을 증명하지 않는다.
4. **최종 평가의 독립성과 서비스 대상이 다르다.** 최근 270명은 이미 개발에 사용했다. 사용자 분리는 검증됐지만 반복해서 본 개발 정답을 새 test라고 부를 수 없다. 현재 TMDB/Wiki와 과거 MovieLens의 비교는 당시 사용 가능 정보만의 예측 실험도 아니다. 연구 카탈로그 85,517편은 MovieLens에 연결된 영화이며 한국 OTT·실제 서비스 카탈로그와 동일하지 않다.

현재 감사에서 ALS 수식이나 저장 예측의 계산 오류가 확인된 것은 아니다.
문제는 모든 과거 실험이 무효라는 것이 아니라, 각 실험이 답할 수 있는 범위를 넘어서 모델을 채택하려는 데 있다.

**논문과 다른 알고리즘을 검토한 판단**

| 검토 대상 | 이번 프로젝트에 주는 의미 | 추천 우선순위 |
|---|---|---|
| [관측 선택 편향: Schnabel 등, ICML 2016](https://proceedings.mlr.press/v48/schnabel16.html) | 사용자가 평가한 영화는 무작위 표본이 아니다. 평점 예측과 목록 선택의 평가를 구분해야 한다. 노출 확률을 모르는 상태에서 인기의 역수를 붙이는 것만으로 편향 제거를 주장할 수 없다 | 기존 평가의 해석·후보 조건을 먼저 정리 |
| [후보 샘플링 지표: Krichene·Rendle, KDD 2020](https://research.google/pubs/on-sampled-metrics-for-item-recommendation/) | 무작위로 줄인 후보의 지표는 전체 후보와 모델 순서도 달라질 수 있다. 우리 관측 후보 J는 그 논문의 무작위 샘플링과는 다르지만, J 성적을 전체 카탈로그 성적으로 바꿔 말할 수도 없다 | 모델마다 후보·분모를 같게 하고 해석 범위 명시 |

| [DropoutNet: Volkovs 등, NeurIPS 2017](https://proceedings.neurips.cc/paper/2017/hash/dbd22ba3bd0df8f385bdac3e9f8be207-Abstract.html) | 콘텐츠와 잠재 표현을 cold-start 조건에 맞게 연결하는 접근. 우리가 한 점수 선형 혼합과는 다른 연구 방향 | 연구 가치는 있으나 새 구현·학습 검증 비용이 큼. 이번 필수 추가 실험으로 권하지 않음 |

이 순서는 논문에서 발표된 모델 성능 순위가 아니라 FEELM의 기간·데이터·기존 구현을 고려한 판단이다.
새 그래프·시퀀스·대형 텍스트 모델을 일괄 추가해도 과거 해외 정답과 현재 한국 서비스의 차이를 자동으로 해결하지 않는다.

| 2. 전체 후보 노출 점검 | 같은 세 묶음의 UNKNOWN·미반환·중복·노출 집중도·TMDB 투표 근거량·MovieLens 학습 지원량·결측 분포. 관측 후보와 분포 차이 확인 | 관측 점수가 놓친 쏠림이 어느 모델·영화 구간에서 나타나는가 |
| 3. ALS 혼합 경계 점검 | 지원/미지원 구간의 예측 오차 방향과 점수 구간별 실제 평균별점, 두 구간 사이의 순서 뒤집힘과 Top2 교체 | 혼합을 그대로 버릴지, 점수 보정 후 한 번만 재검토할 이유가 있는지 |

첫 진단의 자연 분모는 각각 관측 후보 2/4/6편 이상인 176/153/134명이다.
추가 묶음 간 품질 감소는 공통 134명에서도 표시해야 사용자 구성이 바뀐 효과와 구분할 수 있다.
입력 0인 84명은 개인 입력 186명과 분리한다. 입력 상한 1/5/10/30과 실제 입력 수·ALS 지원 입력 수도 구분한다.
입력이 추가되지 않는 더보기는 같은 순위의 다음 두 편으로 평가한다. 새 별점에 따른 재추천은 별도 조건이다.
더보기 자체가 만족/불만족 중 무엇을 뜻하는지는 정답으로 가정하지 않는다. 이 재채점도 실제 이용자의 더보기 행동 확률까지 평가하지는 못한다.

진단 중 모델·seed·혼합 가중치를 더 찾지 않는다. 이미 열린 개발 자료만 사용하고 세 표가 완성되면 진단을 끝낸다.
전체 후보 UNKNOWN을 0점으로 채우거나 임의 최소 투표 수 필터를 추가해 성공으로 만들지 않는다.

**그다음 모델을 결정하는 방법**

FM 계열을 1차 구현 후보로 두는 이유는 적은 입력·새 영화에 정보를 사용할 수 있고 이미 분산 구현이 있기 때문이다.
서비스 품질이 확정돼서가 아니다. **현재 원대중평점 B의 쏠림을 그대로 둔 채 배포하는 선택은 권하지 않는다.**
이미 학습한 근거량 보정 FM과 GBT도 진단 비교에 남겨, 관측 순위와 전체 후보 동작을 함께 본다.
보정 FM이 쏠림을 줄였다고 만족도가 더 좋다고 단정하지 않는다.

모델 선택 우선순위는 다음처럼 제안한다.

| 우선순위 | 판단 기준 |
|---|---|
| 1. 사용할 수 있는가 | 대상 영화에 점수 제공, 새 사용자 입력 처리, 유효한 두 편씩 반환, 데이터 근거에 비해 극단적인 노출 집중·결측 처리·중복 문제 확인 |
| 2. 처음 두 편이 좋은가 | 같은 관측 후보의 NDCG@2를 주지표로 하고 실제 평균별점·낮은 별점·두 편 모두 낮은 평가를 함께 확인 |
| 3. 더 봐도 품질이 유지되는가 | 3–4위·5–6위와 누적 Top4/6의 손실을 공통 사용자에서 확인 |
| 4. 비슷하면 무엇을 고를까 | MSE/MAE, 입력량·지원량별 안정성, 학습 비용과 실제 응답 지연, 운영 복잡도 |

통계적 차이가 없다는 것은 동등함을 입증한 것이 아니다. 개선 최소폭·허용 손실과 비용 한계는 최종 비교 전에 고정하고,
자료가 부족하면 불확실성을 남긴 상태에서 더 단순하고 동작상 문제가 적은 후보를 프로젝트 선택으로 명시한다.
기존 반복 개발 정답의 구간을 최종 일반화 보증으로 사용하지 않는다.

진단에서 수정할 이유가 확인되면 **문제 하나에 대응하는 제한된 validation 비교**만 추가한다.
예를 들어 신뢰도 표현/점수 보정/최적화 점검 중 필요한 하나를 고르고, 분할·입력·후보·튜닝 예산을 먼저 맞춘다.
같은 문제를 고치면서 텍스트·분류·모델·가중치를 한꺼번에 바꾸지 않는다.
ALS 없는 영화에서는 실제 ALS 점수가 없다는 사실과, 참고 ALS가 가린 영화 평점을 학습했다는 정보 차이를 계속 표시한다.
ALS 보조는 관측 전체 순위와 지원 구간에서 이득이 함께 확인되고 비용을 감당할 때만 남긴다.
별점 오차만 줄이는 고정 혼합을 자동 채택하지 않는다.

새 모델을 정말 하나 더 비교한다면 **같은 사용자가 실제 평가한 두 영화의 선호 순서를 학습하는 공유 순위 모델**이 가장 목적이 분명하다.
현재 특징 차이에 정규화 로지스틱 회귀를 학습하고 개별 영화 점수로 정렬하는 작은 Spark 비교부터 가능하다.
동일한 과거 입력으로 두 목표를 만들고, 목표 영화·미래 별점을 입력에서 제외하며, 동점·쌍 개수·사용자 가중치를 먼저 정해야 한다.
이것은 원 BPR 재현이 아니며 기존 FM보다 좋다는 보장도 없다. 앞의 진단으로 해결되면 추가하지 않는다.
[Spark FMRegressor](https://spark.apache.org/docs/4.1.3/api/python/reference/api/pyspark.ml.regression.FMRegressor.html)는
BPR 손실을 고르는 옵션이 없고, `FMClassifier(x_i-x_j)`도 `FM(x_i)-FM(x_j)`를 학습하는 것과 다르다.
[Spark의 선형·로지스틱 회귀](https://spark.apache.org/docs/4.1.3/ml-classification-regression.html)는 기존 분산 환경에서 사용할 수 있다.

마지막으로 한 달 프로젝트에서는 소수 현재 사용자에게 모델 이름을 가린 두 목록을 같은 영화 정보로 보여주고,
표시 순서를 바꿔 가며 이미 아는 영화·보고 싶은 영화·피하고 싶은 추천과 응답 시간을 확인하는 작은 사용성 점검이 현실적이다.
이 신호는 감상 후 실제 별점이나 통계적으로 확정된 성능이 아니다. 대규모 자체 데이터를 새로 모아야만 프로젝트를 끝낼 수 있다는 조건으로 삼지 않는다.
새 독립 MovieLens 평가가 필요하면 과거에 정답을 쓰지 않은 사용자라는 이력을 먼저 확인하고, 후보·설정 고정 후 한 번만 평가한다.
그 자료도 2026년 한국 사용자 정답을 대신하지는 못한다.

현재 가능한 결론은 **FM 계열을 중심으로 최종 검증 범위를 줄일 수 있다**는 것이다.
추가 정보 전체의 가능성을 소진했다거나 현재 FM/FM+ALS가 서비스 최종 승자라고 주장하지 않는다.
