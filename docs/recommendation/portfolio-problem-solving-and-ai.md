# 포트폴리오용 — 추천 데이터 한계와 AI 활용 경험

> 용도: 자기소개서, 면접, 회고 발표, 포트폴리오 본문에 맞게 골라 쓰는 원본
> 기준: 구현 중 발생한 실수를 성취로 포장하지 않는다. 서비스가 원래 가진 문제, 피할 수 없는 한계,
> 그 한계 안에서 선택한 논리와 결과만 쓴다.

## 1. 서비스 개발 중 만난 문제

### 문제 1 — MovieLens만으로는 한국 영화와 수록 이후 영화를 추천하기 어렵다

FEELM은 한국 사용자가 한국 영화를 포함해 탐색하는 서비스지만, 추천 학습에 사용할 수 있는 MovieLens
평점은 외국 영화에 크게 치우쳐 있었다. 측정 결과 한국 제작 영화의 Rating 비중은 0.33%였고, 유명 외국
영화 proxy에 전체 Rating의 78.73%가 모여 있었다. 또한 MovieLens 데이터 수록 시점 이후에 나온 영화는
국가와 관계없이 사용자–영화 상호작용 자체가 존재하지 않는다.

협업 필터링은 반복된 사용자–영화 상호작용으로 영화 표현을 학습한다. 따라서 MovieLens 평점이 거의 없는
한국 영화와 수록 이후 영화는 모델 안에서 충분한 item 표현을 얻기 어렵다. 카탈로그에 영화 제목을
추가하는 것만으로는 이 문제가 해결되지 않는다.

### 문제 2 — 실제 추천 품질을 측정할 사용자 순환이 없다

추천 품질을 가장 직접적으로 확인하려면 다음 순환이 필요하다.

```text
사용자에게 영화 추천
→ 실제 시청 또는 선택
→ 평가·저장·관심 없음 등의 피드백 수집
→ 다음 추천과 비교
```

하지만 출시 전 프로젝트에서는 이 순환을 반복할 실제 사용자와 행동 로그를 확보하기 어려웠다. MovieLens의
timestamp도 영화 관람 시각이 아니라 평점을 등록한 시각이므로, 이를 실제 시청 순서나 미래 취향 변화로
간주할 수 없었다.

따라서 “실제 FEELM 사용자가 만족했는가”를 직접 검증하는 것은 불가능했다.

## 2. 인정한 한계

두 문제를 하나의 데이터나 모델로 완전히 해결할 수 있다고 보지 않았다.

- TMDB 콘텐츠 정보는 평점이 부족한 한국 영화를 벡터 공간에 표현할 수 있게 하지만, 한국 사용자가 그
  영화를 좋아한다는 행동 정답을 만들어 주지는 않는다.
- MovieLens 평점으로는 이미 관측된 사용자의 선호 관계를 재현할 수 있지만, MovieLens 사용자가 FEELM의
  실제 사용자와 같다고 볼 수 없다.
- 사용자가 평가하지 않은 영화는 좋아함도 싫어함도 알 수 없다.
- 오프라인 결과가 좋아도 실제 서비스의 시청률이나 만족도 향상이라고 주장할 수 없다.

그래서 목표를 “한국 사용자 추천을 증명한다”로 두지 않았다. 출시 전에 확인할 수 있는 두 가지 가능성으로
줄였다.

1. 한국 영화와 MovieLens 수록 이후 영화처럼 평점이 희소하거나 없는 영화도 콘텐츠 벡터로 비교·추천
   후보화할 수 있는가?
2. MovieLens를 학습·평가·검증 환경으로 사용해 초기 입력 수, 모델, 점수 기준과 데이터 시점 정책을
   결정할 수 있는가?

## 3. 문제를 풀기 위해 세운 논리

### 3.1 영화 정보와 사용자 행동의 역할을 분리했다

| 데이터 | 사용한 역할 | 사용하지 않은 역할 |
| --- | --- | --- |
| MovieLens 평점 | 사용자 선호 행동 학습, 오프라인 정답 구성, 모델 비교 | 한국 영화 정보 보충, 실제 FEELM 만족도 증명 |
| TMDB 구조 특징 | 장르·언어·연대·러닝타임·감독·배우·키워드 기반 영화 표현 | 사용자의 좋아요 정답 |
| 384차원 multilingual E5 | 줄거리·제목 등 텍스트 의미 기반 영화 표현 | 사용자 행동을 대신하는 평점 |

MovieLens 평점이 풍부한 외국 영화에서만 동작하는 협업 모델과, 평점 밀도에 덜 의존하는 콘텐츠 벡터 모델을
같은 후보와 사용자 조건에서 비교하도록 했다. 콘텐츠 모델이 경쟁력을 보인다면 MovieLens 상호작용이 적은
한국 영화도 같은 표현 방식으로 후보화할 근거가 생긴다. 경쟁력이 없다면 콘텐츠 벡터만으로 편향을
보완할 수 없다는 결론을 받아들인다.

목표 도메인·최신성·한국 영화 범위·제품 사용 가능한 라이선스·사용자 행동을 동시에 만족하는 즉시 사용
가능한 대안은 확인되지 않았다. [ML-32M Extension](https://uwaterlooir.github.io/datasets/ml-32m-extension.html)과
[MovieLens Beliefs](https://grouplens.org/datasets/movielens/ml_belief_2024/),
[KMRD](https://github.com/lovit/kmrd),
[Amazon Reviews 2023](https://amazon-reviews-2023.github.io/main.html)은
각각 watch-interest·미시청 기대평점, 한국 영화 평점, 최신 상호작용을 보완할 수 있지만 연구 접근 제한,
MovieLens 문맥, synthetic·라이선스·최신성 Gate, 상품 리뷰 도메인 한계가 있다. 이 자료들은 콘텐츠
벡터를 정답으로 만들어 주는 대체재가 아니라 후속 보조 검증 후보로만 남겼다.

### 3.2 MovieLens를 학습·평가·검증 환경으로 사용했다

실제 추천 후 피드백을 받을 수 없으므로 MovieLens의 사용자–영화 평점을 대리 실험 환경으로 사용한다.
학습용 사용자 행동, 모델 선택용 Validation, 최종 검증용 Locked Test를 분리하고, 같은 조건에서 여러
추천 방식을 비교한다.

이 실험 환경에서 결정하려는 것은 다음과 같다.

- 사용자가 처음 제공할 선호 입력은 몇 편이 적절한가?
- 인기도, 행동 기반, 콘텐츠 기반, 행동·콘텐츠 결합 중 어떤 모델을 사용할 것인가?
- 사용자 이력량, 영화 인기도, 콘텐츠 정보 유무에 따라 어느 점수나 fallback에 우선순위를 둘 것인가?
- MovieLens를 특정 시점 이전 snapshot으로 제한할 것인가, 전체 관측 범위를 보조 학습에 사용할 것인가?
- 같은 사용자의 관측 평점 일부를 가렸을 때 어떤 방식이 높은 평점 영화를 더 위에 놓는가?

MovieLens timestamp는 사용할 데이터 범위를 고정하는 기준이 될 수는 있지만 실제 관람 순서와 동일하다고
보지 않는다. 현재 `REC-EV-019C`의 시간 cutoff 실험도 위 선택지 중 하나이며, 전체 관측 범위를 사용하는
결과와 분리해 해석한다.

### 3.3 단순 기준선보다 나은지를 먼저 물었다

복잡한 모델끼리만 비교하면 서비스에 추가할 가치가 있는지 알 수 없다. 따라서 모든 모델을 MovieLens
인기도 기준선과 비교한다.

- 사용자 입력은 실제 온보딩 부담을 고려해 K=5와 K=10으로 제한한다.
- ItemKNN과 관측 평점 BPR은 사용자 행동 관계를 이용한다.
- TMDB 구조 벡터와 E5 텍스트 벡터는 콘텐츠만 이용한다.
- LightFM은 행동과 콘텐츠를 결합한다.
- RRF는 서로 다른 추천 근거의 순위를 결합한다.

평균 NDCG만 보지 않고 사용자별 개선·동률·악화 비율을 함께 본다. 영화 인기도 구간과 한국어 원어 영화
구간도 분리해, 평균 개선이 다시 유명 외국 영화에만 집중된 결과인지 확인한다.

## 4. AI를 활용한 부분

AI는 문제와 평가 기준을 대신 정하는 용도로 사용하지 않았다. 사람이 위의 데이터 역할과 비교 질문을
먼저 정한 뒤, 반복 구현과 분석 범위를 넓히는 데 사용했다.

- 인기도, ItemKNN, BPR, 구조 콘텐츠, 텍스트 콘텐츠, LightFM, RRF를 동일한 입출력 형식으로 구현
- TMDB 구조 특징 조합과 E5 임베딩 전처리 코드 생성·점검
- K=5·10과 여러 seed를 반복하는 실험 runner 및 checkpoint 구성
- 같은 사용자에서 기준선 대비 차이를 계산하는 분석 자동화
- 사용자 이력량, 입력 영화 인기도, 영화 인기도, 한국어 원어 여부별 구간 분석 생성
- 결과표·그래프·보고서가 같은 artifact를 읽도록 검증 코드 작성

AI를 사용한 이유는 “AI 모델을 썼다”는 말을 만들기 위해서가 아니다. 제한된 시간에 여러 가설을 같은
조건으로 구현하고, 사람이 결과의 의미와 한계를 판단하는 데 필요한 비교 자료를 만들기 위해서였다.

## 5. REC-EV-019C·019D·019E·019F 결과와 판단

K별 256명 tuning panel을 제외한 confirmatory 보조 비교에서도 LightFM T003은 B0보다 높았다. K5는
1,358명에서 `+0.03331` (95% CI `[0.02582, 0.04114]`), K10은 1,223명에서 `+0.04532`
(95% CI `[0.03681, 0.05462]`)였다. 5-seed 안정성은 전체 Validation이 아니라 tuning panel에서만
측정했다.

K5와 K10은 사용자와 미래 구간이 달라 직접 비교하지 않았다. 공통 1,253명의 LightFM 절대 NDCG는
K5 `0.075359`, K10 `0.075348`로 사실상 같았고, K10의 더 큰 B0 대비 차이는 B0가 낮아진
영향이었다. 그래서 REC-EV-019D에서 같은 K10 사용자 1,479명과 같은 미래 10행을 고정하고 prefix만
first5·first10으로 바꾸는 ablation을 별도 사전등록했다.

tuning panel 합집합 426명을 제외한 1,053명의 common-seen-mask 결과에서 K10−K5 NDCG@10은
`+0.02656` (95% CI `[0.01784, 0.03520]`)였다. 그러나 Harm@2 증가의 one-sided 95% upper가
`0.01235`로 사전 안전 한계 `0.005`를 넘었다. 평균 품질 개선과 안전 판정을 분리해 최종 결과를
`FAIL_SAFETY_MARGIN_EXCEEDED`로 남겼고 K10 정책을 채택하지 않았다. 이 primary는 두 arm 모두 K10
seen mask를 쓰므로 profile 정보량만 바꾸는 통제 실험이며 실제 K5·K10 온보딩 전체 효과도 아니다.

양방향 신호도 효과로 해석하지 않았다. 현재 구현은 최종 후보에 positive와 negative anchor가 모두 없으면
B0로 fallback한다. `97/46`은 REC-EV-019C **full Validation 전체**의 K5/K10 anchor-loss 사용자 수다.
REC-EV-019D confirmatory 1,053명에서는 K5 `61`, K10 `34`다. 서로 다른 모집단의 값을 섞지 않았으며,
둘 다 적용 전제와 후보 매핑 손실이지 신호 조합의 효과 검증이 아니다.

019D 결과와 Harm 원인을 본 뒤, 이미 K5가 적용 가능한 사용자는 K5를 유지하고 K10에서 새로 적용 가능한
사용자만 K10으로 바꾸는 019E 규칙을 threshold 없이 고정했다. 같은 1,053명 재사용에서 ΔNDCG는
`+0.013997 [0.008433, 0.019758]`, Harm upper는 `0.003799`로 post-hoc Gate를 통과했다. 그러나
candidate recall@500은 `-0.020893`였고 benefit/neutral/harm은 `70/957/26`이었다. 그래서 성공을
`PASS_POST_HOC_VALIDATION_REQUIRES_FRESH_CONFIRMATION`으로 제한하고 fresh target-independent Validation
전에는 champion이나 제품 정책을 바꾸지 않았다.

REC-EV-019F에서는 frozen 019E rule을 기존 episode 뒤의 새 source row와 future window에 적용했다. 이는
사용자 독립이 아니라 source-row/window 독립이다. tuning union 477명을 future label 전에 제외한 structural
1,021명 중 strict 802명에서 ΔNDCG는 `+0.003617 [0.000291, 0.007239]`, Harm upper는 `0.003741`이었다.
안전 한계는 넘지 않았지만 mean SESOI 0.005에 못 미쳐 `INCONCLUSIVE`로 판정했다. candidate recall@500
`-0.012469`와 positive rank percentile `+0.020316` 악화도 함께 남겼다. 802명 전원의 K5/K10 1,604개
full-catalog ranking을 독립 재계산해 exact Top-10/Top-500과 source-row overlap 0을 검증했지만, 이 결과를
한국 사용자·한국 영화·최신 영화 또는 제품 정책 confirmation으로 확대하지 않았다.

재현성 감사에서는 019D의 5,916개 ranking을 hashed LightFM item representation에서 full-catalog로 다시
계산해 exact Top-10/Top-500, positive mean rank percentile, aggregate를 검증했다. 과거 lock에 없던
runner/verifier hash와 git revision/dirty attestation은 019E부터 추가했고, 과거 lock을 소급 수정하지 않았다.

그러나 처음 문제 1은 해결되지 않았다. TMDB 구조와 E5 텍스트 단독 모델은 인기도를 이기지 못했다.
관측 positive 자체가 Q4에 K5 95.9%, K10 96.4% 몰려 Q1~Q3의 0 적중을 실패로 확정할 검정력이
부족했다. 한국어 원어 positive는 K5 21건, K10 23건이고 Top-10은 모두 0이었다. Top-500도 B0 대
LightFM이 K5 `10/21` 대 `6/21`, K10 `10/23` 대 `6/23`으로 불리한 방향이었지만 작은 표본으로
열등을 확정하지 않았다. 2020년 이후 후보는 9편, positive는 두 K 모두 0이었고 true cold item도 후보에
0편이었다. 최신·cold-item 품질은 측정하지 못했다.

MovieLens 전체 관측 범위를 사용하는 보조 실험은 수행하지 않았으므로 시간 cutoff 정책도 확정하지
않았다. raw Parquet은 `outputs/` ignore에만 있고 외부 artifact URI가 없어 commit 단독 제3자 재현도
불가능하다. `locked_test_used=false`, `champion=null`, `product_policy_updated=false`를 유지했다.

## 6. 자기소개서 원문 초안

영화 추천 서비스를 개발하면서 두 가지 데이터 한계에 부딪혔습니다. MovieLens는 유명 외국 영화에
평가가 집중되어 있어 한국 영화를 협업 필터링으로 표현하기 어려웠고, 데이터 수록 이후 영화에는
상호작용 자체가 없었습니다. 출시 전에는 추천한 영화를 사용자가 실제로 보고 평가하는 순환도 만들 수
없었습니다.

목표 도메인과 최신성, 한국 영화 범위, 제품 라이선스, 사용자 행동을 동시에 만족하는 즉시 사용 가능한

E5 임베딩으로 영화 콘텐츠를 표현하는 방법을 시도했습니다. 두 번째 문제에는 MovieLens를
대리 학습·평가·검증 환경으로 사용했습니다. 각 K 안에서는 동일 사용자와 후보 41,625편으로

사용자·영화 구간 분석, 중단 재개와 결과 검증 코드를 만드는 데 활용했습니다.

처음 문제의 해결을 분리해 판단하고, Locked Test와 제품 정책을 그대로 유지한 경험입니다.

## 7. 문항별로 줄여 쓰는 핵심 문장

### 어려운 문제를 해결한 경험

> 실제 사용자 피드백을 얻을 수 없는 한계를 MovieLens 대리 검증으로 바꾸고, 가능한 콘텐츠 보완책을
> 동일 조건에서 비교했습니다. 같은 사용자·같은 미래 구간에서 first10의 NDCG 개선을 확인했지만 Harm@2
> 안전 한계를 넘자 사전 규칙대로 실패 처리했습니다. 평균 개선과 정책 채택을 분리하고 기존 정책을 유지했습니다.

### AI를 활용해 문제를 해결한 경험

> AI로 여러 추천 모델의 반복 구현, 5개 seed 학습, 중단 재개, 사용자·영화 구간 분석을 자동화했습니다.
> 문제 정의와 판단 기준은 직접 세웠고, AI가 만든 비교 범위를 이용해 평균 개선이 처음 문제의 해결을
> 뜻하지 않는다는 결론까지 검증했습니다.

### 한계를 인정하고 판단한 경험

> TMDB와 E5로 상호작용이 없는 영화도 표현할 수 있었지만 콘텐츠 단독 모델은 인기도를 이기지 못했고,
> LightFM 개선도 인기 영화에 집중됐습니다. 구현 가능성과 추천 품질을 구분해 한국 영화 문제는 미해결로
> 남기고, 목표 도메인 행동 데이터가 필요하다고 결론 내렸습니다.

## 8. 쓰면 안 되는 표현

- “한국 사용자 추천 정확도를 검증했다” — 실제 FEELM 사용자 데이터가 아니다.
- “TMDB 임베딩으로 MovieLens 편향을 제거했다” — 영화 표현을 보완했을 뿐 행동 분포를 바꾸지 않았다.
- “미래에 좋아할 영화를 예측했다” — MovieLens를 이용한 대리 학습·평가·검증 결과다.
- “AI가 최적 추천 모델을 찾았다” — AI는 반복 구현과 분석을 보조했고 판단 기준과 결정은 사람이 정했다.
- “K10이 K5보다 좋으므로 기본값으로 채택했다” — same-window NDCG는 개선됐지만 사전 Harm@2 안전 Gate를
  실패했고 primary는 양 arm에 K10 seen mask를 쓴 통제 ablation이다.
- “양방향 신호가 효과를 냈다” — 양쪽 valid anchor는 LightFM 적용 전제이며 한쪽이면 B0로 fallback한다.
- “019F가 독립 사용자로 019E를 확인했다” — 독립성은 source-row/window에만 있고 결과도 `INCONCLUSIVE`다.
- “저인기·한국 영화·신작에서 실패했다” — 작은 표본 또는 positive 0으로 검정력이 없다.
- 구현 중 잘못 설계한 split, 인증, 라이브러리 설정을 고친 일을 핵심 문제 해결로 포장하지 않는다.
