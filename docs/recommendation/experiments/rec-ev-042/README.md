# REC042 — 분류를 적용한 추천의 관측 평점 비교

상태: DRAFT — 실행 전 설계. Jira [S15P21E106-300](https://ssafy.atlassian.net/browse/S15P21E106-300).
2026-09-08. 개인 연구이며 제품 정책 계약이 아니다.

## 이번에 답할 질문

**같은 사용자의 같은 입력과 같은 ALS 순위에서, 분류를 적용하면 선택한 영화의 선호가
좋아지는가? 맞춤2편과 발견1편에서 각각 무엇을 얻고 잃는가?**

이미 평점이 있는 영화에서 별점을 가리고 세 추천안을 비교한다. 영화의 평가 여부와 ID는
후보 구성에 사용하고 평점·평가용 Q는 선택이 고정된 뒤 채점에만 사용한다.
따라서 **관측 평점 후보 안의 조건부 추천 비교**다. 실제 서비스에서 미평가 영화를
추천한 뒤 만족도를 측정하는 실험과 구분한다.

REC041은 전체 카탈로그→ALS500→타입100에서 공급은 확인했지만 선택 정답이0개였다.
이번에는 같은 미채점 경로를 반복하지 않고 기존 E 전체의 고정 ALS 부분순서를 사용한다.
후보 경로가 달라졌으므로 REC041의 공급률과 이번 품질을 하나의 서비스 성능으로 합치지 않는다.
기존 개발 자료를 다시 사용하는 탐색적 비교이며 새 독립 확증 실험이라고 부르지 않는다.

## 같은 조건에서 비교할 세 안

| 안 | 선택 방식 | 세 번째 슬롯의 의미 |
| --- | --- | --- |
| ALS_ONLY | 분류 제한 없이 ALS 상위3편 | GENERAL3, 발견으로 부르지 않음 |
| RULE_GENRE_SET | 개선 장르 규칙의 맞춤2+연결형 발견1, 없으면 맞춤3 | 실제 D 또는 T3 대체 |
| KM_GENRE | 고정 장르 K-means의 같은 맞춤2+연결형 발견1 규칙 | 실제 D 또는 T3 대체 |

분류 두 안은 REC041의 CONNECTED 정책 하나로 고정한다. T3_GUARD, 새 분류 학습,
추가 ALS 학습, 입력 개수·선정 방식·전환K·500/100 크기 탐색은 하지 않는다.
두 분류 간 차이는 동일 정책에서의 분류 차이이고, 분류안과 ALS_ONLY의 차이는
분류와 맞춤/발견 선택 제약을 함께 추가한 효과다. 군집 알고리즘만의 인과 효과로 부르지 않는다.

## 고정 입력과 선택 경로

- 사용자2,180명, 기존 hash로 고른 O30, 원별점0.5~5.0·간격0.5, 기존 ALS checkpoint를 유지한다.
- 기존 REC032 ALS-only의 `target-order.npz`에서 n30 축의 점수·전역순서를 재사용한다.
  새 fit·fold-in은0회다. Factor가 없는 영화에는 점수를 만들거나 인기 fallback을 섞지 않는다.
- 기존 E의 사용자-영화191,933개를 그대로 사용한다. O30과 E는 겹치지 않는다.
  공통 후보는 E 중 ALS Factor 지원 영화이며 TV-only 형식12편은 세 안 모두에서 제외한다.
- REC041 `eligibility.npz`의 같은 사용자·카탈로그·T/D mask를 재사용한다.
  T는 긍정 입력이 하나 이상 속한 그룹, D는 O30에 없는 그룹이면서 긍정 입력과
  TMDB 장르·감독·키워드 연결이 있는 영화다. 경험은 O30 안의 proxy다.
- 점수 내림차순·영화ID 오름차순을 유지한다. 기존 전역 순위를 사용하므로 E 안의 순위만 바뀐다.
- 분류안의 T가2개보다 적으면 부족을 기록하고 D를 T로 재명명하지 않는다.
  T≥2이고 D가 있으면 T2+D1, D가 없으면 가능한 T3, 그것도 없으면 T2로 남긴다.
  같은 사용자에게 세 안 모두 동일한 제외와 후보 지원 경계를 적용한다.

## 먼저 확인할 자료

실행 전에는 파일 크기·SHA256·schema·사용자/영화 축·입력과 E 비겹침·Factor 지원·T/D 공급을 확인한다.
E/H의 평점·Q·histogram 값은 새 선택을 봉인하기 전 읽지 않는다. 별도 E membership과
기존 점수/역할 산출물로 후보를 구성하므로 선택 코드에 정답 열을 전달할 필요가 없다.
전체 사용자 수를 줄이지 않고 방법별 공급 가능 수와 공통 비교 가능 수를 남긴다.

독립 읽기 전용 점검에서 공통 후보191,153쌍(사용자당18~106편)을 확인했다.
미지원779쌍과 지원 영화 중 TV-only1쌍이 제외됐다. 세 안 모두2편/3편을 비교할 수 있는
사용자는2,180명이다. D 후보가 있는 사람은 규칙1,795명/KM1,448명, 양쪽 공통1,283명이다.
이 수치는 역할 개수로 확인한 가용성이다. 새 추천 목록 선택이나 평점 채점은 수행하지 않았다.
정확한 입력14개의 해시와 점검은 [설정](config.json), [가용성 기록](data-readiness.json)에 있다.

## 채점과 분모

Q는 기존 사용자 전체 별점 histogram의 동점 midrank를 유지한다.
원별점의 분포도0.5 단위로 제시한다. Q나 ALS 점수를 실제 감상 별점으로 저장하지 않는다.

| 보고 단위 | 지표 | 분모 |
| --- | --- | --- |
| 주 비교: 각 안의 앞2편 | 평균Q, 최소Q, Q≤0.2인 영화가 하나 이상 포함된 비율 | 세 안 모두2편을 제공한 동일 사용자 |
| 전체3편 | 같은 세 지표, 원별점 분포 | 세 안 모두3편을 제공한 동일 사용자 |
| 실제 D1 | 평균Q·Q≤0.2 비율·제공률 | 각 안의 D제공 사용자와 전체 요청 분모를 함께 표시 |
| D끼리 비교 | D의 평균Q·저선호 차이 | 두 분류 모두 D를 제공한 동일 사용자 |
| D로 교체한 손익 | D와 ALS_ONLY의 세 번째 영화 Q·저선호 차이 | 해당 안에서 D를 제공하고 ALS3도 있는 사용자 |
| T3 대체·부족 | 대체/부족 사유와 건수 | 전체2,180명 |

기준선의 앞2편은 일반 개인화2편이고 분류안의 앞2편만 정책상 T2다.
D가 없는 사람을 D의0점·불호0건으로 세지 않는다. 각 비교의 제외 이유와 공통 사용자 수를 보고한다.
전체3편 평균이 발견의 손실을 숨기지 않도록 T2·D1을 함께 제시한다.
관측 후보에서 채점률100%인 것은 설계의 결과이며 추천 정확도100%가 아니다.

## 불확실성과 판정

- 주 비교의 세 쌍(RULE−ALS, KM−ALS, KM−RULE) × 세 지표를9개 비교 family로 고정한다.
- 공통 앞2편 사용자에서 사용자 단위 paired bootstrap20,000회, seed20260908,
  양측 Bonferroni 조정 percentile 구간으로 family95% 구간을 계산한다.
  개별 구간의 분위수는0.05/(2×9), 1−0.05/(2×9)로 고정한다.
  모든 쌍에 같은 재추출 사용자 인덱스를 쓴다.
- 각 차이는 추정값·구간·구간폭·사용자 수·두 안의 지표가 달랐던 사용자 수를 보고한다.
  평균/최소Q는 클수록, 저선호 포함은 작을수록 유리하다. 구간이0을 걸치면 방향 미판정이다.
- 보조 비교는 효과 크기와 분모를 설명하는 기술 통계이며 별도 유의성·우승 판정을 하지 않는다.
- 고정 자료를 모두 사용한다. 결과를 보고 사용자·seed·정책·분모·임계치를 바꾸거나 표본을 늘리지 않는다.
  주 비교 가능 사용자가2명 미만이면 구간을 만들지 않고 자료 부족으로 중단한다.
- 이 구간은 현재 개발 사용자 안의 표본 변동을 나타내며, 기존 후보 선정·반복 연구로 생긴 편향을 제거하지 않는다.
  실용적 채택 한계는 아직 합의되지 않았으므로 제품 승자·동등성·비열등성을 선언하지 않는다.

결론은 분류 적용의 맞춤 선호 이득/손실, 발견의 제공과 교체 손익, 두 분류의 차이를 함께 설명한다.
유리한 지표 하나로 최종8맛·발견 정책·전환K를 확정하지 않는다. 조건부 비교 자체의 결론까지
검증하고 인계하며, 실제 미평가 영화의 만족도·새로움·설명 납득은 관측 근거가 없는 한 미확인으로 둔다.

## 실행·검증·인계

1. 설계와 입력 manifest·선택/채점 코드·합성 검사를 독립 검토한다.
2. 입력 핀을 확인하고 E의 고정 점수/역할에서 세 안의 선택을 만들고 SHA256으로 봉인한다.
3. 봉인 일치 후에만 E/H를 열어 Q를 재계산하고 선택 영화의 원별점과 채점한다.
4. 별도 검수자가 입력 축·선택·누수·모든 집계와 주요 구간을 독립 재계산한다.
5. 이해하기 쉬운 비교표·결론, 최소 실행 코드·설정·집계·출처·재현 안내를 GitLab MR에 올리고 Jira에 연결한다.

현재 파일은 설계이며 아직 새 추천 비교 결과가 아니다. 실행 코드 검토 전 실험은 시작하지 않는다.
실행 예산은15분·프로세스 트리 메모리4GiB이며, 한도를 넘으면 부분 산출물을 보존하고 실패로 기록한다.
원본 사용자별 데이터·평점·모델은 Git에서 제외한다. 기존 결과·봉인은 변경하지 않고 새 출력에 기록한다.
