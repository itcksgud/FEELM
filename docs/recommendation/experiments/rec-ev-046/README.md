# REC046 — 소량 입력을 받는 추천 모델 5종 비교

상태: DRAFT. 개인 로컬 탐색이며 서비스 모델 채택 또는 운영 계약이 아니다.

사용자 질문은 **MovieLens에 없는 영화도 다뤄야 하는 서비스에서 ALS, FM,
ALS+FM, 공유 교차 리지, Spark GBT 중 어느 실행안이 유리한가**이다.
데스크탑에서 같은 조건으로 비교하고 실행 시간과 지원 범위를 함께 본다.
8개 분류·K-means·Top500·Top100·추천 2+1 정책은 전제로 두지 않는다.

## 자료와 역할

- REC032의 이미 사용한 개발 사용자 재분할 3회와 REC045의 85,517편 현재 메타데이터를 재사용한다.
  LOCKED_TEST/FINAL_RESERVE는 열지 않는다. 허용 개발 ID의 해시 조건을 다시 검사한다.
- 평가 사용자 합집합을 모든 회차 학습과 validation에서 제외한다.
  평가자는 기존 시간 진단처럼 2019-01-01 이전 30편 이상, 이후 2편 이상인 사람이다.
  기존 고유 300명과 일치해야 한다. 이미 관측했던 개발 자료이며 새로운 확증 자료가 아니다.
- validation은 3회차 학습 ID의 교집합에서 평가자 합집합을 뺀 사람 중 같은 시간 자격을
  충족한 사람을 해시 순서로 300명 선택한다. 모든 회차에서 validation 사용자는 학습 제외한다.
  100명 미만이면 자료 부족으로 중단하며 cutoff를 결과에 맞춰 바꾸지 않는다.
- 시간 경계는 UTC 2019-01-01 (`1546300800`). 학습과 입력은 `<`, 평가/validation 목표는 `>=`.
  TMDB는 현재 메타데이터이므로 **과거 평점의 시간 경계를 지킨 회고 비교**일 뿐 당시 자료의 재현은 아니다.
- 영화 ID의 고정 SHA256 해시로 20%를 전역 학습 제외한다. 그 영화의 평점은 모든 학습 입력,
  타깃, 집계에서 제외한다. 해당 영화 메타데이터는 예측 시 변환할 수 있으나 vocabulary fit에서는 제외한다.
- 영화 미지원 원인을 구분한다: 실험적 20% 제외 / 허용 개발 집단에 경계 이전 관측 없음 /
  제한한 학습 표본에 없음. 마지막 둘을 실제 신작과 같은 말로 사용하지 않는다.

## 같은 자료로 학습하기

각 회차에서 허용 학습 사용자 중 해시로 최대 12,000명을 선택한다. 각 사용자에게
K=0/1/5/10/30 중 하나를 해시로 배정한다. 해당 K+8편의 경계 이전 비제외 영화를 확보할
수 있는 사람만 사용하며 부족한 사람 수를 기록한다. 그 이력에서 해시 순서로 K+8편을 뽑아
timestamp 오름차순/movie_id 오름차순으로 정렬하고 앞 K편을 입력 O, 나머지 8편을 학습 타깃으로 둔다.
동시 입력 시각은 movie_id로 정렬하며, **동일 timestamp 내의 실제 선후를 안다는 주장은 하지 않는다.**

이 K+8편 전체를 공통 R로 한다. ALS도 R만 학습하며, FM/리지/GBT도 같은 R의
입력 별점과 목표 8개만 사용한다. 모델의 목적함수와 별점의 역할은 다르지만 허용 관측 정보는 같다.
지도학습은 모든 사용자에게 목표 8개로 동일 가중이다. FM의 weightCol에 의존하지 않는다.
입력량별로 모델을 다시 학습하지 않고, 혼합 입력량을 받는 공유 모델을 학습한다.
이는 전체 32M 학습 결과가 아니라 고정 자원·학습량에서의 실행안 비교다.

## 공통 영화 정보와 입력

장르, 키워드, 제작 국가·언어, 개봉 연대·길이, 감독, 상위 5명 배우,
제작사·시리즈의 원래 다중 속성을 사용한다. 인물 정보를 영화 한 유형으로 합치지 않는다.
현재 TMDB 평점·투표수·인기도·수익·OTT 정보와 MovieLens 영화별 별점 집계는 특징에서 제외한다.
후자는 학습 목표가 자기 영화 평균에 들어가는 누수를 피하려는 이번 단순 비교의 선택이다.

카탈로그를 dense화하지 않는다. vocabulary는 회차의 R에 등장한 고유 영화에서만
빈도를 세어 블록별 상한(장르 전체, 키워드128, 국가언어64, 연대길이64, 감독64,
배우128, 제작사시리즈64)을 적용한다. 동률은 토큰 문자열 순이다. 각 블록에는 별도 OOV 열을 둔다.
라벨에 따른 특징 선별은 없다. 각 영화 블록을 L2 정규화하고 이어붙인 CSR을 x로 둔다.
고빈도 특징 상한은 첫 자원 제한 실행안의 일부이므로 전 메타데이터 표현의 최적성은 주장하지 않는다.

입력에서 p=mean(x), q=mean((별점/5)*x)를 계산한다. K=0이면 둘 다 0이다.
사용자 평균/5(입력 없으면 학습 R 평균/5), K/30을 더한다.
FM·리지·GBT 모두 `[x,p,q,p*x,q*x,평균/5,K/30]`의 같은 특징을 받는다.
`*`는 원소별 곱이다. 공유 리지도 사용자×후보 항으로 사람별 순위를 달리할 수 있다.
원 별점은 0.5 단위를 보존하고 계산용 변환만 별도로 한다.

## 모델 선택

Spark 4.1.3의 명시적 ALS, FMRegressor, L2 LinearRegression, GBTRegressor를 쓴다.
후보는 config.json의 각 2개로 고정한다. 각 후보의 모든 validation 예측을 저장한 후
validation 별점을 열어 K별 사용자 MSE를 동일 가중 평균한 값으로 선택한다. 동률은 후보 번호가 작은 것.
리지 objective history, 학습 raw RMSE, 반복 상한과 로그를 보존한다. Spark FM API에는 동일한
objective history가 없어 unavailable로 명시하고 **FM 최적 수렴 확인 불가**로 기록한다.
반복 상한 도달을 최적 수렴으로 부르지 않으며, 이 후보 설정의 결과로 FM 전체의 한계를 단정하지 않는다.

ALS 신규 사용자 벡터는 입력 중 factor가 있는 영화만으로
`solve(Y.T Y + reg*n*I, Y.T r)`를 계산한다. 후보 factor 또는 유효 입력이 없으면
`(입력별점합 + 5*학습R평균)/(K+5)`로 처리한다. 이 경우를 직접 ALS 예측으로 세지 않는다.
FM, 리지, GBT도 오류/비유한 예측을 숨기지 않고 중단한다.

ALS+FM은 ALS가 직접 계산 가능한 행만 `(1-a)*FM + a*ALS`를 사용하고 나머지는 FM이다.
a=0/.25/.5/.75/1 중 validation에서 같은 기준으로 선택한다. 0도 허용한다.
기존 동일 RRF60 결과를 이번 가중치로 가져오지 않는다. test 결과를 보고 후보를 추가하지 않는다.

## 채점과 판정

평가 입력은 경계 이전 최신 30편(timestamp 내림차순, 동률 movie_id 오름차순)의
앞 K=0/1/5/10/30편이다. 후보 E는 이후 관측한 모든 카탈로그 영화이며 ALS 미지원 영화도 남긴다.
O와 E가 겹치면 중단한다. K는 민감도 진단이지 서비스에서 요구할 입력 개수의 결정이 아니다.
모든 회차·모델·설정의 예측을 먼저 만들고 validation으로 설정·결합을 고정한 뒤 선택 예측을
봉인한다. 그 후에만 허용 평가 E의 별점을 수치로 연다. 데이터 역할→영화/시각→허용 별점 순으로 읽는다.

- **별점 오차:** 예측을 0.5~5로 잘라 사용자별 E MSE, MAE를 계산한다.
- **선호 순서 정확도:** 실제 별점이 다른 E 영화 쌍에서 원 예측의 순서가 맞는 비율.
  실제 별점 동점은 제외하고 예측 동점은 0.5로 센다. 별점 오차만 줄어도 취향 개선이라 부르지 않는다.
- 전체, ALS 지원, 실험적 제외, 나머지 미지원과 입력 내 미지원 개수/비율을 기록한다.
  별점 채점과 직접 점수화율을 함께 보고, 후보를 drop해서 모델별 분모를 다르게 만들지 않는다.
- 연도·학습 영화 평가 수 구간별 사용자/영화/평가 수와 오차를 기술 통계로 남긴다.
- 미평가 영화는 UNKNOWN이다. 실제 서비스 카탈로그 Recall/NDCG를 만들지 않는다.

K별 지표와 집단별 차이를 분리해서 보고한다. 같은 사람의 회차 결과를 먼저 평균한 후
사용자를 동일 가중한다. 각 K에서 모델 10쌍×2지표=20대비의 사용자 paired bootstrap
10,000회, Bonferroni 양측95% 구간을 제시한다. 다른 K/집단까지 통틀어 확증 유의성을 주장하지 않는다.
쌍 순서가 없는 사용자 수를 공개한다. 집단 고유 사용자<30이면 수치만 기술하고 승자를 판정하지 않는다.
두 주지표가 충돌하거나 구간이 0을 포함하면 단일 승자를 억지로 고르지 않는다.
이 결과가 2026 한국 사용자에게 가장 좋다는 결론은 낼 수 없다.

## 실행·중단·검토

데스크탑7500F/32GB. 모델별 Docker 프로세스를 하나씩 실행한다. local[4], JVM6GiB,
컨테이너10GiB, swap 추가 사용 없음, 호스트 준비 작업6GiB 상한. 모델별45분 상한.
한 모델의 실패를 다른 모델의 승리로 계산하지 않는다. 자원 축소/코드 수정은 E를 열기 전에
수정 이유·새 fingerprint·재검토를 남기며 이전 시도는 보존한다.
원본·역할·시간·O/E 중복·표현 차원·유한 수치·예측행 누락 검사를 실패하면 중단한다.
별점 없는 합성 smoke로 런타임과 FM 수식 parity를 먼저 점검한다.
설계/실행 코드 fingerprint와 독립 pre-review가 일치해야 실제 자료를 준비할 수 있다.
실행 후 별도 검토자가 원 점수에서 재집계와 누수/주장 범위를 점검한다.

모델·Parquet·개인별 예측은 outputs 아래 LOCAL_ONLY, Git 제외다.
README/config/코드/검토·소형 결과만 보관한다. Jira·GitLab 게시·운영 계약 변경은 이 작업에 포함하지 않는다.

재현은 `docs/runbook/local-development.md`의 REC046 명령을 따른다. 기존 출력은 덮어쓰지 않는다.
