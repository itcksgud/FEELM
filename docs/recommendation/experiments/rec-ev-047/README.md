# REC047 — 동일한 입력·예측 기간에서 학습량을 늘리는 비교

상태: DRAFT. 개인 로컬 개발 자료 비교. 서비스 모델 채택 계약이 아니다.

REC046 구성 감사의 후속이다. 기존 모델 5종(ALS, FM, ALS+FM, 공유 리지, Spark GBT)을
유지하며 사용자 활동량·영화 지원량별로 평가한다. 새 모델을 늘리지 않는다.

## 먼저 정한 범위

1. 별점 없는 가용성 점검에서 같은 역할·기간·K에 어떤 사용자가 존재하는지 확인한다.
2. 입력 생성·예측 기간·역할·표현·학습량·설정과 중단 조건을 고정해 독립 검토받는다.
3. 검증 시점에서 설정을 정하고, 더 뒤인 평가 시점 이전 자료로 다시 학습한 후
   고정된 같은 평가 자료에 학습량별 결과를 비교한다. 검산과 결론까지 로컬에 보존한다.

학습량은 **고정된 학습 사용자 pool의 중첩 25/50/100%**다. 각 사용자에게서 허용되는
과거 이력 전체를 사용하며 K+8개로 잘라 버리지 않는다. 이는 사용자 수를 통한 학습량
곡선이다. 같은 사람의 평점 수만 늘린 효과나 REC046의 절삭 효과만을 분리한 실험은 아니다.

## 가용성 점검 계약

- 원본 `C:/higher/projects/MM/data/raw/ml-32m.zip`의 userId/movieId/timestamp만 읽는다.
  rating 열은 로드하지 않는다. 아직 새로운 별점·검증·평가 정답을 열지 않는다.
- 후보 집합은 기존 REC032 `development_user_ids` 58,014명 안이다. 기존 development
  역할 해시를 다시 확인한다. LOCKED_TEST/FINAL_RESERVE 별점은 사용하지 않는다.
- 새 사용자 역할은 고정 SHA256 `rec047-role|{uid}`의 앞 8바이트 정수 `%100`으로
  0~69 학습, 70~84 검증, 85~99 평가로 나눈다. 이후 모든 시점·학습량에 같은 역할을 쓴다.
  이전에 관측한 개발 자료의 재사용이며 새 확증용 holdout으로 격상하지 않는다.
- 최신의 완결된 미래 기간부터 확인한다. 평가 origin 후보는 2023-01-01, 2022-01-01,
  2021-01-01 UTC 순이며 각 horizon은 정확히 180일이다. 검증 origin은 평가 origin−180일.
- 모든 역할에서 origin보다 이른 최신 K개(0/1/5/10/30)를 입력하고
  `[origin, origin+180일)`의 카탈로그 관측을 목표로 한다. 동일 timestamp를 경계 양쪽으로
  나누지 않는다. K별로 입력을 확보한 사용자만 비교하며 K30 가능을 공통 자격으로 요구하지 않는다.
- MSE 대상은 목표 관측 1개 이상이다. PA의 실제 비동점 쌍 유무는 나중에 정답을 열고
  따로 센다. 평점 없는 현재 점검에서 목표 관측 2개 이상을 PA 가능 사용자라고 단정하지 않는다.
- 활동량은 해당 origin 이전 원본 전체 영화 평가 수: 0, 1~9, 10~29, 30~99, 100~299, 300+.
  카탈로그 내 이전 수와 최근 365일의 평가 수도 병기한다. 활동량은 입력 K와 다르다.
- origin별 각 역할의 전체 사용자 수, K 입력 가능 및 목표 존재 수, 목표 행/영화 수,
  활동량×K별 사용자 수를 기록한다. 빈 셀은 그대로 남긴다.
  고유 목표 영화 수는 K0·활동량 ALL의 범위이며, K별 목표 행 수와 분모가 다르다.
  원본 최대 관측시각이 최신 후보 horizon의 끝 이후인지도 확인한다.
- 날짜 선택은 성능이나 별점 없이 **검증과 평가 각각 K0 및 K1의 목표가 있는 고유 사용자가
  100명 이상인 가장 최신 후보**를 사용한다. 1~29 활동량 셀 부족으로 날짜를 계속 바꾸거나
  현재성 목표를 포기하지 않는다. 그 셀 부족은 명시적인 검증 한계로 남긴다.
  어느 후보도 이 기준을 만족하지 않으면 실제 학습 전에 자료 부족으로 멈추고 결론을 남긴다.
- 가용성에 2019년 이전 30편 기준을 재사용하지 않는다. 영화 전체 보류는 실제 실행 설계에서
  고정하고 모든 학습량에서 같은 집합을 유지한다. 가용성 점검은 보류 전 카탈로그 기준이다.

결과를 보고 임의로 사용자 역할·날짜 후보·활동량 경계를 바꾸지 않는다.
원본 3열 전체 행 수와 소스 해시를 확인하고, 카탈로그·개발 역할의 관측 metadata만 별도
Parquet에 저장한다. 사용자별 metadata는 Git 제외·LOCAL_ONLY다. 기존 REC046 봉인은 보존한다.

## 실제 실행 설계에서 유지할 조건

- 시간 분리와 사용자 분리를 모두 유지한다. 검증 origin 이후의 별점으로 검증 모델을
  학습하지 않는다. 최종 평가도 해당 origin 이전 학습 역할의 별점만 사용한다.
- 지도학습은 과거의 비중첩 180일 구간에서 같은 latest K→다음 180일 목표를 구성한다.
  사용자×origin마다 가능한 K 하나를 라벨과 무관한 해시로 배정한다. K+8 자격 선별은 없앤다.
- 학습량 간 Val/E 사용자·입력·목표는 고정한다. 영화층의 주 비교는 100% 학습 역할의
  origin 이전 지원량으로 고정하고, 각 수준의 실제 지원량과 ALS 직접 점수율은 별도 표시한다.
- 감독·배우 등 원래 ID는 학습 사전 상한으로 하나의 OOV에 합치지 않는다. 원 토큰 CSR로
  목표 영화와 O의 정확한 교집합/유사도/별점 가중 관계를 계산해 공통 저차원 입력을 만든다.
  이 표현은 특정 인물별 전역 효과를 직접 학습하는 full-ID 모델과 다르다.
- 현재 TMDB의 시점 한계와 과거 해외 MovieLens의 대상 차이는 유지된다. 입력·예측 기간을
  맞췄다는 이유로 2026 한국 서비스 성능을 입증했다고 주장하지 않는다.
- 데스크탑에서 순차 실행하고 가장 작은 학습량에서 자원 사용을 측정한다.
  자원 실패를 모델 성능 패배로 처리하지 않는다. 성능을 보고 설정 후보를 늘리지 않는다.

실제 별점 개방과 학습은 별도의 고정 실행 설정·코드에 대한 독립 검토 후 수행한다.
