# 기본 추천 전 그룹 사전작업

상태: DRAFT — 실행 전 독립 검토 대상. 2026-09-11.

## 승인 범위

사용자의 새 요청 ‘기본 추천 구현 전 그룹 수·분할 방식·사용자와 그룹 비교의 사전 작업’에 따라 이 부분을 실행하고 결과 검증한다. 기존 방법 비교의 DESIGN_ONLY 봉인 자체는 수정하지 않는다. 이번은 M1+M2-A의 공통 그룹 준비이며 FM/예상 평점/목표 실제 별점/최종 영화 순위/추천 성능/서비스 변경은 포함하지 않는다. 학습 평점 공통순위 Q도 이번 최소 사전작업에는 필요하지 않아 제외한다. 군집 K-means는 학습하지만 선호 예측모델은 학습하지 않는다.

## 신작 추가 불변 조건 — 최신 사용자 요구

**신작 추가로 그룹 경계가 바뀌지 않아야 한다.** 초기 카탈로그에서 한 번 선정한 K·어휘·IDF·정규화 방식·centroid·canonical group ID·기준 영화 집합 I_g·반경 및 경계 기준 분포를 하나의 불변 버전으로 저장한다. 신작은 frozen transform 후 가장 가까운 기존 중심에 배정만 한다. 신작 추가 경로에서 fit/partial_fit, IDF 갱신, 중심 재평균, 그룹 ID 재정렬, I_g/CDF 갱신을 하지 않는다. 새 model version으로 교체하는 작업도 자동 수행하지 않는다.

중심=I_g의 초기 평균이며 신작을 포함한 현재 소속 영화 전체의 평균일 필요는 없다. 새 키워드/장르는 기존 어휘에 없는 경우 OOV로 기록하고 축을 늘리지 않는다. 기존 어휘에 투영 후 유효 block을 정규화한다. 모든 특징이 OOV/없음이면 GEOMETRY_UNKNOWN이고 배정하지 않는다. 일부 특징만 지원하는 경우 지원량을 기록한다. 기존 영화 ID를 append로 다시 넣는 것은 거부하며, 기존 메타데이터를 조용히 덮어쓰지 않는다.

기존 영화의 저장된 소속·거리·percentile은 원본 배열로 조회하고 재계산으로 자기 동률을 바꾸지 않는다. 신작의 percentile은 초기 I_g의 저장 거리 배열에서 (left search position + right search position)/(2*|I_g|)로 계산한다. 신작 수는 분모에 들어가지 않는다. M2-A의 기준도 고정 I_g이며 같은 긍정 입력에서는 그 기준 영화들의 거리를 한 번 계산한 배열을 재사용한다. 사용자 입력 P/V가 바뀌면 개인 비교값은 변할 수 있지만 군집 경계는 고정이다. 신작 때문에 후보 목록 자체가 달라지는 것은 정상이다.

기하 기준 movie_ids(유효 특징 영화)와 catalog_movie_ids(결측 포함 전체 초기 영화)를 따로 저장한다. append 함수는 호출자가 전달한 최신 등록 ID 목록에 전체 초기 카탈로그가 포함되는지 확인하고, 앞선 신작을 포함한 기존 ID와 충돌하면 거부한다. 함수는 새 등록 목록을 반환하며 고정 I_g는 수정하지 않는다. 이 함수는 상태를 직접 저장하는 서비스 API가 아니다. 향후 서비스 연결 시 호출자가 최신 등록 목록을 원자적으로 읽고 갱신해야 한다. 모델 버전은 features/vocabulary/axis/immutable-model/assignments 파일 해시를 함께 묶어 식별한다.

## 재사용할 고정 규칙

앞선 `group-discovery-comparison/GROUPS-METHODS.md`의 장르+키워드 단위벡터, DF>=5 IDF, 일반 Euclidean KMeans, K={16,32,64}×seed={20260911,20260912,20260913}, n_init=10/max_iter=300/tol=1e-4/lloyd를 유지한다. 8그룹에 맞추지 않는다. 세 seed 모든 run의 최소100편·최대35%·수렴·중심 평균·최근접 배정/중복중심 확인과 쌍별 ARI>=.70를 만족한 가장 작은 K를 선택한다. 대표 run은 첫 seed로 고정한다. 모두 실패하면 GROUPING_NOT_READY이며 K를 억지로 정하거나 조건을 낮추지 않는다.

입력은 원본의 REC033/045 metadata, text339 catalog/texts의 release_date/contexts다. config.json에 기존 seal의 SHA-256와 bytes를 명시한다. 85,517 movie_id 축, cap10 270명의 유일성, 입력/기시청/시간·별점 범위를 확인한다. contexts에서 ei/target_timestamps/목표 별점은 사용하지 않는다. 사용자 그룹 비교는 cap10 270명 전체를 유지한다. h>0 186명·h0 84명은 출처 정합성 assertion이며 긍정 입력을 가진 사용자만으로 모집단을 축소하지 않는다.

현재 카탈로그 전체의 비지도 특징/군집 분석이다. 과거 시점의 데이터 재현, 신규 영화 품질, 사람의 취향 유형을 입증하지 않는다. 그룹 설명은 관측 특징과 대표 영화 제목으로만 제시하며 생성한 의미 이름을 정답으로 취급하지 않는다.

## 단계 및 완료

1. prepare: 파일 무결성·축 확인, frozen 영화 벡터와 어휘·coverage, 허용 입력 context만 저장. 미래 별점/선호 점수/훈련 평점 읽기0.
2. fit: 고정9run을 한 번씩 실행, K별 크기·ARI·시간/메모리와 중단 이유 기록. 모든 run이 있어야 K선정. 통과하면 불변 중심/배정/기준 반경·경계·percentile 및 그룹별 특징·중심 대표 영화 저장. 불변 append API를 합성·저장 모델 사례로 검증한다.
3. profiles: fit 결과가 독립 검산 PASS인 경우 E=V그룹 경험량, A=max 긍정 입력과 중심 cosine, G+ 및 M1(E<=1,A>=.25)/M2-A(G+,A>=.25)의 최대5그룹을 비교. 경계 하위20%, 선호 영화거리 상위25%, 반경 상위1% 제외는 고정 기준 I_g에서 계산. 선택 그룹 내 현재공개·미시청 영화의 기하 후보 수만 집계하고 최종 추천은 하지 않는다.
4. report: 독립 결과 검토 후 그룹수 결정/미결정, 불변 조건 검증, 사용자 비교 가용량과 비용, 다음 모델 연결 지점을 보고한다. 그룹 준비 결과를 발견 추천 효과 입증으로 확대하지 않는다.

코드/설계/config의 정확 SHA를 실행전 검토한다. stage의 output seal 및 독립 결과 검토가 다음 stage의 gate다. 입력·코드·config가 바뀌면 중단하고 재검토한다. 이전 실행 산출물을 덮어쓰지 않는다. 정답 없는 기하 공급량이 좋은 영화의 공급량은 아니다.

승인 당시 코드/config fingerprint와 읽을 부모 seal·결과검토 해시를 시작 때 고정한다. 정상 seal 작성 직전 원입력(prepare)과 부모 산출물/검토 및 코드의 동일성을 다시 확인하며, 변경되면 실패 기록을 남기고 정상 seal을 쓰지 않는다. 각 stage seal에 부모 seal/검토의 해시를 연결한다.

## 자원과 동시 작업

다른 연구가 실행 중이므로 1thread, 자기 프로세스 RSS 2GiB, 호스트 실행 시작 가용3GiB 이상을 적용한다. 실행 중 가용1GiB 미만 또는 자기 RSS2GiB 초과가 3회 연속이면 자기 프로세스만 중단한다. 외부 WSL/Docker/다른 연구는 종료하거나 변경하지 않는다. prepare20분, fit 전체120분, profiles30분 상한. timeout/메모리/수렴 실패로 불완전하면 원인을 보고하고 임의 K선정/부분자료로 통과하지 않는다.

자원 감시 예외도 조용히 무시하지 않고 자기 stage의 resource-stop.json에 원인·메모리·경과시간을 기록한 뒤 자기 프로세스를 중단한다. 감시는 1초 샘플링이므로 보고 peak RSS는 샘플 기반 측정값이며 순간 최대값을 완전히 포착한다는 보장은 없다.

## 합성/불변 검증

namespace·block 정규화·빈/OOV, 최근접 긍정 영화, 2위 중심이 아닌 실제 가장 가까운 초평면, 중심 재정규화에 따른 잘못된 배정, 동률 midrank/CDF, V와 O의 차이, 입력0/긍정0, 중복중심을 검사한다. append의 어휘/IDF/중심/기준 arrays 불변, 낮은 새 movie_id·OOV·동일 특징 반복·순서/배치, 기존 ID 수정 거부를 검사한다. 같은 사용자 입력에서 기존 영화의 판정이 유지되는지 확인한다. 실행용 코드 외 독립 검토자가 결과 source→저장물 관계를 별도로 확인한다.
