# REC037 — c-TF-IDF에서 장르와 세부 키워드를 분리하면 설명이 나아지는가

상태: DRAFT — 개인 연구 진단 계약. 2026-09-08. 사용자 승인: 대표 키워드와 줄거리 구절을 통한 설명 보강 점검.

## 질문과 고정 범위

**혼합 c-TF-IDF가 가렸던 내용 차이가 있으며, 그 차이가 실제 영화 사례도 설명하는가?**
REC033의 같은85,517편·8개 군집·배정·centroid·임베딩을 그대로 유지한다. 새 추천 모델·군집·인코딩·
평점 접근·네트워크 요청·패키지 설치는 없다. 원별점 ALS·외부8맛·반별점·슬롯 정책은 이번 변경 대상이 아니다.
REC036에서 이미 본 개발 자료의 사후 진단이며 새 독립 사용자 평가가 아니다.

## 전체 영화에서 계산할 것

REC033의 장르/키워드 ID 토큰별 영화 빈도와 전역 DF≥5 어휘를 재사용한다. 영화 안에서 같은 토큰은
한 번 센 원시 빈도다. metadata·assignments로 빈도를 다시 검산하고 원본과 같아야 진행한다.
원래 혼합 c-TF-IDF와 상위15개를 먼저 재현한 뒤 **장르만/키워드만** 각각 정규화·IDF를 새로 계산한다.
기존 혼합 점수에서 장르 단어만 가려서 보이는 것과 구분한다.

각 채널에서 counts를 군집별 L1 정규화하고 `log(1 + floor(평균 군집 토큰 수) / 전체 토큰 빈도)`를
곱한다. 동률은 term_key 문자열 오름차순, 점수가 양수인 상위15개만 보이며 적으면 그대로 남긴다.
채널별 정규화 분모가 다르므로 서로 다른 채널의 점수 크기를 직접 비교하지 않는다.

각 문구에는 군집 내 등장 영화 수/군집 전체 수, 군집 밖 등장 수/밖 전체 수, 두 비율 차이를 붙인다.
키워드가 없는 영화도 분모에서 빼지 않는다. 채널별 원시 메타데이터 보유 영화 수와 DF 필터 후 남은
토큰이 있는 영화 수를 모두 보고한다. 고득점이 곧 높은 보급률 또는 사용자 선호라는 뜻은 아니다.
형식·제작 관련어·지명·인물명도 결과를 보고 삭제하거나 재정렬하지 않는다. 보고서 해석에서 내용 주제와 구분한다.
군집 쌍별 상위15개 교집합 수와 전체 c-TF-IDF 벡터 cosine도 채널별로 기록하지만 통과선을 만들지 않는다.
키워드를 따로 본 결과의 중복 감소를 군집 품질 상승으로 부르지 않는다.

## 줄거리 구절과 영화 사례 검수

전체85,517편의 줄거리 c-TF-IDF를 수행하지 않는다. 기존REC036의 **고정120편**(군집당 중심5·hash5·경계5)을
전부 재사용한다. 새 사례를 유리하게 고르지 않는다. 원문은 이전 검증·봉인된 캐시 복원 결과다.
현재 설치된 한국어/영어 형태소 모델은 없으므로, 어설픈 형태소 분석을 가정하거나 의존성을 추가하지 않는다.

원문 줄거리만 남긴 가림 카드에서 별도 AI 검수자가 영화당 연속 원문 구절1~2개(각 최대180 Unicode code point)와
짧은 한국어 내용 기술을 작성한다. 제목·장르·TMDB 키워드·군집·원언어 코드·선정 역할·새 c-TF-IDF 결과는
제공하지 않는다. 구절은 사건·관계·갈등을 설명하는 문장을 우선하며 자료가 없으면 부족함을 기록한다.
두 구절은 서로 같은 문자열이 아니어야 하고, 원문에 없는 줄임표나 번역을 원문 인용에 넣지 않는다.
한국어 기술은 AI 해석이며 원문 구절과 구분한다. 새로 생성한 E5 임베딩이나 자동 형태소 추출이 아니다.

구절과 해석을 파일로 기록하고 **모든 구절이 해당 줄거리의 실제 연속 문자열인지 자동 검사·봉인한 뒤**
군집 연결 자료와 대표 키워드에 대조한다. AI의 가림 추출이 의미의 독립 정답은 아니며, 원문에 영화명 등이
들어 있을 수 있다. 기존 첫 검수는 장르·키워드도 봤으므로 그것을 synopsis-only 결과로 바꾸어 부르지 않는다.

별도 연결 검수자는8개 군집 모두에서 새 키워드 설명의 내용 근거, 중심과hash에서의 지지/반례,
경계 사례의 양쪽 설명 적합성 또는 설명 부족을 기록한다. 표본 검수는 일치·부분 일치·충돌·정보 부족을
사례와 함께 설명하되120편 비율을 전체 영화의 정확도로 일반화하지 않는다.
상위15개를 모두 검토하고 보고서에서 요약한 문구가 표본 전체를 대표한다고 과장하지 않는다.

## 종료와 허용 결론

- 설명 보강: 새로운 구체적 내용 단서를 얻었고 사례의 일부 또는 여러 역할에서 근거를 확인. 보강한 범위를 명시.
- 기존 우려 유지: 새 대표어가 제작·형식 정보이거나 내용이 겹치고, 중심/hash에서도 구별 설명이 유지되지 않음.
- 자료 부족: 키워드 보유율·구절 정보 또는 사례 근거가 부족해 설명을 판단하지 못함.

군집마다 이 상태를 기록할 수 있다. 한 군집의 설명 보강과 전체8맛 준비도는 별도다. 군집 배정은 한 편도
바뀌지 않으므로 이번 결과로 추천 정확도 개선을 주장하지 않는다. 8맛을 충분히 구별할 근거가 생기지 않으면
REC036의INCONCLUSIVE를 유지한다. 추출 규칙·DF·표본·문구 수를 결과에 맞춰 반복 변경하지 않는다.
현재 군집을 최종 채택하거나 k/seed/모델 탐색·수정안 학습을 자동 추가하지 않는다.

## 검증·산출물

독립 설계 검토 → 합성검사·독립 실행 검토 → exact fingerprint의review.json PASS → 실제 집계 →
가린 원문 구절 추출/검사·봉인 → 독립 전수 집계 검산과 연결 해석 검토 → 보고서 순서다.
읽을 입력과 재사용helper를 bytes/hash로 고정하고 기존 완료 봉인과 연결한다. 새output폴더만 쓴다.
부분 실패는 보존하고 완료 재실행은 봉인만 검증한다. 실행 한도30분/프로세스 트리12GiB.
명령은 [runbook](../../../runbook/local-development.md)에 기록한다.

산출물: 채널별빈도/점수, 전체표(top-terms.json), coverage·중복/분포, synopsis-only-cards.json,
sample-keyword-evidence.json, budget/completion-seal. 구절 추출·substring 검증/봉인은 뒤의 별도 산출물로 기록한다.
원문 줄거리·구절은ignored outputs에만 저장하고, 문서에는 요약 해석과 필요한 짧은 사례만 둔다.
주요 파일은이계약/config/review.json/RESULT.md/result-review.json이다. 기존실험봉인은 바꾸지 않는다.
