# 사용자 구성을 바꾼 ALS 반복 검증

상태: DRAFT — 독립 설계·코드 검토 PASS 이후 고정3회 실행하는 연구 계약.
2026-09-08 / REC032_USER_RESPLITS. 기존 결과를 보존하는 별도 후속이다.

## 질문과 이번에 바꾸는 것

기존 ALS 단독의 이득이 특정 학습·평가 사용자 구성에만 의존하는지 확인한다.
같은 ALS 설정과 입력·평가 규칙을 유지하고 사용자 분할만3개로 바꾼다.
회차마다 ALS를 새로 학습하고 같은 학습자의 전체 평점으로 보정 평균 별점 P0를 다시 계산한다.
콘텐츠·군집·새 모델·입력량·가중치 탐색을 추가하지 않는다.

3회는 두 집단을 바꾼 결과의 변동을 확인할 제한된 계산 범위다. 충분한 전체 교차검증 횟수나
통계적 최적값을 주장하지 않는다. 결과를 보고 회차를 늘리거나 유리한 분할만 선택하지 않는다.

## 인구와 고정 분할

개발 인구는 원 user_id1~200,948 중 기존 REC029 외곽 역할만 사용한다.
SHA256의 old bucket0~59, parent train role0~5999, REC028 phase0~7999 조건의58,014명이다.
기존 REC029 내부 calibration/selection/replication 역할만 이번 회차별 학습·평가 역할로 재배정한다.
REC028 attribution/future, Locked Test와 final reserve 외곽은 계속 제외한다.

평가 가능 풀은 기존 REC029 R0 profile30이 있는 SELECTION2,180명+REPLICATION2,200명=4,380명이다.
두 집단의 평점/H는 기존 실험에서 이미 개봉됐다. 새 독립 확인자료라고 부르지 않는다.
기존 calibration 사용자는 이번 평가 풀에 없으므로 모든 MovieLens 사용자에 대한 역할 교환은 아니다.

seed는20260908/20260909/20260910으로 고정한다. 각 seed에서 다음 순서를 사용한다.

1. 평가 풀의 원 ID를 SHA256(`rec032-resplit-eval-v1|seed|user_id`) bytes, user_id 순으로 정렬해 앞2,180명 선택.
2. 개발 인구에서 그 평가자를 제외하고 SHA256(`rec032-resplit-train-v1|seed|user_id`)로 정렬해 앞46,376명 선택.
3. 선택한 학습 ID는 정수 오름차순, 평가 key는 기존 user_key 오름차순으로 저장한다.

학습 사용자 수만 동일하며 평점 수·영화 지원 수는 달라질 수 있다. 실제 행수와 지원률을 보고한다.
회차별 train∩eval=0을 학습 데이터의 user_id 전행에서 다시 확인한다.
회차 간 train/train·eval/eval 중복, 이전 REC032 평가자와의 중복, 원 SELECTION/REPLICATION 구성도 공개한다.

## 회차별 자료 경계

사용자 요청은 위 개발 인구의 선택된 학습자 전체 평점을 해당 회차의 새 학습에 사용하는 범위를 포함한다.
회차1 평가자가 회차2 학습자가 될 수 있다. 그 평점은 회차2 학습에 허용되며 회차1의 ALS/P0에는 넣지 않는다.
따라서 모든 평가자의 평점이 전 회차에서 점수 봉인 전까지 닫혀 있었다고 주장하지 않는다.
회차별 학습 파일·마스크·학습자 목록·factor·P0 연결로 누출을 검증한다.

원본 아카이브는 config에 고정된 ml-32m.zip의 ratings.csv만 사용한다.
각 회차를 별도로 순회하며 user_id를 먼저 읽고 해당 train mask 밖의 movie/rating/timestamp는 해석하지 않는다.
평가 입력은 기존 R0 profile 순서의 원별점30개 중 prefix만 쓴다. timestamp는 읽지 않는다.
평가 정답 파일과 평가 histogram은3회차 모든 점수를 봉인한 뒤 채점 단계에서만 해석한다.
다른 회차의 학습 평점으로 현재 평가자의 H나 정답을 구성하지 않는다.

## 고정 모델·추천·평가

ALS는 explicit raw rating, rank32/reg0.1/반복10회/seed42, nonnegative=False를 유지한다.
회차별 데이터로 독립 fit하며 앞 회차 모델을 이어 학습하지 않는다. 원별점은0.5~5.0, 간격0.5다.
사용자 fold-in은 기존 `solve(Y.T @ Y + 0.1*n_factor*I, Y.T @ raw_rating)`다.
예상 점수는 반올림/clip/양수 필터를 적용하지 않고 동점은 movie_id 오름차순이다.
P0는 `(영화 별점 합 + 50*해당 회차 학습 전체 평균)/(영화 평가 수+50)`다.

입력 n=0/5/10/30, 공통 카탈로그85,517편, BASIC_RANK_TOP2를 유지한다.
개인별 E는 원 cohort의7개 outer membership target 합집합, O30은 원 R0 profile로 유지한다.
회차가 바뀌어도 같은 사람의 O/E/H는 동일하며 E∩O30=0이다.
평가자가 바뀌면 그 사람의 기존 E를 사용하므로 전체 E 행수는 회차마다 달라진다.
전체 카탈로그에서 O(n)를 제외한 점수 순서를 만든 뒤 E에 투영해 두 편을 고른다.
factor 없는 영화는 ALS 미지원이며 E나 사용자를 제거하거나 미평가를 불호로 바꾸지 않는다.
입력0·입력 factor0·사용자 벡터 norm≤1e-12이면 전역 P0 fallback을 기록한다.
활성 ALS 전역 후보 또는 E 투영 결과가2편 미만인 셀이 하나라도 있으면 전 비교를 중단한다.
E 안에서 P0로 보충하지 않는다. n_factor·factor 지원·fallback·P0 선택의 factor 미지원 수를 보고한다.

평가 Q/H와 MEAN_Q/MIN_Q/HARM20은 ALS 단독 후속과 동일하다. H의 정수 분자를 먼저 빼서 짝 차이를 계산한다.
Q는 정확도나 원별점이 아니다. H는 평가 전용이며 raw ALS 입력에 사용하지 않는다.

## 반복 결과의 판단

3회차×입력5/10/30×3지표=27개 ALS−P0 비교를 한 family로 고정한다.
회차별 사용자 동일 가중 paired bootstrap20,000회, seed20260908, alpha0.05, 꼬리0.05/54다.
27개 비교의 작은 꼬리확률에서 재표집 해상도를 확보하기 위해 실행 전에20,000회로 정했다.
모델 학습은3회이며20,000은 통계 재표집 횟수다. 각 회차의9개에는 같은 사용자 추출을 공유한다.
회차 간 중복 사용자를 합쳐6,540명의 독립 표본으로 계산하거나 pooled 유의성으로 승자를 만들지 않는다.
Bonferroni 보정은 회차 간 독립성을 요구하지 않는다. 각 구간은 해당 학습 구성에 조건부다.

선호 두 지표는 큰 방향, HARM20은 작은 방향이 이득이다. 구간이0을 포함하면 미판정이다.
같은 n/지표의3회 결과를 다음과 같이 요약하며27개 원값·구간·폭도 모두 공개한다.

- 3회 모두 유리한 구간: REPEATED_BENEFIT.
- 3회 모두 불리한 구간: REPEATED_HARM.
- 점 추정이0의 양쪽에 존재: SPLIT_SENSITIVE_DIRECTION.
- 그 외: NOT_ESTABLISHED_ACROSS_ALL_SPLITS. 방향이 같아도 유의하지 않은 경우를 승리로 바꾸지 않는다.

입력30에서 세 지표가 모두 REPEATED_BENEFIT이면 기존 핵심 이득이 이3개 분할에서도 재현됐다고 보고한다.
일부 지표/입력에서만 성립하면 그 범위만 말한다. 실질 채택 한계·동등성·K는 판정하지 않는다.
두 집단을 동시에 바꾸므로 변동의 원인이 학습자 또는 평가자 중 어느 쪽인지 분리하지 않는다.
이 결과는 관측 영화·기존 profile 가능 사용자·개발 자료의 분할 안정성 점검이다.
전체 MovieLens 분포·한국 사용자·전체 카탈로그 새 추천·학습 수렴·제품 정책을 확증하지 않는다.

## 검토·실행·보존

문서/ID 메타데이터 점검 → 설계·코드·합성 검사 독립 PASS → 입력과 역할 봉인 →3회 독립 학습
→3회 점수 전부 봉인 → 기존 허용 정답 채점 → 별도 결과 검산 순서다.
원본 및 기존 REC032 코드·보고서·산출물은 수정하지 않고 별도 user-resplits 폴더만 쓴다.
부분 실행은 보존하고 자동 재시도/덮어쓰기를 하지 않는다. 완료본은 필수 출력과 의존 hash를 전부 검증해 재사용한다.
전체30분·프로세스 트리12GiB를 상한으로 하며 중단 시 예산/실패 기록을 남긴다.
사용자 ID·개별 평점은 보고/콘솔에 출력하지 않는다. 새 라이브러리·외부 서비스·배포·커밋은 없다.
