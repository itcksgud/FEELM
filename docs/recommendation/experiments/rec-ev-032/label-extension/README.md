# 같은 추천 목록의 정답을 원본에서 보충

상태: DRAFT — REC032의 채점 자료 보충 설계. 새 모델 비교나 제품 정책 변경이 아니다.

## 이번에 확인할 것

**앞서 채점하지 못했던 추천 영화에, 같은 MovieLens 사용자가 남긴 평점이 원본에 더 있는가?**

추천 목록·사용자·입력량·모델·평가식은 그대로 둔다. 이미 봉인한 실제 추천 영화의 평점만 추가로 찾아
같은 결과를 다시 채점한다. 원래 결과와 파일은 보존하고 보충 결과를 별도 폴더에 저장한다.

이번 조회를 마치면 미채점 이유를 구분할 수 있다.

| 구분 | 의미 |
| --- | --- |
| 기존 정답 | 최초 REC032에서도 이미 채점한 추천 |
| 새로 찾은 정답 | 원본에 평점이 있었으나 기존 정답 집합에는 빠졌던 추천 |
| 원본에 평점 없음 | 이 사용자의 해당 영화 평점이 MovieLens 원본에 없음. 선호는 여전히 모름 |
| 입력용 영화여서 제외 | 뒤에 입력할 O30에 포함돼, 모든 입력량에 공통인 평가에서 제외하는 추천 |

채점 가능률이 높아지는 것 자체는 추천 품질 개선이 아니다. 새로운 평점으로 미판정 범위가 얼마나 줄어드는지 확인한다.

## 고정할 범위

- 원실험: REC032의 같은2,180명, 입력0/5/10/30, P0와 M0의 봉인된 상위2편.
- 요청 영화: 사용자별 모든 입력량·두 정책의 상위2편을 합친 뒤 O30을 제외한 집합 W.
- 모든 정책·입력량의 W를 함께 잠그며 원점수나 유불리에 따라 조회 대상을 고르지 않는다.
- 후보를 정답이 있는 영화로 좁히거나, 목록을 다시 생성하거나, 모르는 영화를 다른 영화로 바꾸지 않는다.
- O30에 포함되는 앞선 입력량의 추천도 출력·분모에 남기고 평가값만 null로 둔다.
- 새 Q의 기준 H는 기존 SELECTION/R0 label의 full_history_histogram을 사용한다. H를 새로 학습하거나 변경하지 않는다.
- 최초 결과를 이미 보았으므로 이번도 **후속 탐색 재채점**이다. 새 독립 확증·최종 K·서비스 채택으로 보고하지 않는다.

## 원본을 읽는 순서

원본은 기존 config에 고정한 이 컴퓨터의 `C:/higher/projects/MM/data/raw/ml-32m.zip`과
그 안의 정확한 `ml-32m/ratings.csv`뿐이다. 문서 범위는 FEELM-standalone/S15P21E106 두 저장소를 유지한다.

1. userId를 읽고, 봉인된2,180명의 SELECTION 역할에 맞는지 확인한다.
2. 해당 사용자이면 movieId를 읽는다.
3. W에 속하는 영화일 때만 rating을 읽는다.
4. 다른 사용자의 movieId/rating, 해당 사용자의 W 밖 rating, 모든 timestamp는 해석하지 않는다.

역할은 기존4개 hash 조건과 user_key 대응을 재확인한다.
CALIBRATION·REPLICATION·Locked Test·reserve의 평점 조회를 추가하지 않는다.
영화 목록·배우·장르·factor·feature payload도 이 작업에 필요하지 않다.

허용 사용자의 총 행수는 rating을 읽지 않고 세어 기존 H의 합계와 대조한다.
W에 속한 user/movie 중복, 원본 행수 불일치, H 부재, 반별점 격자 오류가 있으면 실패한다.
조회한 기존 정답의 원별점/Q가 원실험 값과 다르거나 원본에서 다시 찾을 수 없으면 실패한다.
그 밖의 원평점은 교차검증 목적으로 추가 개방하지 않는다.

## 채점·판정

원별점0.5~5.0·간격0.5를 보존하고 Q는 기존 고정 H의 midrank로 계산한다.
모든 n·정책에서 같은 user/movie에는 같은 Q를 쓴다.
미평가는 null이며 기존 MEAN_Q/MIN_Q/HARM20의 미채점 범위를 유지한다.
공통 미채점 영화의 평균 차이 상쇄와 동일 목록의 차이0 처리도 그대로다.

사용자 동등 가중, paired bootstrap5,000회·seed20260907·9개 비교 family를 유지한다.
기존과 확대된 채점 가능률, 미채점 원인, 정책 차이 범위와 탐색 구간을 함께 보고한다.
추가 정답 때문에 식별 범위가 오히려 넓어지거나 기존 정답이 사라지면 구현 오류로 처리한다.
결과가 유리한 입력량/지표만 골라 전체 우위를 선언하지 않는다. 채택/최종 K는 이번에도 정하지 않는다.

원본까지 확인해도 미판정이면 같은 봉인 목록에 대해 이 원본을 다시 조회하는 일을 반복하지 않는다.
이 자료에 없는 평점을 다른 사람이 해당 MovieLens 사용자를 대신해 만들어 넣지 않는다.
다음에는 기존 오프라인 근거로 말할 수 있는 범위와 실제 FEELM 대상 사용자에게 확인할 질문을 분리한다.

## 실행·검토

1. 보충 설계·코드·합성 테스트를 다른 대화 이력 없는 검토자가 확인하고 필수 지적을 수정한다.
2. 최종 PASS와 문서·config·runner·tests·기존 base runner hash를 review.json에 고정한다.
3. 원실험의 prepare/train/score/evaluate seal 연결과 필요한 입력 파일 hash를 검증한다.
4. W와 H를 만들고 request-seal을 저장한 뒤, 원본에서 허용 pair만 읽는다.
5. 재채점 결과를 별도 completion-seal로 저장하고 원실험 입력·봉인이 그대로인지 다시 확인한다.
6. 결과는 독립 재집계/보고 검토를 거친다.

학습·추천 재실행은0회다. 원실험의 핵심4파일과 원래 산출물을 수정하지 않는다.
새 실행 중 오류가 나면 부분 산출물을 보존하고 완료로 재사용하지 않는다.
완료 산출물만 hash 검증 후 재조회 없이 재사용한다. 한 실행의 wall-clock 상한은5분이며
원본 스캔4백만 행마다 및 저장 전 점검한다. 실패한 부분 실행은 자동 재시도하지 않는다.
