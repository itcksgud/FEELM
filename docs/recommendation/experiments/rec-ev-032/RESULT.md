# 첫 기본 추천 비교 결과

상태: COMPLETED_EXPLORATORY — 실행·결과 독립 검토 완료. 추천 품질 우열은 미판정.
실험: REC-EV-032 / 2026-09-07. 개인 연구이며 공식 제품 계약은 변경하지 않았다.

## 결론부터

**개인화 추천을 계산하는 경로는 작동했다. 그러나 이번 평가 자료로는 인기 추천보다 좋은지 판단할 수 없었다.**

입력0개에서는 두 방식의 추천이 같았다. 입력5·10·30개에서는 모든 평가 사용자에게 ALS와
콘텐츠 성분이 활성화됐고, 인기 기준과는 다른 상위2편 목록을 만들었다.
이것은 입력을 활용해 다른 추천을 생성했다는 동작 확인이다. 좋아할 영화를 추천했다는 품질 증거는 아니다.

결론이 미판정인 이유는 **추천된 영화 대부분에 채점할 정답이 없었기 때문**이다.
예를 들어 입력30개에서 개인화 추천이 제공한4,360개 슬롯 중 기존 평가를 찾을 수 있었던 것은
89개(2.04%)였다. 나머지를 싫어한 영화나 실패한 추천으로 처리하지 않았다.
인기 추천도171개(3.92%)만 채점할 수 있어 어느 쪽의 전체 품질도 확인되지 않았다.

## 실제로 무엇을 했나

- 동일한 평가 사용자2,180명에게 같은 입력 순서와 같은 후보 조건을 적용했다.
- 학습은 별도46,376명의 원별점7,355,439건으로 했고 평가 사용자와 교집합0을 확인했다.
- 인기 기준 하나와 raw ALS + 상대 별점 콘텐츠 + RRF60의 연구 구성 하나를 비교했다.
- 기존 공통feature 카탈로그85,517편에서 현재 입력 영화만 제외하고 실제 상위2편을 생성했다.
- 입력량0·5·10·30개를 사용했고 모든 추천 목록을 봉인한 뒤 기존 SELECTION 정답을 읽었다.
- 기존7개 outer의 정답을 합쳐 사용자·영화별191,933개 평가를 재사용했다.
  같은 영화의 중복 평점과 사용자 상대척도 기준이 일치하는지 확인했다.

이 구성은 공식 서비스 Hybrid 구현의 재현체가 아니다. 과거 ALS 설정을 재사용해 새로 학습한
연구 구성이고 콘텐츠도 기존 구조화 특징이다. 실제 맞춤2·발견1 자격과 후보500/100 절단은 아직 적용하지 않았다.
profile30을 확보할 수 있었던 조건부 표본이며 입력 순서는 hash 순서다.
이미 개봉한 정답과 회고적 메타데이터를 쓴 탐색 비교이므로 실제 온보딩·미래 예측·새 확증으로 부르지 않는다.

## 왜 점수를 비교해 승자를 정할 수 없나

표의 비율은 **기존 정답으로 채점할 수 있었던 추천 슬롯의 비율**이다.
추천 정확도나 만족도, 영화를 실제로 봤을 비율을 뜻하지 않는다.
같은 영화가 여러 사용자에게 추천되면 사용자별 슬롯으로 센다.

| 입력 영화 수 | 인기 추천의 채점 가능 슬롯 | 개인화 추천의 채점 가능 슬롯 | 개인화 두 편 모두 채점 가능한 사용자 |
| --- | --- | --- | --- |
| 0 | 167/4,360 (3.83%) | 167/4,360 (3.83%) | 1/2,180 |
| 5 | 168/4,360 (3.85%) | 109/4,360 (2.50%) | 11/2,180 |
| 10 | 168/4,360 (3.85%) | 106/4,360 (2.43%) | 12/2,180 |
| 30 | 171/4,360 (3.92%) | 89/4,360 (2.04%) | 11/2,180 |

191,933개의 알려진 평가가 있어도 실제로 추천된 영화와 잘 겹치지 않았다.
기존 정답은 사용자당20~108편, 평균88.0편이다.
알려진 영화만의 평균을 전체 추천 품질로 발표하면 정답이 있는 영화만 골라 판단하는 문제가 생긴다.

미채점 영화를 가능한 최저/최고 선호로 두어도 결론이 유지되는지를 계산했다.
개인화−인기의 평균 상대 선호 차이는 다음처럼 양쪽 방향을 모두 포함했다.
상대 선호 차이의 범위는−1~1이며 확률이나 추천 성공률이 아니다.

| 입력 영화 수 | 미채점 값을 고려한 차이 범위 | 사용자 재표집까지 포함한 탐색 구간 | 판정 |
| --- | --- | --- | --- |
| 5 | [-0.970, 0.965] | [-0.976, 0.971] | 미판정 |
| 10 | [-0.970, 0.965] | [-0.976, 0.971] | 미판정 |
| 30 | [-0.972, 0.965] | [-0.977, 0.972] | 미판정 |

최저 선호와 저선호 위험도 미판정이었다. 입력량3개 × 지표3개, 총9개 비교 모두 미판정이다.
이는 인기 승리, 개인화 무효, 두 방법의 동등성을 뜻하지 않는다.
정답 누락에 따른 범위가 이미 매우 넓어서, 같은 자료의 bootstrap 반복을 늘리는 것으로 해결되지 않는다.

## 지금 결정할 것

1. **구현:** 재현 가능한 연구용 개인화 경로와 이번 산출물은 보존한다. 제품 채택 상태로 올리지 않는다.
2. **품질:** 인기/개인화 승자와 최종 전환 K는 정하지 않는다.
3. **다음 작업:** 추가 품질 비교 전에 실제 추천 결과를 충분히 채점할 수 있는 평가 자료의 범위를 정한다.
   기존 평가를 더 사용할 수 있는지와 실제 사용자 판단이 필요한 부분을 구분한다.
   이번 미판정을 이유로 모델·가중치·입력 개수를 자동으로 추가 탐색하지 않는다.

상대값과 원별점의 우열, 온보딩의 편의성과 효과, K-means의 효과도 이번 실험에서 판정하지 않았다.
전체 단계와 맞춤2·발견1의 제품 구성은 기존 계획을 유지한다.

## 검토와 재현 기록

실행 전 설계 검토 PASS → 코드 검토 지적1건 → 수정·재검토 → 코드 최종 PASS 순서로 진행했다.
지적은 자원 제한 뒤 재시도에서 소비 예산이 누락되는 문제였으며 watchdog·guard 양쪽을 수정했다.
합성 테스트18개 및 합성 Spark 학습을 통과했다. 학습/입력 추출 약55초, ALS 학습 약47초,
추천 생성 약251초, 채점 약3초로 실데이터 실행은 합계약356초(5분56초)였다.
기록된 Python+자식 프로세스 최대 RSS는 약1.81GiB였다. 준비·검토에 쓴 시간은 이 실행 시간에 포함하지 않는다.

코드 검토는 학습·평가 설계의 실행 가능성 확인이고, 품질 결과의 우위를 승인한 것이 아니다.
결과 독립 검토는 PASS이며 필수 지적은0건이다. 허용 산출물17,440행에서 채점 비율·개별 지표 범위·
정책 차이를 재계산했고, 사용자 재표집5,000회의 구간도 별도 계산으로 재현했다(최대 오차4.44e-16).
이는 계산·보고의 정합성 확인이다. 원본 H/정답 union과 전체 점수 digest는 재생성하지 않았으며,
실행 합계·최대 RSS는 확인했고 단계별 시간은 root 실행 로그에 근거한다.
