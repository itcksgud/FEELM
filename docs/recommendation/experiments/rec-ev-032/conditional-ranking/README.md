# 기존 관측 영화 안에서 기본 추천의 순서 비교

상태: DRAFT — REC032의 고정 P0/M0에 대한 조건부 진단 실행 계약. 품질·제품 채택 승인이 아니다.

## 목적과 결과 범위

**같은 사용자의 기존 관측 영화 중, 개인화가 인기보다 더 선호한 두 편을 앞에 놓는지 확인한다.**
기존 REC030의 콘텐츠 개인화 근거는 재사용하고, 이번 ALS+콘텐츠 결합과 P0의 직접 비교만 수행한다.
원래 전체 카탈로그의 실제 상위2편 품질과 다른 질문이다. 실제 맞춤2·발견1, 온보딩 편의성,
분류법, 최종 전환 K를 결정하지 않는다. 새 모델·가중치·입력량 탐색과 학습은0회다.

이전 결과를 이미 보았고 개방 자료를 재사용하므로 탐색이다.
관측 영화 선택 편향이 남는다. 채점률100%는 이 진단의 후보 구성 결과이며 실제 추천 정확도가 아니다.

## 고정 입력과 평가 후보

- 원실험과 같은 SELECTION/R0 2,180명, 기존 입력30편의 prefix0/5/10/30개.
- 원실험 prepared.npz의 사용자 동등 prior·Bayesian prior50, 동일 factor와 구조 feature를 재사용한다.
- E는 원실험 evaluation-membership.parquet의 같은 사용자의 R0–R4/KR/RECENT target union이다.
  기존191,933개 user/movie 조합과9,972개 membership 행을 재현한다. 결과를 보고 후보를 새로 고르지 않는다.
- E는 모든 n·정책에 공통이며 O30과 겹치지 않는다. 후보별 원점수는 순위 봉인 뒤에만 읽는다.
- 점수 전에는 봉인된 membership의 ID 열만 읽는다. labels 파일의 원평점/Q/H payload를 읽지 않는다.
- 출력에 반응해 추가 조회한 label-extension의2,244개 정답은 사용하지 않는다.
- E의 카탈로그 누락이나 정책별 지원 부족은 삭제·교집합 필터로 숨기지 않는다.
  ID/입력/라벨 대응 오류는 중단한다. 두 편 미공급이 한 셀이라도 생기면 전체 집단을 유지한
  공급 진단을 저장하고 품질 채점 전에 중단한다. 해당 사용자만 제거한 지표를 발표하지 않는다.

원시 ratings archive·training.parquet·이전 복제/Locked Test/reserve·timestamp는 읽지 않는다.
준비/학습/점수/평가 seal의 연결과 재사용 파일의 bytes/SHA256을 config로 고정한다.
이 명세는 원래 Run 객체나 원실험 budget 파일을 수정할 권한을 주지 않는다.

## 원래 순위를 유지하는 방법

1. 원래 전체 카탈로그85,517편에서 현재 O(n)만 제외한다.
2. 원래 raw ALS fold-in과 상대값 구조 콘텐츠를 동일 방식으로 계산한다.
3. **전체 카탈로그에서 성분 순위를 매기고 기존 RRF60을 계산한다. E 안에서 RRF를 재계산하지 않는다.**
4. 전체 점수의8개 SHA256과 원래 상위2편을 모두 이전 score-seal/rankings와 정확히 대조한다.
   부동소수점 점수가 한 비트라도 달라 digest가 다르면 허용 오차로 우회하지 않고 중단·검토한다.
5. 유효 성분이 있으면 원래 양수 RRF의 전역 부분순서를 사용한다.
   원래 전역 후보 부족으로 발생한 P0 보충만 보존한다. E 필터 뒤 부족하다고 새 보충하지 않는다.
   무입력/무성분은 원래 P0 전체 순서를 사용한다.
6. 평가측에서만 고정 E에 해당하는 부분순서를 추려 앞의 두 편을 고른다.

원래 모든 사용자의 활성 성분·fallback·factor 수를 원래 score-diagnostics와 대조한다.
E의 각 영화가 가진 전역 순위와 점수, 조건부 상위2편, 공급 정보를 별도 저장한다.
요청 E와 전체 순위 재현 결과를 모두 봉인한 뒤 채점한다. 기존 산출물은 덮어쓰지 않는다.

## 채점과 통계 판정

원래 SELECTION labels 파일에서 해당2,180명의 허용 outer만 읽는다.
기존193,104개 label 슬롯 →191,933개 user/movie union, 고정 H, 중복 평점/Q 일치,
원별점0.5~5.0·간격0.5를 확인한다. 같은 영화 Q는 모든 n·정책에서 동일하다.
기존 REC032에 알려진 정답과도 교차검증한다. E와 추천에 누락 label이 있으면 품질 계산을 중단한다.

평균 상대 선호 MEAN_Q, 두 편 중 낮은 상대 선호 MIN_Q, 하위20% 영화 포함 HARM20을 사용한다.
사용자 동등 가중, n=5/10/30 ×3지표의9개 paired 비교,
bootstrap5,000회·seed20260907·family9·alpha0.05를 이전 설정대로 유지한다.
n=0은 두 정책 일치 점검이며 우승/K 판단에 쓰지 않는다.

완전관측의 차이는 고정 H의 정수 빈도로 계산한다. Q의 분자는2×낮은 빈도+동점 빈도,
분모는2×전체 빈도다. 평균/최저 선호의 정책 차이는 같은 분모에서 정수 분자를 먼저 빼고
나누며 HARM20도 정수 비율로 판정한다. 수학적 동률이 소수점 누적 오차 때문에 미세한
양수/음수가 되지 않게 한다. 채점 의미는 기존 식과 같고 원래 봉인 코드는 수정하지 않는다.

- 각 차이는 M0−P0다. 평균/최저 선호는 양수가, HARM20은 음수가 유리하다.
- 다중 비교를 반영한 탐색 구간이0을 넘는 방향만 BETTER_DIRECTION/WORSE_DIRECTION으로 표시한다.
  0을 포함하면 UNDECIDED다. 방향 기준은0이며 실용적 효과 크기나 제품 허용 손실 기준이 아니다.
- 효과 추정치·구간 양끝·구간 폭을9개 모두 보고한다. 지표끼리 이득/손실이 갈리면 함께 보고한다.
- 제품의 실용적 최소 이득·허용 손실이 합의되지 않았으므로 수치를 임의 설정하지 않는다.
  이번에는 제품 채택/동등성/최종 K 판정 자체를 하지 않는다.
- 정밀도 부족도 결과다. 표본2,180명과 반복5,000회를 고정하고 결과를 본 뒤 확대하지 않는다.

## 검토·실행·종료

설계/코드/합성 검증 → 다른 대화 이력 없는 독립 검토 → 필수 수정·재검토 → hash 고정 → 실행 →
허용 결과의 독립 재집계 → 결과 문서 순서다. 실행 전 PASS가 없거나 hash가 바뀌면 실패한다.

새 경로는 outputs/recommendation-evidence/rec-ev-032/conditional-ranking뿐이다.
요청/점수/완료 봉인을 따로 저장한다. 부분 실행은 자동 재시도하거나 덮어쓰지 않는다.
완료본만 입력/출력 hash 검증 후 재사용한다. 단일 실행15분·프로세스 메모리4GiB 상한을 적용한다.
자원 초과는 예산/실패 기록을 저장하고 종료한다. 원래 모델 학습을 다시 실행하지 않는다.

설계 범위·판정·출력은 [평가 문제 수정안](../../../plans/service-policy-redesign/evaluation-repair.md)을 따른다.
