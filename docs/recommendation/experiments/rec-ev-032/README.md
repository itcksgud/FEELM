# REC-EV-032 — 기본 개인화 추천을 인기 추천과 비교

상태: DRAFT — 개인 연구 실행 설계. 공식 모델·제품 정책의 채택 문서가 아니다.

## 이번에 답할 질문

**지금 준비한 개인화 경로가, 같은 입력을 받은 인기 기준보다 좋아할 영화를 위에 놓는가?**
추천 목록의 실제 상위2편을 채점한다. 500개 안에 정답이 있는지를 성공 기준으로 삼지 않는다.

결과는 다음 셋 중 하나로 보고한다.

- 차이를 판단할 수 있고 개인화 쪽이 유리함: 이 연구 구성을 맞춤2·발견1 통합의 검토 대상으로 넘긴다.
- 차이를 판단할 수 있고 불리함: 입력·ALS·콘텐츠 결합에서 확인된 결함을 좁힌다.
- 정답 누락이나 불확실성 때문에 판단할 수 없음: **품질 미판정**으로 끝낸다. 인기 우승이나 개인화 무효로 바꾸지 않는다.

이는 기본 순위 계산의 탐색 비교다. 온보딩 UI, 분류 방식, 실제 맞춤2·발견1, 최종 전환 K의 결론은 후속 단계다.
이번 실행에서 모델·가중치·표본을 바꾸거나 비교 대상을 추가하지 않는다.

## 왜 이 구성인가

공식 저장소 조회 HEAD `43e2884d295cc885c9d2b22958ef2be72ab04669`에는
ALS+콘텐츠 ADR이 있으나 batch/train은 골격이고 재현 가능한 모델 설정·산출물은 없다.
연구 recommender core는 인기 순위와 ALS 예상 별점 head다.
따라서 다음 **연구용 고정 구성 한 개**를 명시한다. 공식 E5 Hybrid의 성능이라고 발표하지 않는다.

| 부분 | 고정한 방법과 이유 |
| --- | --- |
| P0 인기 | 허용 calibration 사용자 전체 평점으로 Bayesian prior50. 기존 core의 식을 재현 |
| M0의 ALS | REC003의 explicit raw ALS: rank32, reg0.1, 10회, seed42. 평가 사용자를 제외한 같은 calibration으로 새 학습 |
| ALS 입력 | 현재 n개의 원별점 중 factor가 있는 영화만 사용. 정규화는 reg × n_factor. 학습과 fold-in의 척도 일치 |
| M0의 콘텐츠 | 기존 TMDB 구조 특징과 관측 별점의 상대 weight. 수축 강도5·사용자 동등 prior 재사용 |
| 결합 | 유효 ALS 순위와 콘텐츠 순위의 동일 가중 RRF, 상수60. 기존 연구의 순위 결합 방식을 한 값으로 고정하며 최적값으로 주장하지 않음 |
| 무입력 | M0도 P0와 같은 출력. 개인화 벡터를 만들지 않음 |
| 입력량 | n=0·5·10·30. 기존 profile30의 prefix를 그대로 사용. 30은 최적 개수나 요구 입력 수가 아님 |

ALS 학습은 공통 카탈로그로 줄이기 전 calibration 전체 7,355,439행이다.
인기 평균은 평점 행 평균이고, 상대값 prior는 사용자별 histogram을 같은 비중으로 평균한다.
평가 사용자와 ALS·인기·prior 학습 사용자는 서로 겹치지 않아야 한다.

콘텐츠는 장르/context(언어·10년대·길이)/감독·배우/키워드 네 그룹을 각각 정규화하고 연결한 뒤
영화별 L2 정규화한 기존 structured-common이다. 기존 코드와 같은
`h = sum(w_j * feature_j) / sum(abs(w_j))`, `s_content = feature_i · h`를 쓴다.
w는 현재 n개 입력만으로 계산하고, 모든 w가0이거나 h norm≤1e-12이면 콘텐츠 성분은 비활성이다.
별점 원값은 반별점 그대로 보존하며 실제 온보딩 LIKE/DISLIKE는 이번에 입력하지 않는다.

RRF는 성분별 **실제로 점수가 있는 현재 미관측 영화**의 순위를 사용한다.
전체 길이의 기여 벡터를0으로 초기화하고 유효 위치에만 `1/(60+rank)`를 넣어 합산한다.
factor가 없는 영화에는 ALS 기여0, 콘텐츠 기여는 가능하다. 없는 factor에 임의 점수를 넣지 않는다.
성분 하나가 비활성이면 남은 성분만 사용한다. 둘 다 비활성이면 P0.
유효한 성분의 고유 후보가2편 미만이면 P0에서 중복 없이 보충하고 fallback 사유를 남긴다.
성분의 원점수가 같으면 movie_id 오름차순이며 최종 RRF 동점도 같은 규칙이다.
RRF 순위는 int64로 저장한다. 카탈로그 크기 때문에 int16을 쓰지 않는다.

## 사용할 데이터와 알려진 한계

새 설정·코드의 독립 검토가 끝나기 전에는 아래 payload를 열지 않는다.
파일 경로·bytes·SHA256과 역할은 config.json에 고정한다.

| 역할 | 사용할 범위 |
| --- | --- |
| 학습 T | REC029 calibration 조건의 46,376명 전체 평점7,355,439행 |
| 평가 사용자 | 이미 개봉된 REC029 SELECTION/R0의2,180명 |
| 입력 O(n) | R0 profile30 중 현재 n개만. 기존 hash 순서이며 실제 감상/온보딩 시간 순서가 아님 |
| 평가 E | 같은 R0 사용자에게 있는 SELECTION의 R0–R4/KR/RECENT 기존 정답을 사용자·영화별 union |
| 상대 정답 기준 H | 기존 selection label에 저장된 사용자 전체 이력 histogram. 채점 전용 |
| 후보 C(n) | 기존 공통feature 카탈로그85,517편에서 현재 O(n) 영화만 제외 |

R0 초기2,511명 중 profile30 부족331명이 이미 제외된 조건부 표본이다.
추가로 높은 n을 완성한 사람만 결과에 유리하게 골라내지 않는다.
정답 union은 채점할 영화 수를 늘리는 용도이며 후보 필터나 모델 입력으로 전달하지 않는다.
각 outer의 선정 편향도 남아 있으므로 알려진 영화만의 성과를 전체 카탈로그로 확대하지 않는다.
KR/RECENT를 합친 이유는 이미 있는 평가값의 재사용이며 한국/신작 성능을 별도로 입증하지 않는다.

같은 user/movie의 정답이 여러 outer에 있으면 반별점·Q가 일치해야 하며 한 번만 채점한다.
사용자별 모든 H histogram이 같고 저장된 Q가 H에서 다시 계산한 값과 같아야 한다.
`E ∩ O(30) = ∅`를 검사한다. 뒤에 입력할 영화를 앞선 n의 후보에서 미리 빼지 않는다.

원본 archive는 이 컴퓨터의 `C:/higher/projects/MM/data/raw/ml-32m.zip`이다.
문서 확인 대상은 연구·공식 두 저장소로 유지하며, 이 파일만 학습 원천의 명시적 데이터 예외로 둔다.
ratings.csv를 순차 읽을 때 user ID를 먼저 검사하고 calibration 밖의 movie/rating/timestamp는 해석하지 않는다.
어느 행에서도 timestamp는 해석하지 않는다. 선택/복제 평가자 원평점이나 Locked Test/reserve를 추출하지 않는다.
그 밖의 archive 멤버나 외부 저장소 문서를 읽지 않는다.

메타데이터는 2026-09-06 생성된 회고적 snapshot이며 source_updated_at은 없다.
85,517편은 비영 structured와 E5-small384가 모두 있던 기존 교집합이다.
이번 점수에 E5를 쓰지는 않지만 그 카탈로그 선택 조건은 유지한다.
과거 서비스 재현·미래 예측·실제 FEELM 만족도·새 확증으로 보고하지 않는다.

## 채점과 판정

상위2편 출력은 BASIC_RANK_TOP2다. 실제 TASTE2 또는 DISCOVERY1 자격은 아직 없다.
MEAN_Q·MIN_Q·HARM20과 미채점 범위는 [1단계 설계](../../plans/service-policy-redesign/stage-1-input-evaluation.md)를 따른다.
반별점 원값, 공급 실패, 0/1/2편 채점 사용자, fallback, 입력 반영 여부를 함께 보고한다.

미채점은 null이다. 알려진 영화만의 평균은 조건부 참고값이며 대표 성능으로 대신 쓰지 않는다.
MEAN_Q 정책 차이는 같은 미채점 영화의 기여를 상쇄한다.
MIN_Q/HARM20은 범위 차이로 보수적으로 계산하고, 두 목록이 같은 집합이면 차이는 정확히0이다.
두 편 공급 실패는 별도 실패율과 함께 해당 사용자 지표를 보수적으로 미판정 처리한다.

동일 사용자 차이를 사용자 동등 가중으로 집계한다.
n=5·10·30 × MEAN_Q/MIN_Q/HARM20의9개 차이가 보고 family다.
사용자 paired bootstrap5,000회, seed20260907, family 전체95%를 위한 Bonferroni 구간을 사용한다.
각 차이의 하한 분포 0.05/18 분위수와 상한 분포 1−0.05/18 분위수를 보고한다.
n=0은 무입력 동작 일치 검사이며 승자·K 선택에 사용하지 않는다.
같은 사용자 여러 n을 독립 사람처럼 합산하지 않는다.

이번에는 연구 구성의 방향과 채점 가능성을 기술한다. 서비스 채택의 실질 이득·불호 허용치는
합의된 값이 없으므로 이번에 임의로 정하지 않는다. 서비스 채택·동등성·최종 K 판정은 없다.
n별로 평균/최저의 구간 하한>0이면 해당 지표 개선 신호, 상한<0이면 악화 신호다.
HARM20은 반대로 낮을수록 좋다. 구간이0을 포함하거나 미채점 값에 따라 방향이 달라지면 미판정.
일부 지표/일부 n만 유리해도 전체 모델의 승리로 요약하지 않는다.
기능 정상과 품질 미판정을 동시에 기록할 수 있다.

## 실행과 검토 순서

1. 이 설계·config·runner·합성 테스트를 다른 대화 이력 없는 검토자가 확인한다.
2. 필수 지적을 수정하고 재검토 PASS와 정확한 파일 hash를 review.json에 남긴다.
3. prepare: 해시 확인 → calibration 추출/집계 → SELECTION/R0 입력과 membership 분리 검사.
4. train: 고정 raw ALS 학습. 학습사용자/행수·factor·환경을 봉인한다.
5. score: 모든 정책·n의 출력과 전체 점수의 digest, 입력 처리 진단을 저장·봉인한다.
6. evaluate: 점수 봉인 검증 후 허용된 selection label을 읽고 고정 Q·미채점 범위로 채점한다.
7. 결과와 결론을 독립 검토하고 지적이 있으면 정정한다. 결과를 보고 모델을 다시 튜닝하지 않는다.

단계별 완료 seal과 code/design/config/test hash를 검증한다.
부분 파일을 완료로 재사용하지 않으며 기존 파일을 덮어쓰지 않는다.
합성 테스트는 새 runner의 필터·fold-in·결합·채점·봉인 실패 처리를 확인하며 성능 실험으로 세지 않는다.
실행 시간 상한30분, Python+자식 프로세스 메모리 상한12GiB로 둔다.
학습/채점 실패나 범위 위반 시 완료 seal을 남기지 않고 원인과 부분 상태를 기록한다.
합의된 표본이나 모델을 실행 중 조용히 축소하지 않는다.

재현 명령은 검토 완료 후 [로컬 runbook](../../../runbook/local-development.md)에 추가한다.
결과·모델·원평점 추출은 outputs 아래이며 commit하지 않는다.
