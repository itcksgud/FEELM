# 근거량 보정 GBT와 순위 학습 비교

상태: DRAFT — 2026-09-11 개인 연구. 서비스 채택 계약이 아니다.

사용자 질문: 새로운 학습이 실제로 유용한가? 별점 오차와 첫2편/추가2편,
미지원 영화, 쏠림과 비용을 함께 비교한다. K-means·분류별 맞춤/발견은 보류한다.

## 고정 범위와 실행 순서

설계·코드 독립 검토 → GBT_R → LGBM_REG_R → LGBM_RANK_R →
별도 보정 사용자로 점수 보정 → 공통 비교 사용자 평가/전체 후보 진단 → 독립 검산 → 결론.
각 실행 단계는 해당 코드의 별도 PASS와 해시가 있어야 실행한다. 추가 학습은 세 번만 한다.
합성 환경 검증은 실제 자료 학습과 구분한다. 실패 시 원인·부분 산출물을 보존하며
수정 코드를 재검토한다. 결과를 보고 파라미터/가중치/판정 기준을 탐색하지 않는다.

1. **GBT_R**: combination340 GBT와 동일한 4,997,069학습행·행 분할·60 trees·깊이5·seed339.
   foundation340/R의 대중평점 근거량 보정 여섯 열만 다르다. 기존 GBT_B를 대조군으로 삼는다.
2. **LGBM_REG_R / LGBM_RANK_R**: 같은 R의 230특징·전체 학습행, 동일 query 분할·정렬,
   60 trees·31 leaves·깊이5·learningRate0.05·maxBin32·seed339.
   목표함수만 regression / lambdarank로 비교한다. 각 query는 `(학습사용자, episode.origin)`이다.
   사용자 ID만으로 서로 다른 입력 시점의 목표를 한 묶음으로 만들지 않는다.
   모든 행을 유지한다. 73,771 queries 중 단일행2,739개, 서로 다른 별점이 있는70,057개/
   4,988,691행을 기록한다. 균일 별점 query에는 순위 학습 신호가 없는 한계도 기록한다.
3. 기존 FM B/R/RH, GBT_B, 실제 ALS와 기존25%혼합은 저장 예측을 그대로 재사용한다.
   새 가중치 혼합, 신경망, 텍스트 재학습은 이번 범위에 포함하지 않는다.

R은 학습에서 h=0인 행이82.34%인 기존 episode 입력을 유지한다. RH의 목표별 이력을
query로 잘못 합치지 않기 위한 선택이며, 현재 사용자 입력 분포와 일치한다는 뜻은 아니다.
60회 고정 실행은 최적화 수렴이나 알고리즘 전체의 최고 성능을 입증하지 않는다.

## 데이터 분리와 정답

학습사용자39,859명과 기존 개발사용자270명은 완전히 분리한다. C 영화는 학습평점0,
NATURAL_ZERO도0이지만 인위적 차단과 자연 미지원을 별도 집계한다. 학습영화 지원량은
학습평점만으로 계산한다. 현재 TMDB 정보는 과거 시점 복원이 아니다.

기존270명은 이미 여러 번 확인한 **개발 표본**이다. 새로운 최종 holdout으로 부르지 않는다.
이 중 h0/hpositive별 UID의 SHA256(`research343-role:<uid>`) 순서로 1/3씩
보정90명(h0=28,hpositive=62), 비교180명(h0=56,hpositive=124)으로 고정한다.
분리에 별점/모델 점수를 쓰지 않는다. 모든 기존 모델 지표도 동일180명에서 재계산한다.
따라서 이전270명 표와 직접 증감을 비교하지 않는다. 비교 사용자 별점은 모델/보정 학습에 안 쓴다.
학습당4997069행, 관측예측93230행(270명×입력상한0/1/5/10/30)은 기존 축을 유지한다.

미평가는 UNKNOWN이며 음성 샘플을 만들지 않는다. 관측 품질은 사용자가 실제 평가한 J
안의 순위이고 전체 서비스 카탈로그 정답/한국2026 품질을 뜻하지 않는다. 실제 별점은0.5단위다.
전체 후보는 기존2026스냅샷의 개봉일 확인 영화, 기존 viewed 제외 조건을 그대로 사용한다.

## 순위 점수와 MSE

순위 학습 등급은 실제별점에서 `(별점-0.5)*2` 정수0..9로 변환하고 선형 labelGain=0..9를
명시한다. 평가 NDCG gain=(별점-0.5)/4.5와 상수배 관계다. 기본 지수 gain을 쓰지 않는다.
Ranker 원점수는 별점이 아니므로 native MSE=N/A다. 순위는 항상 raw score 내림차순,
동점은 movie_id 오름차순이다. 별점 범위 clipping으로 순위를 다시 만들지 않는다.

모든 모델에 같은 단조 affine 보정 `a+b*score`, b>=0을 적용한다. 입력상한별로 별도2계수,
보정90명의 실제 관측평점만 사용하며 각 사용자의 합산 가중치가 같도록 최소제곱을 푼다.
보정계수와 사용자 목록을 먼저 저장·봉인한 뒤 비교180명을 채점한다.
보정된 점수를0.5..5로 잘라 calibrated MSE/MAE를 계산하고 clipping 전 오차·범위 밖 비율도 남긴다.
회귀/ALS에는 원점수 및 clipped native MSE/MAE도 남긴다. Ranker MSE는 이 별도 보정을
거친 값이라고 표기한다. 유효보정 사용자20명 또는 평점40행 미만이면 보정 MSE는 N/A다.
점수의 사용자 가중 분산<=1e-12이면 b=0,a=가중평균별점으로 고정하고 상수보정 상태를 표시한다.
음수 공분산도 b=0으로 제한한다. b=0/유효보정 사용자 부족을 명시한다.
ALS는 지원하는 입력과 영화가 있어 유한 점수가 나오는 행만 예측한다. 미지원에0점을 넣지 않는다.

## 지표와 비교 기준

주 비교는 입력상한10, 실제 입력>0, ALL 관측목표에서 사용자 동등 가중이다.
공동 주 지표는 **MSE와 NDCG@2**다. GBT_R−GBT_B는 clipped native MSE,
LGBM_RANK_R−LGBM_REG_R은 calibrated MSE를 비교한다. NDCG는 raw score다.
이 두 대조×두 지표에 paired-user bootstrap20,000회, seed343,
Bonferroni98.75% percentile CI를 사용한다. MSE차는 음수, NDCG차는 양수가 개선이다.
고정 학습·보정 계수 조건부 CI이며 재학습/보정 표본의 변동성은 포함하지 않는다.
이 외의 다수 지표는 설명용이며 유의성 검정 승자를 추가로 만들지 않는다.

- 별점: user-macro MSE/MAE, bias, raw/clipped/calibrated 오차, movie-macro MSE/MAE,
  사용자MAE의95백분위. 전체 행 평균도 보조로 표시해 가중 방식 차이를 구분한다.
- 순위: Top1/2/4/6 NDCG·실제평균별점·별점<=2 비율·별점>=4 비율.
  페이지1–2/3–4/5–6 평균별점·낮은 별점 비율·두 편 모두<=2인 비율.
  각 N에 필요한 J>=N 유효 사용자 수와 공통 J>=6 비교를 함께 표시한다.
- 구간: 입력상한0/1/5/10/30, 실제h0/hpositive; C/NATURAL_ZERO/W_DIRECT;
  학습평점수0/1–9/10–49/50+; 실제 입력편수·ALS지원입력편수·사용자 활동량의 분모.
  ALS와의 직접 대결은 모든 모델 동일 W_DIRECT 행·사용자·후보에서 별도 집계한다.
- 전체 후보(비교180명, 상한10): 후보수·유한 예측률·미반환/중복·UNKNOWN,
  각2편 페이지의 투표1개/평균10점 노출, 고유 영화수/HHI/최대영화노출 비중,
  지원량/개봉연도/메타누락 분포. UNKNOWN은 품질이 낮다는 뜻이 아니다.
- 비용: 학습 wall time/peak memory/모델 크기, 보정시간, 전체후보 feature 및 predict 비용,
  사용자별 후보 점수계산+Top6 시간의 중앙값/95백분위. 이는 로컬 계산 시간이고 API SLA가 아니다.

단일 임의 가중점수로 승자를 정하지 않는다. 두 주 지표가 함께 개선되고 저평가·쏠림·지원범위·
비용에 문제가 없는지 확인한다. 서로 엇갈리거나 CI가0을 포함하면 장단점/불확실성을 유지한다.
MovieLens 품질만으로 서비스 채택을 확정하지 않는다. 새 모델이 나쁘면 기존 후보를 유지하며
이번 세 학습과 최종 비교를 끝낸다. 결과에 따라 자동으로 실험 수를 늘리지 않는다.

## 환경과 증거

GBT는 기존 고정 Spark4.1.3 이미지, LightGBM은 같은 이미지에 SynapseML1.1.3의
Spark4.1/Scala2.13 component와 native lightgbmlib3.3.510을 추가한 격리 연구 이미지다.
실제 학습 컨테이너는 network none,4CPU,12GiB,driver8GiB,fit당5400초 상한.
기존 wj-editor-api/팀설정은 변경하지 않는다. 학습 데이터/코드는 read-only mount,
연구 출력만 쓰기 허용한다. LightGBM query는 한 partition에 모으고 내부 정렬한다.
native 저장/재로딩과 관측93230행 portable 추론을 비교해 오차<=1e-8을 요구한다.
데이터·코드·환경·모델·보정·결과 해시와 독립 검토를 보존한다.
