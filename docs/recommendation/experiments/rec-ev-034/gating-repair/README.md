# REC034 후속 — 평균 부호 때문에 선호 근거가 사라지는지 한 대안만 확인

상태: DRAFT. 독립 검토 전에는 새 목적의 계산을 실행하지 않는다. 2026-09-08.

원 공급 진단은 A3명·B141명에서 맛별 평균 양수인 맛이 없었고, 추가로 B13명은100개 단계에서 T2를 잃었다.
따라서 모델·군집·입력량을 더 늘리지 않고 **양수 선호 입력이 있는데 평균으로 상쇄돼 전부 막혔는지**부터 확인한다.
양수 입력 자체가 없는 사용자에게 이 대안이 답한다고 가정하지 않는다.

## 이번에 바꿀 하나의 규칙

| 부분 | 원안 | 대안1개 |
| --- | --- | --- |
| T를 공급할 맛 | 관측 상대weight의 맛별 평균>0 | 관측 weight>0 영화가 하나 이상 있는 맛 |
| D의 연결 anchor | 평균>0 맛 안에 있는 weight>0 입력 영화 | weight>0 입력 영화 자체 |
| D 대상 맛 | 관측 입력 내 경험0이고 기존 긍정 맛이 아닌 맛 | 같은 경험0이며 새 T지원 맛이 아닌 맛 |

한 가지 변화는 맛별 평균 부호로 개별 양수 선호 근거를 제거하지 않는 것이다.
T지원 맛과 D anchor를 함께 바꾸는 묶음 규칙이므로 둘의 개별 인과 효과를 분리했다고 주장하지 않는다.
양수1편·음수29편인 맛도 지원할 수 있다. 상대 weight가 음수인 입력도 원별점 그대로 고정 ALS 순위에 반영돼 있지만,
이 자격 조건에서는 거부권을 갖지 않는다.
원별점 n30 자료에서 양쪽 T지원 맛은 모두 관측 경험 맛의 부분집합이므로 D의 경험0 후보 맛 자체는 같다.
anchor 확장으로 연결 적격 D 영화가 늘 수 있다. 전체목록에서 T/D가 늘어도100개 절단에서는 서로 밀어낼 수 있다.
그 회귀를 전체 사용자에서 확인한다. 새 지원 맛을 “사용자가 그 맛 전체를 좋아한다”는 판정으로 부르지 않는다.

## 고정할 것과 접근 순서

REC034의2,180명·입력30개·학습 prior·A/B 배정·메타데이터·raw ALS500과 점수를 재사용한다.
ALS fold-in·전체 점수·군집은 다시 계산하지 않는다. 후보500/100·동률·제외·슬롯·fallback을 바꾸지 않는다.
새 평가 E/H/정답/원본 archive/네트워크는 없다. 전체 감상 경험이나 실제 LIKE/DISLIKE로 확장하지 않는다.

REC034 원 결과의 독립 PASS 후 source hash를 고정한다. 사용자 역할·원천 봉인 뒤에만 profile30와 prior를 읽는다.
저장된 제외 전500 순서를 그대로 사용해 원안의500/100 슬롯·공급 집계를 먼저 재현한다.
원안 재현이 모두 맞은 뒤에만 같은 사용자에서 대안1개의500/100 슬롯을 계산한다.
전체 카탈로그의 T/D 자격 수는 계산할 수 있지만 대안의 전체 ALS 순위/슬롯은 재계산하지 않는다.
새 대안에 대한 원천 상한은 같은 저장된500이다. 전체 순위에서의 새 결과가 있는 것처럼 보고하지 않는다.

첫 집계는 원안의 긍정 맛0 사용자에게 양수 weight 입력이 실제로 있었는가다.
양수 자체0 / 양수는 있으나 모든 맛 평균에서 상쇄 / 양수지만 미배정으로만 남음의 수를 구분한다.
원안에서 정상인 사용자도 모두 유지해 실패 사례만 골라 대안을 유리하게 평가하지 않는다.

## 판정 범위와 종료

사용자별로 원안→대안의 T2/D1, T3, T부족 상태 변화를 A/B별로 집계한다.
500에서 회복됐는데100에서 다시 소실된 T/D, 원안에서2+1이었으나 대안에서아닌 사용자,
기존 T3→2+1, 기존 T부족→T3 또는2+1을 모두 남긴다. “공급 개선”은 이 상태의 기술 지표 이름이며 품질 향상은 아니다.
원안의 T지원 맛/anchor/T후보/D후보가 대안에 포함되는지 검사한다. 새로 선택된 T 중 원래 평균≤0 맛인 영화 수,
새 D가 기존 anchor로도 연결됐는지 여부를 따로 기록한다. 전체2,180명·A/B×원안/대안의 네 조합으로 닫는다.

원안의 병목 설명이 맞고 공급 회복을 보여도 제품 채택이나 A/B 품질 우승은 결정하지 않는다.
새로 허용된 맛 안의 낮은 선호 영화 노출 위험은 실제 선호 채점이 필요한 항목으로 남긴다.
실제 별점 만족·발견 납득을 채점하지 않았으므로 더 많은2+1을 더 좋은 추천으로 보고하지 않는다.

대안은 하나·고정 n30·기존500재사용·학습0회로 종료한다. 결과를 보고 양수 임계치·최소양수개수·군집 수를 튜닝하지 않는다.
회복이 부족하거나 회귀가 있으면 해당 수와 원인을 보고하고 또 다른 규칙을 자동 추가하지 않는다.
최종 T/D 의미·이진 랭킹 adapter·품질 자료·K 전에 남은 결정을 읽기 쉬운 요약에 반영한다.

config는 REC034 원천12개와 이전 완료·공급/슬롯/500목록·감사, 이 계약·코드·테스트·참조helper hash를 고정한다.
실행 순서는 원천·검토 hash 확인 →역할 봉인 →원안 전행500/100 재현 봉인 →대안 계산 →짝집계·완료 봉인이다.
필수 출력은 role-seal.json, baseline-check.json, baseline-seal.json, eligibility-diagnostic.parquet,
comparison.parquet, slots.parquet, summary.json, comparison-seal.json, budget.json이다.
원안의 원파일은 변경하지 않는다. 완료본은 필수출력·원천·의존봉인 확인 뒤 재계산 없이 재사용한다.
30분/프로세스 트리12GiB 상한을 적용하고 실패/부분 실행은 보존하며 자동 재시도하지 않는다.
합성 검사는 원안포함관계·양수0·미배정·평균0·양수1/음수다수·100개에서 D소실·원안재현·완료보존을 확인한다.
독립 결과 검산은 원안을 다시 학습하지 않고 같은 입력/500으로 전행 자격·슬롯·원인·짝집계·봉인 hash를 확인한다.
실행은 [runbook](../../../../runbook/local-development.md)의 해당절을 따른다.
