# REC-EV-031: 관측 별점 콘텐츠 프로필의 카탈로그 검색 연결

상태: DRAFT — 개인 연구이며 제품 구현 계약이 아니다.
시작일: 2026-09-07. 기준: 팀 `cb280bd`, 연구 `17600a8`.

## 제품 질문과 이번 묶음의 범위

REC-EV-030은 이미 평가한 영화 중에서 자신의 콘텐츠 프로필이 타인의 프로필보다 유용함을 확인했다.
이 결과는 실제 인기도보다 좋은 전체 카탈로그 추천이나 온보딩 30개 응답의 필요성을 증명하지 않는다.
이번에는 **0.5점 단위 관측 별점으로 만든 구조 콘텐츠를 인기도의 대체 순위기로 쓸지,
추가 후보 생성기로만 검토할지, 이 조건에서는 사용하지 않을지**를 결정한다.

이미 사용한 REC-EV-029 SELECTION을 재사용하는 사전 명시 탐색 실험이다.
새 사용자 확증·실제 온보딩·시간 순서 예측·실제 만족도·신작 성능이라고 부르지 않는다.
미개봉 Locked Test·최종 reserve·REC-EV-030 확인 표본은 사용하지 않는다.

## 설계

### 대상과 고정 조건

- 기존 REC-EV-029 `SELECTION`, `R0`의 모든 2,180명과 고정된 사용자별 정답 영화 20편을 사용한다.
- 입력 영화는 기존 순서의 profile30 앞 5·10·30편이다. 0.5~5.0점 원점수를 10bin 그대로 보존한다.
- 이 순서는 평점·시간을 보지 않은 hash 순서이며 실제 관람/온보딩 순서가 아니다.
- 동일 사용자가 30편 입력을 제공할 수 있는 조건부 표본이다. R0 초기 대상 2,511명 중
  global target union 제외 후 profile30 부족 331명이 빠진 기존 선택을 그대로 보고한다.
  전체 MovieLens 사용자나 실제 신규 사용자의 적용 가능 비율로 확대하지 않는다.
- 후보는 REC-EV-027의 구조·E5 공통 유효 카탈로그 85,517편 전체다. 기존 R0의 20개
  정답 ID를 후보에 추가 주입하지 않는다. 후보가 full common catalog라고 해도 정답은
  R0의 균형 선정된 20개에 한정되므로 전체 카탈로그 만족도의 완전한 정답이 아니다.
- 각 K에서 모델과 후보 필터가 볼 수 있는 사용자 정보는 첫 K 영화와 별점뿐이다.
  입력하지 않은 나머지 profile 영화나 숨긴 정답 ID를 본 영화 필터에 쓰지 않는다.
- K마다 실제로 입력한 K편만 후보에서 제거한다. 따라서 K별 후보 차이는 실제 관측 차이이며
  채점할 20편은 고정한다. 사용자의 숨긴 전체 이력은 채점 전용이다.
- 특징은 기존 2026년 TMDB 스냅샷이며 회고적 평가다. 과거 시점에 이용 가능했던 특징이라고 주장하지 않는다.

### 사전학습·인기도와 개인 입력

- 인기도 학습은 REC-EV-029 calibration 사용자만 사용한다: old bucket≤59,
  model train role≤5999, REC-EV-028 phase≤7999, REC-EV-029 split≤7999.
  46,376명, 7,355,439개 허용 평점이라는 기존 집계와 일치해야 한다.
- raw CSV는 user ID부터 읽어 위 조건에 맞지 않으면 movie/rating/timestamp를 해석하지 않는다.
  평가 사용자와 calibration 사용자 교집합은 0이어야 한다. timestamp는 어느 행에서도 해석하지 않는다.
- 전체 학습 기간의 calibration 이력을 쓰므로 미래 예측 실험이 아니다. 동일한 calibration을
  prior와 popularity에 사용한다. 019C 인기도 cache는 이번 평가자와의 학습 중복 가능성 때문에 재사용하지 않는다.
- Bayesian 점수 `(sum + 50*global_mean)/(count+50)`를 사용한다. 50은 희소 항목에 50개
  평균 평점의 사전 질량을 주는 고정 기준선 설정이며 최적값/사용자 합의로 주장하지 않는다.
  평점 수 내림차순 기준선도 함께 보고해 단일 smoothing 설정만 이긴 결론을 방지한다.
- 콘텐츠는 기존 동일한 구조 벡터 생성기를 재사용한다. 장르·언어/시대/길이·인물·키워드
  그룹별 정규화 후 결합한다. E5는 이번 점수에 쓰지 않고 과거 표본과 카탈로그 정합성에만 쓰인다.
- 각 K의 10bin histogram과 calibration prior만으로 `q=(below+0.5*equal+5*prior_mid)/(K+5)`;
  `w=2*q-1`을 계산한다. `score(item)=sum(w*cos(item,profile))/sum(abs(w))`.
  음수 선호는 유지하며 모든 가중치가 0이거나 프로필 벡터가 0이면 인기도로 fallback한다.

### 비교 정책: K=5,10,30에서 각각 동일 조건

1. `BAYES`: Bayesian 인기도 상위 500 후보와 상위 3편.
2. `COUNT`: calibration 평점 수 인기도 상위 500 후보와 상위 3편.
3. `CONTENT`: 관측-prefix 상대 별점 구조 콘텐츠 상위 500 후보와 상위 3편.
4. `UNION`: BAYES와 CONTENT에서 각각 250개를 합치고, 중복으로 500개가 안 되면
   두 원래 순위를 번갈아 계속 읽어 고유 500개가 될 때까지 채운다.
   최종 순위는 전체 후보에서의 원래 BAYES/CONTENT 순위로 `1/(60+r_b)+1/(60+r_c)`.
   60은 고정 RRF 완화 상수이며 이번 결과로 튜닝하지 않는다. 후보 단계와 최종 노출을 따로 평가한다.
5. `SHUFFLE`: 같은 표본의 user_key 정렬 순환 이동으로 고정한 다른 사용자의 K개 입력으로
   CONTENT를 계산한다. 본 영화 제거는 수신 사용자 K편으로 유지한다. 인기도를 대신하는 기준선이 아닌 귀속 대조군이다.

원점수·이진화·E5·ALS·군집·2+1 비율 전수 탐색은 이 묶음에 넣지 않는다.
binary UI와 별점 UI 우열은 이번 실험으로 결정하지 않는다. 낮은 입력 수는 정보량 진단이며 입력 시간은 측정하지 않는다.
모든 정렬은 score 내림차순, movie_id 오름차순으로 동률을 처리한다.

### 채점과 미관측 범위

- 공개된 selection label의 사용자 전체 이력 midrank `target_q`를 채점에만 사용한다.
  `q≥0.8`은 알려진 높은 상대 선호, `q≤0.2`는 알려진 낮은 상대 선호다.
- primary: 알려진 높은 선호 영화의 Recall@500. 분모는 고정 정답 20편 중 q≥0.8 편수;
  해당 영화가 없는 사용자는 primary 계산에서 제외하고 수와 비율을 보고한다.
- secondary: 같은 Recall@10·@3, 관측 정답으로 제한한 NDCG@10·@3,
  후보/노출의 채점 가능 비율, 상위3의 알려진 낮은 선호 개수/3,
  채점 가능한 상위3 중 낮은 선호 비율, catalogue coverage, fallback 비율, 시간/비용.
- NDCG에서 정답 집합 밖의 위치는 관측 gain 0으로 기여하지만 이는 알려진 높은 선호의
  검색 지표 정의일 뿐 해당 영화를 싫어한다는 정답이나 추천 실패 판정이 아니다.
  알려진 낮은 선호 개수/3은 관측된 낮은 선호 노출의 하한이다. 채점 가능 비율이 낮으면
  실제 만족/위험을 판정하지 않는다. 조건부 비율은 분모 0에서 null로 둔다.
- NDCG gain은 `1[target_q≥0.8]`, discount는 `1/log2(rank+1)`로 고정한다.
  IDCG는 고정 target20의 positive 수와 지표의 노출 길이로 계산하며 IDCG=0은 null·평균 제외다.
- 사용자별 차이, 입력의 별점 분산, 학습 인기도 구간, K별 결과를 보고한다. 결과에 따라
  임의의 segment를 골라 전체 성공을 선언하지 않는다. 대표 사례는 user_key 고정 hash로 3명 선정한다.
  사례 영화명은 기존 MovieLens archive의 movies.csv에서 표시용으로만 읽으며 점수에 사용하지 않는다.
- R0 대상 영화가 균형 선정됐고 다른 fold는 채점하지 않으므로 표본·정답 선택 한계를 명시한다.

### 통계·실질 차이·중단 기준

- K30의 CONTENT와 UNION 각각을 BAYES와 COUNT에 비교하는 4개 Recall@500 차이가 primary family다.
  사용자 단위 paired bootstrap 5,000회, seed 20260907, Bonferroni 98.75% percentile CI를 보고한다.
  같은 사용자 다중 입력은 별개 표본으로 세지 않는다. 영화 일반화에 대한 독립 추론은 하지 않는다.
- 사전 screening 기준: 두 인기도 기준선 대비 CI 하한>0이며 점추정 개선≥0.02이면
  `후보 생성 후속 검증 대상`. 0.02는 사용자 평균 Recall 2%p 개선을
  구현 검토의 최소 가치로 삼는 **연구상의 임시 비용 기준**이다. 사용자별 분모가 달라
  pooled 추가 검색 영화 수로 환산하지 않는다. 기존 실험 수치를
  상속한 것이 아니며 실제 사용자 효용이나 팀 승인 기준이 아니다.
- 이 표본에서 bounded paired 차이 [-1,1]의 보수적인 CI 반폭은 0.05대까지 가능하다.
  작은 0.02 효과 검출을 보장하지 않는다. 표본 부족이면 낮은 기준으로 바꾸지 않고 효과와 CI를 보고한다.
  결과를 보고 새 표본을 추가하지 않는다. 사용 가능한 전체 2,180명을 쓰며 0.02와 0.05의
  실질 해석을 함께 남기고 0.05를 대체 성공 기준으로 사용하지 않는다.
- K5/10, OWN-SHUFFLE, 최종 노출 지표와 개별 사례는 탐색/진단 결과다. 95% paired CI를
  제공하되 추가 확증으로 부르지 않는다. K10 대 K30은 같은 사용자 비교이고 UX 최소 응답 수를 확정하지 않는다.
- 후보 recall이 좋아져도 알려진 낮은 선호 노출·미채점 노출과 최종 품질을 별도로 확인한다.
  위험/관련성의 허용 손실은 아직 팀 합의가 없어 이번에 서비스 승격은 하지 않는다.
  CONTENT의 primary Recall@500 차이 CI 상한이 두 인기도 대비 모두 0 미만이면
  해당 조건의 단독 후보 생성기로 기각한다. 상위3 대체 순위기의 품질은 별도 탐색적
  노출 지표와 채점 가능 범위에 한정해 기술한다.
  UNION이 screening을 통과하면 후보 생성 역할만 후속 대상으로 남긴다.
  효과 크기나 표본이 부족하면 그 이유를 분리하고 기존 인기도 운영 후보를 유지한다.
- 데이터/해시/역할/행수/분리 검증 실패 시 실데이터 채점 전에 중단한다.
  사전 점검은 합성 정답과 점수만 사용한다. prepare·score·evaluate의 합산 실행 시간이 30분,
  또는 프로세스 최대 resident 메모리가 8GiB를 넘으면
  실패/부분 실행을 기록하고 설계를 다시 확인하며 표본·정책을 조용히 축소하지 않는다.
  별도 CLI 실행에도 누적 시간 장부를 이어 쓰며 검토 대기 시간은 제외한다. 단계 시작·진행 점검·
  label 접근 직전·봉인 기록 직전에 감사 상태와 코드/설정/설계 hash 및 자원 제한을 다시 확인한다.
  검증 실패 시 완료 봉인을 쓰지 않는다. 부분 산출물은 유효 완료 결과로 사용하지 않는다.
- 예상량: 허용 학습 735만 행 집계, 2,180명×3K×85,517편 구조 sparse dot/정렬.
  최고 500개와 대상 순위만 저장하고 전체 score 행렬은 저장하지 않는다. 신규 유료 API/학습 의존성 없음.

## 실행 순서와 허용 접근

1. 이 설계와 참조 파일 hash를 독립 검토하고 지적 처리 기록을 남긴다.
2. 새 runner·합성 단위검증을 만들고 독립 구현 검토에서 허용 경로·누출·지표를 확인한다.
3. `prepare`: 고정 manifest hash 검증 → calibration 선필터 집계 → profile30 중 SELECTION R0만 읽기.
   원본 selection/replication이 같은 parquet에 있으므로 열 projection과 predicate를 지정한다.
   label 파일/채점 열은 이 단계에서 열지 않는다. user-key 관계/정답 ID 분리는 membership으로 확인한다.
4. `score`: 15개 정책×K 셀의 후보·최종 순위·fallback을 저장하고 코드·설계·설정·출력 hash를 봉인한다.
5. `evaluate`: 봉인이 정확히 일치할 때만 공개된 selection label의 R0와 필요한 열을 읽는다.
   이미 공개된 데이터여서 새로운 독립 확증이 아니지만 이번 실행에서도 점수/채점 경계를 유지한다.
6. 결과 수치·해석을 독립 검토하고 제품 질문 연결표·정책 제안에 반영한다.
