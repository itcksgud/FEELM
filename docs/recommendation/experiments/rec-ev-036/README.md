# REC036 — 현재 K-means 후보를 8가지 취향으로 설명할 수 있는가

상태: DRAFT — 개인 연구 진단 계약. 공식 정책·맛 이름·색상은 변경하지 않는다. 2026-09-08.

## 결정과 범위

사용자가 승인한 현재 군집의 준비도 점검이다. REC033에서 이미 본 장르 설명 중복과 언어 분포 차이를
살펴보는 **사후 진단**이며, 독립적인 새 자료의 확증 실험이 아니다. 현재 E5-small384→K-means8
후보를 설명 가능한 8맛 후보로 후속 품질 비교에 넘길 근거가 있는지 판단한다. 모든 K-means의 우열,
최적 내부 k, 사용자 선호, 실제 발견 품질을 이 자료로 판단하지 않는다. 외부8맛은 유지한다.

입력은 TMDB 제목·줄거리·장르명·감독명·배우5명·키워드명을 연결한 기존 임베딩이다. MovieLens는
카탈로그 ID 연결에 사용했지만 군집 fit에 사용자 별점을 넣지 않았다. 원언어 코드와 인기·평점·평가 수는
임베딩 템플릿에 없다. 전체512토큰 제한 때문에 뒤쪽 필드가 잘렸을 수 있다. 이번에는 재인코딩,
tokenizer 실행, 절단 비율 집계 없이 이 제한을 명시한다. 공식 E5-base768 재현으로 부르지 않는다.

새 fit·seed·k·모델·하이퍼파라미터 탐색은 0회다. ratings·사용자 입력·평가 정답 접근도 0회다.
기존 REC033 결과와 REC027 임베딩·검증된 TMDB 캐시만 읽고 원본은 수정하지 않는다.

## 결과를 계산하기 전에 고정하는 검사

1. 입력 파일 bytes/SHA256와 REC033 완료 봉인을 확인한다. 85,517개 ID·384차원·유한값·L2 오차
   ≤1e-4, descriptor, 기존 centroid·배정·거리 일치를 검사한다. 같은 ID 순서로 재정렬하며 누락·중복은 실패한다.
2. 기존 8개 중심과 각 영화의 제곱거리를 직접 계산한다. 동률은 코드 오름차순, 다음 중심도 같은 순서다.
   최근접 거리 d1, 차근접 거리 d2, margin=(d2-d1)/(d2+d1)을 기록한다(둘 다0이면0).
   군집별 거리·margin의 min/5/25/50/75/95/max 분위수, 차근접 군집 수, 중심 간 거리를 보고한다.
   **통과 margin·silhouette·언어 비율 기준을 만들지 않는다.** 작은 margin 자체는 결함이 아니다.
3. 원언어 분포와 전체 장르별 포함 비율을 군집별로 보고한다. 첫 장르만 쓰지 않고 다중 장르를 모두 센다.
   군집 간 장르 빈도 벡터의 cosine similarity는 설명 중복 진단일 뿐 의미 동일성·언어 인과 검증이 아니다.
4. 군집별 기존 중심 근접5편과 기존 hash5편을 그대로 재검증하고, margin 최소5편을 경계 사례로 추가한다.
   근접 정렬은 (거리,movie_id), 경계는 (margin,movie_id), hash는 REC033의 SHA256
   `rec033-example-v1|movie_id`와 movie_id 순서다. 겹치는 영화는 한 카드에 모든 선정 역할을 표시한다.
   최대120편은 검수 작업량 제한이다. hash5편도 전체 품질 비율을 추정할 충분한 표본이라고 주장하지 않는다.
5. 선택된 영화만 기존 캐시에서 줄거리까지 복원한다. ko 응답은 기존 ledger 파일·body hash와 일치해야 한다.
   필요한 영어 fallback은 기존 두 허용 cache root에서만 읽으며 요청·2xx·ID·body hash를 검사한다.
   기존 merge_text/build_embedding_input으로 만든 **전체 입력 문자열 hash가 저장 input_text_sha256와
   같은 조합만** 받아들인다. 없으면 진단 실패로 남긴다. 영어 캐시도 사용한 파일 hash를 새 ledger에 봉인한다.
   이는 인코딩 전 문자열의 일치이며 과거 토큰/벡터 재생성의 비트 재현 증명은 아니다.

## 내용 검수와 해석

첫 검수자는 영화별 전체 줄거리·전체 장르·키워드가 있는 카드에서 짧은 내용 기술을 작성한다.
카드는 `rec036-card-v1|movie_id` hash 순서의 C001… 코드로 섞고, 군집·선정 역할·거리·원언어·
기존 c-TF-IDF 설명을 가린다. 제목으로 언어/지역을 추정할 수 있고 검수자가 과거 집계를 봤으므로
완전한 맹검으로 부르지 않는다. 제공된 내용만 사용하고 불충분·모호함을 표시한다.
첫 기술을 파일 hash로 봉인한 후 별도 검수자가 군집 연결 자료와 함께 8개 설명의 근거·반례를 점검한다.
검수는 AI 메타데이터 감사이며 사람 평가나 사용자 취향 정답이 아니다. 같은 메타데이터의 거리·단어·
설명을 독립적인 세 근거로 세지 않는다. 경계 사례를 일반적인 영화처럼 취급하지 않는다.

세 층의 결과를 구분한다: (1) 입력/배정 재현의 정확성, (2) 군집 내용 설명과 구별 근거, (3) 제품 취향 유용성.
03/05/06과07/08을 반드시 검토하되 모든 군집을 같은 표본 규칙으로 확인한다.

| 판정 | 증거 조건 |
| --- | --- |
| NEEDS_REPAIR | 정확한 계약 위반 또는 의도한 내용 설명과 명백히 충돌하는 사례를 확인. 결함 위치·재현 근거를 기록 |
| PROVISIONAL_SUFFICIENT | 정확한 계약 검사 통과, 8개 모두 중심·hash 표본에 근거한 내용 설명과 상호 구별 근거가 있고 알려진 중복/언어 쟁점에 후속 비교 해석을 막는 미해결 문제가 없음. 고정 후보의 비교 진입만 허용 |
| INCONCLUSIVE | 자료·표본·AI 판단이 부족하거나 내용과 언어 영향이 얽혀 구별 근거를 세우지 못함. 언어 연관성이나 낮은 margin만으로 자동 실패시키지 않음 |

입력 계약 위반이 있으면 실패 보존, 의미 판정은 불확실성을 그대로 기록한다. 일부 어울리지 않는
경계 영화 하나로 모든 군집의 실패를 선언하지 않는다. 군집 설명 결함과 원인 규명도 구분한다.
원인이 특정됐을 때만 문제 하나를 겨냥한 수정안 최대1개를 **별도 사전 고정 비교**로 설계할 수 있다.
이번 runner는 수정안을 학습하지 않는다. 원인이 모호하면 INCONCLUSIVE로 종료하고 탐색을 늘리지 않는다.

## 실행·검증·산출물

독립 설계 검토 → 합성 검사와 독립 실행 검토 → exact fingerprint의 review.json PASS → 실제 진단
→ 내용 검수 봉인 → 독립 결과 검산과 해석 검토 순서다. 설계·코드·config·tests·재사용 helper hash를 고정한다.
명령은 [runbook](../../../runbook/local-development.md)에만 기록한다. 실행 한도30분/프로세스 트리12GiB.
새 출력 폴더에만 쓴다. 부분 실패를 자동 덮어쓰거나 재시도하지 않고, 완료 재호출은 봉인만 검증한다.

출력: 전행 distances.parquet, diagnostics.json, masked-cards.json, card-key.json, selected-cards.json,
selected-cache-ledger.json, budget.json, completion-seal.json. 원문 카드는 ignored outputs에만 둔다.
