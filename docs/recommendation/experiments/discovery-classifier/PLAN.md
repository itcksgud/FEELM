# 비LLM 영화 분류와 발견 추천 — 전체 연구 설계

상태: DRAFT / 독립 설계 재검토 중. 2026-09-11. 현재 범위: DESIGN_ONLY.

## 1. 질문과 현재 승인 범위

사용자의 질문은 기존 실험 자산으로 영화의 주제·분위기를 분류하고, 사용자가 경험이 적으면서 좋아할 만한 영화를 더 잘 발견하도록 할 수 있는가이다. 최초 지시는 설계 검증 통과 후 실행이었으나, 최신 지시 **“통과되면 하지는 말고 말해줘”**가 이를 대체한다. 이번 업무는 전체·단계별 설계 수정과 독립 검토 및 결과 보고까지만 수행한다. 설계가 PASS여도 코드 작성·데이터 집계·모델 학습·추천 실험을 실행하지 않는다. 아래 단계별 실행조건은 향후 사용자가 별도로 실행을 요청할 때 적용할 조건부 명세다.

이번 작업은 개인 연구다. 원본 `FEELM-standalone`에는 다른 작업의 미커밋 변경과 맞춤/발견 보류·2편씩 추가 추천 검토가 있으므로 이 worktree에서만 새 문서·코드·결과를 작성한다. 해당 서비스 결정을 번복하거나 기존 active-experiment.md, 운영 API/DB, Jira/MR을 변경하지 않는다. 과거 맞춤2+발견1은 통제된 오프라인 비교 장치로만 사용한다.

원본 데이터는 `C:/higher/projects/FEELM-standalone` 아래 고정 파일에서 읽고 원본을 변경하지 않는다. 기존 source archive는 해당 저장소 manifest에 기록된 MovieLens ZIP만 읽는다. 다른 저장소 문서는 추적하지 않는다. LLM 호출·LLM에 의한 의미 라벨 생성·기존 AI 판단표의 정답 사용을 하지 않는다. 신규 데이터 다운로드나 라이브러리 설치는 이 실행안에 없다.

## 2. 목표의 구분

- **의미 분류 목표:** 영화가 정의된 주제/분위기를 실제로 포함하는지. 영화×라벨의 POSITIVE / NEGATIVE / UNKNOWN과 검수 출처가 필요하다.
- **원자료 키워드:** TMDB 또는 MovieLens에 기록된 표현. 의미 라벨 후보와 출처이지 완결된 의미 정답이 아니다. 미등록은 UNKNOWN이다.
- **사용자 선호:** 기존 FM의 점수 및 별도로 보존된 관측 평점. 영화 주제 분류의 정답으로 바꾸지 않는다.
- **발견:** 미시청 후보, 충분한 선호 근거, 사용자별 낮은 경험, 기존 긍정 이력과의 연결. 기록이 적음을 실제 미경험의 보증으로 해석하지 않는다.

8개 맛이나 군집 수를 고정하지 않는다. 주제 분류를 장르 예측·키워드 등록 예측·좋아요 분류로 조용히 대체하지 않는다. K-means/NMF의 배정은 정답이 아니며 성분 기여도/거리도 선호 확률이 아니다.

## 3. 기존 근거와 고정 비교 장치

- REC033/045: 85,517편 ID 정합, 복수 장르·키워드·인물·언어 등 원속성.
- text339: 원 TMDB overview 85,517편. 본문이 주 분류 입력이다. 이전 장르명·키워드명을 포함한 E5-small384를 같은 라벨 예측 입력으로 쓰지 않는다.
- REC017: 자유 태그 정규화/기여자 편향/TF-IDF 부품. 태그는 불완전하고 Tag Genome이 아니다.
- REC034/041/042: 긍정 입력과의 공통 장르/감독/키워드 및 미경험 그룹 후보 로직. REC042에서 발견 교체 시 관측 선호가 낮아졌으므로 효과를 가정하지 않는다.
- policy341/final341: FM 고정점수, P0와 P2_010, fallback 포함 세트 평가·UNKNOWN/공급 진단. 재사용 표본은 이미 개발에 사용됐으며 새 최종 test가 아니다.

## 4. 단계와 실행 게이트

| 단계 | 목적 | 실행 조건 | 종료/산출물 |
|---|---|---|---|
| S1 | 원자료·라벨 준비 상태 조사 | S1 설계 및 코드의 정확한 해시를 독립 검토하여 PASS | 출처 해시, 키워드/태그 지원량, 영화 분할 제안, 사람 검수용 후보표, 라벨 readiness |
| S2 | 비LLM 다중 라벨 분류 학습·평가 | S1 결과 검토 PASS + 검수된 라벨/음성 근거 + 고정 라벨 사전 + S2 상세 실행안/코드 PASS | 분류기, held-out 의미 성능·오류, 실행 로그 |
| S3 | 분류 표현을 기존 FM과 연결 | S2 결과 검토 및 실제 의미 정확도/출력 임계값 게이트 PASS + 정책 코드 PASS | 고정 후보 순위, 교체/fallback/연결 근거 |
| S4 | 원메타데이터 대비 발견 기여 평가 | S3 순위 봉인 + S4 통계·평가 코드 PASS | 실제별점·독립 새로움·공급·UNKNOWN·결론 |

**설계 구조가 PASS여도 모든 단계의 실행 승인이 생기지는 않는다.** 각 reviewer는 `reviewed_files`의 SHA-256와 `authorized_stages`를 기록한다. 변경하면 이전 승인은 무효다. 결과 PASS도 계산 검증과 연구 주장/서비스 채택을 구분한다.

S1에서 완결된 주제 정답이 없다고 확인되면 표준 OneVsRest 분류 학습을 실행하지 않는다. 현재 승인된 대체 실행은 없다. PU나 관측키워드 복제 모델은 별도 가정·설계·코드 검토가 필요한 탐색안이며 인간 의미 정답이나 실제 발견 검증을 대신하지 않는다. 장르 baseline도 새로운 목표로 몰래 바꾸지 않는다.

## 5. S2~S4의 사전 원칙과 아직 채울 실행 명세

S2는 TF-IDF + 라벨별 로지스틱 회귀를 1차 비교 후보로 둔다. 라벨별 POS/NEG/UNKNOWN을 구분하여 검증된 행에서만 각 classifier를 학습한다. UNKNOWN에 0을 채운 전체 binary matrix를 일반 OVR에 전달하지 않는다. vocabulary/IDF/차원축소는 train 영화에서만 fit한다. 검수된 음성·양성의 최소 표본, 라벨별 threshold 및 성능·비용 기준은 S1 결과 후 정답 성능을 열기 전에 고정하며 상세안이 비어 있으면 실행 불가다.

분류 train/validation/test는 영화 ID 및 같은 본문 중복을 함께 묶어 나누고, 공유 시리즈·번역/개작·near-duplicate 영향은 별도 보고한다. source keyword 및 정답 목록은 입력에서 제외한다. label vocabulary 선택과 tuning은 train/validation만 사용하며 test는 마지막에 한 번 사용한다. 기존 캐시에 이미 쓰인 추천 사용자를 새 최종 표본이라고 하지 않는다.

S3는 FM 학습과 점수 캐시를 고정한다. (A) FM P0, (B) 기존 장르 P2_010, (C) 원키워드 직접 표현, (D) 새 분류 표현을 동일 입력·후보에서 비교한다. 알려진 라벨만의 효과와 새 분류기의 추가 효과를 분리한다. 후보 universe를 기존 Top100 등으로 좁히지 않는다. 미시청 제외, 동률 movie_id, 후보 부족/fallback 및 입력0 처리 고정. 의미 정확도가 검증되지 않은 희귀 라벨을 새로움 보상에 넣지 않는다. 실제 노출 정책은 이번 연구에서 결정하지 않는다.

S4는 후보 선택에 사용한 예측 라벨로 자기 새로움을 채점하는 순환을 금지한다. 모델과 독립적으로 검수한 특성의 새로움을 주 의미 지표로 두며, 기존 장르 novelty는 별도 proxy다. 원키워드와 예측키워드의 지표 단위가 다르면 그대로 숫자를 비교하지 않는다. 관측 후보의 실제별점·낮은평가 비율·NDCG, 전체 카탈로그 공급/결측/UNKNOWN, fallback을 포함한 고정 모집단, 실제 발견 수신자 기술통계를 구분한다. 관측되지 않은 추천을 실패나 성공으로 대체하지 않는다.

S4의 허용 별점 손실/낮은평가 증가/새로움 증가/공급률과 사용자별 paired bootstrap family는 S1~S2 뒤 고정 모델·라벨 범위로 상세화하고 검토를 다시 받는다. 기존 P2_010 수치(.1 novelty 증분, .3 예측점수 손실)는 장르 기준 비교안의 상수이지 새 표현으로 자동 전이하지 않는다. 실제 만족도·놀라움 자료가 없으면 최종 서비스 채택은 보류한다.

## 6. 완료와 중단의 보고

전체 연구 완료는 분류기 자체가 아니라 발견 추천 질문에 답한 상태다. 준비 부족이면 `S1_COMPLETE / S2_BLOCKED_LABEL_READINESS / S3_S4_NOT_RUN`과 부족한 근거를 명시하며 추천 연구 전체를 완료했다고 하지 않는다. 실패를 피하기 위해 라벨·임계값·범위·지표를 바꾸지 않는다. 사람 판단이 필요한 경우 S1의 구체 후보표와 검수 형식을 준비한 뒤 요청한다. 데이터 조사만으로 새 학습을 기정사실화하지 않는다.

## 7. 독립 검토 역할

- 설계/라벨 검토: 기존 분류 의미·UNKNOWN 처리·라벨 출처·목표 변경 여부.
- 평가/누수 검토: 영화 분할·사용자 역할·자기검증·비교군·후보와 허용 주장.
- 실행/결과 검토: 승인 해시·실제 원본→산출물 집계·빈/누락·재현·기존 변경 보존.

검토 에이전트는 이 worktree를 읽기만 한다. root만 새 파일을 작성하며 승인/결과 기록은 reviewer 메시지 원문·식별자·대상 해시를 보존한다.
