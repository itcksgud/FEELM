# REC040 — 전체 장르를 사용하는 개선 규칙 한 안

상태: DRAFT — 개인 연구의 고정 실행 계약. 2026-09-08.

사용자가 ‘잘 설계한 규칙을 적용하는 것도 해봐야 하지 않나’라고 지적했다. 기존 첫 장르 규칙은
수작업 규칙 전체를 대표하지 않는다. 이번에는 순서 의존을 없애고 복합 장르를 함께 사용하는
개선 규칙 ONE을 실제 적용한다. ‘최적 규칙’이나 최종 제품 계약으로 부르지 않는다.

## 사전에 고정하는 규칙

이전 REC033의 8개 장르 묶음과 코드 순서를 그대로 유지한다. 묶음 자체의 의미를 재설계하는 작업은 아니다.

| 내부 의미 코드 | 장르 묶음 |
| --- | --- |
| ADRENALINE | 액션, 모험 |
| HEART | 드라마, 로맨스 |
| JOY | 코미디, 가족 |
| LEGACY | 역사, 전쟁, 서부 |
| REAL | 다큐멘터리 |
| RHYTHM | 음악 |
| SHADOW | 범죄, 공포, 미스터리, 스릴러 |
| WONDER | 애니메이션, 판타지, SF |

영화의 알려진 내용 장르를 중복 없는 집합 G로 만들고, 각 묶음 H와의 binary cosine 유사도를 비교한다.
순위는 `|G∩H|² / |H|`로 계산해도 같다. 영화 쪽 분모 |G|는 8그룹에 공통이기 때문이다.
정수 분수로 비교하므로 부동소수점 반올림이 동률을 깨지 않는다. 동점이면 위 고정 코드 순서의 앞쪽을 고른다.
최종 동률 후보 전부, 그룹별 일치 수, 선택 점수와 2위 점수 차이를 남긴다. 점수는 선호 확률이 아니다.

그룹 크기 보정은 장르 종류가 많은 묶음이 일치 수만으로 유리해지는 영향을 줄이기 위한 설계 가정이다.
좁은 묶음이 상대적으로 유리해지며 이것이 의미적으로 더 좋다는 근거는 없다.
음악 1개와 SHADOW 2개는 정확한 동점, 음악 1개와 SHADOW 3개는 SHADOW 승리다.
장르별 임의 가중치·예외 목록·KM 중심 복사·결과를 본 뒤 튜닝·여러 규칙 탐색은 하지 않는다.
현재 알려진 장르 조합을 기준으로 만든 개선이며 이전 결과를 이미 본 뒤의 탐색임을 공개한다.
기존128편의 판단 자료를 규칙 계산·수정·재채점·선정에 사용하지 않는다.

## 입력·출력과 제품 경계

입력 형식 검사는 REC039와 같다. bool·실수·문자·0·음수·중첩·None을 거부한다.
TV Movie10770은 형식 정보로서 점수에서 제외한다. 빈 입력은 NO_GENRE, TV-only는 FORMAT_ONLY,
알려진 내용 장르가 없으면 NO_KNOWN_CONTENT_GENRE로 미지원한다. 일부만 알면 알려진 내용으로
계산하고 ASSIGNED_PARTIAL_VOCABULARY 및 정렬된 미지 ID를 반환한다. TV-only 표시도 유지한다.
미지원 native=-1/code=null이며 임시 표시용 보충은 없다. 아예 새로운 장르의 의미를 자동 이해하지 않는다.

방법 이름은 RULE_GENRE_SET, 연구 패키지는 REC040_GENRE_SET_RULE, 그룹은 GENRE_SET_01~08이다.
semantic_code는 기존 RULE과의 의미 대응을 연구에서 확인할 때만 쓴다. KM의 같은 번호는 같은 뜻이 아니다.
공식 맛명·색상·API·DB·ADR-0015의 K-means 계약은 수정하지 않는다. 외부 8종과 실제 별점 0.5 단위는 유지한다.

## 같은 영화에서 비교할 것

REC039의 고정 RULE_GENRE/KM_GENRE와 같은 85,517편에 적용한다. 새 KM 학습은 없다.
원천은 config의 pin으로 고정하고 전체 이전 봉인·검토를 확인한다. 내용 해석은 장르 ID/이름과 예시 제목뿐이다.

1. 전체 지원 수, 미지원 이유, 실제 점유 그룹 수와 그룹별 영화 수. TV-only 12편의 KM 배정은 내용 지원 우위가 아니다.
2. 3방법×8그룹×19장르=456개 구성 행. 비율은 복수 장르이므로 합이100%를 넘을 수 있다.
3. 같은 입력을 뒤집거나 중복해 넣었을 때 배정 변화, 관측된 동일 장르 집합 안의 배정 불일치.
   반전 입력은 전체 순열 검사가 아니다. 새 규칙의 일반적 순서 불변성은 집합 계산과 합성 순열 검사로 확인한다.
4. 개선 규칙의 정확 동점 비율·후보 수·점수 차이. 정해진 순서가 얼마나 자주 배정을 결정했는지 공개한다.
5. 알려진 내용 장르가2개 이상인 영화에서 그 장르를 하나씩 제거한다. TV정보와 나머지 입력 순서는 유지한다.
   모든 영화×제거 장르를 동일 가중치로 집계하며 변화 수/변형 입력 수, 하나라도 바뀐 영화 수/대상 영화 수도 함께 기록한다.
6. 공통 지원 영화에서 3쌍의 8×8 대응표와 ARI. 원본 RULE↔새 RULE은 같은 의미 코드의 이동 수도 보고한다.
   KM과의 숫자 label 일치를 정확도로 계산하지 않는다.
7. 고정 hash 기준으로 새 그룹당3편, 기존 RULE과 달라진8편의 제목·장르·배정·동점 정보를 사례로 보존한다.
   대표 정답·사람 취향 평가 표본으로 사용하지 않는다. config의 합성 예시도3방법으로 계산한다.

이것은 같은 카탈로그의 개발·동작 진단이다. 구성비는 배정 입력을 다시 세므로 품질의 독립 증거가 아니다.
그룹 균형·동점 적음·ARI 높음·장르 삭제 변화 적음에 우승 기준을 붙이지 않는다. 특히 장르 삭제는 실제 내용을
바꾸는 조작이라 배정이 바뀌는 것이 적절할 수도 있다. 실제 추천·발견 품질과 새 영화 일반화는 이번에 평가하지 않는다.
기존128편의53/21·44/27점수를 이번 규칙으로 옮기거나 다시 채점하지 않는다.

## 실행·검증·종료

root만 파일을 쓴다. 별도 검수자의 설계·코드·합성검사·정확 fingerprint PASS 후 한 번 실행한다.
py -3.12의 기존 환경, 계산30분/12GiB 상한. 새 의존성·설치·네트워크·평점·ALS·slot·임베딩·fit은 없다.
과거 master 문서5개는 REC039 검토 pin과 같은 해시로 먼저 보존한 후 현재 문서만 갱신한다.
과거 봉인·모델·보고서는 수정하지 않는다. 완료 재사용은 원천·출력·당시 master snapshot만 검사한다.
부분 실행은 자동 덮어쓰지 않는다. 정확 출력목록과 지문을 봉인하고 독립 전수 검산·보고서 검토 후 종료한다.

종료점은 개선 규칙의 실제 적용 결과와 원본 RULE/KM과의 동작 차이, 다음 추천 비교에 쓸 추론 입력이다.
필수 입력·단일 배정·재현 검사 실패 시 기술 인계를 보류하고, 점수/균형을 맞추려 규칙을 바꾸지 않는다.
이 규칙이 최적이거나 추천에서 우월하다고 선언하지 않는다. 슬롯 비교는 이번에 추가하지 않는다.
