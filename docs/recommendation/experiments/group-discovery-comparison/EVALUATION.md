# 비교·검증·결론 기준

상태: DRAFT — 설계 검토용. 모든 실행 단계는 미승인.

## 1. 동일 조건과 모집단

주 관측 비교는 기존 H10, h>0, J>=3의 같은 158 UID다. 각 UID에서 J 전체를 대상으로 P0/M1/M2-A/M2-B의 한 슬롯을 비교한다. 앞 두 편을 고정하거나 2+1 정책으로 묶지 않는다. 158은 이미 알려진 개발 모집단이며 새 평가자를 의미하지 않는다. 해당 UID 목록과 source hash를 S1에서 봉인하고 불일치하면 중단한다. 미래 평점 값, 긍정 anchor 유무, 그룹 공급 여부로 사용자를 골라내지 않는다.

전체 카탈로그 적용성은 기존 H10의 h>0 186명 모두, 입력0은 별도 84명이다. 이 숫자는 코드가 읽을 source와 다시 일치해야 한다. h0은 세 방법이 동일 P0 fallback이어야 한다. h>0이지만 긍정 입력이 없는 사용자도 분모에 남긴다. 학습 사용자는 평가 사용자와 분리하고 실제 context 입력 stars만 정책에서 허용한다.

주방법별 원후보·모델·군집·Q·q/m·점수 기준은 동일하다. 다르게 허용된 것은 M1/M2 그룹 조건과 M2-A/B 내부 거리 조건뿐이다. 원후보는 같아도 필터 후 후보 수는 다를 수 있다. 고정 예산 **최대 50회 점수 조회**와 실제 조회 수, Q 스캔 수, 거리 계산량을 함께 보고한다. 계산량이 같다는 보장은 하지 않는다.

## 2. 구현 전 검증할 불변조건

향후 코드 검토에는 다음의 작은 합성 사례와 출처 검사가 필요하다. 지금 테스트 코드를 작성하거나 실행하지 않는다.

- 영화/사용자/score offset 축, 입력과 목표·viewed 분리, 날짜 및 학습 사용자 역할, Q train_count 동일성.
- 중심을 정규화했을 때 Euclidean 배정이 달라지는 사례를 포함해 원래 중심·거리 사용 확인.
- 2차원에서 계산 가능한 중심/초평면: 원점 중심 반경, 같은 그룹 내부, 정확 경계 동률, 가장 가까운 초평면이 단순 2위 중심과 다른 사례.
- 좋아한 영화와 같지만 중심에서 먼 영화와, 중심과 같지만 좋아한 영화와 먼 영화: M2-A/B의 차이 확인.
- 가까운 긍정 영화 하나가 있을 때 다른 긍정 영화와의 먼 거리가 평균을 부풀려 D_A를 통과시키지 못함.
- 중복 중심·빈 벡터·긍정 입력 없음·동률 거리 전부 .5 percentile·작은 군집·수렴 실패 처리.
- 기하 필터→Q quota 순서, q/m 부족을 숨긴 backfill 금지, m=1/10과 exhaustive의 포함 관계.
- 미시청 배제, 점수 동률 movie_id, raw score 경계, fallback 동일성, 공급/교체 분리, 전체 후보 누락 금지.
- 미래 평점 및 평가용 인물 특징을 K/벡터/임계값/후보 선택에 전달하지 않는 함수 인터페이스.

## 3. 지표와 새로움의 의미

관측 pool의 실제 별점은 S3의 모든 주방법·고정 진단 순위를 봉인한 뒤 읽는다. 원 MovieLens 0.5~5 별점을 사용한다. 예측 평점으로 실제 평점을 대체하지 않는다. P0 fallback을 포함한 158명 한 슬롯 평균 실제 별점, 실제 낮은평가(<=2) 비율, 좋은평가(>=4) 비율을 보고한다. 추천 모델과 일치하는 비율은 선호 정확도가 아니다.

경험이 적은 그룹 비율은 M1이, anchor 거리/반경/경계는 M2가 직접 최적화한다. 이 지표로 ‘발견 추천 승자’를 선정하지 않는다. 각 방법의 동작 점검·설명용 지표로만 나란히 공개한다.

공통 보조 새로움은 군집·조건 선택에서 제외한 **감독 ID + 상위5 배우 ID**로 계산한다. 역할 namespace를 구분한 binary 벡터 z_i를 L2 정규화한다. 관측 기록이 비어 있으면 UNKNOWN이고 novelty=1로 보상하지 않는다. 이는 관측 인물 메타데이터의 거리이지 주제·감정의 새로운 경험, 통계적으로 독립인 정답 또는 실제 만족도 자체가 아니다. FM이 인물 특징을 사용했을 수 있으므로 ‘FM과 독립’이라고 하지 않는다.

N(u,i)=1-max_{j in V_u} cosine(z_i,z_j). V 중 하나라도 z가 비었거나 V가 비면 사용자 N 불가다. 비교 네 정책의 모든 반환 영화와 V가 유효한 공통 UID에서만 point novelty를 계산한다. 공급된 영화만 따로 골라 계산하지 않는다. V는 P가 아닌 알려진 전체 과거 기록으로 고정한다. z가 비지 않았어도 원메타데이터의 불완전성은 남는다는 제한을 표기한다.

공통 novelty 계산 가능 UID가 158명 중 90% 이상(143명 이상)이어야 proxy 판정 자격이 있다. 미달이면 실제 별점 비교는 그대로 수행하되 PROXY_REFERENCE_INSUFFICIENT로 표시하고 새로움 개선을 판정하지 않는다. 빠진 UID는 정책별 별도 complete-case로 갈라서 유리한 분모를 만들지 않는다.

각 정책쌍의 novelty 차이는 [-1,1]이다. 공통 유효 UID는 계산한 차이, 나머지는 하한 -1/상한 +1을 두어 전체158명 식별 구간을 보고한다. bootstrap도 각 재표집 안에서 하한/상한 endpoint 평균을 계산한다. 개선 gate에는 하한 endpoint의 보정 CI 하한을 사용한다. 결측 부분을 0으로 채우거나 유효부분의 평균만으로 통과시키지 않는다.

실제 사용자가 느끼는 ‘처음 접하는 유형이면서 좋아할 영화’ 여부는 이 proxy로 판정할 수 없다. 사용자 경험·선호를 아는 별도 블라인드 평가가 없는 현재 자료에서는 **실제 발견 만족도 우열은 미검증**으로 남긴다. 새 사람 평가를 자동 시작하지 않는다.

## 4. 고정 비교 가족과 판정

주 네 정책 P0, M1, M2-A, M2-B의 모든 6쌍에 대해 평균 실제 별점, 낮은평가 비율, 공통 인물 novelty의 3지표, 총18개 대조를 하나의 family로 고정한다. 정렬된 동일158 UID를 20,000회 paired bootstrap(seed=20260911)하고, 양측 분위수 .05/(2*18), 1-.05/(2*18)을 사용한다. novelty 결측은 앞 절의 endpoint 방법을 적용한다. 기준선/비교 방향과 family를 결과 뒤 바꾸지 않는다. 이는 이미 반복 사용한 개발 자료에서 명목 구간일 뿐 절차 전체의 확증적 오류율 보장이 아니다.

저장할 대조 방향은 M1−P0, M2-A−P0, M2-B−P0, M2-A−M1, M2-B−M1, M2-B−M2-A다. 반대 방향 해석은 같은 구간의 부호·상하한을 뒤집어 사용하며 새로운 검정이나 별도 family를 만들지 않는다.

방법 X가 P0 대비 개발자료에서 ‘선호를 크게 잃지 않고 보조 새로움 증가’를 지지하려면 다음 모두가 필요하다.

- 실제 별점 차이 CI 하한 >= -.10점.
- 낮은평가 비율 차이 CI 상한 <= +.03.
- 공통 인물 novelty coverage gate 및 결측 bounds를 반영한 CI 하한 > 0.
- 주 관측158명과 전체카탈로그186명에서 각각 실제 방법 공급률 >=10%. P0와 같은 영화인 공급도 따로 보여주며 changed_from_P0 비율이 0이면 추가효과를 주장하지 않음.

이 margin은 연구 비교를 위해 사전 제안한 허용치이며 서비스 요구사항/실제 만족도 기준이 아니다. 통과해도 ‘그룹 기반 발견 품질 입증’이라고 쓰지 않는다. X와 Y 사이에서 같은 조건을 적용한 paired 대조가 통과하면 해당 고정 개발자료의 proxy tradeoff로만 우위를 표현한다. 각 방법의 점추정 최고값이나 개별 supplied 사용자 평균만으로 승자를 정하지 않는다. CI가 넓거나 조건이 충돌하면 동률이라고 하지 않고 우열 미확정/장단점 병존으로 결론 낸다. 어느 쪽도 P0 gate를 넘지 못하면 추가 기여 미확인으로 보고한다.

보조 진단과 입력0/1개 anchor/여러 anchor, 활동량, train_count 0/1~4/5~49/50+, keyword 결측, TMDB vote_count 0/1/2~9/10+, 언어·개봉연대별 수치는 기술통계다. 결과 뒤 유리한 구간으로 주집단을 바꾸지 않는다.

## 5. 후보 회수와 비용

각 방법별 geometry 및 score>=4 조건을 만족하는 전체 후보에 고정 FM 점수를 적용한 exhaustive reference를 만든다. 이 reference는 offline 비용으로 별도 집계하며 실제 추천 후보 예산을 우회하지 않는다. q 제한 전후, m 제한 전후의 oracle top1 보존율·oracle top10 회수율·raw prediction regret=max(exhaustive score)-max(retrieved legal score)를 보고한다. exhaustive legal이 비면 NOT_APPLICABLE, 존재하는데 추출 legal이 비면 top1/recall=0, regret는 MISSING_RETRIEVAL로 별도 수를 보고한다. 성능 회수 지표의 실제 분모도 함께 공개한다.

추천마다 누적 group affinity 비교 수, M2-A anchor-영화 비교 수, 그룹별 percentile 계산량, Q 스캔 행 수, 추출 후보 수, FM 점수 조회 수, wall time, peak RSS를 기록한다. 사전 군집/Q/반경/경계 생성 비용, 공통 P0/cache 읽기 비용, method별 요청 처리 비용, exhaustive 평가 비용은 각각 기록한다. 원본 파일 읽기를 제외한 시간과 포함한 시간을 섞지 않는다.

현재 점수 캐시 재사용 실험에서는 **새 FM 추론 시간을 측정하지 않으므로 전체 서비스 속도 개선 gate는 판정하지 않는다.** q*m가 작다는 이유만으로 빨라졌다고 결론 내리지 않는다. 후보축소에 대한 연구 적합성 표시는 CATALOG에서 exhaustive legal이 있는 사용자 중 top1 보존율>=.90을 별도 조건으로 쓰고, 미달이면 RETRIEVAL_LOSS_HIGH로 보고한다. 예산/표현을 결과에 맞춰 자동 변경하지 않는다. top1 보존은 FM과의 일치일 뿐 사용자 선호 정답이 아니다.

## 6. 전체 카탈로그와 결론 산출물

CATALOG는 반환 ID의 실제 미래 별점이 없으면 UNKNOWN을 유지한다. 전체 카탈로그 공급률·abstain/fallback 이유·선택그룹/후보 중복·서로 다른 영화 수·상위 영화 집중도·지원0/키워드 결측/투표1개 노출·예측 범위·비용을 보고한다. 일부 관측된 반환 영화의 평균을 전체 만족도로 확대하거나 미관측을 싫어요로 채우지 않는다.

추천을 봉인한 뒤 평가 코드의 별도 검토자가 원본 별점 연결, 세 정책 규칙, percentile 기준, Q 순서, 후보 회수 분모, bootstrap family, 결측 bounds, 표와 결론을 독립 재계산해야 한다. 실패한 방법도 삭제하지 않고 함께 기록한다.

최종 표에는 방법별 정의, 사용 그룹 수, 실제 후보 수, 공급/교체율, fallback 포함 실제 별점·낮은평가, 공통 proxy와 결측 범위, oracle 회수, 방법별 비용을 함께 둔다. 결론 상태는 설계 통과 / 실행 준비 부족 / 군집 부적합 / 개발자료 내 추가 기여 미확인 / 개발자료 내 제한적 tradeoff 지지 / 실제 발견 만족도 미검증을 구분한다. 이번 업무에서는 첫 번째인 설계 검토만 수행한다.
