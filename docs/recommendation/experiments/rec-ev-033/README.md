# 단계3 — 비교할 두 8맛 분류안 준비

상태: DRAFT. 독립 설계·실행 검토를 통과한 뒤 수행할 연구 계약. 2026-09-08.
이름: REC033_TASTE_PREPARATION. [전체 계획](../../plans/service-policy-redesign/experiment-design.md) 단계3.

## 이번 결과로 결정할 것

**TMDB 장르 한 가지를 기준으로 묶은 안과 기존 E5 영화 표현을 K-means8로 묶은 안을 실제 산출물로 만든다.**
다음 단계에서 두 안을 같은 맞춤2·발견1 규칙에 연결할 수 있는지, 어디서 미배정·해석·안정성 문제가
생기는지를 확인한다. 추천 품질의 승자·최종 맛 이름/색상·최종 K는 여기서 고르지 않는다.
모델·군집 수·단순 규칙을 결과에 맞춰 늘리거나 변경하지 않는다.

기본 추천의 ALS 사용자 분할 검증은 종료했다. 이번에는 ALS 재학습이나 사용자 평점·H·정답 파일을
읽지 않는다. 평점 독립 영화 메타데이터와 이미 봉인한 콘텐츠 임베딩만 사용한다.

## 공식 계약과 연구 범위

공식 기준은 S15P21E106 HEAD `43e2884d295cc885c9d2b22958ef2be72ab04669`의 ADR0014/0015와
요구·API다. 외부8맛, 영화별 단일 대표 맛, 원시 cluster ID 비공개, 고정 centroid와 신규영화 predict는
유지한다. 이름·색상, 임베딩 세부 전처리와 T/D 정의는 추가 결정 대상이다. 공식 계약·제품 코드는 수정하지 않는다.

가용 임베딩은 `intfloat/multilingual-e5-small`, revision
`614241f622f53c4eeff9890bdc4f31cfecc418b3`의384차원 float32다. 공식 ADR의 MVP E5-base768과
동일하다고 부르지 않는다. 기존 E5-small 콘텐츠 표현을 활용한 연구 baseline 하나다.
장르만 쓰는 A와 텍스트·인물 등을 포함한 E5를 쓰는 B의 차이는 분류 정책 전체의 차이이며
K-means 알고리즘만의 효과가 아니다. 다른 임베딩 후보나 새 인코딩은 추가하지 않는다.

## 자료·영화 범위와 접근 순서

REC027의 평점 독립 전체 카탈로그87,585편에서 identity 적격86,456편, 구조 적격85,733편,
텍스트 적격86,209편을 확인했다. 구조·텍스트 공통 적격85,517편은 기존 `universe.npz`와 ID가 같다.
두 안 모두 이85,517편을 대상으로 하며, A의 미배정도 이 분모에서 제거하지 않는다.
밖의 영화는 전체 identity manifest에 제외 사유와 함께 기록한다. 새로운 미사용 영화 평가집합이 아니다.

각 입력 파일의 bytes/hash와 기존 catalog manifest를 확인한 뒤 공통 movie ID와 자료 역할을 봉인한다.
임베딩은 모델명·revision·384차원·유한값·L2 오차≤1e-4를 전행 검사하고 float64로 변환해 사용한다.
다른 좌표계의 sparse 구조 특징은 입력하지 않는다. 같은 TMDB에 연결된 MovieLens ID 중복 수를 보고하되
분석 단위는 기존 카탈로그와 같은 MovieLens movie_id이며 movie_id마다 동일 가중치를 준다.

공통 영화의 한국어 TMDB 원응답은 config의 기존 두 cache root에서만 읽는다. 파일명·요청 endpoint·
언어·params·2xx 상태·body ID 및 canonical body hash를 검증하고 identity.response_sha256와 정확히
일치하는 응답만 사용한다. canonical JSON은 sort_keys·compact separators·UTF-8·마지막 newline을 포함한다.
현재 캐시가 달라도 고정 hash와 일치하는 다른 허용 캐시가 있으면 그것을 쓰며, 없으면 실패로 보존한다.
네트워크 조회·캐시 수정·영어 fallback 추가 조회는 없다.

읽은 응답에서 제목·원제·원언어·장르 순서·장르명·키워드 이름만 추출하고, 장르/키워드 ID는 구조
파일과 대조한다. 줄거리 원문을 새로 모으지 않는다. TMDB popularity·vote_average·vote_count는
특징·fit 가중치·대표 영화 선정에 사용하지 않는다. 사용자별 평점과 평가 정답은 이 작업에 없다.
검증된 영화 메타데이터·응답별 출처·정확한 캐시 파일 hash를 별도 산출물로 봉인한다.

## A — 첫 내용 장르의 고정8그룹

기존 C1의 첫 TMDB 장르→8그룹 방식을 연구 기준으로 삼는다. 기존 SQL의 다른 제품 규칙이나 정수
별점 계약은 상속하지 않는다. 첫 장르는 TMDB 응답의 순서이며 공식적인 중요도 순위라고 가정하지 않는다.

| 연구 코드 | 내용 장르 ID | 해석 초안 |
| --- | --- | --- |
| ADRENALINE | 28,12 | 액션·모험 |
| WONDER | 16,14,878 | 애니메이션·판타지·SF |
| JOY | 35,10751 | 코미디·가족 |
| HEART | 18,10749 | 드라마·로맨스 |
| SHADOW | 80,27,9648,53 | 범죄·공포·미스터리·스릴러 |
| REAL | 99 | 다큐멘터리 |
| LEGACY | 36,10752,37 | 역사·전쟁·서부 |
| RHYTHM | 10402 | 음악 |

`TV Movie(10770)`는 형식 정보이므로 건너뛰고 그다음 내용 장르를 사용한다. 기존의 TV Movie→RHYTHM은
음악 내용의 근거가 없어 이 연구안에서 제외한다. TV Movie만 있으면 FORMAT_ONLY로 미배정한다.
빈 목록은 NO_GENRE, 첫 내용 장르가 표에 없으면 UNMAPPED_GENRE로 미배정한다. 다른 맛으로 보충하지 않는다.
중복 장르는 최초 위치만 유지한다. 신규 영화도 같은 순서·규칙을 쓰며 통계나 재학습이 필요 없다.
장르 응답 순서 변경에 대한 민감도는 한 번의 목록 역순 진단으로만 기록하며 실제 A 배정은 바꾸지 않는다.

## B — 기존 E5-small 공간의 K-means8

입력 좌표계는 기존 제목·줄거리 fallback·장르명·감독명·배우명·키워드명을 연결한 passage-prefix,
최대512token, attention-mask mean pooling→L2→float32의 봉인 결과다. 이번에는 추가 정규화,
PCA·표준화·재인코딩을 하지 않는다. 현재 런타임이 원 encoder와 달라 새 텍스트 인코딩의 비트 재현은 주장하지 않는다.

scikit-learn1.9.0 KMeans, k=8, init=k-means++, n_init=10, max_iter=300, tol=1e-4,
algorithm=lloyd, 주 seed20260908, threadpool4개로 고정한다. float64 Euclidean 최근접 centroid를 쓴다.
centroid를 다시 정규화하는 spherical K-means가 아니다. n_iter·inertia·군집 수·크기·언어 분포를 기록한다.

주 fit으로 만든8개 centroid마다 자신에게 배정된 가장 가까운 movie_id를 찾고, 그 ID 오름차순으로
`SEMANTIC_01`~`SEMANTIC_08` 코드에 연결한다. 동점은 movie_id 오름차순이다. 이 매핑은 고정 산출물에
저장하고 신규 영화에서도 유지한다. 원시 sklearn label을 외부 맛 코드로 쓰지 않는다.
최종 배정은 코드 순서로 정렬한 centroid의 최소 제곱거리를 사용하며 동점이면 코드 오름차순을 따른다.

이8개 연구 코드를 A의 같은 번호·이름과 의미가 같다고 취급하지 않는다. 공통8색 표시 슬롯은 유지할 수
있지만 B의 표시명은 대표 영화·키워드를 본 뒤 검수할 초안이다. 공식 맛 이름/색상이나 코드 매핑 확정은 아니다.

배정 안정성은 seed20260909의 진단 fit 한 번만 추가해 label 순열 불변 ARI와 최적1:1 정렬 후 일치율로
확인한다. 주 모델은 결과와 무관하게 seed20260908이며 진단 모델을 대체품으로 고르지 않는다.
이는 군집 초기화 민감도 확인용2회 fit이며 서비스 재학습 정책이나 추천 품질 비교가 아니다.
다른 k·seed·모델 탐색과 silhouette로 승자를 고르는 행동은 수행하지 않는다.

## 대표 정보와 검증

두 안에 동일한 TMDB 장르·키워드 텍스트를 사용해 c-TF-IDF를 계산한다. 장르/키워드 ID로 구분한
문구 하나를 토큰 하나로 다루고 영화마다 중복을 제거한다. 전체 공통 영화에서5편 이상 나타난 토큰만
남긴다. 이 빈도 조건은 단발 고유명사보다 반복된 설명을 얻기 위한 표현 규칙이며 품질 최적값이 아니다.

각 맛의 토큰 빈도를 L1 정규화하고 `log(1 + floor(평균 맛별 토큰 수)/전체 토큰 빈도)`를 곱한다.
BM25·seed word 가산·재가중은 없다. A 미배정 영화는 A의8개 class 문서에서 제외하고 그 수를 보고한다.
상위15개 문구와 빈도, 원언어 분포를 표시한다. 언어로만 뭉친 군집을 좋은 취향 군집이라고 포장하지 않는다.
대표 영화는 B의 centroid 근접5편, 두 안의 맛별 고정 hash 표본5편을 함께 남긴다.
표본 hash는 `rec033-example-v1|movie_id`의 SHA256 bytes이며 결과를 보고 영화 예시를 고르지 않는다.

필수 기계 검사는 공통 ID 동일, 코드 각8개, 배정된 영화의 맛1개, B 미배정0개, 유한 centroid,
predict와 저장 배정의 일치, 임의 batch/입력 순서에도 같은 결과, 잘못된 모델/revision/차원·결측 거부다.
새 영화는 같은 descriptor의 기존 좌표계 vector가 주어졌을 때 predict만 검증한다. 새 텍스트→vector
encoder 실동작이나 미래 영화 품질은 이번 검증 범위가 아니다.

결과는 두 분류 산출물 준비 여부와 해석·지원·안정성에 관한 후속 사항으로 정리한다.
A 미배정은 숨기지 않고 다음 단계 후보 공급 규칙의 입력으로 넘긴다. 실제 맛 명명은 미검수로 남긴다.
추천 이득·발견 성공·최종 K는 판정하지 않는다. 영화 metadata의 retrospective 시점 한계도 유지한다.

## 실행과 보존

설계·코드·합성 검사의 독립 PASS와 현재 파일 hash 일치 후 한 번 실행한다.
30분·프로세스 트리12GiB를 상한으로 한다. 원천 검증부터 완료 봉인 전까지 감시하고 예산을 보존한다.
부분 실행은 자동 덮어쓰기/재시도하지 않는다. 완료본은 원천·캐시 출처·필수 출력·의존 봉인을 모두
검증해 fit과 배정 재계산 없이 재사용한다. 원 파일·기존 모델·정답은 수정하지 않는다.

독립 검산은 학습을 다시 하지 않고 고정 centroid의 전행 최근접 배정, A 규칙·미배정, c-TF-IDF와
대표 표본·언어 집계·안정성 통계 및 hash를 별도 계산한다. 최종 보고도 독립 검토한다.
실행 명령은 [runbook](../../../runbook/local-development.md)의 REC033 절에 기록한다.

근거: [KMeans 공식 문서](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.KMeans.html),
[c-TF-IDF 공식 구현](https://maartengr.github.io/BERTopic/api/ctfidf.html).
E5 세부 설정은 기존 `rec-ev-019b-artifacts.json` 및 봉인된 REC027 생성 기록을 기준으로 한다.
