# 추천 정책 상세 — 구현자가 같은 결과를 만들기 위한 규칙

상태: **DRAFT · 로컬 선정안** · 2026-09-13. [먼저 읽을 전체 흐름](README.md).
`SERVICE-REC-20260913-v1`이라는 로컬 정책 이름을 사용한다. 기존 팀 API 필드나 배포 버전이 아니다.

## 1. 입력과 제외를 분리한다

| 입력 | 사용하는 곳 | 사용하지 않는 곳 |
| --- | --- | --- |
| 실제 별점 0.5~5, 0.5 단위 | K, GBT 특징, ALS 입력, 개인 콘텐츠 방향 | 평균·예측을 0.5 단위로 강제 반올림하지 않음 |
| 확정 감상 이력 전체 | 미시청 후보·발견 그룹 경험량 | 최신 10편 입력과 혼동하지 않음 |
| 온보딩 LIKE/DISLIKE | 별도 초기 콘텐츠 방향 | K·실제 별점·팝콘·감상량 |
| 관심없음 | 두 추천 경로의 해당 영화 제외 | 낮은 실제 별점·감상량 |
| 이번 세션에서 반환한 영화 | 같은 세션의 두 경로에서 중복 제외 | 감상량·덜 본 그룹의 분모 |
| 조회·OTT 링크 클릭 | 전역 행동 통계와 관측 로그 | 감상 완료·개인 모델의 실제 별점 |

별점 이력은 영화별 현재 값 하나를 사용하고 `(rating_updated_at DESC, service_movie_id ASC)`로
정렬한다. 먼저 최신 원본 10편을 선택한 뒤 각 모델에 필요한 ID/특징으로 매핑한다. 지원되지
않는 영화를 더 오래된 영화로 대체하지 않는다. 수정한 별점은 최신 입력으로 이동한다.
삭제 후 K=9가 되면 초기 경로로 돌아간다. 이 정렬은 runtime 호출 전에 적용해야 한다.

GBT 입력 지원, ALS factor 지원, 발견용 GKT 벡터 지원은 별도 플래그다. ALS가 없다고 GBT를
중단하지 않고, GKT가 0이라고 GBT도 불가능하다고 간주하지 않는다. GBT에 필요한 유효 이력이
전혀 없으면 초기 경로를 사용한다. 일부 메타데이터 결측은 기존 특징 생성기의 결측 규칙을 따른다.

K≥10의 분기는 GBT 불가이면 양쪽 초기 추천, GBT 가능·GKT 방향 불가이면 맞춤만 개인 예측,
둘 다 가능하면 맞춤·발견 개인 예측이다. K<10의 발견 요청도 초기 추천으로 응답하고 유형을 구분한다.

## 2. 추천 가능한 영화

공통으로 현재 서비스에 존재하고 삭제되지 않은 영화, 개봉일이 후보 기준일 이하이며
`Released`, 성인/비디오 플래그가 명시적으로 false인 영화를 대상으로 한다.
사용자가 명시한 필터, 기시청, 관심없음, 세션 노출을 제외한다. unknown을 false로 바꾸지 않는다.

맞춤 개인 경로는 GBT 특징을 만들 수 있는 영화를 대상으로 하고 TMDB 투표수 문턱을
새로 추가하지 않는다. 발견·초기 그룹 경로는 이 조건에 GKT 유효 벡터 및 유효 TMDB Q를
요구한다. **이번 KOBIS 발견 후보도 같은 조건을 적용한다.** 흥행만 있고 품질 정보가 없는
영화를 억지로 Q=0으로 채워 넣지 않는다.

K=0 전역 KOBIS 경로도 위의 안전한 공통·Q 조건을 유지한다. KOBIS 누적 관객과 영화 연결이
검증된 항목만 사용한다. 미매칭·모호한 영화는 대기 상태다. TMDB Q 유효 여부와 KOBIS
관객 유효 여부를 서로 대신하지 않는다.

OTT 구독은 기본적으로 링크 표시/정렬에 사용한다. 사용자가 구독 OTT만 보기 필터를
명시했을 때만 후보를 좁힌다. OTT 자료 결측을 선호도 감점으로 쓰지 않는다.

## 3. 초기 추천의 정확한 순서

K<10에서는 다음 순서로 유효 콘텐츠 방향을 찾는다.

1. 실제 별점이 있으면 5절의 signed 프로필을 계산한다.
2. 실제 프로필이 없거나 0이면 온보딩의 `normalize(Σ LIKE x − Σ DISLIKE x)`를 사용한다.
   같은 영화는 최신 온보딩 신호 하나만 쓰고 실제 별점이 있는 영화의 온보딩 신호는 제외한다.
3. 이것도 유효하지 않으면 전역 TMDB Q 목록과 KOBIS 관객 목록을 1편씩 교대로 읽는다.

유효 방향이 있으면 **전체 하위 그룹**을 방향과 평균 대표의 내적 내림차순으로 방문한다.
이 단계에서는 '덜 봄' 자격 조건을 적용하지 않는다. 각 그룹은 6절의 Q20+KOBIS5로 최대25편을
공급하고 최대100편을 준비한다. 그룹 순서를 유지하며, 각 그룹 안에서는 준비된 Q 출처
영화와 KOBIS 출처 영화를 Q부터 1편씩 번갈아 이어 붙인다. 한 출처가 소진되면 남은 출처를
이어 붙인다. 개인 예상 별점은 제공하지 않는다.

전역 교대도 Q부터 시작한다. 두 목록을 통틀어 service ID로 중복을 제거하고 중복 항목은
해당 목록에서 다음 유효 항목을 찾아 채운다. 한쪽이 비면 다른 쪽으로 이어 간다.
결과 부족 시 존재하는 영화만 반환한다. 초기 방향·교대 비율은 **운영 규칙**으로 정한 것이며
기존 ALS 이진 입력 실험 또는 K128 별점 실험의 성능을 그대로 인용하지 않는다.

## 4. 개인 예상 별점

기존 RH230 생성기·스케일러·GBT120_s339·ALS factor·보정 계수를 하나의 검증된 세트로 쓴다.
GBT 입력 열 순서를 바꾸거나 KOBIS 열을 덧붙이지 않는다. 모든 영화에서 GBT 점수가 기준으로
존재하고, 실제 ALS 계산이 가능한 영화에만 아래 비중을 적용한다.

```text
a_ui = n_i_train / (n_i_train + 100)  if ALS(u,i) is available, else 0
P_ui = a_ui × cal_ALS(ALS_ui) + (1−a_ui) × cal_GBT(GBT_ui)
```

순위는 clipping 전 P 내림차순, 완전히 같으면 service ID 오름차순이다. 오차 계산과 예상
별점 표시에는 `[0.5,5]`로 clipping한다. 실제 입력 별점과 예측값은 별도 필드다.
ALS가 없을 때 0점 또는 인기점수를 ALS 점수처럼 넣지 않는다.

ALS 미지원이면 식의 `0×없는 값`을 실제 계산하지 않고 곧바로 보정 GBT를 반환한다.
원본 cap10에서 매핑 후 8~9편만 남아도 cap10용 보정 계수를 유지한다. 지원된 편수로
보정표의 cap을 바꾸지 않는다.

`n_i_train`은 **배포 ALS factor를 만든 학습 입력**의 영화별 평가 수와 짝을 이루어야 한다.
전체 MovieLens 공개 평가 수와 혼용하지 않는다. 다른 119 ALS 산출물로 교체하면 기존 보정계수와
shrink 정책의 수치가 자동으로 유지되는 것이 아니므로 동일 입력 예측·보정을 다시 검증해야 한다.

## 5. 고정 분류와 사용자·그룹 비교

상위 8맛은 장르 기준 `G-913`의 전처리·중심·ID·명칭을 고정한다. 장르는 복수 장르를 모두
사용한다. 새 영화는 고정 상위 중심에 배정한 뒤 해당 맛의 고정 128개 하위 중심에 배정한다.
`group_id=taste_id×128+child_id`. 작은 그룹을 실행 때 임의 병합하지 않는다.

하위 분류 및 콘텐츠 검색 공간은 131차원이다.

```text
g = L2(19개 장르 벡터)
k = L2(고정 키워드 IDF → SVD64)
t = L2(고정 줄거리 TF-IDF → SVD48)
x = L2(concat(√0.5·g, √0.35·k, √0.15·t))
```

이 줄거리는 TF-IDF/SVD 표현이다. Qwen 의미 임베딩이나 c-TF-IDF 군집 설명을 예측기에
추가한 것이 아니다. 대중평점·관객 수는 분류 벡터에 넣지 않는다.
0벡터 영화는 분류 ID를 가질 수 있지만 대표 평균과 이 콘텐츠 후보에서는 제외한다.

그룹 검색 대표는 **고정 기준 스냅샷의 지원 영화 벡터들을 동일 가중한 평균**이다. 평균 대표를
다시 단위 정규화하지 않는다. 사용자와 대표의 내적은 그 기준 구성 영화별 내적의 평균이다.
중심과 검색 대표는 서로 다른 산출물이며 각각 버전을 기록하고 일반 영화 추가·삭제 때 유지한다.
새 영화가 추가된 현재 목록 전체의 평균이라고 부르지 않는다. 대표 자체 변경은 별도 분류
산출물 버전 변경이며 기존 스냅샷 기준 결과와 parity를 주장하지 않는다.

별점 기반 signed 사용자 방향은 기존 코드의 다음 식을 유지한다.

```text
rbar = (선택한 원본 별점 합 + 5×3.5) / (선택 원본 편수+5)
anchor = 3 + 0.5×(rbar−3)
w_i = r_i−anchor
raw_p = Σ(지원 영화 w_i×x_i) / (Σ지원 영화 |w_i|+5)
p = raw_p / ||raw_p||
```

원본 평균은 매핑 전에 선택된 별점을 사용하고 벡터 합은 지원되는 영화만 사용한다.
norm≤1e−8이면 상쇄/미지원으로 처리한다. 기시청 제외용 전체 이력과 이 프로필 입력을 구분한다.

개인화 발견의 그룹 자격은 다음과 같다.

```text
viewed_in_group ≤ 2
AND viewed_in_group / max(1, 모든 매핑된 distinct viewed 수) ≤ 0.20
AND 제외 조건을 통과하는 후보가 그 그룹에 존재
```

낮은 별점을 준 영화도 viewed에 포함한다. 노출·온보딩·관심없음은 포함하지 않는다.
자격 그룹만 `p·group_mean` 내림차순, 동률이면 작은 group ID로 방문한다.
음수 유사도라는 이유로 제외하는 추가 임계값은 두지 않는다.

## 6. 대중 목록과 KOBIS 후보 결합

```text
Q_i = (v_i×R_i + 300×C) / (v_i+300)
C = 6.314301027022476 (기준 카탈로그에서 고정)
```

R은 TMDB가 제공한 **0~10 척도 평균 원점수이며 10으로 나누지 않는다.** v는 TMDB 투표 수다.
Q는 10점 척도 후보 정렬용이며 개인 점수에
더하지 않는다. 300은 최소 투표수 조건이 아니다. 결측·모순인 R/v는 Q UNKNOWN으로 유지한다.
Q 동률은 투표 수 내림차순 → service ID 오름차순으로 푼다.

KOBIS 목록은 국적 K/F를 합친 **국내 누적 관객 수** 내림차순이며 같은 관객 수는 service ID
오름차순이다. 한국영화와 외국영화에 별도 가중치를 주지 않는다. 현재 보유 범위는 국적별
역대 Top200 표본이지 전체 국내 상영 영화가 아니다. 결측은 미관측이다.

각 그룹에서는 전체 Q순 목록과 전체 KOBIS순 목록을 저장해 둔다. **상위25편만 저장한 뒤
사용자의 시청 영화를 빼면 안 된다.** 개인 제외 조건을 먼저 적용한 전체 목록을 읽는다.

```text
선택 = Q 목록의 처음 20편
추가 = KOBIS 목록에서 선택과 겹치지 않는 처음 5편
25편 미달 → 남은 Q 목록에서 보충 → 그래도 미달이면 남은 KOBIS에서 보충
그룹 하나에서 최대25편, 그룹 순서대로 합계100편까지 수집
```

Q에 이미 뽑힌 KOBIS 영화는 중복으로 세지 않는다. 출처는 다중 태그로 남길 수 있지만
후보 수는 고유 영화 수다. 그룹 내 영화가 부족하면 다음 그룹으로 넘어간다.
KOBIS가 없으면 Q 최대25로 돌아간다. 개인화 발견에서는 후보100을 P로 재정렬해 상위10을
버퍼에 둔다. 초기 경로는 3절의 그룹·목록 순서를 유지한다.

이 추가안의 이름은 `GKT-K128:mean:B100:Q20:KOBIS5`로 구분한다. 검증된 대조안
`GKT-K128:group:mean:B100:Q25`의 코드·점수·봉인은 덮어쓰지 않는다.
후보가 부족해도 무관한 전역 영화를 개인화 발견으로 섞지 않는다. 초기 추천으로 전환할
때는 반환 유형/사유를 달리 기록하고 개인화 발견으로 표시하지 않는다.

## 7. 2편씩 계속 제공하는 방법

기본 진입은 맞춤 두 편이다. 발견을 요청하면 발견 두 편을 별도 경로에서 받는다.
맞춤1+발견1을 암묵적으로 섞지 않는다. 이는 이번 로컬 연결안이며 팀의 기존 3편 API를
이 작업에서 수정하지 않는다.

한 추천 세션에 model/feature/catalog/policy/input 버전과 두 경로의 cursor를 고정한다.
처리 순서는 **최신 inputVersion·세션 유효성 검사 → 최신 강제 제외 적용 → 같은 버전의
request/page 재사용**이며, 구버전 request는 이전 응답을 재생하지 않고 새 계산 대기로 처리한다.
실제로 반환한 ID는 두 경로가 공유하는 노출 집합에 기록한다. 아직 화면에 반환하지 않은
버퍼10 전체를 노출 처리하지 않는다. 같은 request ID 재전송은 같은 페이지 할당을 재사용하고
cursor를 한 번만 전진시킨다. 그사이 삭제·관심없음·권한 등 강제 제외가 생기면 최신 제외를
우선해 같은 페이지의 교체 revision을 저장한다. 이후 재시도는 그 revision을 재사용한다.
동시 요청은 사용자 세션 기준 원자적으로 예약해 중복 반환을 막는다.

발견의 첫 버퍼10을 소진하면 **노출 집합만 늘린 상태에서 5~6절을 다시 실행**한다.
시청 집합과 그룹 경험량은 바꾸지 않는다. 이전에 후보에 있었지만 노출되지 않은 영화도
다음 계산에 참여할 수 있다. 개인화 맞춤은 같은 점수 스냅샷의 남은 순위를 계속 읽는다.
후보 전체를 소진하면 `hasMore=false`; 부족하면 1편 또는 0편을 정확히 반환한다.

발견은 **각 10편 버퍼 안에서만** P 내림차순이다. 다음 B100 후보에 이전 버퍼보다 높은 점수의
영화가 들어올 수 있어 전체 탐색 세션의 전역 점수 내림차순은 보장하지 않는다.

별점·온보딩·필터 변경은 입력 버전을 갱신해 오래된 개인화 결과를 폐기하고 새 세트를 만든다.
현재 탐색 세션의 노출 집합은 보존해 방금 본 추천이 반복되지 않도록 한다. 관심없음/삭제 영화는
반환 직전에도 제외한다. 일반 카탈로그·모델 갱신은 준비된 새 세션부터 적용하고, 삭제/권한
같은 강제 제외는 현재 세션에도 즉시 적용한다.

확정 감상 이력의 등록·삭제 역시 inputVersion을 올리고 발견 버퍼를 무효화한다. 그룹 경험량의
분자·분모를 새로 계산한 후 후보를 만든다. 관심없음·단순 노출은 이 경험량을 바꾸지 않는다.
별점 삭제와 감상 이력 삭제는 각각 실제 도메인 변경을 따른다. 별점만 지워지고 감상은 남으면
K는 감소해도 감상 경험량은 남는다.

여기서 **세션**은 사용자의 한 번의 연속 탐색, **버퍼/세트**는 그 안에서 준비한 최대10편이다.
일반 카탈로그·모델 변경은 버퍼를 보충할 때가 아니라 다음 새 탐색 세션부터 적용한다.
사용자 입력 변경은 예외로 즉시 새 입력으로 재계산하되 같은 탐색의 노출 집합을 보존한다.

화면을 다시 열어 새 세션을 시작하면 미시청·비관심없음 영화가 재추천될 수 있다.
무기한 추천 금지 이력과 실제 감상 이력을 혼합하지 않기 위한 운영 선택이다.
