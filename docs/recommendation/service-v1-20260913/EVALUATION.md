# 추천 v1 평가의 정답과 분모

이것은 새 모델/정책을 구현한 뒤 사용할 고정 평가 명세다. 이번 작업에서 새 학습·추천 성능
평가를 실행하지 않았다. [MODELS](MODELS.md)의 원행·사용자 역할·보정45/선정45/확인180을
그대로 사용하고, 아래 지표를 잘 만들기 위해 관측 사용자를 다시 뽑지 않는다.
상세 유사 영화의 검색 검수는 [SIMILAR-MOVIES §7](SIMILAR-MOVIES.md)의 별도 기준이다.
개인별점 평가 역할45/45/180이나 맞춤2+발견1의 분모를 영화 간 유사 검색에 적용하지 않는다.

[ALS 결합 비교군](HYBRID-COMPARISONS.md)도 같은 지표·정답·분모를 사용한다. 결합−단독은
각 비교 쌍의 공통 행/사용자에서 계산하고 ALS 미지원 행의 별도 결과를 보존한다. 일곱 경로의
교집합만으로 전체 성능을 판단하지 않는다. 아래 B1/B2/B3 활성화 게이트와 Holm family는
그대로이며, 새 결합 비교는 이를 통과한 새 노출 정책이라고 주장하지 않는다.

## 1. 비교를 나누는 기준

| 평가 | 후보·정답 | 말할 수 있는 것 |
| --- | --- | --- |
| 관측 목표 별점 | 기존 text339 contexts의 ei와 catalog ID축으로 복원한 동일 목표행, 기존 score.row_id/uid/label 대조 | 같은 관측 행에 대한 별점 예측 오차 |
| 관측 후보 재정렬 | 같은 cap10 사용자·같은 관측 목표 영화 목록, 원본 H의 영화 제외 | 주어진 평가 영화들 사이의 순서. 전체 서비스 추천 성공률은 아님 |
| 실제 정책 출력 재생 | 현재 적격 전체 카탈로그→배치500/발견10×10→2+1 조립 | 실제 후보/노출/집중·지원·미관측·비용. 정답이 없으면 만족도 판정 불가 |
| 같은 후보 shadow | GBT의 동일 pool≤500·발견≤100에 FM/ALS 점수 | 같은 후보 안 모델 차이 |
| END_TO_END | 모델마다 같은 적격 전체 카탈로그에서 자신만의 pool500 생성 | 모델별 후보 생성과 재정렬을 합한 차이 |

서비스 출력에서 UNKNOWN을 먼저 지운 뒤 남은 영화로 Top2를 다시 만들지 않는다.
그렇게 만든 결과는 실제 첫2편의 품질이 아니다. MovieLens 영화가 현재 서비스에 매핑되지
않으면 기술적 지원/매핑 누락으로 따로 세고 학습·원관측 목표를 조용히 제거하지 않는다.

GBT/FM/ALS의 별점 오차 직접 차이는 **동일 사용자·동일 목표행을 모두 지원하는 교집합**에서
계산한다. 전체/ALS 미지원 행의 지원률과 GBT/FM 오차는 별도 표다. ALS factor가 없는 영화의
예측값을0·평균·GBT로 채워 ALS 점수라고 기록하지 않는다.

## 2. 오차와 순위 수식

모든 모델은 보정45명으로 얻은 고정 affine을 사용한다. 순위는 보정 연속값,
MSE/MAE는 [0.5,5] clipping 값이다. 실제 별점과 예측 모두 임의0.5 반올림을 하지 않는다.

```text
MSE_user(u) = mean_i((clip(pred_ui,0.5,5)-rating_ui)^2)
MSE_macro  = mean_u(MSE_user(u))
MAE도 같은 순서로 절대오차를 평균
MSE_micro  = 모든 지원 목표행 오차의 평균
MSE_movie_macro = 영화별 오차 평균을 영화 동일 가중으로 평균

gain(r) = 2^(r-0.5)-1
DCG@k = sum(j=1..k) gain(ranked_rating_j)/log2(j+1)
IDCG@k = 같은 관측 후보를 실제 별점 DESC/ID ASC로 정렬한 DCG@k
NDCG@k = DCG@k / IDCG@k
```

관측 후보가 k편 이상이고 IDCG>0인 사용자만 해당 NDCG@k에 포함한다. 부족·모두0.5점은
계산 불가로 세고0점으로 채우지 않는다. 모델끼리 비교할 때 유효 사용자 교집합을 사용한다.
모든 표에 사용자 수·목표행 수·고유 영화 수와 제외 사유를 붙인다. 기존 발표 NDCG 숫자는
당시 평가식/보정/분모의 결과로 보존하며 새 정의의 숫자로 대체 표기하지 않는다.

관측 순위에서 맞춤 @2/4/6/10과 라운드별 (1~2),(3~4),(5~6)…를 기록한다.
low는 실제 별점≤2.0이며 각 사용자의 해당 k슬롯에서 low 수/k를 계산한 뒤 사용자 평균이다.
실제 별점 평균도 먼저 사용자별로 계산한다. 비교 모델마다 k편 지원 여부가 다르면 공통 후보
순위 비교를 새로 명명하고, 각자의 전체 순위와 같은 표의 직접 차이로 섞지 않는다.

실제 정책 재생에서는 맞춤 첫2·누적4/6/10, 발견 첫1·누적2/3/5/10과 각2+1 응답을 기록한다.
UNKNOWN이 있는 출력의 NDCG는 산출하지 않는다. 대신 관측 슬롯 수/전체 슬롯 수,
관측된 슬롯만의 low·평균(조건부 기술통계), 전체 UNKNOWN 비율을 같이 표시한다.
발견 대체는 actualType=PERSONALIZED로 집계하며 발견 만족도에 넣지 않는다.

## 3. 불확실성과 고정 대조

주 추정은 사용자 동일 가중이다. 선정·확인 각각 **사용자 블록 paired bootstrap 10,000회,
NumPy PCG64 seed339**로 같은 사용자의 모든 행/순위를 함께 재표집한다. 사용자 ID ASC 목록에서
원 사용자 수만큼 복원추출하고 같은 draw를 모든 모델에 적용한다. 2.5·97.5백분위(선형 보간)를
95% 구간으로 보고한다. seed에 집합명을 더해 바꾸지 않고, 집합마다 새 PCG64(339)로 시작한다.

같은 영화가 여러 사용자에게 반복되는 영향을 보기 위해 별점 오차는 추가로 **영화 블록
bootstrap 10,000회, PCG64 seed340**을 수행한다. 영화 ID ASC에서 복원추출한 multiplicity를
각 영화의 모든 목표행에 적용하고 사용자 평균을 다시 계산한다. 해당 draw에서0행인 사용자는
그 draw에만 제외하고 빈 draw는 NA로 센다. 영화 블록으로 후보를 복제해서 NDCG를 재정렬하지 않는다.
이것은 두 방향 군집 상관을 동시에 해결한 검정이 아닌 별도 민감도 분석이다. 두 분석의 방향이
엇갈리면 오차 개선이 반복 영화에 민감하다고 기록한다.

고정 우위 대조 family는 **B1−B0, B2−B0, B3−B0의 사용자 macro MSE 3개**다.
각 차이에서 사용자 단위 paired sign-flip 10,000회, PCG64 seed341, 단측 개선 대립으로
`p=(1 + count(permuted_delta <= observed_delta))/(10000+1)`를 계산한다. 세 p에 Holm의
step-down 보정, family α=.05를 적용한다. 표본 미달/실행 실패 대조는 p=1로 유지한다.
같은 flip 행렬을 세 대조에 사용하고 공통 사용자 교집합으로 검정한다. FM/ALS와 여러 층의
비교는 기술적 비교이며 이 family의 유의성 승리로 확대하지 않는다.

새 GBT의 안전 한계는 NDCG@2 차이≥−0.01, Top2 low 차이≤+0.02,
핵심 구간 MSE 상대 변화≤+0.05다. 상대 변화는 `(MSE_new−MSE_B0)/MSE_B0`이며
B0=0이면 new도0일 때만0, 그 외 실패다. **사용자 bootstrap의95% 구간까지** 한계 안에
있어야 비열등을 주장한다. 여러 안전 항목을 모두 만족해야 통과하는 규칙이다.
작은 층의 넓은 구간은 실패/판단 불가를 숨길 이유가 아니며 결과를 보고 한계를 바꾸지 않는다.

### 활성화 게이트의 정확한 집합과 단계

게이트는 **자연 상태 view의 cap10 관측 목표**를 사용한다. 학습용 가림 view나 실제 서비스의
UNKNOWN 슬롯으로 대체하지 않는다. 비교하는 Bn과 B0가 모두 지원하고 정답이 있는 동일 행에
한정하며 사용자별 해당 행의 MSE를 먼저 평균한다. 관측 목표에서 추천 하한을 이유로 행을 지우지 않는다.
다음 층은 서로 겹칠 수 있고, 겹침을 제거하거나 하나의 평균으로 합치지 않는다.

| 층 ID | 정확한 행 조건 | 필수 변형 |
| --- | --- | --- |
| ALL | 위 공통 관측 목표 전부 | B1/B2/B3 |
| ALS_TARGET_SUPPORTED | 고정 ALS factor에 목표 영화 ID가 존재 | B1/B2/B3 |
| ALS_TARGET_UNSUPPORTED | 고정 ALS factor에 목표 영화 ID가 없음 | B1/B2/B3 |
| KR | 목표 영화의 고정 TMDB production_countries에 KR 포함 | B2/B3 |
| KO_LOW | 목표 KOBIS 값 valid이며 10,000≤누적 관객<1,000,000 | B2/B3 |
| KO_ONLY | 목표 KOBIS valid=true, TMDB 평균평점 present=false | B2/B3 |
| KO_RESPONSE | 원본 H에서 KOBIS 유효 m≥2이고 z분산>1e−8인 사용자의 관측 목표 | B3 |

KOBIS valid는 [데이터 연결 기준](KOBIS-DATA.md)의 확정 영화 연결·누적 범위·기준일 검증을
전제로 한다. 확대 수집72,700행은 영화·연도 관측이고, KO_LOW의 고유 목표영화/사용자/평가행 수가 아니다.
연간 관객1만~100만 미만5,352행을 누적 저관객 층에 대입하지 않는다. KO_ONLY는 동일 작품 연결 후
TMDB 평균의 실제 결측을 확인한 경우이며, 연결 실패나 제안 ID만 있는 경우는 포함하지 않는다.
출처 간 확정 연결0개의 현재 확대 자료로는 이 층들의 평가 지원 수가 아직 입증되지 않았다.

ALS_TARGET 두 층은 목표 factor 존재만으로 나눈다. 서비스 ALS의 fold-in 성공/실패를 나눈
support 지표와 이름·분모를 구분한다. 각 필수 층은 **선정45/확인180 각각** 최소30사용자·
30고유 목표영화·200행을 만족해야 한다. KO_RESPONSE도 동일 조건을 쓴다. NDCG/low 안전
게이트는 ALL의 동일 관측 후보에서 k=2를 모두 채우고 IDCG>0인 공통 사용자 최소30명이다.
미달이면 INSUFFICIENT이며 해당 변형의 활성화 통과가 아니다. 자연 결측 층 미달을 인위적
가림으로 채우지 않는다. 이 엄격한 하한은 통계적 검정력 보장이 아닌 사전에 둔 운영 준비 조건이다.

각 변형은 선정45에서 NDCG/low와 **모든 필수 MSE 층**을 먼저 통과해야 확인180 단계로
이행할 수 있다. 계수·특징·설정을 고정하고 확인180에서도 같은 조건을 모두 통과해야 최종
비열등 PASS다. 확인 결과를 보고 다른 변형으로 교체하거나 계수를 바꾸지 않는다. v1 목표는
B3이며 B1/B2의 통과만으로245열 준비 완료를 선언하지 않는다. 확인이 실패하면 B3 미준비다.

각 층 bootstrap은 그 층의 공통 사용자 ID ASC 목록에서 새 PCG64(339)로 시작한다.
각 draw에서 Bn과 B0의 사용자 macro MSE를 각각 다시 계산한 뒤 **그 draw 안에서**
`(MSE_Bn*−MSE_B0*)/MSE_B0*`를 구한다. 관측된 B0를 고정 분모로 쓰지 않는다.
B0*=0이면 Bn*=0일 때0, 그 외+∞다. 유효 사용자0인 draw 또는 NA/비유한 원점수는
INDETERMINATE로 보고 게이트를 통과시키지 않는다. +∞ draw가 하나라도 있으면 해당
상대 MSE 게이트는 FAIL이다. percentile을 계산할 때 문제가 있는 draw를 몰래 버리지 않는다.

통과 방향은 NDCG 차이의 **95% CI 하한≥−0.01**, low 차이의 **CI 상한≤+0.02**,
각 필수 층 상대 MSE의 **CI 상한≤+0.05**다. 경계값과 같으면 통과다. 사용자 bootstrap이
공식 안전 판정이며 영화 블록 결과는 별도 민감도 설명이다. Holm 우위와 이 안전 판정은
다른 질문으로, 안전 통과에 반드시 우위 유의성이 필요한 것은 아니다.

## 4. 관측 범위와 서비스 확인

항상 전체·ALS 지원/미지원·한국/외국·개봉 시기·TMDB/KOBIS 출처4조합·관객/투표 규모·
사용자 평가량·유효 근거 m을 함께 요약한다. 자연 표본과 인위 가림을 분리한다.
KOBIS 저관객·TMDB 평균 결측의 최소 표본은 MODELS 준비 게이트를 따른다.
수집 전체→직접 코드→검증된 서비스/평가 영화 연결→같은 기준 누적 유효→평가 정답 교집합의
각 단계에서 남는 관측행·고유영화·사용자 수를 구분해 기록한다. 전체 수집 분포와 순위로 선택된
직접 코드 표본의 분포를 함께 보여주며, 연결률 상승을 추천 성능 향상이라고 해석하지 않는다.

노출 중복0, 최대10공급그룹/그룹10편, 2+1 실제 구성, 대체/부분 반환율, 영화/그룹 집중,
model_input_supported 비율, pool 밖 누락과 소진, batch/특징/추론/정렬 지연·메모리를 기록한다.
이 수치는 만족도 정답 없이도 측정할 수 있지만 좋은 추천이라는 결론을 대신하지 않는다.
실제 서비스 반응은 당시 예측·노출·버전과 연결해 축적하고, 미노출/미평가를 싫어요로 만들지 않는다.
