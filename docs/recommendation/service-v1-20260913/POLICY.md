# 추천 v1 정책

상태: **APPROVED — 로컬 구현 기준**. [전체 문서](README.md).
기계 설정은 [config.v1.json](config.v1.json), 저장·게시·API는 [CONTRACTS.md](CONTRACTS.md)를 따른다.
§1~8은 맞춤·발견 정책이다. 상세의 비슷한 영화는 아래 §9의 별도 검색 경로이며 세트/세션 규칙을 그대로 적용하지 않는다.

## 1. 입력의 의미

| 데이터 | 사용하는 곳 | 제외할 해석 |
| --- | --- | --- |
| 현재 실제 별점0.5~5,0.5단위 | K·공유 모델 특징·ALS fold-in·콘텐츠 방향 | 모델 예측값을 실제 별점으로 저장하지 않음 |
| 확정 감상 전체 | 시청 제외·발견 그룹 경험량 | 최신10편으로 전체 감상량을 대체하지 않음 |
| 온보딩 LIKE/DISLIKE | 저이력 콘텐츠 방향 | K·실제 별점·감상량에 포함하지 않음 |
| 관심없음 | 두 유형의 후보에서 제외 | 실제 낮은 별점/감상으로 만들지 않음 |
| 세션의 반환 영화 | 맞춤/발견 공통 중복 방지 | 감상·별점·K로 세지 않음 |
| 클릭·OTT 이동 | 행동 로그·별도 분석 | 자동 감상 완료/별점으로 만들지 않음 |

K는 삭제되지 않은 현재 실제 별점이 있는 서로 다른 서비스 영화 수다. 영화별 최신 값 하나를
`rating_updated_at DESC, service_movie_id ASC`로 정렬해 원본 H=min(K,10)을 먼저 선택한다.
그 뒤 각 모델/콘텐츠에 매핑한다. 누락분을 오래된 영화로 채우지 않는다. 인기가 낮다는 이유로
이력 선택에서 빼지 않는다. 삭제 후 K=9이면 저이력으로 전환한다. K≥10이어도 사용할 수 있는
GBT 이력이0이면 초기 경로로 처리하고 사유를 기록한다.

별점 수신은 decimal 또는 손실 없는0.5 단위 정수 표현으로 처리한다. `Integer score=4`로
4.5를 전달할 수 없다. API·이벤트·DB·Python 간 실제 별점 parity가 필수다.
실제 별점을 등록하면 감상 영화로도 제외한다. 별점 삭제와 감상 삭제는 별도 도메인 상태이며,
별점을 지웠다고 남아 있는 감상 기록까지 제거하지 않는다.

## 2. 영화 원천과 추천 자격

원천 레코드는 `source`, `source_movie_id`, `service_movie_id`, `collected_at`, `scope`,
`raw_value`, `valid`, `missing_reason`, `mapping_status`를 가진다. NOT_COLLECTED,
FETCH_FAILED, NOT_IN_RANKED_EXTRACT, AMBIGUOUS, NOT_FOUND_IN_QUERIED_SCOPE는 관객0이 아니다.
KOBIS는 같은 누적 범위를 검증한 관객 값만 쓴다. 연간 관객과 생애 누적의 max를 섞지 않는다.
확대 수집 원행·직접 코드·영화 연결 제안은 [KOBIS-DATA](KOBIS-DATA.md)에 따라 구분한다.
원문 검산 PASS 또는 제목·연도·국가의 유일 후보만으로 `mapping_status`를 확정하지 않는다.
직접 KOBIS 코드가 있어도 서비스 영화와의 crosswalk 및 누적 기준일 검증을 거쳐야 한다.
연간 기록이나 오래된 기간 말 누적을 현재 누적으로 바꾸어 `K_ok`를 계산하지 않는다.

공통 후보는 서비스에서 활성이고, 후보 기준일까지 개봉한 `Released` 영화이며, 성인/비디오
플래그가 명시적으로 false여야 한다. 영화 ID·표시 정보·해당 scorer의 입력 지원이 필요하다.
맞춤·발견에서는 사용자가 명시한 필터·감상·현재 별점·관심없음·현재 세션 노출을 제외한다.
구독 OTT 정보는 기본적으로 링크 표시에 쓰며, 구독 OTT만 보기 요청에서만 후보를 좁힌다.
OTT 결측 자체를 낮은 취향 점수로 만들지 않는다.

대중성 최소 근거는 다음 OR다.

```text
T_ok = 유효 TMDB 평균평점(0<R≤10) AND 정수 vote_count≥21
K_ok = 연결이 확정되고 같은 누적 범위의 KOBIS 관객이 검증됨 AND audience≥10,000
public_eligible = T_ok OR K_ok
```

양쪽 false이면 콘텐츠 유사도가 높아도 추천 후보에서 제외한다. 두 숫자는 운영 하한이며,
21표와1만 관객이 같은 선호·같은 인기라는 뜻은 아니다. `popularity`만으로 통과시키지 않는다.
이 하한은 **추천 후보에만** 적용한다. 검색·평점 저장·감상 이력·학습의 유효 원천 값은 보존한다.
실제 낮은 관객 수도 사용자가 무엇을 좋아했는지 계산하는 정보다.

TMDB 영화 속성이 있는 것과 TMDB 평점이 있는 것은 다르다. KOBIS만 최소 근거를 충족해도
기본 영화 특징을 만들 수 있으면 개인 예측할 수 있다. 영화 정보 자체가 없어 특징을 만들 수
없으면 `MODEL_INPUT_UNAVAILABLE`이며 KOBIS 기록만으로 영화 특징을 창작하지 않는다.

## 3. 대중 목록의 정확한 순위

한 카탈로그 버전에서 출처별 전체 적격 목록을 미리 정렬한다. 그룹별 목록도 전체 순서를
보관한다. 상위10개 ID만 저장한 뒤 시청 제외를 하면 공급이 줄어드므로 전체 순서를 읽을 수 있어야 한다.

```text
Q = (vote_count×vote_average + 300×6.314301027022476)/(vote_count+300)
T: T_ok인 영화만 Q DESC, vote_count DESC, service_movie_id ASC
K: K_ok인 영화만 audience DESC, service_movie_id ASC
```

Q의300은 최소 투표수가 아니다. 후보 공급용 Q와 GBT 내부 평점 축소(C=6.173088067675869,m=48)는
용도가 다르다. v1에서 임의로 서로 치환하지 않는다.

사용자 제외를 반영한 같은 범위(전역 또는 해당 그룹)에서 각 목록의 순위를1부터 다시 센다.
`best_rank=min(rank_T,rank_K)`이며 해당 출처 gate를 통과하지 못하면 rank=∞다.
best_rank ASC, service ID ASC로 합치고 ID 중복을 제거한다. 양쪽에 있다는 추가 보너스는 없다.
이것은 강한 한쪽 근거를 후보에 살리는 규칙이다. 서로 다른 출처의 평점·관객 수를 같은 만족도
점수로 바꾸었다는 뜻은 아니다. 최신 수치가 갱신되면 동일 식으로 목록을 다시 만든다.

## 4. 맞춤: 배치 후보500과 현재 입력 재정렬

1. Spark 배치는 해당 사용자의 최신 원본 H와 활성 bundle을 읽는다.
2. K≥10이며 GBT 유효 이력이 있으면 전체 적격 카탈로그를 partition별로 GBT 점수화하고,
   점수 DESC/ID ASC의 Top500을 만든다. 그 외에는7절의 초기 콘텐츠/대중 순위로 Top500을 만든다.
   배치 시점의 감상·관심없음은 제외한다. 일시 세션 노출은 사용자별 영구 후보에서 삭제하지 않는다.
   다만 소진 재공급(reason=POOL_EXHAUSTED)은 현재 세션 노출·다른 활성 예약을 제외한
   전체 적격 카탈로그에서 다음500편을 만든다. 같은 입력으로 같은500편만 반복하지 않는다.
3. Consumer는 현재 입력으로 사용자 반응 특징을 다시 만들고 pool의 모든≤500편을 다시 점수화한다.
   중간 Top100을 먼저 자르지 않는다. 최신 제외를 반영하고 GBT 보정점수 DESC/ID ASC로 정렬한다.
4. 출력 조립기는 맞춤 순서에서2편씩 소비한다. 발견과 중복이면 다음 적격 맞춤 영화를 읽는다.

기본 점수는 GBT 단독이다. ALS factor의 존재 여부로 GBT를 덮어쓰거나 shrink100을 자동 적용하지 않는다.
pool이 없거나 소진되면 비동기 targeted 후보 배치를 요청한다. 온라인 요청이 전체 카탈로그
계산을 기다리지 않는다. 임시 공유500·pool 입력 버전·새로고침 상태는 OPERATIONS의 절차로 구분한다.

배치 후보500 밖의 영화는 재정렬만으로 등장할 수 없다. 강한 입력 변경 시 targeted batch를
등록하는 이유다. 기존 pool의 ID만 잠시 재사용할 수 있지만 점수·사용자 반응은 현재 입력으로 계산한다.
소진 재공급 pool에는 제외에 사용한 sessionId·exposureRevision·ID 집합 해시를 기록한다.
해당 세션에서만 재사용하며 새 탐색에서는 일반 pool 또는 임시 공유500을 쓰고 새 pool을
요청한다. 제외 스냅샷의 세션/노출 revision이 바뀐 작업은 CAS 게시를 거부한다.

## 5. 고정 그룹과 사용자 방향

상위8맛은 기존 G-913 장르 기준으로 고정한다. 복수 장르를 모두 사용한다. 각 맛 안의
고정128개 중심에 배정하며 `group_id=taste_id×128+child_id`, 전체1,024개다.
신규 영화는 같은 전처리/중심으로 배정한다. 크기가 작다고 그룹을 합치지 않는다.

콘텐츠 공간은 기존131차원 GKT다.

```text
g = L2(19개 장르)
k = L2(고정 keyword IDF, SVD64)
t = L2(고정 줄거리 TF-IDF, SVD48)
x = L2(concat(sqrt(0.5)g, sqrt(0.35)k, sqrt(0.15)t))
```

대중평점·관객 수를 이 분류 벡터에 추가하지 않는다. 대표는 고정 기준 스냅샷에서 지원 영화
벡터를 동일 가중 평균한 값이다. 평균 대표를 다시 단위 정규화하지 않는다. 배정 중심과 검색
대표를 별도로 저장한다. 일반 영화 추가·삭제·대중 수치 갱신으로 중심/대표를 다시 학습하지 않는다.

실제 별점 방향은 원본 최신 H로 다음을 계산한다.

```text
rbar = (sum(original_ratings) + 5×3.5)/(H+5)
anchor = 3 + 0.5×(rbar−3)
w_i = rating_i−anchor
raw_p = sum(supported w_i×x_i)/(sum(supported abs(w_i))+5)
p = raw_p/||raw_p||
```

norm≤1e−8이면 방향 없음이다. 원본 평균에는 매핑 전 선택 별점이, 벡터 합에는 지원 영화만
들어간다. 이력 인기 하한은 없다. 0벡터 영화는 GKT 비교에는 쓰지 않지만 실제 감상으로 남는다.
발견의 그룹 매핑은 **장르 근거가 있는 상위 맛 배정(top_supported)**과 **유효 GKT 근거
(sub_supported)**가 모두 있을 때만 인정한다. 장르0에 진단용 그룹 ID가 배정되어 있어도
발견 공급·전체 mapped 감상 분모에는 넣지 않는다. 이 영화도 개인 맞춤·실제 감상 제외에는 남는다.
구체적인 원파일 선택·전처리·동률·신규 영화 배정은 [GROUPS](GROUPS.md)의 고정 계약을 따른다.

## 6. 발견: 최대10개 공급 그룹×최대10편

그룹의 ‘덜 봄’ 자격은 전체 distinct mapped 감상 영화로 계산한다.

```text
viewed_g ≤ 2 AND viewed_g/max(1,total_mapped_viewed) ≤ 0.20
AND 그룹에 현재 적격·미노출 후보가 한 편 이상
```

낮은 별점을 준 영화도 감상에 포함한다. 상위 맛을 많이 보았다고 그 맛 전체를 제외하지 않는다.
기존 세션 노출을 감상량 분자·분모에 넣지 않는다. 방향과 고정 그룹 대표의 내적 DESC,
group ID ASC 순서로 적격 그룹을 검토한다. 음수라는 이유로 별도 제외하지 않는다.

```text
candidates = []; supplying_groups = 0
for group in ordered_eligible_groups:
    movies = first_10(group.best_rank_list after all current exclusions)
    if len(movies) == 0: continue
    candidates.extend(movies)
    supplying_groups += 1
    if supplying_groups == 10: break
```

한 그룹이1~9편만 공급해도 공급 그룹1개로 센다. 10개 공급 그룹 이후11번째 그룹에서100편을
억지로 채우지 않는다. 한 그룹의11번째 영화로 다른 그룹 부족분을 대신하지 않는다.
따라서 실제 후보는100편보다 적을 수 있다. 그룹이 부족하면 가능한 그룹만 사용한다.

모은 후보를 현재 GBT로 개인 점수화하고 DESC/ID ASC로 정렬한다. 발견은 그 순서에서1편씩
소비한다. 그룹 검색 점수·best_rank·GBT점수를 하나의 가중합으로 더하지 않는다.
`dv2_retrieve.gather`의 quota만10으로 바꾸면 공급 그룹 수가 제한되지 않으므로 별도 중단
조건이 필요하다. `variant=original`도 GBT 단독이 아닌 기존 router이므로 재사용하지 않는다.

다음 버퍼는 같은 세션에서 이미 제공한 영화와 이미 예약한 미소비 영화를 제외하고 같은10×10
규칙을 다시 적용한다. 그룹 경험량은 실제 감상만으로 계산한다. 버퍼 간 전체 점수 단조감소나
매번 다른10개 그룹을 보장하는 정책은 아니다.

## 7. K<10·빈 이력·방향 없음

개인화 전환 K10은 운영 기본값이다. 실제 별점으로 콘텐츠 방향을 먼저 시도하고, 없으면
`L2(sum(LIKE x)−sum(DISLIKE x))` 온보딩 방향을 사용한다. 같은 영화의 최신 신호 하나만 쓰고,
실제 별점이 있는 영화의 온보딩 신호는 제외한다. 온보딩은 실제 별점으로 환산해 GBT/ALS에 넣지 않는다.

| 상태 | 맞춤 슬롯 | 발견 슬롯 |
| --- | --- | --- |
| K<10, 방향 있음 | 공유/개인 pool 안에서 콘텐츠 내적 DESC, 동률 best_rank/ID | 덜 본 그룹10×10 후보를 콘텐츠 내적 DESC로 정렬 |
| K<10, 방향 없음 | 전역 T/K best_rank | 그룹 방향을 꾸며내지 않고 맞춤 초기 후보로 대체, 사유 표시 |
| K≥10, GBT 이력 있음, GKT 방향 있음 | GBT | 그룹10×10 뒤 GBT |
| K≥10, GBT 이력 있음, GKT 방향 없음 | GBT | 발견 불가로 맞춤 대체, 사유 표시 |
| K≥10, GBT 유효 이력 없음 | 가능한 초기 콘텐츠/대중 경로 | 방향 있으면 초기 발견, 없으면 대체 |

초기 콘텐츠 순위는 `mode=INITIAL_CONTENT`, 대중 순위는 `INITIAL_PUBLIC`로 기록한다.
GBT 개인화라고 표시하지 않고 예상 별점도 null이다. GBT 오류 시에도 초기 순위를 같은 GBT
성공 결과처럼 저장하지 않는다. 준비 중·오류·후보 소진은 별도 상태다.

## 8. 맞춤2+발견1 세트와 부족 처리

기본과 추가 요청은 모두 논리 슬롯 `[PERSONALIZED, PERSONALIZED, DISCOVERY]`다.
Consumer는 정렬된 맞춤≤500편·발견≤100편을 게시한다. **20/10으로 미리 자르지 않는다.**
Spring은 이 전체 순서에서 라운드별 맞춤2편→발견1편을 순서대로 조립한다. 세트 버퍼는
최대10라운드, 타입별 맞춤20/발견10을 목표로 저장한다. 화면에는 한 라운드만
제공한다. 같은 세션 안에서 유형 간 중복도 금지한다.

조립 순서는 맞춤2편 예약 후 이2편을 제외한 발견1편이다. 발견이 맞춤 후보와 겹치면 발견의
다음 후보를 소비한다. 예약/노출은 트랜잭션으로 기록해 동시 요청이 같은 영화를 소비하지 않게 한다.
소비하지 않은 버퍼의 예약 목록과 실제 반환한 세션 노출 목록은 분리한다.
다른 라운드에 먼저20편을 일괄 예약하고 발견을 고르는 방식도 아니다. 한 라운드를 완성할
때마다 다음 라운드로 진행하고, 이미 조립한 모든 슬롯을 이후 두 순서에서 제외한다.

발견이 부족하면 같은10×10 규칙의 다음 버퍼를 한 번 준비한다. 그래도 없으면 기존 팀 정책에
맞춰 다음 맞춤 후보로 채울 수 있다. 이 슬롯은 `requestedType=DISCOVERY`,
`actualType=PERSONALIZED`, `fallbackReason=DISCOVERY_EXHAUSTED`로 남긴다.
방향 없음은 `NO_CONTENT_DIRECTION`이다. 3편이 모두 맞춤인 응답을 발견이 포함됐다고 표시하지 않는다.
맞춤 자체가 부족하거나 합계3편을 만들 수 없으면 짧은 결과와 부족 사유를 반환한다.
부적격 영화·재노출·미평가0점·ALS 자동 전환으로 수량을 채우지 않는다.

같은 요청의 재시도는 같은 라운드를 반환한다. 감상/관심없음 등 강제 제외가 새로 생겼으면
동일 라운드 revision을 갱신해 교체하고 재시도에 그 revision을 재사용한다. 입력 버전 변경은
기존 미소비 순위를 무효화하며 세션의 이미 반환한 ID는 보존한다. 자세한 CAS·API는 CONTRACTS를 따른다.
확정 감상의 추가·삭제와 추천 필터 변경도 그룹 경험량/후보 조건을 바꾸므로 입력 버전을
증가시킨다. 별점 등록과 파생 감상 등록이 한 트랜잭션에서 일어나면 한 번만 증가시킨다.

최초 조회 때 세션을 만들고, 일반 추가 요청·버퍼 소진·별점 변경은 세션을 바꾸지 않는다.
명시적인 새 탐색은 `POST /recommendations/sessions`의 requestId로 생성하며 과거 노출 로그는
보존한다. 같은 요청 재시도는 같은 세션이다. 시간 경과만으로 노출 제외를 몰래 초기화하지 않는다.

## 9. 상세 페이지의 비슷한 영화

[SIMILAR-MOVIES](SIMILAR-MOVIES.md)의 별도 정책을 적용한다. 기본10편이며 기존 API의
size 최대20을 유지한다. 대상 영화와의 콘텐츠 cosine으로 순서를 정하고 공용50편을 캐시한다.
§2의 후보 공개/대중 근거는 공유하지만 기준 영화의 인기 하한은 요구하지 않는다. 로그인 시
감상·현재 별점·관심없음만 후처리하고 맞춤/발견 세션 노출·개인 필터를 가져오지 않는다.
K10·pool500·발견10×10·2+1 세트·추가 라운드와 독립이다. 부족분은 있는 만큼 반환한다.
