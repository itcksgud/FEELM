상태: **APPROVED — 사용자 요청에 따른 로컬 v1 데이터 연결 기준 보완** · 2026-09-13.
팀 API·DB 이행이나 모델 학습 완료를 뜻하지 않는다. 정책 수식은 [POLICY](POLICY.md),
특징·학습 조건은 [MODELS](MODELS.md), 실제 수집 결과는 [분석 문서](../../research/kobis-expanded-20260913/REPORT.md)를 따른다.

이번 확대 자료의 검증된 crosswalk 또는 확대 상관계수로 재사용하지 않는다.

## 2. 원관측, 연결 제안, 서비스 입력을 분리한다

세 자료는 같은 테이블의 상태만 바꾸며 덮어쓰는 대신 원문을 추적할 수 있게 분리한다.

| 층 | 필수 내용 | 허용하는 사용 |
| --- | --- | --- |
| 원관측 | source_row_id, 상영연도, 기간 시작/끝, 연간값·기간 말 누적값, 수집 시각, 원문 SHA, 실제 직접 코드 또는 null, 음수 정정 표시 | 전체 자료 점검·연도별 기술통계 |
| 식별 제안 | 제안 KOBIS/TMDB ID, 후보별 원행·제목·개봉일·국가 등 근거, 모호/충돌 상태 | 검토할 대응 목록. 후보 자격·특징·정답 연결에는 사용하지 않음 |
| 검증된 영화 입력 | service_movie_id↔tmdb_id↔kobis_movie_code crosswalk, 검증 방법·근거·버전, 선택한 누적 통계의 출처·범위·기준일 | 유효성 검사 후 후보와 GBT/FM 특징에 공통 사용 |

제목·개봉일·국가가 유일하게 일치해도 `PROPOSED`다. 직접 KOBIS 코드가 있다는 사실도
TMDB/서비스 영화와의 동일성을 증명하지 않는다. 공식 식별자 연결 또는 양쪽 영화 상세의
원제·개봉 정보·감독 등 작품을 구분하는 근거를 대조한 검토 기록으로 crosswalk를 확정한다.
근거 원문과 판정 버전을 남기고 동명이작·재개봉 판본·다대일 충돌을 해결하지 못하면 미확정으로 유지한다.
이 절차는 매 행마다 사용자에게 승인을 받는 업무 흐름이 아니라 재현 가능한 데이터 검증 기준이다.

직접 코드가 없는 행도 삭제하지 않는다. 확정된 crosswalk로 원행의 작품 정체를 검증한 뒤에만
영화별 자료에 연결한다. 현재 `linked-v2`의 제안 열을 ID 열로 이름만 바꿔 게시해서는 안 된다.

## 3. 추천에 사용할 관객 수의 선택

1. 데이터 버전에서 KOBIS 전국 발권 누적의 대상 범위와 기준일을 먼저 고정한다.
2. 검증한 영화 연결에 대해 그 범위·기준일에 해당하는 누적 관객 수와 원문을 확보한다.
   최신 서비스 스냅샷은 그 기준일의 영화 상세 발권 통계 등으로 확인한다.
3. `연간 관객 수`, `기간 말 누적`, `현재 상세 누적`, `공식 연감 통계`를 서로 다른 지표로 보존한다.
   서로 다른 누적 관측을 합하거나, 연간값과 누적값의 max로 새 누적을 만들지 않는다.
4. 한 영화에 같은 기준일·범위의 값이 충돌하면 검토 대상으로 남긴다. 큰 값을 임의 선택하지 않는다.
   더 오래된 행을 선택하고 `collected_at`만 새 시각으로 바꾸어 최신값으로 표시하지 않는다.
5. 후보와 이력의 반응 특징은 같은 게시 스냅샷에서 읽는다. 서비스용 누적값의 연결·범위·기준일을
   확인하지 못하면 KOBIS 채널은 미지원이며, TMDB 채널의 기존 OR 조건은 별도로 계산한다.

`collected_at`은 조회 시각이고 `statistics_as_of`/`period_end`는 통계의 기준이다.
예를 들어 명량의2025년 말 누적17,616,661명과2026-09-12 상세 누적17,616,791명은 다른 관측이다.
`linked-v2`의 `last_observed_*`는 **직접 코드가 있는 행 중 마지막 관측**일 뿐이며,
원자료의 모든 연도 중 마지막 값이나 현재 누적을 자동 보증하지 않는다.

2026년은9월12일까지의 진행 연도다. 과거 연도도 현재 조회한 통계이므로 당시 이용 가능했던
스냅샷을 재현했다고 주장하지 않는다. 2004 이전 원개봉작의 재상영값과 초기 전산망 관측 범위도 보존한다.
현재 TMDB·KOBIS와 과거 MovieLens를 결합하는 한계가 연도별 수집만으로 사라지지 않는다.

음수 정정16행은 원문 그대로 남긴다. 누적 관객 자체가 음수이면 `log1p`·후보 자격에 넣지 않는다.
연간 정정이 음수이고 검증된 누적은 양수인 경우에는 두 필드를 구분하여 판단한다.
미수집·미연결·범위 밖을0관객으로 바꾸지 않는다. 특징의 계산용0과 valid=0 처리는 MODELS를 따른다.

## 4. 학습 준비로 넘어가는 순서

| 순서 | 완료 조건 |
| --- | --- |
| 전체 수집 | 이번72,700행과 원문 검산으로 완료 |
| 영화 연결 | 서비스 카탈로그 및 고정 학습/보정/선정/확인 이력·목표를 기준으로 crosswalk 검증. 상위 순위 코드만 선택하지 않음 |
| 관객 입력 | 선택한 영화의 같은 범위·기준일 누적 검증, 충돌·미지원·음수 상태 분리 |
| 평가 교집합 | 사용자 수·고유 목표영화 수·평가행 수를 역할별로 집계. 미연결은 별도 결측으로 보고 |
| 모델 준비 | 기존 KR/KO_LOW/KO_ONLY/KO_RESPONSE 하한과 별점·순위 안전 조건을 모두 충족한 뒤 새 학습·검토 수행 |

이번 **연간** 관객1만~100만 미만5,352행은 저관객 **누적 영화**5,352편 또는 MovieLens 평가행5,352개가 아니다.
KO_LOW는 검증된 누적1만~100만 미만의 고유 목표영화를 기준으로 정의한다.
KO_ONLY는 KOBIS 값과 영화 연결이 유효한 영화에서 TMDB 평균이 없는 경우다.
KOBIS↔TMDB 연결이 안 된 것을 TMDB 평균 결측으로 간주하지 않는다.

72,700행을 q99 학습에 그대로 넣어 재상영이 많은 영화를 중복 가중하지 않는다.
학습 역할에 속한 유효 영화마다 고정한 누적 한 값을 사용한다. 자료 확보가 넓어진 만큼
수집 범위·확정 연결률·날짜/범위 유효률·평가 지원률을 각각 보고한다. 모델 계열·245열·운영 하한은
기존 v1대로이며, 수집량을 근거로 하한을 낮추거나 한국영화 보너스를 새로 적용하지 않는다.
