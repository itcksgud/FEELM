# 발견 추천 설계 교정: 고정 분류, 그룹 검색, TMDb 보정 정렬

상태: DRAFT — 2026-09-12 사용자 피드백에 따른 설계 검토. 새 실험의 실행 설정이나 서비스 채택 계약은 아니다.
이 문서의 검토 완료는 실험·추천 품질 검증 완료를 뜻하지 않는다. 기존 fixed-k8-discovery 결과와 봉인은 보존한다.
개인 연구의 최신 루트 AGENTS/active-experiment를 확인했다. 현재 사용자의 K=8·발견 추천 요청과 TMDb 보정 정렬 지시가 과거 연구 방침보다 우선한다.

## 1. 이번에 바로잡는 질문

발견 추천의 목적은 **사용자가 적게 접한 영역에서, 기존 선호와 연결되는 볼 만한 영화를 제안하는 것**으로 둔다.
MovieLens의 미래 고평점 회수율 최대화로 이 목적을 대체하지 않는다. 미평가 영화는 UNKNOWN이다.
MovieLens 평점은 실제 MovieLens 이용자의 관측된 영화 평가다. 그러나 FEELM에서 추천을 받고 새 영화를 발견한 만족도의 정답은 아니다.

검증은 세 층으로 구분한다.

1. 규칙과 계산: 고정 분류, 벡터 공간, 개인 입력, 후보 예산, 근거 부족 처리 등이 명세대로 작동하는가.
2. 추천 행동과 근사 성능: 취향에 따라 그룹이 달라지는가, 덜 접한 영역의 후보를 실제로 공급하는가, 소수 후보만 계산하면서 어떤 기회를 놓치는가.
3. 사용자 가치: 본인이 새롭고 관심 가는 제안이라고 느끼는가, 선택·감상에 도움이 되는가. 현재 데이터만으로 확정할 수 없다.

1·2의 실패는 구현/설계 기각 근거다. 1·2의 통과를 3의 통과라고 쓰지 않는다. 반대로 3을 아직 관측하지 못한다는 이유로 1·2를 생략하지 않는다.

## 2. 바뀌지 않는 분류와 추천 계산의 경계

- 상위 8개 분류와 기존 할당 번들의 전처리·중심·ID·동점 규칙을 현재 고정 기준으로 보존한다. 이번 교정으로 다시 학습하지 않는다.
- 기존 16개 하위 그룹은 비교 출발점이다. 최적이라는 주장은 철회한다. 다른 하위 그룹 수를 연구하면 별도 연구 버전으로 비교하며 기존 번들을 덮어쓰지 않는다.
- 최종 선택한 하위 분류와 검색 대표 벡터도 한 번 계산해 동결한다. 새 영화는 고정 변환과 중심으로 배정하고, 삭제 영화는 후보에서만 제외한다. 기존 영화의 동일 입력은 동일 ID를 받아야 한다.
- 분류 중심과 검색 대표는 역할이 다르다. 장르로 고정된 맛 안에서 장르·키워드·줄거리 공간의 평균으로 검색할 수 있다. 그 경우 검색 대표를 원래 K-means 중심이라고 부르지 않는다.
- TMDb 평점 갱신으로 후보 순서가 바뀌는 것과 분류 기준이 바뀌는 것은 구분한다. 평가 시에는 TMDb 스냅샷·정렬 상수·후보 캐시 버전을 고정한다.
- 영화를 추가/삭제해도 대표를 다시 계산하지 않는다. 대표와 현 후보의 차이는 진단한다. 향후 자동 재계산은 이번 설계에 포함하지 않는다.

## 3. 후보 정렬: TMDb 평균 평점을 평가 수에 따라 수축

기본 비교안은 다음 점수다. R은 TMDb 0~10점 평균, v는 TMDb 평가 수, C는 기준 평점, m은 보정 강도다.

```text
Q = (v * R + m * C) / (v + m)
  = C + [v / (v + m)] * (R - C)
```

평가가 적으면 평균 평점의 극단값을 C 쪽으로 당긴다. 평가 수 자체로 정렬하지 않는다.
예시용 C=6.5, m=100일 때 평가 1개·10점은 약 6.53, 평가 1,000개·8점은 약 7.86이다.
이는 원리를 설명하는 가상 값이며 현재 카탈로그에서 선택한 상수가 아니다.

이 식은 수축 점수다. 개별 투표 분포·독립성·분산을 확인하지 않고 정확한 신뢰구간이나 '좋은 영화일 확률'로 표현하지 않는다.
낮은 R도 C 쪽으로 올라가므로 저평가 영화에 항상 보수적인 점수는 아니다. 작은 v의 영화가 절대 상위에 오지 않는다는 보장도 없다.

입력 계약부터 교정한다. 기존 prepare는 원본 누락/null과 0을 합친다. 새 준비에서는 원본 필드 존재·null·숫자 유효성 상태를 보존한다.
v=0, R 누락, 범위 밖 값, v와 R이 모순되는 행을 '0점 영화'로 처리하지 않는다. 점수 UNKNOWN과 원인을 별도 저장한다.
v>0/R=0 행의 원자료·공급자 의미를 확인하기 전 임의로 정상 저평점 또는 결측이라고 확정하지 않는다.
UNKNOWN 영화도 8개 분류에는 남는다. 근거 있는 품질순 후보 목록과 동일한 품질 보증을 부여하지 않는다.

C 후보는 유효 영화별 평균과 투표 가중 평균이다. 각각 '영화 하나의 전형적 평균'과 '투표 하나의 전형적 점수'라는 다른 가정을 가진다.
같은 후보 자격을 적용한 고정 참조 집합에서 전역 C를 계산하고 집합·C·m을 버전으로 고정한다. 새 영화가 들어와도 C/m을 재추정하지 않는다.
m은 최소 허용 평가 수가 아니다. v=m일 때 개별 R과 기준 C를 반반 반영하는 보정 강도다.
m 후보는 예컨대 10/30/100/300의 유한 민감도 비교로 시작할 수 있지만 이 문서에서 선정하지 않는다.
MovieLens NDCG를 최대화해서 C/m을 고르지 않는다. 평가 수별 노출·희소 그룹 공급·순위 변화·시대/언어/한국 영화 손실을 함께 보고, 절충과 선택 이유를 기록한다.
TMDb 집계만으로 보정의 통계적 최적성을 확정할 수 없다. 추가 스냅샷이 없다면 미래 평점 안정화 효과도 미검증으로 남긴다.

기본 순서는 Q 내림차순, 동점은 v 내림차순, 마지막은 고정 service ID다. count-only와 raw-R-only는 실패 양상을 확인하는 대조안이다.
같은 Q를 기준으로 'Q가 올랐으므로 좋은 추천'이라고 결론 내리지 않는다.

후보 단계와 최종 단계 모두에서 TMDb 평가 수 0/1~5/6~20/21~100/101+ 구간, 평가 수 최솟값, Top1 노출, 고유 영화 수·사용자 수·노출 슬롯 수를 구분해 집계한다.
이 구간은 진단용이며 20회 미만 영화의 일괄 배제 정책이 아니다. TMDb 평가 수와 MovieLens 학습 지원 수는 서로 다른 열로 유지한다.
수축 정렬만으로 문제가 해결되지 않으면 최소 지원 조건 또는 낮은 지원 후보 한도와 후보 부족 시 동작을 별도 정책 대안으로 검토한다. 숫자를 결과에 맞춰 조용히 추가하지 않는다.

## 4. 그룹 벡터와 사용자 벡터

영화 i의 콘텐츠 벡터 x_i는 장르·키워드·줄거리 등 동일한 변환·차원·가중치로 만든다. 장르만의 기존 표현도 대조안으로 남긴다.
어휘·IDF·투영·블록 정규화·누락/OOV 규칙을 동결한다. 새 고품질 의미 임베딩이 이미 준비됐다고 가정하지 않는다.
TMDb 인기/평점은 x_i에 넣지 않는 것을 기본으로 하여 콘텐츠 선호와 후보 품질을 분리한다.
ALS 사용자 벡터와 콘텐츠 그룹 벡터를 직접 내적하지 않는다. 차원 수가 같더라도 공간이 다르면 비교할 수 없다.

기본 그룹 대표는 동결 시점의 지원되는 구성 영화 벡터의 **동일 가중 평균**이다.

```text
c_g = (1 / |G_supported|) * sum(x_i)
```

그룹에는 모든 배정 영화가 남지만 0벡터·특징 누락 상태를 숨기지 않고 대표 계산의 지원 분모와 제외 수를 기록한다.
분류 이름용 대표 영화 목록과 검색용 c_g는 다른 산출물이다.

기본 사용자 벡터 p_u는 평가한 영화 벡터를 개인의 선호 가중치로 합한 것이다. 좋아한 영화의 특징은 더하고 싫어한 영화의 특징은 뺀다.
가중치의 기준 평점·개인 평균 보정·소수 입력 수축은 별도 실행 설정으로 고정한다. 모든 별점이 같다는 이유만으로 선호 정보가 없다고 단정하지 않는다.
비교안으로 좋아함/싫어함을 별도 평균 p+와 p-에 보존하고 score = p+·c_g - lambda * p-·c_g를 계산한다.
두 갈래 표현도 취향의 여러 모드를 모두 해결하지는 않는다. 각 방향의 근거 수와 정규화 전 크기를 저장한다.
신뢰 수축 뒤 단위벡터로 다시 정규화하면 크기 수축이 사라지므로, 방향과 근거량을 분리해 관리한다.

대표에 대한 사용자 점수의 출발점은 p_u·c_g다. c_g를 다시 단위 길이로 만들지 않으면 아래 등식이 성립한다.

```text
p_u · c_g = 구성 영화별 (p_u · x_i)의 평균
```

즉 그룹을 사용자의 영화별 콘텐츠 유사도 평균으로 요약한 것이다. 실제 예상 별점 평균이라는 뜻은 아니다.
단위 정규화한 중심의 cosine도 대조한다. 이는 방향 비교이며 위 평균 등식이 깨진다. 흩어진 그룹과 응집한 그룹의 크기 차이를 지우는 선택임을 명시한다.

후보 대표 비교는 동일 평균을 기본으로, medoid(실제 영화 한 편), Q 가중 평균, 고정 다중 대표를 대조한다.
medoid가 카탈로그에서 삭제되어도 저장한 대표 벡터를 다시 선정하지 않는다.
Q 가중 평균은 품질 상위 영화에 가까운 검색을 의도한 비교안이며 인기작 쏠림을 점검한다.
다중 대표는 단순 max만 쓰면 대표가 많은 그룹이 유리해지므로 대표 수·집계 규칙을 고정하고 비용을 함께 비교한다.
검색 다중 대표 수와 하위 그룹 개수는 별도 변수다. 먼저 같은 하위 분류에서 대표만 비교한 뒤 하위 그룹 수를 비교한다.

0개 평가, 지원되는 영화 0개, 방향 상쇄/극소 벡터는 별도 상태로 처리한다. 이들을 group ID 동점 순으로 검색해 개인화라고 부르지 않는다.
개인화 비교는 유효한 선호 방향이 있는 사용자에 한정하고, 제외 수와 이유를 보고한다. 새 사용자와 인위적으로 입력을 숨긴 cap0는 따로 진단한다.

## 5. 전체 그룹의 평균이 상위 후보를 대표하는가

그룹 전체의 c_g가 유사하더라도, TMDb 보정 정렬 상위 후보가 다른 내용이면 잘못된 그룹을 검색할 수 있다.
평균만으로 극소수의 잘 맞는 영화나 여러 모드를 놓칠 수도 있다. 이 문제가 대표·하위 그룹 수 선택의 핵심 실험 질문이다.

- 고정된 품질 순서의 prefix와 관람 제외 후 실제 공급 prefix 각각에서 평균 벡터와 c_g의 거리, 지원률, 점수 분포를 측정한다.
- c_g로 고른 그룹 순위와 각 그룹의 실제 후보들을 전부 비교해 얻은 순위의 차이를 측정한다. 후보 평균과 '사용자와 맞는 상위 일부' 집계는 구분한다.
- 후보를 전부 계산하는 느린 참조 경로에서 놓친 상위 후보, 점수 손실, 비용을 측정한다. 이 참조는 계산 근사의 기준일 뿐 사람의 정답이 아니다.
- 동결 이후 추가/삭제를 모의하여 기존 ID 불변과 검색 대표-현재 후보 차이를 동시에 확인한다. 불변성 PASS가 대표성 PASS를 뜻하지 않는다.

품질 상위 목록을 기준으로 대표를 만들고 동일 목록과 가깝다는 이유만으로 우승시키지 않는다. 검토에 사용하지 않은 영화/사용자 입력과 별도 콘텐츠 검토를 둔다.
추천과 같은 벡터로 계산한 새로움·유사도만으로 의미적 품질을 증명하지 않는다. 원본 키워드·줄거리 및 한국인에게 알려진 영화 사례를 가린 순서로 검토한다.
AI 검토는 설명 오류·명백한 불일치 검출용이다. 한국 이용자의 만족도 대체 정답으로 쓰지 않는다.

## 6. 발견 추천 경로와 비교안

2026-09-12 후속 사용자 교정: **덜 시청한 세부 그룹으로 선택 범위를 먼저 제한한 뒤, 그 안에서 사용자와 잘 맞는 그룹을 고른다.**
경로는 '시청 이력으로 덜 시청한 세부 그룹 선별 → 그 그룹들만 유효 사용자 벡터와 대표 벡터로 비교 → 유사도 상위 그룹 → 그룹 안 Q 순 미시청 후보 → 제한된 후보의 예상 별점 → 결과'다.
덜 시청함은 그룹 선택의 자격 조건이다. 유사도와 가중합해서 많이 본 그룹이 다시 들어오게 하지 않는다. 가장 덜 본 그룹부터 순서대로 고르는 정책도 아니다.
사용자 u의 적격 세부 그룹 집합 E_u는 '덜 시청함 조건 충족 AND 자격 있는 미시청 후보 존재'로 정의하고, E_u 안에서만 p_u·c_g로 순위를 매긴다.
덜 시청함의 횟수/비율 경계는 실행 명세에서 고정할 미정 항목이다. 상위8 맛의 시청량만으로 모든 하위 그룹을 일괄 제외하지 않는다.
시청 기록은 그룹 노출과 영화 제외에, 평가 기록은 선호 벡터 구성에 사용한다. 평가하지 않았다고 미시청으로 단정하지 않는다. MovieLens 시뮬레이션의 평점 이력은 관측 가능한 시청의 대리 자료라는 한계를 기록한다.
이미 본 영화와 명시적으로 싫어한 영역을 구분한다. 적게 보았다는 사실은 낯섦의 대리 지표이며 싫어한다는 뜻도 새롭다고 느낀다는 뜻도 아니다.
상위 8개 맛을 넘어야만 발견이라고 정의하지 않는다. 같은 맛의 다른 하위 영역에서도 발견이 가능하다.
하위 그룹 수를 늘리면 덜 본 그룹 비율이 기계적으로 커진다. 서로 다른 계층은 고정 상위 8맛 노출과 동일 원본 콘텐츠 특징의 노출/겹침을 공통 축으로 비교한다.
작은 하위 그룹이 많아서 얻은 미관람 그룹 비율 상승만으로 더 나은 발견이라고 판정하지 않는다. 활성 후보가 없는 고정 그룹 ID는 유지하고 검색에서 건너뛴다.

모든 대조는 같은 영화 자격·관람 제외·Q 순서·사용자 입력·예상 별점 모델·최종 편수를 사용한다.

| 대조 | 확인할 질문 |
| --- | --- |
| 전체 Q 선두 B개 → 동일 예상 별점 | 그룹 검색에 실제 이득이 있는가 |
| E_u 소속 미시청 영화 전수 콘텐츠 검색 상위 B개 → 동일 예상 별점 | 같은 발견 조건에서 그룹 대표가 놓치는 후보와 계산 절약은 무엇인가 |
| 덜 접한 그룹 중 무작위 선택 → 같은 Q/예산/예상 별점 | 그룹-사용자 벡터 비교가 기여하는가 |
| E_u 안에서 그룹 대표 검색 → 같은 Q/예산/예상 별점 | 제안 방식 |
| 모든 자격 영화의 동일 예상 별점 | 최종 후보 제한으로 발생하는 모델상 손실은 무엇인가 |

무작위 대조는 고정 seed 반복과 실제 평가 비용을 기록한다. 전수 경로는 느린 참조로서 비용이 같다고 주장하지 않는다.
그룹 대표 근사의 주대조는 동일 E_u 제약을 지킨 경로다. E_u를 적용하지 않은 전체 Q/전체 예상 별점 경로는 발견 제약의 비용을 확인하는 참고 대조이며 주대조와 구분한다.
대표 검색만의 손실을 분리할 때는 같은 E_u·관람 제외·후보 자격·그룹별 Q 정렬 prefix까지 맞춰 모든 그룹의 prefix를 직접 비교한다. Q prefix 제한도 푼 전수 비교와의 차이는 대표 검색과 후보 제한의 합산 손실이다.
B, 검색 그룹 수, 그룹별 한도는 별도 비용·공급 곡선으로 본다. 부족분을 인기 목록으로 대량 채워서 발견 공급이 좋아진 것처럼 집계하지 않는다.
그룹 후보가 부족하면 같은 E_u에서 유사도 순서상 다음 그룹으로 진행한다. 총 후보 계산 예산은 유지한다.
E_u를 모두 소진하면 적게 반환하거나 발견 후보 없음 상태를 기록한다. 전역 인기 영화로 채워 발견 결과에 섞지 않는다.
기존 연구의 전역 보충 결과는 과거 정책의 비교 기록으로만 보존한다. 개인화 벡터가 없을 때의 별도 비개인화 경로도 발견 개인화 성공으로 합산하지 않는다.

최종 예상 별점이 TMDb Q 정렬을 뒤집을 수 있다. 따라서 후보 목록 검사만으로 정렬 문제 해결을 선언하지 않는다.
기존 ALS 덮어쓰기 경로의 낮은 학습 지원 문제를 그대로 승계하지 않는다. 예상 별점 모델은 독립된 모델 선택 근거를 확인하고 모든 정책에 동일하게 고정한다.
Q와 예상 별점을 임의 가중합하지 않는다. 최종 낮은 지원 노출·예측 보정/오차·후보→Top1 상승 사례를 검토한 뒤 근거가 필요하면 별도 제한/수축 대안을 검토한다.
최종 순위 효과는 동일 후보에서 Q 순서 유지/기존 예상 별점/지원 보정 예상 별점을 별도 대조해 분리한다. Q/2를 개인 예상 별점으로 표시하지 않는다.

## 7. 판정과 검증 루프

현재 주판정은 MovieLens 정답 맞히기가 아니다. 다음 표를 병렬로 보며 서로의 증거를 대신 사용하지 않는다.

| 영역 | 비교/검사 | 통과해도 말할 수 없는 것 |
| --- | --- | --- |
| 고정성 | 추가·삭제·순서·배치·재로딩 후 같은 입력의 같은 ID/대표 | 영화 의미가 자연스럽게 8가지라는 주장 |
| 개인화 작동 | 사용자 교체·좋음/싫음 변경·프로필 shuffle·0벡터 예외 | 유사도 변화가 곧 만족도 증가라는 주장 |
| 대표 근사 | 전수 콘텐츠/동일 predictor 대비 후보 손실, 그룹/접두 목록 대표 차이 | 참조 모델의 선두가 실제 정답이라는 주장 |
| 발견 행동 | 덜 접한 영역 공급, 시청 특징과 겹침, 반복/시리즈 쏠림, 사용자별 차이 | 단순 희귀성·그룹 ID 차이가 체감 발견이라는 주장 |
| 품질 근거 | TMDb 지원별 Top1/최종 노출, Q·m 민감도, 후보 부족, ML 모델 지원 | 높은 보정 대중평점이 개인의 만족도라는 주장 |
| 비용 | 실제 후보 계산 수·p95·캐시 준비 비용·메모리 | 저장 예측을 잘라 얻은 시간이 실제 서빙 비용이라는 주장 |
| ML 참고 | 관측 평가의 예측 오차/순서·강한 부정 노출, 미래 양성 회수율·UNKNOWN 비율 | 미평가 영화 실패, 한국 사용자 만족도, 발견 성공률 |
| 사람/서비스 | 제안이 새롭고 관심 가는지, 선택·감상 후 도움 여부 | 클릭·찜만으로 감상 만족을 확정하는 주장 |

MovieLens 미래 평점은 참고 패널이며 그룹 수·대표·Q의 우승자를 단독으로 정하거나 필수 NDCG 비열등성 문턱으로 사용하지 않는다.
다만 예상 별점을 표시/이용하는 모델의 관측 오차와 근거 부족은 별도 모델 진단으로 남긴다. '발견이니까 어떤 예측 오류도 무시'하지 않는다.
현재 TMDb 스냅샷을 과거 MovieLens와 결합한 결과는 현재 카탈로그를 이용한 개발 시뮬레이션이다. 과거에 가능한 추천을 재현한 무누수 성능이라고 쓰지 않는다.
이미 반복 사용한 270명을 새 test라고 부르지 않는다. 신규 사용자 평가 자료가 없으면 추천 만족도는 미검증으로 남는다.

루프는 '설계 독립 검토 → 반례 수정 → 재검토 → 입력·코드·설정 봉인 → 실행 → 독립 계산/주장 검토 → 실패 원인 수정한 새 버전'이다.
새 버전에서는 이전 결과를 보았다는 사실을 기록한다. 같은 결과를 반복 열어보고 test라고 부르거나 유리한 지표만 남기지 않는다.
무한 탐색으로 만족도를 만들어 내지 않는다. 시작 전에 유한 비교안·수정 회차/자원 한도·근사 손실/지연 허용치를 별도 실행 명세로 고정한다.
이 문서에서 아직 수치가 없는 부분을 채택 기준이 완성되었다고 부르지 않는다. 코드 검토도 아직 수행한 것이 아니다.

최종 상태는 결함 발견이면 수정/기각, 기술 절충이 남으면 복수 후보 유지, 기술 조건을 충족하면 사용자 검토용 후보 선정이다.
실제 체감 가치가 없으면 '발견 추천이 더 좋다'는 결론은 보류한다. 실제 평가자 모집·설문·서비스 노출은 이번 로컬 문서 작업에 포함하지 않는다.

## 8. 이번 작업의 산출물과 다음 실행의 준비 조건

이번 작업은 문제 정의 교정과 독립 설계 검토다. 학습·전체 추천 실험·서비스 변경·외부 게시를 수행하지 않았다.
다음 실행 전에는 원본 TMDb 입력 상태, 검색 공간·사용자 가중치·유효 벡터 판정, C/m·UNKNOWN 정책,
하위 그룹/대표 비교 범위, B/검색수/한도, 동일 예상 별점 모델, 독립 표본 역할, 진단의 수치 허용치와 종료 조건을 실행 명세·코드와 함께 봉인해야 한다.
그 준비를 하지 않고 기존 NDCG 설정만 바꿔 재실행하는 것은 이 설계를 구현한 실험이 아니다.
