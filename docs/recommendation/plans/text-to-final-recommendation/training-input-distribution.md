# 다음 결합 실험에서 먼저 정할 학습 입력 분포

상태: DRAFT — 2026-09-10. 실제339 전처리 독립 검산에서 나온 후속 설계 메모.
이번339의 네 학습 조건이나 선정 규칙을 변경하지 않는다. 아래 입력 분포 검토는 성능 결과를 보기 전에 기록했다.
마지막 '결과 이후 추가 점검' 절은 실제 결과를 본 뒤 추가한 진단이며 앞선 사전 기록과 구분한다.

## 확인한 문제

339는 같은 180일 묶음 시작 전 이력만 입력으로 사용한다. 학습 목표4,997,069개 중
4,114,737개(82.34%)는 입력0이다. 입력이 있는 목표는882,332개이며, 기여 사용자는8,245명이다.
평가H10 사용자270명 중 입력0은84명이다. 주 지표의 관측후보2편 이상 기준에서는84/260명이다.

학습 목표 행과 평가 사용자 수는 분모가 다르다. 이 비율의 차이만으로 손실 가중치를 역산하지 않는다.
MovieLens 개발 사용자의 입력분포를 현재 서비스의 실제 입력분포라고 부르지 않는다.

## 340 설계에서 선택할 두 방법

| 방법 | 무엇이 달라지는가 | 비용·한계 |
|---|---|---|
| 목표마다 바로 이전 이력을 구성한다. | 목표 시점 직전의 허용된 이력을 입력으로 사용한다. 같은 timestamp 평점끼리는 입력으로 쓰지 않는다. | 목표를 유지하고 인위적인 입력0을 줄일 수 있지만 전처리 비용이 커진다. |
| 현재 입력 구성에서 사용자·입력 편수별 고정 표본을 만든다. | 목표 개수·층·예산을 먼저 정하고 ID·timestamp·고정 해시로 선택한다. | 현재 FM 구현을 유지하기 쉽지만 일부 목표가 제외되고 180일 묶음의 한계가 남는다. |

한 달 일정에서는 두 번째 방법의 구현 부담이 작다. 아직 채택한 것은 아니다.
사용자당 또는 추천 요청당 무엇을 동일하게 평가할지, 목표 입력분포가 어떤 연구 목적을 갖는지
설계에서 먼저 선언한다. 별점 크기·텍스트 유무·모델 오차로 표본을 고르지 않는다.
모든 비교 조건은 같은 표본을 사용하고, 새 결과를 본 뒤 비율이나seed를 바꾸지 않는다.
목표를 제외했다고 허용된 과거 입력까지 지우지는 않는다.

## Spark FM의 가중치 주의점

현재 실행 이미지의 Spark4.1.3 Python 부모 파라미터에는 `HasWeightCol`이 있지만
`FMRegressor` 생성자와 `setParams`에는 `weightCol` 인수가 없다.
더구나 실제 JVM 학습 경로는 label과features 두 열을 `(label, vector)`로 넘긴다.
따라서 **weightCol 설정 한 줄로 현재 FM의 가중 손실을 적용할 수 있다고 전제하지 않는다.**
필요하다면 별도 구현·수치 검증이 선행되어야 한다. 339 worker에는 가중치가 적용되지 않았다.

## 이번 결과에서 이어 받을 것

텍스트 정제·임베딩·출처 검산은 재사용할 수 있다. 사전 규칙으로 선택한 표현은 후속 고정 후보가 된다.
다만339의 성능은 현재 학습 분포에서 얻은 개발 결과다. 다른 입력분포에서도 우수하거나
개인 반응 자체가 개선됐다고 그대로 일반화하지 않는다.

입력 없는 사용자 추천에서는 이 투표 조건의 영화 노출이0개였다.
[실제 결과와 검산](../../experiments/text339/README.md)에 범위와 근거를 기록했다.

투표 수가 특징에 들어 있다는 사실만으로 신뢰도가 반영됐다고 전제하지 않는다.
예를 들어 평균을 근거량에 따라 수축하는 표현이나 근거량별 반응 표현은 비교 후보가 될 수 있지만,
아직 방식·강도·대조 조건을 채택하지 않았다. 비교 조건·분모·개선 기준을 독립 검토한 후 실행한다.
기존340 예산을 자동으로 늘리거나 희귀 영화에 임의의 최소 투표 수 필터를 추가하지 않는다.
입력0 학습 비중이나 특정 특징이 이 현상을 일으켰다는 인과적 결론도 내리지 않는다.
