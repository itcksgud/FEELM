# 줄거리 실험부터 최종 추천안까지

상태: DRAFT — 2026-09-10 사용자 요청에 따른 연구·Jira 범위안. 서비스 계약 변경이나 모델 채택이 아니다.

**텍스트가 도움이 되는지 → 어떤 정보 조합을 쓸지 → 실제 추천 목록을 어떻게 구성할지** 순서로 결정한다.
자료 수집은 끝났다. 이제 수집한 자료를 이용해 판단을 내리는 세 업무로 묶는다.

| 순서 | Jira 업무 범위 | 비교할 것 | 끝나면 답할 수 있는 질문 |
|---|---|---|---|
| 1 | 줄거리·Wikipedia 정제와 텍스트 추가 효과 | 기존 정보 / TMDB 줄거리 추가 / Wiki 추가 / 의미를 보존한 정제 | 줄거리가 도움이 되는가? Wiki를 더 넣을 가치가 있는가? 정제는 무엇을 바꾸는가? |
| 2 | 개인 반응·콘텐츠 결합과 ALS 보조 효과 | 1단계 표현을 고정하고 텍스트·대중성 반응·근거량 보정을 빼 보며 비교 | 어떤 조합을 남길 것인가? 개인화를 하는가? ALS가 있을 때 추가 이득이 있는가? |
| 3 | 취향 맞춤·발견 추천과 최종안 | 같은 모델 점수에서 맞춤 정렬 / 연결된 새로움 / 선호 손실을 제한한 발견 | 앞의 몇 편이 좋은가? 발견이 너무 싫을 영화를 늘리지는 않는가? 후보가 부족하면 어떻게 하는가? |

각 업무에 설계·독립 검토·실행·결과 재검산·비교표/그림·채택 또는 보류 결론을 포함한다.
현재 요청으로 Jira에 진행 범위를 등록한다. 실험 결과의 GitLab 인계는 결론을 정리한 뒤 한다.
이번 설계 작업에서 새 모델 학습이나 운영 코드를 실행하지 않는다.

## 숫자는 세 가지다

- **입력 H**: 사용자가 알려준 영화 수. 0·1·5·10·30편 조건으로 보고, 실제로 제공한 편수도 표시한다.
- **Top N**: 추천 목록에서 앞의 몇 편을 채점하는지. **2·4·6을 함께 보고 10은 기존 비교용**으로 남긴다.
- **서비스 세트**: 현재 팀 계약은 **맞춤 2편 + 발견 1편**, 발견 후보가 없으면 맞춤 3편이다.
  그래서 맞춤 2/4/6편, 발견 1/2/3편, 전체 3/6/9편의 누적 세트도 별도로 확인한다.

Top N을 여러 개 본다고 모델을 N마다 다시 학습하지 않는다. 같은 예측과 목록의 앞부분을 잘라 채점한다.
ALS 후보 500, 중간 순위 100, 버퍼 20은 또 다른 값이며 이번 실험의 정답 개수나 새 확정값이 아니다.

## 무엇을 점수로 믿을 것인가

| 평가 | 볼 수 있는 것 | 해석 범위 |
|---|---|---|
| 나중에 실제 별점을 남긴 영화끼리 비교 | 앞쪽 실제 별점, 선호 순서, 좋은/낮은 별점 비율 | MovieLens 관측 영화 안의 순위 품질 |
| 전체 카탈로그에서 추천을 생성 | 추천 가능 편수, 미평가 비율, 중복, 새로움, 후보 누락, 처리 시간 | 목록 공급과 동작 품질. 별점 없는 추천의 만족도는 모름 |
| 소규모 현재 사용자 확인 | 이미 아는지, 보고 싶은지, 불편한 추천인지 | 가능하면 확인할 현재 한국 사용자 신호. 감상 후 만족도와는 구분 |

미평가 영화는 싫어요로 바꾸지 않는다. **새롭기만 한 영화와 좋아할 만한 발견도 구분한다.**
선호 품질이 나빠지거나 근거가 부족하면 복잡한 조합·발견 정책을 채택하지 않는 결론도 허용한다.

## 복잡해지지 않게 멈추는 기준

1. 한 모델로 텍스트 차이를 먼저 확인한다. 처음부터 모든 모델·텍스트·정제·정책을 교차하지 않는다.
2. 1단계에서 표현 하나, 2단계에서 최종 후보 하나와 기준선 하나를 고정한다. 지표별 승자 목록을 만들지 않는다.
3. 3단계는 모델을 계속 바꾸는 실험이 아니라 추천 구성과 손실을 확인하는 실험이다.
4. 이미 본 정답은 개발용이다. 최종 확인 자료를 따로 검증하고, 결과가 약해도 정답·seed를 바꿔 재시도하지 않는다.
5. 최종 결과는 추천 모델·사용 정보·ALS 사용 조건·맞춤/발견 정책·fallback·비용·검증하지 못한 범위를 한 장으로 정리한다.

현재 팀 문서에는 K-Means 8군집이 남아 있다. 이번 사용자 지시에 따라 관계·모델 분석에는 강제하지 않는다.
마지막 정책 연구의 결과가 공식 계약과 다르면 **변경 제안**으로 표시하고, 자동으로 API·Redis·팝콘 정책을 바꾸지 않는다.
