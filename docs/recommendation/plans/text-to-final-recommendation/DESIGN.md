# 텍스트·요인 결합·추천 정책의 단계별 비교 설계

상태: DRAFT — 실행 전 독립 검토 대상. Jira 업무 범위 설계이며 운영 계약·실험 결과가 아니다.

## 1. 기준과 현재 근거

- 사용자 2026-09-10 요청: 줄거리/Wiki, 정제, 유효 정보 결합을 비교하고 Top2/4/6 및 맞춤·발견까지 평가한 최종안에 도달한다. Jira로 업무 범위를 등록한다.
- 공식 문서 확인 기준: 팀 `origin/develop` 44b591f. FR-10/12/19, API-045/046, ADR-0015/0017, streaming-contract.
- 공식 노출은 TASTE2+DISCOVERY1, 발견 부족시 TASTE3, 입력 불변시 같은 결과, 감상·관심없음 제외다. 새로움/저이력 판정식은 미정이다.
- K-Means8은 팀의 현재 계약이지만 관계 분석에 강제하지 않는다는 최신 사용자 지시를 따른다. 연구와 계약 변경 제안을 분리한다.
- 337/338에 공유한 REC046/047/cold 결과는 개발 근거다. FM 대중성 반응 개선은 제한된 표본의 조건부 결과이며 FM 우승·ALS 동급·현재 한국 성능의 확정이 아니다.
- Wikipedia 85,517편 조회, 정제본문 51,353편 확보. [결과](../../../research/wikipedia-collection/RESULT.md), [품질 한계](../../../research/wikipedia-collection/QUALITY.md), [수집 감사](../../../research/wikipedia-collection/result-review.json)를 입력으로 사용한다. 수집 업무를 다시 만드는 것이 아니다.

## 3. A에서 먼저 통과해야 할 공통 평가 계약

현재 단계에서 아직 정해지지 않은 실제 cohort ID·파일 경로·분할 날짜·embedding revision·예산은 A의 실행 명세에서 **결과를 보기 전에** 고정하고 독립 검토한다. 아래 기준 없이 B/C로 진행하지 않는다.

### 사람·영화·시점

1. REC046/047/cold 및 이전 연구의 사용자 역할/예측/정답 사용 이력을 모은다. 개인 단위 최종 확인 자료는 과거 공동학습·튜닝·평가에 사용하지 않은 cohort임을 먼저 검증한다. 확인할 수 없으면 미개방 test라고 부르지 않고 개발 결과로 제한한다.
2. 동일한 train 사용자, 허용 과거 시점, 평가 사용자 사전 입력, 후보 영화 ID와 미래 관측 목록을 모든 비교에 사용한다. 평가 사용자는 공동학습에서 제외하고 사전 입력의 프로필 계산만 허용한다.
3. 기존 개발 관측은 표현/조합/정책 선택에 사용할 수 있으나 최종 확인으로 다시 세지 않는다. 최종 예측·선택 명세를 봉인한 뒤 정답을 한 번 연다. 이후 변경은 새 연구이며 같은 test로 재선정하지 않는다.
4. 영화 지원량은 학습 사용자·허용 과거 평점만으로 계산한다. 0 / 1–9 / 10–49 / 50+를 분리한다. 최신 TMDB 투표수와 혼동하지 않는다.
5. ID 기반으로 사전 고정한 영화 보류 집합 C의 모든 평점을 콘텐츠/실사용 ALS 학습의 목표·사용자 이력·집계에서 먼저 제거한다. 미래 관측 J(u) 전체를 차단하는 것이 아니다. J(u)에는 W(보류하지 않은 지원 영화)·C(인위 차단)·본래 지원0을 함께 유지하고, C의 콘텐츠 검증과 W의 ALS/콘텐츠/혼합 비교를 따로 낸다. 평가자의 사전 입력은 모든 모델에 동일하게 제공하고, 입력 중 ALS 미지원 편수도 보고한다. 참고 ALS만 다른 학습 사용자의 C 영화 과거 평점을 유지할 수 있으며 정보 우위 참고선으로 별도 표시한다.
6. 본래 지원0인 영화와 인위적으로 평점을 가린 영화, 현재 서비스 전용 영화는 각각 표시한다. 실제 서비스 전용 영화에 MovieLens 정답이 생기는 것은 아니다.
7. 기준 시점에 아직 개봉하지 않은 영화는 오프라인 관측 후보에서 제외한다. 현재 카탈로그 진단은 현재 개봉/이용 가능 조건으로 따로 만든다. 2026 TMDB/Wiki는 두 경우 모두 최신 스냅샷이므로 과거 as-of 재현이라고 주장하지 않는다.

### 입력과 표본

- 입력 상한 H=0/1/5/10/30, 그 시점까지 실제 있는 최근 min(H, 과거 편수)개를 제공한다. 부족한 사람을 자동 제외하지 않는다. 상한과 실제 입력 h를 둘 다 기록한다. H0은 개인화 효과 근거로 쓰지 않는다.
- 주 비교 입력 상한은 H10으로 고정한다(과거 실험과 연결하기 위한 연구 기준이며 최적 입력량이 아니다). H1/5/30 및 실제 h별은 보조 분석이다. K30 보유자만 뽑아 저이력 사용자를 대체하지 않는다.
- 과거 활동량 0 / 1–9 / 10–29 / 30–99 / 100+ 및 영화 지원량, 개봉연대, Wiki 유무/언어별 분모를 공개한다. 전체 자연분포 사용자 평균과 집단별 수치를 함께 낸다. 균등 가중표는 진단이며 한국 서비스 인구 비중으로 가정하지 않는다.
- A는 별점 값 없이 각 N의 후보수·유효 사용자 수를 확인한다. 표본이 적다는 이유로 좋은 점수가 나올 seed/영화 분할을 탐색하지 않는다. 유효 30명 미만 셀은 기술통계로 끝내며, 30명도 검정력 보장은 아니다.

### 세 가지 평가 판

**관측 후보 품질**: 사용자별 정해진 미래 기간에 실제 평가한 영화 집합 J(u) 안에서 모든 모델을 같은 후보로 정렬한다. 임의의 미평가 음성 샘플을 추가하지 않는다. 미래 관측 존재로 만든 조건부 평가이며 서비스 전체 검색 성능은 아니다.

**전체 카탈로그 목록**: 사전 입력/감상·관심없음 등 확인 가능한 제외 조건만 적용한 공통 영화 목록을 직접 점수화한다. 연구에만 알려진 미래 별점/관측 여부로 후보를 필터링하지 않는다. 서비스 감상·관심없음 로그가 없으면 임의 생성하지 않고 해당 규칙은 합성 검사로 확인한다. 평가 모델을 ALS 후보500으로 제한하지 않는다. 기존 500의 공급 한계는 별도 진단이다.

**현재 사용자 확인**: 가능하면 소규모 자발적 참여자가 동의한 실제 입력으로 모델/순서를 숨기고 목록을 비교한다. '이미 아는가·보고 싶은가·연결되면서 새로운가·불편한가'를 분리한다. 보지 않은 영화의 시청 의도를 감상 별점으로 저장하지 않는다. 모집/실제 사용자 연구는 사용자와 일정·질문을 합의한 뒤 진행하며 대규모 신규자료 확보를 완료 조건으로 두지 않는다. 없으면 현재 한국 만족도는 미검증으로 남긴다.

## 4. 채점 기준

| 축 | 기본 지표 | 규칙 |
|---|---|---|
| 앞쪽 선호 순서 | 관측후보 NDCG@2/4/6, @10 보조 | gain=(실제 별점−0.5)/4.5, log2 할인. IDCG=0이면 결측·인원 보고. 주 지표는 H10의 NDCG@2 |
| 직관적인 만족도 | 평균 실제 별점@N, Hit@N·Precision@N·Recall@N | 좋음≥4.0을 연구 기준으로 사전 고정. 모두 관측후보 조건부이며 전 카탈로그 만족도로 부르지 않음 |
| 피해야 할 추천 | 낮은 별점 비율@N, 1개 이상 낮은 별점인 목록 비율 | 낮음≤2.0. 실제 0.5 단위 별점 유지. 미평가는 분모에 넣지 않음 |
| 전반적인 예측 | 사용자 평균 MSE·MAE, 다른 별점 쌍의 순서 정확도 | 모든 동일 관측에서 계산. ALS와 점수/순서 일치는 참고 지표이며 정답 지표 아님 |
| 공급·편향 | 반환 길이, 후보 부족·fallback·UNKNOWN 비율, 영화 커버리지·집중도 | 전체 카탈로그 생성 결과에서 계산. 관측0 추천도 삭제하지 않음 |
| 비용 | 학습/특징 생성 시간, 최대 메모리, 1사용자 전체 점수·TopN p50/p95 | 같은 하드웨어·batch·warm/cold 조건을 기록. NFR 응답 SLO를 임의 확정하지 않음 |

- N마다 |J(u)|≥N인 모든 사용자의 표와, |J(u)|≥6인 공통 사용자 표를 함께 낸다. 공통6 집단은 고활동 편향이 있다. 후보 부족/0정답/동점 인원은 숨기지 않는다. Recall 분모에 좋은 관측0이면 결측으로 보고한다.
- 주 비교는 같은 사용자의 짝 차이, 사용자 단위 bootstrap을 사용한다. 같은 영화에 대한 반복 관측의 의존성은 영화별 민감도 표로 확인하고 사용자 CI가 새 영화 모집단까지 보장한다고 표현하지 않는다.
- A의 주 family는 3개 인접 텍스트 비교의 H10 NDCG@2. B의 주 family는 사전 제거 비교와 최종 점수 비교의 H10 NDCG@2다. 각 family는 Holm 0.05 또는 동등한 동시 구간 방법을 실행 명세에서 하나로 고정한다. N/H/집단별 보조 점수로 승자를 바꾸지 않는다.
- 텍스트/조합은 주 지표 개선과 저선호 손실을 함께 보고, 개선 불확실하면 단순 기준선을 유지한다. 정확한 효과 크기·구간을 표기하며 비유의=동급이라고 쓰지 않는다.
- 전체 카탈로그 TopN은 별점 확인된 수/N을 **채점 가능 비율**로 반드시 함께 표시한다. 확인된 항목만의 평균은 관측 조건부로만 낸다. 관측된 좋음/N과 (관측된 좋음+UNKNOWN)/N은 전체 만족도의 느슨한 가능 범위이며 신뢰구간이 아니다. 범위가 겹치면 순위를 확정하지 않는다.
- 노출 확률 로그가 없으므로 임의 propensity 가중치를 만들어 MNAR 편향을 해결했다고 주장하지 않는다. 현재 데이터의 상관적 예측 기여만 확인한다.

## 5. A — 텍스트·정제 비교

공통 안전 정리는 모든 텍스트 조건에 적용한다. 다른 작품/시리즈 범위, 불일치 QID, 줄거리 밖 평점·흥행·비평 섹션은 모델 입력에서 격리한다. 기존 수집 v3 원본/feature_ready는 변경하지 않고 별도 사용 명세와 가공 산출물을 만든다.

| 조건 | 추가 정보 |
|---|---|
| T0 | 기존 구조화 정보·개인 반응(CROWD_RESPONSE), 텍스트 없음 |
| T1 | T0 + TMDB overview |
| T2 | T1 + Wiki 줄거리, 수집 v3의 템플릿 제거 방식 |
| T3 | T1 + Wiki 줄거리, 의미를 보존하도록 검토한 정제 방식 |

- FM을 표현 비교용 기준으로 고정한다. 우승 모델로 채택했다는 뜻은 아니다. GBT/ALS/리지/임베딩 모델을 모두 교차 비교하지 않는다.
- T3은 확인한 Quote류 서술 보존·마크업/중복 문장 정리 등 규칙 기반으로 제한한다. 자동 요약/새 사실 생성, 전체 Wikipedia 재수집, 무제한 transclusion 확장은 포함하지 않는다. 의미 손실이 없는지 별점과 독립인 고정 표본(언어·길이·템플릿·연결방식)을 원문과 비교한다. 위험 사례는 격리한다.
- 기본 임베딩은 팀의 multilingual-e5-base 한 체크포인트로 제한하고 revision/tokenizer/prefix/pooling/정규화/청크 길이·중첩·청크 결합을 A의 실행 명세에 고정한다. 긴 줄거리를 처음512토큰으로만 잘라 '결말 활용'이라고 부르지 않는다. 청크화와 문서별 가중 평균은 모든 텍스트 조건에서 같은 규칙을 쓴다. A 실행 전 고정표본의 시간·메모리로 자원 예산을 확인한다.
- overview와 Wiki는 따로 인코딩하고 별도 특징 블록으로 결합한다. Wiki의 T2/T3는 정제 전에 비어 있지 않은 원문 줄거리 절이 있는 ko를 우선하고 없으면 en을 선택해, 영화별 QID·언어·page_id·revision_id·원문 해시를 동일하게 고정한다. 정제 후 빈 상태라고 비교 중 다른 언어를 다시 선택하지 않는다. 동일 원문 쌍의 정제 효과와 T3의 본문 복원 집단을 분리한다. 실사용 언어 fallback 전환을 별도 진단하면 전환 집단으로 따로 보고하며 주 정제 효과에 합치지 않는다. 영어/한국어·둘 다 존재하는 집단 결과를 별도 공개하고 번역을 새 실험 축으로 만들지 않는다.
- 텍스트의 후보 벡터와 입력 영화 벡터의 유사도, 그 유사도에 대한 별점 반응·근거편수를 같은 공식으로 사용한다. 평점 이력이 없는 새 영화도 자기 텍스트와 사용자 입력으로 계산한다. 차원축소·정규화·학습 어휘를 쓰면 train 역할만으로 fit한다. E5 사전학습 내용을 MovieLens로 사전학습했다고 표현하지 않는다.
- Wiki가 없는 영화도 공통 모집단에 남긴다. Wiki 블록은 결측표시와 0으로 두고 TMDB/구조화 정보로 예측한다. 전체 적용 효과와 같은 Wiki가 있는 영화 집합의 추가효과, T2/T3 둘 다 본문이 있는 집합의 정제효과를 구분한다. T3이 본문을 복원한 효과와 동일본문 정리효과도 따로 표시한다.
- 한 표현을 선택하거나 T0/T1을 유지한다. 텍스트가 유용하지 않으면 B에서 억지로 넣지 않는다.

## 6. B — 유효 요인 결합과 ALS 역할

- A의 표현을 고정하고 동일 FM에서 **완성 조합 / 텍스트 제거 / 대중성의 개인 반응 제거 / 근거량·수축 제거** 최대4조건을 비교한다. 없는 블록은 비교하지 않는다. 대중성 반응 제거 시 후보의 TMDB 대중 지표는 유지해 개인 반응의 조건부 기여를 구분한다. 수축 제거는 원래 미보정 반응으로 되돌리며 관련 추가 근거량 열도 제거한다.
- 장르·키워드·국가/언어·감독·배우 등 기본 블록의 기존 근거를 유지한다. 모든 조합을 탐색하지 않는다. 제거 비교는 해당 조합 안의 기여이며 인과적 영향력 순위가 아니다.
- GBT는 고정 기본 표현과 FM에서 선택한 조합의 2조건만 교차 확인한다. 리지는 기존 단순 기준 근거로 남기되 같은 새 자료의 점수가 없으면 수치 우열표에 끼워 넣지 않는다. 기존5종 실험·학습량곡선을 반복하지 않는다.
- 선택한 콘텐츠 모델에서 사용자 반응 프로필을 끈 대조를 한 번 계산한다(영화 정보·입력 편수·본인 평균 별점은 유지). 이 대조는 학습분포 밖 입력 가능성이 있는 개인화 민감도 진단이며 인과적 입증이 아니다.
- ALS 직접 점수 존재 구간에서 **ALS 단독 / 콘텐츠 단독 / 결합**을 같은 영화·사용자에서 비교한다. 점수 결합은 dev에서만 보정하고 가중치 후보를 0/0.25/0.5/0.75/1로 제한한다. 양끝이 단독이다. 최종 정답으로 보정하지 않는다.
- ALS 직접 점수가 없는 곳에서는 콘텐츠로 처리하고 그 fallback 비율을 공개한다. 전체 혼합 점수 개선을 미지원 영화에서 ALS가 기여한 증거로 쓰지 않는다. 실제 ALS(영화차단 적용)와 목표 이력을 아는 참고 ALS를 다른 이름·산출물로 구분한다.
- 선정표는 같은 새 자료에서 실제 학습한 기준선과 비교한다. 표현/조합 후보1개와 기준선1개를 C로 넘긴다. 근거가 약하면 기준선 유지가 최종 후보가 될 수 있다.

## 7. C — 맞춤·발견과 최종 확인

모델·표현·기본 점수와 후보 모집단을 고정한다. 영화유형을 8개로 나누거나 단일 장르로 강제하지 않는다. 다음은 **실험 정책 후보**이며 공식 새로운 맛 판정을 대신 확정하는 것이 아니다.

| 정책 | 역할 |
|---|---|
| P0 맞춤 순위 | 예상 선호 점수순. 발견 교체가 없는 기준선 |
| P1 연결된 새로움 | 맞춤2편은 고정하고, 입력 취향과 최소 연결을 가진 후보 중 상대적으로 덜 익숙한 후보를 발견 슬롯에 배치 |
| P2 선호 손실 제한 발견 | P1 후보 중 예상 선호가 맞춤 대체 후보보다 크게 낮지 않은 후보만 허용. 없으면 맞춤으로 채움 |

- 낯섦은 장르 분포 또는 고정 콘텐츠 유사도와 사전 입력의 거리로 정의한다. 한 정의·연결 하한·새로움 기준·예상 선호 제한과 동률 규칙을 dev에서만 고정한다. 배우/감독/국가/텍스트마다 별도 정책행렬을 만들지 않는다. 배우가 같거나 희귀하다는 사실 자체를 좋은 발견 정답으로 삼지 않는다.
- 정책 튜닝 후보는 dev에서 최대6개 설정 조합으로 제한한다. 구체 숫자/정규화는 실행 전 동결한다. 지표를 본 뒤 그리드를 늘리지 않는다.
- 발견 평가는 새로움·연결 정도, 관측후보의 낮은 별점 비율과 평균 별점, 좋음≥4이면서 새로움 조건을 만족한 관측 비율을 함께 본다. 이는 '발견 proxy'이고 실제 감상·평가로 성립하는 FR-32 발견 성공과 다르다.
- 연구용 보수적 판정 기준: P2가 P0 대비 새로움을 늘리면서, 관측후보 누적 세트의 평균 별점 손실≤0.1점 및 낮은 별점 비율 증가≤3%p를 만족하는지 **짝 차이의 보정 구간**으로 확인한다. 이는 사업적으로 승인된 허용 손실이 아니며 A 실행 명세 검토에서 사전 고정할 제안값이다. 효과를 본 뒤 바꾸지 않는다. 구간이 넓어 입증 못하면 '안전함'이라고 말하지 않는다.
- 주 정책 확인은 H10 첫3편 세트와 첫 발견1편이다. P1/P2 대비 P0의 새로움·평균 별점·저선호 손실을 한 family로 보정한다. 위0.1점/3%p는 실제3편 세트 비교에 적용하고 발견 슬롯의 별도 손실도 공개한다. 6/9편은 보조로 보고 주판정을 바꾸지 않는다.
- P0의 세 번째 맞춤 영화가 P1/P2의 첫 발견 슬롯 대체 기준이다. 첫3편 비교는 동일 |J(u)|≥3 사용자에서 수행한다. fallback을 포함한 전체 세트의 짝 비교를 주 분석으로 두고, 실제 발견이 발생한 사용자만의 조건부 표는 별도 보고한다. 발견 슬롯이 없다는 이유로 P0를 분모에서 빼지 않는다.
- 기본 순위 Top2/4/6/10, 누적 맞춤2/4/6, 발견1/2/3, 전체3/6/9를 각각 표시한다. 전체 세트를 하나의 점수순 목록이라고 가정하지 않는다. fallback 슬롯은 TASTE로 따로 세어 발견 성공률을 부풀리지 않는다.
- 관측후보에서는 같은 미래 관측 풀 안에서 비교하며 정책조건과 좋은 관측을 함께 만족하는 후보가 원래 있었는지도 점수 봉인 후 집계한다. 후보없음과 후보는 있는데 못 고른 경우를 분리한다. 서비스 카탈로그에는 미평가가 많아 같은 정답 존재 판정을 할 수 없다.
- 전체 카탈로그에서도 같은 정책을 실행해 유효후보→최종슬롯별 공급, 중복·이미감상 제외, 발견부족·맞춤fallback·미충족길이, ALS미지원 노출률과 비용을 확인한다. 모든 미래 관측 후보만으로 생성한 목록을 실서비스 목록으로 보여주지 않는다.
- 마지막에 선택된 기준선/후보·정책을 고정하고 미개방 cohort의 최종 점수를 한 번 산출한다. P0/P1/P2 비교 이외에 최종 점수를 보고 새 후보를 추가하지 않는다. 모델·정책 불확실하면 P0 중심의 보수적 연구 권고와 미검증 범위를 남긴다.
- 최종 확인은 개발 A/B의 보정과 별개다. H10에서 선정 모델 대 기준선의 P0 관측후보 NDCG@2 1개와, 선정 모델의 P1/P2 대 P0의 새로움·평균 별점·저선호 손실 6개를 합한 7개 대조를 주 family로 동결한다. 전체 대조표·alpha·짝 차이/동시 구간 방법을 최종 개방 전에 독립 검토한다. 앞 단계의 개발 결과를 최종 모델 확인으로 대신하지 않는다.
- 최종표: 사용정보·정제·모델·ALS지원/미지원 처리·입력부족 fallback·맞춤/발견 조건·Top2/4/6 및3편세트 품질·비용·한계·팀 계약 변경 제안. 실제 2026 한국 품질은 관측 여부에 따라 미검증으로 분리한다.

## 8. 제한과 정지 조건

- 개발 텍스트 FM≤4fit, 조합 FM≤4fit+GBT≤2fit, 최종 콘텐츠 기준/후보≤2fit. ALS는 역할/시점 일치 검증을 통과할 때만 재사용하며 필요시 dev/final의 실제/참고 최대4fit. 총 상한16fit이며 오류수정 재실행은 별도 기록한다. 전교차나 추가 하이퍼파라미터 탐색은 포함하지 않는다.
- 임베딩은 고정 원문해시별 캐시를 재사용한다. H/N/정책 변화는 원칙적으로 재학습 없이 고정 모델로 예측/재정렬한다. Spark 데스크탑 local[4]에서 모델 하나씩 실행한다. local 실행을 여러 서버 분산 성능 검증이라고 부르지 않는다.
- 기존12GiB 컨테이너·8GiB JVM 기준으로 고정표본 측정 후 실제 예산을 봉인한다. 초과시 축소 재학습을 자동 수행하지 않고 실행 가능성 실패와 설계 수정으로 기록한다. 데이터/후보 축소가 필요하면 정답을 보기 전에 수정·재검토한다.
- 역할·시점 누수, 예측/후보 ID 불일치, 결과파일 변경, 의미범위 격리 실패, 비교별 다른 제외는 즉시 중단한다. 표본 부족·넓은 구간·새 정보 무효는 정상적인 보류 결론이다.
- 최종 cohort의 미개방을 증명할 수 없으면 추가 모델 탐색을 늘리지 않는다. 개발 권고+검증 한계로 마무리하고 현재 한국 품질 보증을 주장하지 않는다.
