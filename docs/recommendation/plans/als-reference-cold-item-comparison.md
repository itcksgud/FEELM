# 평가 이력을 아는 ALS와, 그 이력을 가린 콘텐츠 모델 비교

2026-09-09 · 로컬 설계 초안. 새 학습·채점은 아직 하지 않았다. 실행 코드와 데이터 명세 검토가 남아 있다.

## 무엇을 알아보는가

**같은 영화의 다른 사람 평점을 아는 ALS를 참고선으로 두고, 그 영화의 학습 평점을 전혀 보지 않은 FM·공유 리지·GBT가 얼마나 접근하는지 확인한다.**

예를 들어 영화 A의 과거 평점을 ALS에게는 주고, 콘텐츠 모델에게는 전부 가린다. 처음 보는 평가 사용자가 다른 영화에 입력한 동일한 별점을 각 모델에 준 뒤, 영화 A의 예상 별점을 비교한다. 마지막에는 그 사용자가 나중에 실제로 남긴 A의 별점과도 비교한다.

| 구분 | 참고 ALS | FM·공유 리지·Spark GBT 각각 |
| --- | --- | --- |
| A에 대한 다른 학습 사용자의 과거 평점 | 학습에 사용 | 모든 학습 경로에서 제거 |
| A의 TMDB 영화 정보 | ALS 요인 학습에는 미사용 | 예측에 사용 가능 |
| 나머지 영화의 허용 과거 평점 | 사용 | 사용 |
| 평가 사용자의 입력 별점 | 동일한 사전 입력으로 fold-in | 동일한 사전 입력으로 취향 특징 계산 |
| 평가 사용자의 미래 정답 별점 | 학습·입력에 사용 금지 | 학습·입력에 사용 금지 |

이는 **정보가 더 많은 ALS와의 격차**를 보는 비교다. 같은 정보를 준 알고리즘 순위표가 아니며, ALS도 틀릴 수 있다. 콘텐츠 모델은 남은 실제 별점을 학습한다. ALS 출력을 학습 정답으로 주는 증류나 ALS+FM 혼합은 이번 비교에 넣지 않는다.

## 데이터를 나누는 방법

1. **사용자와 시간:** REC047의 학습·검증·평가 사용자 역할을 유지한다. 평가 사용자는 ALS의 공동 학습에도 넣지 않는다. 검증 기준 시점은 2022-07-05, 평가 기준 시점은 2023-01-01이며, 각 기준 시점 이전 학습 사용자 평점만 학습에 쓴다. 각 시점 이후 180일의 실제 관측 별점이 검증/평가 대상이다.
2. **영화:** 검증 시점 이전 학습 평점이 있고 TMDB 특징을 사용할 수 있는 영화를 canonical TMDB ID로 묶는다. 학습 평점 수 1–9 / 10–49 / 50+ 층 안에서 seed 47의 고정 영화 분할로 콘텐츠 학습 80% / 검증 보류 10% / 평가 보류 10%를 배정하는 초안이다. 이 비율은 학습용 영화를 대부분 남기면서 서로 다른 두 보류 집합을 확보하기 위한 실험 설정이며 서비스 정책이 아니다. 실제 ID 목록·해시 규칙·반올림 규칙·집단별 인원은 실행 전 명세에 고정한다. 미래 별점이나 모델 점수를 보고 영화를 선택하거나 seed를 다시 고르지 않는다.
3. **콘텐츠의 영화 보류:** 검증·평가 보류 영화 모두를 양 학습 단계에서 제외한다. 그 영화의 평점은 목표 행뿐 아니라 학습 사용자의 입력 이력, 별점 가중 취향 특징, 평균·prior·정규화 통계에서도 제거한다. **기존 특징 테이블에서 목표 행만 지우면 안 된다.** 원래 허용 이력에서 영화 차단 후 학습 예제와 특징을 다시 만든다. 같은 작품의 별칭 ID도 함께 차단한다. 배우·장르가 겹치는 다른 작품은 남긴다.
4. **TMDB 특징:** 보류 영화도 메타데이터로 표현할 수 있다. 평점 기반 통계는 앞 항목처럼 차단한다. REC047의 기본 표현은 메타데이터 전체의 실제 ID 연결표로 교집합을 계산하며, 학습 빈도로 특징 사전을 고르거나 미등록 ID를 하나의 OOV로 합치지 않는다. 새로 학습하는 인코더·정규화기를 추가할 때만 허용 학습 자료에 맞추는 규칙을 별도 고정한다. 현재 168개 특징을 기준 표현으로 두고, 아래 사용자 요청에 따른 대중성 등 확장 여부를 실행 전 특징 명세에서 검토한다. 아직 추가 특징을 구현하거나 학습하지 않았다.
5. **평가 입력:** 첫 비교에서는 보류 영화 밖에서, 해당 학습 시점에 평점 지원이 있는 영화의 사용자 사전 별점으로만 입력을 구성한다. 최근 K편을 같은 규칙으로 뽑아 모든 모델에 동일하게 준다. K=1/5/10/30별로 정확히 K편을 확보한 사용자를 보고한다. 영화 필터 이후 다시 자격을 계산하므로 기존 REC047 인원과 같다고 가정하지 않는다. 목표 영화와 같은 작품의 별칭은 입력에 들어갈 수 없다.
6. **같은 채점 대상:** 검증에서는 검증 보류 영화, 평가에서는 평가 보류 영화에 대한 같은 사용자·영화·미래 관측 행을 전 모델에서 사용한다. ALS 영화 factor와 입력 factor가 실제 존재하는지도 확인한다. 점수가 없는 모델의 행을 몰래 빼서 평균을 높이지 않고, 실패·제외 인원과 이유를 함께 보고한다.

입력 K와 사용자 전체 과거 활동량은 다르므로 둘 다 보고한다. 학습 사용자는 활동이 많은 사람만 골라 쓰지 않는다. 활동량과 영화 지원량별 사용자 수·영화 수·관측 수·순서 비교 가능 사용자 수를 함께 낸다. 영화 지원량 층은 고정된 검증 전 기준과 해당 평가 시점의 실제 수를 구분한다. 50건 이상이라고 ALS가 정확하다고 보장하지 않는다.

이번 비교는 **추천할 목표 영화에 평점 학습이 없는 상황**부터 분리한다. 입력 영화도 전부 새 영화인 경우는 별도 질문이다. K=0은 개인화 ALS 참고 점수가 없으므로 본 비교에서 제외한다. 기본값을 실제 ALS 점수로 채우지 않는다. 원래 학습 평점이 0건인 영화 역시 ALS 재현도는 계산할 수 없으므로 이 보류 영화 비교에 섞지 않는다.

## 사용자별 대중성·장르·감독·배우는 이미 쓰고 있는가

사용자 추가 질문에 따라 REC047 코드를 확인했다. **장르·감독·배우와 개인 별점의 관계는 들어갔고, 대중성의 명시적 수치는 들어가지 않았다.**

| 정보 | 기존 FM·공유 리지·GBT의 동일 168개 입력 |
| --- | --- |
| 장르 | 후보의 18개 장르, 사용자 입력의 장르별 빈도·별점 요약, 후보 장르와 사용자 요약의 교차값 |
| 감독·배우 | 입력 영화와 후보의 실제 ID 연결 정도, 연결된 영화의 별점 평균·사용자 평균 대비 편차. 배우는 top5 범위 |
| 그 밖의 연결 | 키워드·국가/언어·연대/길이·제작사/시리즈도 동일한 연결 요약 사용 |
| 대중성·대중 평가 | TMDB 평균 평점·평가 수·인기도와 영화별 MovieLens 평균·평가 수는 모델 입력에 없음 |

각 방법은 여러 학습 사용자의 사례로 학습한 공유 모델 하나다. 사용자 입력이 바뀌면 위 특징 값이 바뀌어 예측도 달라진다. 그러나 사용자별로 “장르 30%·감독 20%” 같은 별도 계수를 학습·저장하지는 않는다. 특정 감독·배우 ID별 전역 계수도 없고, 설명용 개인별 영향도를 따로 계산한 구현도 없다. 장르·배우를 조건에서 분리한 인과 효과를 측정한 것으로 설명하지 않는다.

다음 특징 설계는 영화 자체의 속성, 그 속성과 사용자 입력 별점의 관계, 그 관계를 뒷받침하는 입력 수를 함께 다룬다. 여러 장르·여러 인물을 유지하며 수동 비율로 중요도를 고정하지 않는다. 기존 표현만으로 TMDB 정보의 활용 가능성을 모두 검증했다고 결론 내리지 않는다.

대중성 확장에서는 **평균 평점(평가), 평가 수(참여 규모), popularity(관심)**를 구분하고, 사용자가 어떤 수준의 영화에 높거나 낮은 별점을 주는지 후보 영화와 연결하는 특징을 검토한다. popularity는 조회·투표·즐겨찾기 등의 영향을 받는 TMDB 지표로 실제 관객 수와 같지 않다. [TMDB 공식 설명](https://developer.themoviedb.org/docs/popularity-and-trending)

현재 TMDB 수치를 과거 MovieLens 평가 시점에 이미 알았던 값으로 취급할 수는 없다. 당시 스냅샷이 확인되지 않은 동적 수치는 엄격한 과거 시점 평가의 입력에 섞지 않고, 사용한다면 현재 메타데이터를 결합한 탐색 비교로 별도 표시한다. 보류 영화의 MovieLens 평균·평가 수를 예측 입력으로 되돌려 넣어서도 안 된다. TMDB 집계 평점을 추가한 조건은 “MovieLens 학습 평점은 없지만 외부 집계 평점은 있는 조건”이며 순수 영화 콘텐츠 조건과 구분한다. 이 정보의 출처·시점·결측·특징 산식을 고정한 후 세 콘텐츠 모델에 같은 입력을 제공한다.

## 두 종류의 성적표

같은 관측 영화 목록에서 사용자별 지표를 먼저 구하고 사용자 평균을 낸다. 두 성적표를 합친 종합 점수는 만들지 않는다.

| 질문 | 지표 | 해석 |
| --- | --- | --- |
| ALS와 얼마나 비슷한 점수를 내나? | ALS 예측 대비 평균 절대 차이(MAE) | 낮을수록 점수가 비슷함 |
| ALS와 영화의 선호 순서가 비슷한가? | ALS가 서로 다르게 점수 준 영화 쌍의 순서 일치율 | 높을수록 ALS 순서를 재현함 |
| 실제 사용자 별점을 얼마나 맞히나? | 실제 별점 대비 MSE와 ALS 대비 차이 | 낮을수록 실제 별점 오차가 작음 |
| 사용자가 더 좋아한 영화를 구분하나? | 실제 별점이 다른 영화 쌍의 순서 정확도(PA)와 ALS 대비 차이 | 높을수록 실제 선호 순서를 맞힘 |

- ALS 재현도와 순서 지표는 반올림하지 않은 원래 예측을 쓴다. 실제 별점 MSE에서는 예측을 0.5–5.0 범위로 제한한다. 사용자 실제 별점은 원래의 0.5 단위를 유지한다.
- 순서 비교에서 기준 점수가 같은 쌍은 제외하고, 후보 모델만 동점이면 0.5점을 준다. ALS/모델 예측 동점 허용 오차는 절대 차이 1e-12다. 유효 쌍이 없는 사용자는 그 순서 지표에서 제외하되 수를 공개한다.
- 각 콘텐츠 모델과 ALS의 차이는 동일 사용자에서 짝지어 계산한다. 사용자 bootstrap 구간은 **이번 고정 영화 집합에 대한 불확실성**이다. 영화 전반으로 일반화하려면 영화 단위 재표집/반복 보류를 추가 검토해야 한다.
- “통계적으로 차이를 못 찾았다”를 “동급이다”로 쓰지 않는다. 우선 격차와 불확실성을 보고하며, 동급 판정을 하려면 허용 손실 폭을 점수 확인 전에 별도로 정해야 한다.
- 이번 목록은 사용자가 실제 평가한 영화들이다. 전체 서비스 카탈로그 Top-N 성능이나 미평가 영화에 대한 정답을 측정한 것으로 부르지 않는다.

예상 결론의 형식은 “FM은 평점 이력이 가려진 영화에서, 평점 이력을 아는 ALS보다 실제 별점 오차가 얼마 더 크거나 작았다. ALS와 순서는 얼마나 비슷했다”이다. **ALS와 달라도 실제 별점을 더 잘 맞힐 수 있다.**

## 실행 순서와 해석 범위

1. 현재 설계를 독립 검토한다. 이 문서의 완료는 실행 코드 검토나 실험 완료를 뜻하지 않는다.
2. 새 정답 값은 열지 않고 영화 분할과 사용자 자격·표본 수·학습량을 점검해 실행 명세를 고정한다. 표본이 부족하면 그대로 한계를 기록하고 설계를 다시 검토한다. 점수가 잘 나오는 영화나 사용자를 찾아 바꾸지 않는다.
3. 영화 차단 전후 데이터·특징 경로와 사용자/시간 분리를 독립 검토한 뒤 학습한다. 기존 전체 학습량의 모델 설정을 고정해 한 번 비교하고 학습량 25/50/100% 반복은 추가하지 않는다. REC047의 ALS factor는 사용자 역할·원본·시점·설정·봉인이 정확히 일치할 때만 재사용하고, 바뀐 입력에 대한 fold-in과 예측은 다시 만든다. 콘텐츠 모델은 영화 차단 후 새로 학습해야 한다.
4. 검증 보류 영화로 실행 건전성을 확인한다. 레시피를 바꾼다면 이유와 검증 근거를 기록하고 최종 예측 전에 다시 고정한다. 평가 예측 봉인 후 실제 별점을 대조하고, 독립 검산을 거쳐 두 성적표와 집단별 격차를 정리한다.

REC047의 개발용 평가 정답은 이미 확인했으므로 재사용 결과는 **탐색 결과**다. 새 최종 검증 자료처럼 부르거나 미개봉 예비 자료를 자동으로 열지 않는다. 기존 모델의 최적 수렴도 보장하지 않으므로 결과는 해당 고정 학습 설정의 비교다.

이 실험은 기존 영화의 평점을 인위적으로 숨긴 상황이다. 실제 2026년 신작·한국 사용자 전체의 성능 보증은 아니다. 별점을 숨기지 않은 동일 콘텐츠 모델 대조가 없으므로, ALS와의 차이를 오직 “해당 영화 평점 제거의 효과”로 분해하지 않는다. 기존 REC047 결과·봉인·코드는 보존하고, Jira·GitLab/GitHub 게시와 서비스 모델 결정은 별도다.

## 방법 참고

영화 단위로 해당 영화의 모든 상호작용을 함께 보류하는 cold-item 평가 방식은 [NFC 논문의 평가 절차 6.1절](https://link.springer.com/article/10.1007/s11257-021-09303-w)에 사용된다. 위 문서는 이 원칙을 참고하되, 사용자·시간 분리를 추가한 FEELM용 초안이다. 논문의 모델·튜닝·분할 비율·성능을 그대로 채택한 것이 아니며, 여기의 ALS는 콘텐츠 모델의 학습 목표가 아닌 평가 참고선이다.
