# FM과 GBT의 마지막 비교 설계

상태: DRAFT — 로컬 연구 설계. 독립 설계 검토 PASS이며 학습·서비스 채택은 아직 수행하지 않았다. 2026-09-11.

**이번에 확인할 것은 ‘같은 영화 정보와 같은 사용자 이력을 받은 FM과 GBT 중 무엇을 남길까’다.**
직전 절충 후보인 FM_RH와 GBT_B는 입력 구성이 달랐다. 같은 B/R 조건의 비교는 이미 있다.
그 두 절충 후보의 숫자만 다시 비교하면 모델과 입력 구성의 차이가 함께 남는다.
먼저 입력 조건을 맞추고, 정해진 범위에서 학습을 더 했을 때의 변화까지 확인한다.

| 정할 것 | 이번 설계 |
| --- | --- |
| 모델 | Spark FM 회귀와 Spark GBT 회귀 두 종류 |
| 공통 입력 | 검증된 230개 구조 특징. 영화 정보＋사용자의 과거 반응＋그 반응의 근거량 |
| 대중평점 | 투표가 적은 극단값을 공통 방식으로 완화 |
| 사용자 이력 | 목표 평점보다 엄격히 이전에 입력된 최근 평가만 사용 |
| 제한된 추가 비교 | FM 최대150/300회, GBT 최대60/120개 트리. 다른 설정은 고정 |
| 안정성 | 개발 자료에서 각 모델 설정을 정한 뒤 추가2개 seed. 좋은 seed만 고르지 않음 |
| 핵심 지표 | 예상 별점 MSE와 관측 후보 Top2를 함께 판단. 학습평점 없는 영화도 별도 주 비교 |
| 부가 지표 | 첫1편·다음2편·그다음2편, 낮은별점, 오차가 큰 사용자, 입력량·영화지원량, 추천 쏠림·비용 |
| 결과가 엇갈리면 | 한쪽을 억지로 승자로 만들지 않고 오차·추천순위·비용의 절충으로 종료 |

**중요하게 바로잡은 세 가지가 있다.**

1. 기존 FM_RH와 GBT_B는 서로 다른 완성 레시피였다. 이번에는 두 모델 모두 RH 입력을 쓴다.
   학습된 기존 B/R 모델은 과거 참고로 보존한다. RH가 모든 모델에 최적이라는 주장은 하지 않는다.
2. 이미 확인한 270명과 그 안의90/180명은 새 최종 test가 아니다. 미사용 사용자 존재는 아직 입증되지 않았다.
   실행 전 사용 이력 감사가 통과할 때만 별도 확인 표본을 사용하고, 그렇지 않으면 개발 비교로 끝낸다.
3. FM의 반복 증가와 GBT의 트리 증가가 같은 계산량은 아니다. 최대 학습8회·회당90분·4CPU/12GiB를
   공통 상한으로 두고 실제 비용을 함께 공개한다. 모델 전체의 최적 설정을 찾았다고 말하지 않는다.

논문에서 가져온 것은 새로운 모델 목록보다 **학습과 추천 입력을 맞추기, 비교 예산 고정,
관측 평점과 실제 노출 평가 분리**다. 사용자 균등 평균이나 TMDB 투표 수 보정이 MovieLens의
시점·국가·관측 편향을 없애지는 않는다.

이번 요청은 설계와 검증이다. 실제 학습, 미개봉 평점 열람, Jira·GitLab·커밋·Push는 수행하지 않는다.
후속 실행에서는 코드·합성 검사·실제 입력 봉인의 검토까지 통과해야 학습한다.
