# 동일 입력에서 FM·GBT를 비교하는 최종 로컬 연구

상태: DRAFT — 설계 검토 대상. 제품 계약이나 실행 코드 승인서가 아니다. 2026-09-11.

## 1. 질문과 범위

질문은 두 가지다.

1. 검증된 동일 RH 특징에서 제한된 학습 예산을 준 FM·GBT가 별점 오차와 앞쪽 추천에서 어떤 절충을 보이는가?
2. 그 결과가 학습평점 없는 영화, 적은 사용자 입력, 전체 후보 노출과 비용까지 고려해도 유지되는가?

‘모든 FM과 모든 GBT 중 최고’를 찾거나 MovieLens로 한국2026 만족도를 확정하는 연구가 아니다.
같은 조건의 FM_B↔GBT_B, FM_R↔GBT_R는 이미 존재한다. 이번에 비어 있는 GBT_RH를 채우며,
RH 표현에 조건부인 두 모델 비교로 결론을 제한한다. 기존 FM_RH↔GBT_B는 완성 레시피 비교로 보존한다.

고정 제품 방향은 첫2편·추가 요청마다2편이다. 입력을 추가하지 않은 더보기에서는 같은 순위의
3–4위,5–6위를 반환한다. 더보기를 불만족 레이블로 바꾸지 않는다. 새 별점 입력 후 재추천의 실제
행동 효과, 온보딩 영화 선택, K-means·8분류·맞춤/발견 분리는 이번 비교에 포함하지 않는다.

## 2. 공통 학습·특징 계약

- foundation340의 **RH** 학습 자료·부모 봉인 재사용:39,859명,4,997,069개 목표 평점,230개 특징.
- 같은 사용자/목표 영화/실제 별점/row_id/입력 이력/특징 값/partition 순서. FM과 GBT의 행 집합이 정확히 같아야 한다.
- 실제 별점은0.5~5의0.5단위다. 계산용 예측은 연속값이며 서비스의 실제 감상 별점을 덮어쓰지 않는다.
- 장르·키워드·국가·언어·감독·배우 등 기존 관계, 사용자 별점 습관·연결 반응·근거량,
  TMDB 평점/투표수/인기도의 기존 구조 특징을 유지한다. 각 특징의 실제 출처는 열 이름 manifest로 확인한다.
- 이번에 새 텍스트 임베딩·희소 사용자/영화 ID·새로운 원시 배우 ID·교차특징을 추가하지 않는다.
  현재 FM은230개 집계 특징의 상호작용 모델이며 원 FM 논문의 희소 ID 모델과 같지 않다.
- R: `(v*r + 48*mu)/(v+48)`, `mu=6.173088067675869`. 학습지원 W의 기존44,920편으로 정한 값이다.
  입력 영화와 후보 영화에 동일하게 적용하고 결측 flag를 유지한다. test로 mu/48을 재추정하지 않는다.
- H: 같은 사용자의 `timestamp < 목표 timestamp`인 최근 cap편만 입력한다. 같은 timestamp의
  다른 평가, 목표 영화, 미래 목표는 포함하지 않는다. 동률은 timestamp 내림차순/movie_id 오름차순이다.
- cap0/1/5/10/30의 기존 label-blind 배정을 유지한다. cap은 상한, 실제 h와는 다르다.
  B의 h0 82.34%와 RH의21.04%는 서비스 사용자의 비율이 아니다. RH가 입력량·최신성·갱신 빈도를
  함께 바꾼다는 기존 해석도 유지한다. 학습에서는 목표마다 입력이 갱신되지만 평가 후보 묶음에서는 입력을 고정한다.
- C10,952편은 MovieLens 학습 목표·입력·집계에서 제외한 기존 mask를 유지한다. 기존 W support를
  고정하고 자연적 support0과 C를 구분한다. C의 외부 TMDB 평점/투표수 등은 동일 스냅샷의
  허용 특징이며, 그 영화의 MovieLens 평점이 학습 집계로 유입되지 않는 것과 구분한다.
- 학습 행의 가중치는 양쪽 모두1이다. 사용자당 행 수·상위1% 사용자 기여율·cap별 목표 수를 공개한다.
  평가를 사용자 균등 평균으로 한다고 학습 기여까지 균등해지는 것은 아니다.

Spark4.1.3 FM의 실제 학습은 label/features 두 열만 읽는다. 상속된 weightCol 표기만 보고
FM에 사용자 가중치가 적용됐다고 가정하지 않는다. GBT에만 weightCol을 주거나 FM 행을 임의로
반복해 두 학습 분포를 다르게 만들지 않는다. 사용자별 균등 표집은 의미 있는 다른 가설이지만,
이번에는 검증된 목표 행을 고정해 입력/모델/표집을 한꺼번에 변경하지 않는다. [구현 근거](EVIDENCE.md)

## 3. 평가 역할과 아직 입증되지 않은 새 표본

### 개발 역할

research343의 역할 파일을 그대로 사용한다. 기존270명 중 보정90명, 선택180명이며 모두 이미
여러 연구에서 열어본 개발 사용자다. 학습39,859명과는 이 비교의 학습 역할상 분리한다.
‘이전에 어느 모델에서도 학습하지 않은 사용자’라는 의미는 아니다.

- 보정90명: 모델/seed/cap별 별점 보정 계수만 적합한다.
- 선택180명: 반복 예산 선택과 개발 결과 비교에 사용한다. 현재 h10>0은124명이며 NDCG@2는117명이다.
- 기존 사용자의 원 입력 O와 관측 목표 J, 사용자 ID 및 역할을 그대로 유지한다. 좋은 별점이나
  모델 Top 목록으로 사용자를 재선택하지 않는다. 180명을 새 test라고 부르지 않는다.
- 평가 사용자가 origin 전에 직접 남긴 C 영화의 별점은 O에 포함될 수 있다. C는 글로벌 모델의
  MovieLens 학습에서 제외하는 것이며, 실제 사용자에게서 이미 받은 입력까지 삭제한다는 뜻은 아니다.
  동일 O 안에서 C/W/자연미지원의 수와 ALS가 사용할 수 있는 입력 수를 별도 기록한다.

### 별도 확인 표본의 실행 전 gate

현재 `FINAL_RESERVE`라는 이름만으로 미사용을 증명할 수 없다. 기존9,670명 중8,992명의 과거
학습/검증 사용이 확인됐고, 나머지678명도 미사용이 확정된 것이 아니다. 별점 값을 열기 전에:

1. 기존 학습·개발·평가·수집의 UID 사용 manifest 전체와 후보 membership을 대조한다.
   출처가 누락된 사용 이력은 ‘미사용’으로 처리하지 않는다. 필요하면 원본의 UID/movie_id/timestamp만 읽는다.
2. 감사로 미사용이 입증된 사용자만 대상으로2023-01-01 UTC 이전 입력과 다음180일 관측의
   존재를 확인한다. 영화 개봉일/연결/관측 수 자격은 label-blind로 적용한다.
3. 자격자는 기존 연구 카탈로그에 목표가1개 이상 있는 사용자다. 최대1,000명까지
   `SHA256("final-fm-gbt-confirm|"+uid)` 오름차순으로 정한다. 층을 억지로 같은 크기로 만들지 않는다.
4. h10>0이고 J≥2인 사용자가100명 이상이면 별도 확인 표본으로 고정한다. 이 수는 실행
   가능성의 최소값이며 검정력 보장이 아니다. C/NATURAL_ZERO의 규모는 별도로 공개한다.
5. UID/입력/후보/기간 manifest와 과거 사용 이력 감사가 독립 검토를 통과해야 이 경로를 활성화한다.
   역할을 찾으려고 날짜·hash·모집단을 결과에 맞춰 바꾸지 않는다.

위 gate 미통과 시 **개발 자료의 최종 비교로 끝낸다.** 미사용 확인이 없다는 이유로 새 실험을
계속 늘리거나 기존180명을 test로 개명하지 않는다. 이번 설계 단계에는 새 UID 원본·별점 개방이 없다.
어느 경로인지 실행 전 availability-manifest에서 고정한다. 두 경로의 결과를 같은 증거 수준으로 말하지 않는다.

## 4. 시간과 후보

학습 평점 마감은2023-01-01 UTC 이전, 평가 입력도 같은 origin 이전, 관측 정답은 이후180일이다.
TMDB는 현재 수집 스냅샷이므로 **최신 메타데이터를 결합한 과거 평점의 회고적 비교**다.
strict-past 평점을 지켜도 당시의 TMDB를 복원했다거나 한국2026 사용자 일반화가 검증되는 것은 아니다.

- 관측 품질: 실제 평가한 J 중 origin에 개봉한 영화, 같은 O·J·원별점으로 비교한다.
- 전체 후보: 기존85,517편 연구 카탈로그에 고정 스냅샷시각1788998400의 개봉일 조건과
  origin 이전 전체 기시청 제외를 적용한다. 최신 카탈로그에 과거 입력을 넣는 동작 점검이다.
  현재 한국 OTT 카탈로그 또는 실제 서비스 노출 분포로 부르지 않는다.
- 100/500개 임의 후보나 정답1개＋미평가 부정 후보를 새로 만들지 않는다. 후보 수를 모델별로 다르게 줄이지 않는다.
- 동점은 raw prediction 내림차순/movie_id 오름차순. 모든 후보 점수는 같은 순서·dtype로 보존한다.
- 영화의 학습 평점0, 메타데이터 결측, 학습에 없던 범주, 연구 ID축 밖의 새 영화는 서로 다른 조건이다.
  축 밖 새 영화는 고정 차원 특징을 만들 수 있는 별도 adapter 합성검사를 실행 전 검토에 포함한다.
  합성검사 통과는 점수 계산 경로 확인이며 새로운 영화의 만족도 검증이 아니다.

학습 손실, 개발 손실, 실제 반복/트리 수를 기록한다. FM이 반복별 loss를 제공하지 않으면
N/A로 남기고 실행시간만으로 수렴을 판정하지 않는다. 조기 종료가 발생하면 실제 반복 수도 공개한다.

   기존 FM_RH는 수치 참고/재현 대조이며 peak12GiB+4096B의 EXCEPTION을 지우지 않는다.
2. 아래 개발 선택 규칙으로 가족마다 한 설정을 고정한다. 최종 정답을 보고 고르지 않는다.
3. 선택된 두 설정만 seed344·345로 한 번씩 더 적합한다. 총최대8회, 가족당 최대4회다.
   seed339/344/345를 모두 보고하고 좋은 seed로 교체하거나 평균 예측 앙상블을 새로 만들지 않는다.

row_id hash8partition/partition 내부 row_id 정렬/AQEfalse다. 한 프로세스90분 상한,
학습 총상한12시간이다. 실제 시간은 모델마다 다를 수 있다. 데이터 준비·검산·보고 시간은 별도 기록한다.

## 6. 예상 별점·개발 선택

각 모델·seed·cap마다 보정90명의 사용자 균등 가중으로 `a+b*raw`, b≥0인 단조 선형 보정을 적합한다.
분산≤1e-12 또는 음의 covariance이면 b=0인 상수 보정으로 기록한다.20명/40행 미만은 N/A다.
보정 MSE는 예측만[0.5,5]로 clip해서 계산한다. native MSE/MAE,보정 전후 bias/범위 이탈도 함께 공개한다.
학습 정답은 계속 원별점이며 이 보정이 FM의 학습 손실이나 사용자 별점을 바꾸지 않는다.
추천 정렬은 raw score를 사용한다. 보정으로 생긴 clip 동점을 영화ID로 재정렬하지 않는다.

개발 선택은 seed339,180명 중 H10 h>0의 ALL 관측 J에서 계산한다.
가족별 큰 반복 설정이 작은 설정보다 **보정 MSE≤,NDCG@2≥이고 적어도 하나 엄격히 개선**할 때만
큰 설정을 남긴다. 둘이 엇갈리거나 같으면 작은 설정을 남기는 비용상 보수적 규칙이다.
큰 설정이 미완료이거나 보정/주 지표가 N/A면 작은 설정을 남기되 미확보 사실을 공개한다.
작은 설정의 보정/주 지표도 N/A면 설정 선택 미완료로 종료한다. 두 설정의 전체 표와 Pareto 관계도 보존한다.
이 선택은 ALL에 맞춘 반복 예산 선택이며 C에 최적화한 설정은 아니다. C에서의 성능은 별도 주 비교로 확인한다.
이 규칙은 개발 단계 선택이며 두 설정의 동등성·통계적 우월성 증명이 아니다.
형식적으로 임의 가중합을 만들거나 MSE를 나중의 동률 처리 지표로만 사용하지 않는다.

## 7. 주 비교·지표·판정

주 비교는 선택된 **GBT−FM**이다. 각 사용자별 지표를 먼저 구하고3seed의 지표 평균을 낸다.
그 후 사용자 균등 평균을 낸다. 모델 점수 평균의 앙상블 성적과 혼동하지 않는다.
UID 오름차순과 seed339/344/345 순서를 고정해 동일 UID를 짝지어20,000회 bootstrap,seed344로 비교한다.
모든 cap/seed/영화행을 독립 표본으로 세지 않는다. 부가 cap 보정의 N/A는 해당 부가 지표의 N/A이며
주 cap10이 모두 유효할 때의 공식 비교까지 취소하지 않는다.

사전 주 비교는 다음 네 개다.

| 집단 | 주 지표 | 의미 |
| --- | --- | --- |
| H10 h>0, ALL J | 보정 MSE | 알려진 영화·미지원 영화를 함께 포함한 별점 오차 |
| 같은 집단, J≥2,IDCG>0 | NDCG@2 | 관측한 후보 중 앞쪽2편 선택 |
| H10 h>0, C∩J | 보정 MSE | 의도적으로 학습평점을 제외한 영화의 별점 오차 |
| 같은 집단,J_C≥2,IDCG>0 | NDCG@2 | 해당 미지원 영화 안의 앞쪽 선택 |

네 비교에98.75% 양측 CI를 사용한다. NDCG gain은(r−0.5)/4.5,discount는1/log2(rank+1).
각 지표의 실제 유효 사용자·영화·행 수를 적는다. 유효30명 미만 셀은 수치만 보고 CI·판정을 N/A로 둔다.
30명 이상도 충분한 검정력을 뜻하지 않는다. 빠진 비교만큼 나머지 CI를 느슨하게 바꾸지 않는다.

MSE 차이는 음수, NDCG 차이는 양수가 유리하다. 두 주 지표가 서로 엇갈리면 **절충**으로 끝낸다.
ALL의 두 CI가 각각0보다 작음/큼을 동시에 충족하고, C에서도 같은 두 조건을 충족할 때만
‘관측된 전체와 C에서 두 지표의 일관된 개선을 확인’이라고 쓴다. 반대 방향도 대칭이다.
C가 부족하거나 CI가0을 포함하면 전체 우승·동등함을 선언하지 않는다. 사후 허용 손실을 만들지 않는다.
서비스에서 감수할 MSE/Top2 손실 폭은 아직 제품 정책이 아니므로 비열등성 한계로 임의 확정하지 않는다.

3seed 각각의 효과 방향·범위도 별도로 표시한다. 한 seed에서 주 지표 방향이 뒤집히면
‘seed에 안정적인 개선’이라고 쓰지 않는다. 사용자 bootstrap CI는 고정된 적합·보정 모델에
조건부이며 학습/보정 불확실성을 모두 반영한 CI가 아니다.3개 seed를 모집단 전체의 변동 추정으로 과장하지 않는다.
새 확인 표본 gate 통과 시 이 네 비교는 그 표본에서 한 번만 개봉한다. 개발 자료에도 같은 표를
내지만 독립 확인과 분리한다. gate 실패 시 모든 선택/비교는 반복 개발 자료의 조건부 결과로 제한한다.

## 8. 함께 볼 지표 — 승자 선정용 추가 검정을 늘리지 않음

- 별점: native/보정 MSE·MAE,RMSE,평균 signed error,사용자 MAE의95백분위,
  영화균등 MSE와 행균등 MSE,예측구간별 실제 평균별점·평가수,clip 발생률.
- 상단: NDCG@1/2/4/6,선택 영화의 실제 평균별점,≥4비율,≤2비율,2편 모두≤2인 사용자 비율.
  1–2/3–4/5–6 묶음과 누적TopN을 구분한다. 자연 분모와 같은J≥6 사용자 표를 함께 낸다.
- 개인화: 같은 h>0 사용자·목표에서 실제 O 입력과 O를 비운 입력의 차이를 기술통계로 비교한다.
  cap0 예측 재사용 시 정확히 같은 사용자/목표축인지 검증한다. 새 사용자 실험의 인과효과나 온보딩 효과로 부르지 않는다.
- 입력: cap0/1/5/10/30,실제h0/1–4/5–9/10–29/30,이전 전체 활동량0/1–9/10–29/30–99/100–299/300+.
  입력 상한10의 일부 사용자만 보고 전체 서비스 K를 정하지 않는다.
- 영화: W,C,NATURAL_ZERO를 분리하고 지원량0/1–9/10–49/50+,개봉연도,TMDB 투표 근거량,
  원 메타데이터 결측/새 범주를 교차 보고한다. 작은 셀을 좋은 지표가 나올 때까지 합치지 않는다.
- 전체 후보: 첫2/다음2/그다음2의 UNKNOWN·반환/미반환·중복·고유영화수·HHI·최대영화 비중,
  투표1개·10점 노출·학습지원0·개봉2024+·메타데이터 결측. UNKNOWN은 실패나 정답이 아니다.
  쏠림 감소·신작 노출 증가를 만족도 점수로 합산하지 않는다.
- 비용: 두 모델 모두 같은 실행기/CPU/후보·배치·동시작업 조건에서 특징생성/모델추론/TopN시간을
  구분해 p50/p95와 모델 크기를 기록한다. 기존 모델의 추론비용을 새 모델의 합산시간과 비교하지 않는다.

ALS는 같은 학습 평점 집합의 기존 factor를 수치 참고로만 사용한다. 주 후보·혼합은 아니다.
같은 W_DIRECT의 동일 사용자/영화에서만 실제 별점 오차·순위를 대조하며 지원 없는 값은 N/A다.
C 평점을 아는 과거 참고ALS를 새 콘텐츠 모델과 동급 정보 조건으로 비교하지 않는다.

## 9. 실행 전후 검증과 종료

이번 문서의 design PASS는 학습 실행 PASS가 아니다. 후속 구현에서 다음을 순서대로 확인한다.

1. availability와 코드 검토: 입력·평가·새 표본 사용 이력,미사용 증명 여부,모든 설정/분기/산출물 경로 고정.
2. 합성검사: 같은시각/목표 제외/입력0/부족cap/결측/새 범주/축 밖 영화/동점/추가2편/clip와raw순위/IDCG0/N/A,
   개발 선택의 개선·절충·미완료 분기. native와portable의 임계값 양옆·FM수식 검산도 포함한다.
3. 실제 입력 감사: 기존RH 부모·정답행/특징값/사용자분리/입력시간/동일partition·schema·열 의미 전수 대조.
4. 네 설정 학습과 독립 native/portable 예측 검산 후 개발 선택. 설정 고정 뒤 추가4seed 학습과 검산.
5. 모든 최종 모델/보정/후보 점수·순위·예상 분모를 봉인한 뒤에만 허용된 새 확인 정답을 연다.
   기존 개발 라벨을 쓴 선택과 새 정답 개봉 시점을 구분한다.
6. 모델 코드를 가져오지 않는 독립 검산으로 실제 별점 오차·순위·CI·전체 후보 노출을 확인한다.
   최종 보고서/그림/단위/분모/출처/주장도 별도 검토한다.

산출물은 설정·역할/입력 manifest·실행로그·native/portable 모델·예측·보정·사용자/영화/페이지
지표·CI·전체 후보 노출·비용·최종 비교표와 검토 기록이다. 대용량은 outputs 아래 Git 제외로 보존한다.
최종 표에는 반드시 ‘어떤 질문은 확인됐고, 어떤 질문은 표본/편향 때문에 미확인인지’를 같이 적는다.
추가 정보·새 모델·가중치 탐색은 이 결과를 보고 자동으로 재개하지 않는다.
서비스 모델 채택·추천혼합·Jira·GitLab·GitHub·배포는 이번 설계 및 이후 로컬 비교의 자동 후속이 아니다.
