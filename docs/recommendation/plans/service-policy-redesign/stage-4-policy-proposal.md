# 단계4 — 맞춤과 발견을 실제 상태에 연결할 연구 제안

상태: DRAFT. 2026-09-08. 제품 채택안이 아닌 비교 준비안이다.
공식 기준: S15P21E106 `43e2884d295cc885c9d2b22958ef2be72ab04669`.

## 먼저 읽을 결론

**영화를8맛으로 나누는 것만으로는 맞춤2편·발견1편이 정해지지 않는다.**
이번에는 “좋아하는 맛에서 맞춤2편, 아직 경험하지 않은 다른 맛 중 연결 근거가 있는 영화1편”이라는
연구안 하나를 구체화한다. A/B에서 영화의 맛 배정만 바꾸고 나머지 규칙은 같게 둔다.

예를 들어 액션 맛을 좋아하고 음악 맛은 감상한 적이 없다고 하자. 액션 맛에서 개인화 순위가 높은2편을
맞춤으로 고르고, 음악 맛에서 좋아한 액션 영화와 감독·키워드·장르 중 하나가 같은 영화를 발견 후보로 삼는다.
같은 감독이라는 사실은 설명 근거일 뿐, 사용자가 좋아하거나 발견을 납득한다는 정답은 아니다.

이 제안을 제품 규칙으로 확정하지 않는다. 먼저 합성 상태에서 무엇이 가능한지, 어디서 추천을 못 채우는지
보여준다. 이후 두 실제 분류안의 후보 공급과 채점 가능한 범위의 선호를 비교할 계약을 별도로 고정한다.
기본 ALS를 다시 학습하거나 K 후보를 늘리는 단계가 아니다.

## 바꾸지 않는 조건과 이번 제안

| 항목 | 그대로 지킬 조건 | 연구에서 구체화할 제안 |
| --- | --- | --- |
| 맛 표시 | 외부8종, 영화별 대표 맛 하나 | REC033 A/B를 같은 규칙에 연결. 코드·표시명은 연구용 |
| 감상량 | 평가한 감상 수와 선호는 다름 | 현재 평점 수, 감상 경험, 선호 신호를 별도 계산 |
| 새 맛 | 구체 기준 미정 | 확인된 감상 경험이0이고 현재 긍정 맛에도 속하지 않는 맛 |
| 맞춤 | 선호할 가능성이 높은2편 | 현재 긍정 맛에서 고정 추천 순위가 높은2편 |
| 발견 | 새로운 맛이면서 기존 취향과 연결된1편 | 새 맛 후보 중 긍정 입력 영화와 공통 콘텐츠 사실이 있는 영화의 최고 순위1편 |
| D 없음 | T3 fallback | 적격 T가3편일 때만 T3. T도 부족하면 공급 실패 기록 |
| T2 부족 | 일반 fallback 미정 | INSUFFICIENT_TASTE로 진단. D를 T로 이름만 바꾸거나 인기 보충하지 않음 |
| 무입력 | 인기 시작 | NO_INPUT은 P0의3편 예시. 개인화 근거 없는 D는 만들지 않음. 다른 상태 전체로 확대하지 않음 |
| 전환 | 무입력 인기→개인화, 정확한 K 미정 | 전환 상태를 외부 입력으로 받는 합성 검증까지만. K값·역전환 원칙을 정하지 않음 |

여기서 새 맛의0은 공식 임계치 채택이 아니다. “아직 경험하지 않은 맛”이라는 한 연구 가정이다.
`평가 수<3이면 D, 나머지 T`와 의미가 다르며 그 미합의 규칙을 기본값으로 사용하지 않는다.
많이 봤어도 싫어한 맛은 T로 강제되지 않는다. 적게 봤어도 좋아하는 맛은 T가 될 수 있다.

## 입력 상태를 분리한다

영화마다 현재 온보딩 응답, 감상 상태, 현재 감상 별점을 따로 유지한다.
원별점은0.5~5.0·간격0.5 그대로 저장한다. LIKE/DISLIKE에 숨긴 별점 강도를 복원하지 않는다.
skip·모름·미응답은 입력이 없으며 부정 선호나0점이 아니다.

감상 평점 수정은 그 영화의 팝콘 수를 늘리지 않는다. 평점 삭제는 팝콘 수를 줄이지만
WATCHED_UNRATED로 감상 경험과 추천 제외를 유지한다. 따라서 삭제만으로 이미 경험한 맛이 새 맛이 되지 않는다.
LINK_CLICKED는 추천 제외에는 포함하되 감상을 확인한 상태로 세지 않는다.

같은 영화에 감상 별점과 온보딩 응답이 모두 있으면 현재 감상 별점 하나를 선호 입력으로 우선 사용하는
연구안을 둔다. 평점을 삭제하면 남아 있는 온보딩 응답을 다시 선호 입력으로 사용할 수 있지만,
그 영화의 감상 경험·추천 제외는 그대로다. 입력 건수는 고유 영화 수이며 이중 집계하지 않는다.
이 우선순위와 온보딩 수정·삭제 동작은 연구 상태 모델이며 공식 API가 구현됐다는 뜻이 아니다.

온보딩 응답 영화는 같은 카드의 재추천을 피하는 연구용 별도 제외로 둔다. 이를 감상한 영화로 바꾸거나
팝콘을 추가하지 않는다. 공식 계약은 온보딩 응답만으로 자동 감상 제외를 규정하지 않았다.
EXPIRED의 재노출·제외 의미는 미정이므로 이 상태를 일반 감상/불호로 변환하지 않고 UNSPECIFIED_STATE로 남긴다.

## 선호·경험·후보를 계산하는 순서

1. 현재 시점까지의 상태를 합친다. 다른 시점의 입력·삭제 전 평점·숨긴 평가 정답은 보지 않는다.
2. 관측 감상 별점의 상대 weight는 기존 REC032 방식(관측 histogram+고정 학습 prior, 수축5)을 사용한다.
   LIKE는+1, DISLIKE는-1로만 표현한다. 별점 상대값과 이진 부호의 동등 가중은 한 연구 가정이며 정보량 동등의 증거가 아니다.
3. 영화별 유효 신호 하나를 그 영화의 맛에 배정하고 맛별 평균 weight가0보다 크면 긍정 맛으로 둔다.
   관측 없음·합계0은 긍정 맛이 아니다. 잘못된 모델·미배정 맛은 별도 누락으로 기록한다.
4. 확인된 감상(RATED/WATCHED_UNRATED)이 있는 맛은 경험 맛이다. 온보딩은 경험 맛을 만들지 않는다.
5. T는 긍정 맛의 적격 영화다. D는 경험 맛도 긍정 맛도 아니며, 긍정 맛 안의 weight>0 입력 영화와
   공통 TMDB 장르 ID·감독 ID·키워드 ID가 적어도 하나 있는 영화다. 연결 사실의 종류·ID·근거 영화를 함께 남긴다.
6. 감상 기록·LINK_CLICKED·관심없음·이번 연구의 온보딩 응답 제외를 적용한다. 미배정 영화는 T/D 어느 쪽에도 억지 배정하지 않는다.
7. 고정 점수 내림차순·movie_id 오름차순으로 T2를 고른 다음 D1을 고른다. T/D는 이번 제안의 맛 조건상 겹치지 않는다.
   D가 없으면 T3를 시도한다. 중복 없이 채울 수 없으면 부족 사유를 반환한다.

**상대 weight는 맛 선호와 연결 근거 계산용이다.** 기존 explicit ALS는 원별점으로 학습·fold-in한 모델이므로
이진±1이나 상대 weight를 그 raw ALS에 그대로 넣지 않는다. 이진/혼합 입력에서 사용할 랭킹 adapter는 아직
고정되지 않았다. 합성 검증은 주어진 순위를 사용하며 이 문제를 해결했다고 보고하지 않는다.

무입력 P0는 MovieLens 보정 평균 별점의 연구 proxy다. TMDB 인기와 다르며 실제 서비스 Trending 구현이 아니다.
개인화 상태에서 전부 DISLIKE 등으로 긍정 맛이 없으면 NO_POSITIVE_TASTE다. 입력이 있는 이 상태를 NO_INPUT으로 숨기지 않는다.

## 먼저 재현할 상태표

| 상태 | 이 제안에서 확인할 결과 | 제품 결정으로 남는 것 |
| --- | --- | --- |
| 입력0·skip만 | 개인화 없음, P0 예시, 팝콘0 | 운영 주체·정확한 출력 표현 |
| LIKE만·감상0 | 긍정 맛의 T2 가능, 다른 미경험 맛의 D 가능, 팝콘0 | 온보딩 후보 제외·이진 랭킹 adapter |
| DISLIKE만 | 입력은 존재, 긍정 맛 없음과 T부족을 기록 | 저이력·부정 입력만 있을 때 fallback |
| 좋아한 감상1편 | 그 맛이 T가 될 수 있음 | 낮은 표본의 신뢰도·실제 품질 |
| 낮게 평가한 감상 다수 | 경험 맛은 유지, 감상량만으로 T가 되지 않음 | 해당 사용자 T공급 부족 처리 |
| 모든 맛 경험 | D없음→가능하면 T3 | 발견 재정의가 필요한지 여부 |
| D가 전체에는 있고100에는 없음 | 후보 절단으로 D 소실 | 후보 보충을 할지 여부 |
| T1/D다수 | T2 부족으로 기록, D를 T로 바꾸지 않음 | 일반 T부족 처리 |
| 평점 수정·삭제 | 수/선호/경험/제외의 변화가 각각 맞음 | K 역전환·혼합 입력 우선순위 채택 |
| 관심없음·추가추천 | 같은 타입 교체, 해당 타입 소진 시null, 새 목록2+1 | 확정 버퍼 계약의 실제 통합 검증 |

입력 변경·버퍼 소진에 따른 재생성과 관심없음의 기존 세트 내 같은 타입 교체는 현행 계약으로 유지한다.
이번 합성 검증은 슬롯 선정 함수의 동작을 확인하며 PostgreSQL의20편 세트 버퍼·Redis candidates500/topn100·
이벤트 소비자의 실제 통합 검증을 대신하지 않는다.

합성 검사의 목적은 이 표의 동작과 공백을 드러내는 것이다. 통과했다고 유형 의미·만족도·편의성을 승인하지 않는다.

## 실제 자료로 넘어가기 전 고정할 것

REC033 완료·독립 검산 뒤에만 A/B 실물 hash를 고정한다. 실데이터 실행 계약에는 입력 사용자·고정n·관측 순서,
학습 factor/prior, 제외, 후보500→100→실제 슬롯, 후보부족 분모, 별도 평가 접근 시점과 예산을 기록한다.
우선 원별점 경로의 기존n=30을 검토할 수 있지만 최종 K30이 아니며, 온보딩·혼합 경로의 검증을 대신하지 않는다.

감상 경험의 원천은 추천 cutoff 이전에 확인된 전체 감상 상태이며, 선호 입력으로 선택한 O(n)과 분리해야 한다.
O(n)에 없는 과거 감상을 없었던 것으로 취급하지 않는다. 기존 REC032 profile30은 hash로 고른 입력이고,
실제 서비스의 전체 감상 상태나 시청 시각 자료가 아니다. MovieLens 평점 timestamp도 실제 시청 시각은 아니다.
O(n)만 쓸 수 있는 진단은 '관측 입력 내 미경험'이라는 proxy로 명명하고, 실제 경험 기반 D 자격과 발견 품질의
판정은 보류한다. 정답 histogram·미래 입력·평가 대상의 존재를 몰래 전체 감상 이력으로 넘기지 않는다.

후보 공급 진단은 사용자 선호 정답 없이 가능하다. A/B의 실제 자격·후보 손실·T2/D1 제공 여부를 확인한다.
관측 영화 안의 선호 비교를 한다면 고정 평가 범위 안에서의 조건부 결과로 한정하고, 전체 추천의 미평가를 불호로 세지 않는다.
연결 사실·새 맛 조건 통과를 발견 품질의 정답으로 쓰지 않는다. 인간의 선호·납득 자료가 필요한 항목은 별도 기록한다.

이진 입력 비교는 실제 LIKE/DISLIKE 랭킹 경로를 먼저 고정해야 한다. 원별점을 이진으로 축약하는 대리 실험을 한다면
축약 기준·동점·중복·같은 응답 수를 사전에 명시한다. 현재는 공식 adapter·혼합 입력 처리·실질 효과 허용치가 미정이다.
합성 상태 검증과 실제 공급 진단을 준비한 뒤, 이 남은 선택을 사용자가 읽고 판단할 수 있는 한 문서로 정리한다.
