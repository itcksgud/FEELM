## 1. 이번에 정할 것

1단계의 목적은 **같은 입력과 같은 정답으로 비교할 수 있는 계약을 만든 뒤 기본 추천 검증으로
넘기는 것**이다. 모델·분류·온보딩 UI의 승자나 전환 K는 여기서 선택하지 않는다.

| 항목 | 이 설계에서 정한 기준 |
| --- | --- |
| 실제 입력 | 별점 원값0.5~5.0·간격0.5와 온보딩 LIKE/DISLIKE를 별도 보존 |
| 별점의 상대 표현 | 관측 입력만의 midrank와 사용자 동등 학습 prior, 수축 강도5를 기존 코드대로 재사용 |
| 채점 기준 | 입력량 n에 따라 변하지 않는 개인 상대 정답 Q. 평균 선호·최저 선호를 주로 보고 기존 HARM20은 진단 지표로 유지 |
| 인기 기준 P0 | 기존 실행 코드의 Bayesian prior50를 기준 하나로 재현. 실시간 Trending과 구분 |
| 개인화 기준 M0 | 공식 ALS+콘텐츠의 실제 설정/산출물 대응을 확인해야 함. 현재 연구 core의 인기 순위를 M0라고 부르지 않음 |
| 실행 전 조건 | 데이터 역할/접근 범위, O/H/E 분리, 모델 척도·학습집단·후보/제외·정답 개방 순서가 확인돼야 함 |

**현재 결론:** 입력·채점의 계산 정의는 구체화할 수 있다. 실제 Hybrid 설정/산출물과 새 목적에 맞는
평가 자료 대응은 미확인이다. 문서·합성 계산 점검은 진행하고, 실데이터 성능 실행은 이 빈칸을 채운 뒤 한다.

## 2. 입력 계약: 원값과 의미를 보존한다

연구용 정규화 레코드이며 API/DB 필드를 변경한다는 뜻이 아니다.

| 필드/정보 | 규칙 |
| --- | --- |
| user_key, movie_id | 익명 사용자 키와 고정된 영화 ID/index 매핑. 동일 영화의 중복 ID를 합의 없이 합치지 않음 |
| signal_source | RATING / ONBOARDING을 구분. 감상·관심없음·노출 상태는 다른 자료형 |
| rating_raw | RATING일 때만 유효. `2 × rating_raw`가 정수1~10이어야 함. 0·3.7·NaN 등을 임의 반올림하거나 정상값으로 넣지 않음 |
| onboarding_value | LIKE / DISLIKE 또는 활성 응답 없음. 각각 독립적인 범주이며 5점/0.5점으로 치환하지 않음 |
| observation_time, event_version | 관측 시점까지의 최신 유효 상태를 재구성. MovieLens timestamp는 평점 입력 시각이지 관람 시각이 아님 |
| active/current state | 수정은 같은 영화·같은 출처의 값 교체, 삭제는 해당 활성 입력 제거. 상태 충돌·동일 버전의 상반된 값은 검증 실패 |
| watch/dismiss state | 입력 변환에서 생성하지 않음. 온보딩은 감상 기록·팝콘을 만들지 않으며 모름·skip·미평가도 불호가 아님 |

같은 영화의 수정 횟수를 입력 수로 세지 않는다. RATING-only의 n은 현재 활성인 서로 다른 영화 수다.
ALS factor가 있는 영화 수 `n_factor`는 따로 기록하며 `n_factor ≤ n`이다.
동일 영화에 RATING과 ONBOARDING이 함께 있는 경우 어느 값을 우선할지·혼합 n을 어떻게 셀지는
단계4에서 정한다. 1단계에서 두 출처를 합산하거나 혼합 경로의 실행을 허용하지 않는다.

## 3. 별점 상대값의 계산

정의의 출처는 [REC022A core](../../../../scripts/rec_ev_022a_core.py)의
`user_equal_prior`·`smoothed_profile_percentiles`·`encoding_weights`다.
수축 강도5는 기존 처리의 재현값이며 새 최적값으로 주장하거나 이번 단계에서 다시 탐색하지 않는다.

### 학습 사전분포

평점 격자 R은 0.5, 1.0, …, 5.0이다. 허용 학습 사용자 v의 격자별 빈도를 h_v(r)라 하면:

```text
pi0(r) = mean_v [h_v(r) / sum_s h_v(s)]
G0(r)  = sum_{s<r} pi0(s) + 0.5*pi0(r)
```

평점이 없는 학습 사용자는 prior 평균에서 제외하고 수를 기록한다.
**사용자별 분포를 같은 가중치로 평균한다.** 모든 평점 행을 합친 빈도분포와 다르다.
평가 사용자와 평가용 이력은 prior를 만드는 데 쓰지 않는다.

### 관측 입력의 변환

O_u(n)은 현재 모델에 허용한 n개의 활성 별점이다.

```text
q_input(u,r,n) =
    [N_{O_u(n)}(<r) + 0.5*N_{O_u(n)}(=r) + 5*G0(r)] / (n+5)

relative_weight = 2*q_input - 1
```

입력을 추가·수정·삭제하면 O의 histogram과 기존 영화들의 상대값도 다시 계산한다.
n=0에는 영화 weight가 없으므로 가짜 개인화 벡터를 만들지 않는다.
동점만 있거나 n=1이어도 prior 때문에 weight가 0이라고 보장되지 않는다.

실제 온보딩 LIKE/DISLIKE에는 `+1/-1`의 범주 부호만 별도 전달할 수 있다.
이 값은 상대 강도나 별점 척도가 아니다. 별점으로 만든 `sign(relative_weight)`는
BINARY_PROXY라는 별도 출처를 붙이고 실제 UI 응답이라고 부르지 않는다.
relative_weight가 정확히0이면 sign 결과도0인 중립 proxy다. 실제 LIKE/DISLIKE의 두 범주와 다르다.
기존 REC015의 반별점 양자화·`(1 + N< + 0.5N=)/(n+2)`는 다른 효용 보정이며 여기 섞지 않는다.

## 4. 상대 입력과 ALS의 척도를 맞춘다

[기존 fold-in 코드](../../../../recommender/src/feelm_recommender/factors.py)는
원별점으로 학습한 explicit ALS factor에 원별점을 넣는다. 알려진 factor 행렬을 Y라 하면:

```text
p_u = solve(YᵀY + lambda*n_factor*I, Yᵀr_raw)
score_ALS(u,i) = p_uᵀy_i
```

기존 REC003 연구 설정은 rank32·reg0.1·iteration10·seed42, 원별점 목표·중심화 없음이다.
이는 [기존 설정/학습 코드](../../../../scripts/recommendation_cold_start_curve.py)의 이력이며,
현재 공식 Hybrid 설정이나 이번 평가에 재사용 가능한 checkpoint라는 뜻은 아니다.

**원별점 factor를 그대로 둔 채 r_raw만 relative_weight로 바꾸는 것은 금지한다.**
상대값이 필요하다는 근거와 서로 다른 척도의 모델을 연결해도 된다는 주장은 다르다.

M0의 manifest에는 다음을 반드시 선언한다.

- ALS의 학습 목표 척도, centering/bias, implicit/explicit, 정규화와 fold-in 식.
- 상대값이 적용되는 위치: 콘텐츠 profile / 재정렬 / ALS 학습·fold-in 중 무엇인지.
- 상대값 ALS라면 학습과 fold-in 모두 같은 변환을 사용했는지.
- factor가 없는 영화, `n_factor=0`, 콘텐츠 벡터 없음/0벡터의 처리.

지금은 상대 입력 표현을 정의하되 M0에 적용할 위치를 확인하지 않은 채 꽂지 않는다.
상대값 ALS의 새 학습이 필요하면 별도 이름의 고정 연구 구성으로 명시한다. 모델 대안들을 전수 비교하지 않는다.

## 5. 데이터 역할과 고정 정답

| 기호 | 누가 읽는가 | 고정할 내용 |
| --- | --- | --- |
| T | 학습/집계 | ALS·인기·prior 학습 역할, 사용자·기간·영화/feature/index·hash |
| O_u(n) | 입력/추천 | 그 시점에 관측하도록 허용한 입력만. 다른 n에서도 누적 순서는 동일 |
| H_u | 채점 전용 | 사용자 상대척도의 기준 이력. 출처·사용자·역할·기간/선정방식·hash를 지정 |
| E_u | 채점 전용 | 실제 평점이 있는 평가 영화와 정답. 모든 n·정책에 공통인 평가 범위 |
| C_u(n) | 추천 | 그 시점의 후보와 제외. 정답 보유 여부로 후보를 몰래 줄이지 않음 |

콘텐츠의 메타데이터 스냅샷·영화 가용 시점도 기록한다. 당시 사용 가능한 정보임을 확인하지 못하면
해당 평가는 과거 시점의 실제 서비스 재현으로 부르지 않는다. MovieLens 결과를 한국 FEELM 사용자의
실측 만족도나 실제 신작 성능으로 확대하지 않는다.

`E_u ∩ O_u(n_max) = ∅`여야 한다.
H_u를 “전체 이력”이라고만 쓰지 않는다. 사용할 고정 이력이 어떤 자료인지 명시한다.
기존028B/030의 full-history Q는 계산 정의의 근거이며 그 데이터 접근 범위를 이번에 자동 승계하지 않는다.
H_u는 평가 척도에만 사용하고 모델 입력·seen·맛 경험량으로 전용하지 않는다.
H_u가 비거나 허용된 reference가 없으면 Q는 미판정이다. n마다 다른 reference나 global 대체를 조용히 쓰지 않는다.

```text
Q_u(i) =
    [count_{H_u}(r < rating_eval(u,i)) + 0.5*count_{H_u}(r = rating_eval(u,i))]
    / |H_u|
```

**Q와 H/E는 모든 n·정책에서 같다.** 입력 q_input을 평가 정답으로 쓰면 n이 달라질 때
정답 자체도 바뀌므로 금지한다. 사용자 독립 평가에서는 평가자와 T·인기·prior·튜닝 사용자의
교집합이 각각0이어야 한다. 평가자에게 허용되는 모델 정보는 그 n의 O를 이용한 fold-in이다.
같은 사용자의 후행 시간창 검증은 사용자 독립이라고 부르지 않는다.

후보와 제외는 시점별로 정의한다. 나중에 O에 들어올 영화를 앞선 n에서 미리 제외하지 않는다.
현재 cutoff 이전 전체 감상 이력이 별도로 허용됐다면 양쪽 정책에 똑같이 적용하되 O/H와 구분한다.
기본 진단에서 입력 영화 제외는 재추천 방지 조건으로 명명하며 MovieLens에 감상 이벤트를 만든 것처럼 쓰지 않는다.
동점 정렬은 고정 movie_id 오름차순이며 같은 점수·후보에서는 순서를 재현한다.

실데이터 순서는 `역할/설정 고정 → 입력만 열기 → 모든 정책·n의 점수/목록 봉인 → 허용 정답 열기 → 채점`이다.
이미 본 정답은 탐색 재사용이라고 표시하고 새로운 독립 검증으로 발표하지 않는다.
Locked Test·reserve·현재 목적의 allowlist 밖 payload는 이번 설계 작업에서 열지 않는다.

## 6. 채점: 두 편의 선호와 불호를 본다

단계2 출력은 `BASIC_RANK_TOP2`로 표기한다. 군집/맛 자격을 적용하기 전에는
TASTE2·DISCOVERY1 품질이나 최종 K를 평가한 것으로 보고하지 않는다.
두 편을 못 만든 상태는 공급 실패이며, 두 편이 있으나 평점이 없는 경우와 구분한다.

출력 A={i1,i2}에 대해 다음을 사용한다.

| 지표 | 정의와 해석 |
| --- | --- |
| MEAN_Q | `(Q(i1)+Q(i2))/2`. 평균적인 개인 선호, 클수록 좋음 |
| MIN_Q | `min(Q(i1),Q(i2))`. 두 편 중 낮은 선호도, 클수록 좋음 |
| HARM20 | `1[어느 한 편의 Q≤0.2]`. 기존 저선호 진단을 이어 쓰며 서비스의 허용 불호율을 20%로 정하는 뜻이 아님 |
| raw rating | 정확한 반별점 원값과 정책별 차이도 함께 보존. 서로 다른 사용자 원별점 평균만으로 순위를 정하지 않음 |
| supply/label coverage | 요청 사용자, 두 편 제공 사용자, 채점0/1/2편 사용자를 모두 보고. 실패·누락 사용자를 몰래 제외하지 않음 |

동점이 있는 midrank의 Q≤0.2가 항상 그 사용자의 정확히20% 영화를 뜻하지는 않는다.
평균 두 편의 원별점은 0.25 단위가 나올 수 있지만 사용자 입력 격자는 여전히0.5다.

### 미채점 처리

Q 미관측은 null이며 0점/불호가 아니다. 알려진 Q 합을 S, 미채점 수를 m이라 하면:

- MEAN_Q 범위: `[S/2, (S+m)/2]`.
- MIN_Q 범위: 미채점이 있으면 하한0, 상한은 알려진 Q의 최솟값. 둘 다 미채점이면 [0,1].
- HARM20: 알려진 저선호가 있으면1, 저선호가 없으나 미채점이 있으면 [0,1], 모두 채점되고 저선호가 없으면0.

정책 차이는 같은 사용자에서 계산한다. MEAN_Q 차이는 영화별 계수
`c_i=(1[i∈개인화목록]−1[i∈인기목록])/2`를 사용해 공통 미채점 영화를 상쇄한다.
`known=sum_known c_i*Q_i`라 하면 차이 범위는
`[known+sum_unknown min(c_i,0), known+sum_unknown max(c_i,0)]`다.
MIN_Q/HARM20은 우선 정책별 범위의 차이로 보수적인 범위를 보고한다.
미채점 값에 따라 판단이 바뀌면 서비스 우열·동등성·K는 미판정이다.

사용자 단위 차이를 사용자 동등 가중으로 집계한다. 같은 사용자의 여러 n·슬롯·반복 세트를
독립 표본으로 세지 않는다. 동일 사용자 재표집을 공유하는 paired bootstrap을 사용하며,
실행 manifest에 반복수·seed·신뢰수준·비교 family·다중비교 방식을 정답 개방 전에 잠근다.
단계2의 탐색 보고와 실제 채택을 구분한다. 실질 이득/손실 허용치가 없는 보고는 채택 판정을 내리지 않는다.

### 단계4에서 붙일 발견 평가 필드

T2에는 위 지표를 실제 슬롯에 적용한다. D1에는 `eligible`, `provided`,
`Q`, `connection_fact_verified`, `user_connection_judgment`, `discovery_completed`를 분리한다.
자격/연결 식은 단계4에서 정한다. 개인화 점수·유사도·분류 규칙 통과를 품질 정답으로 쓰지 않는다.
사용자 납득과 감상+평가 완료가 없으면 해당 값은 미관측이다. 지금 숫자로 채우지 않는다.

## 7. 실제 기준선과 아직 없는 연결

### P0 — 재현할 인기 기준 하나

[현행 core](../../../../recommender/src/feelm_recommender/service.py)와
[인기 계산](../../../../recommender/src/feelm_recommender/bias.py)의 prior50를 재현 기본안으로 쓴다.

```text
P0(i) = (sum_{T(i)} rating_raw + 50*mu_T) / (count_{T(i)} + 50)
mu_T = 허용 T의 평점 행 평균
```

이는 기존 실행 경로를 재현하기 위한 선택이다. prior100·COUNT·TMDB 인기를 동시에 추가 비교하지 않는다.
앞의 사용자 동등 prior pi0와 평점 행 평균 mu_T는 다르다.
n_i=0이면 P0는 mu_T이며 선호가 확인된 영화라는 뜻은 아니다.
서비스의 실제 VIEW/상승량 기반 Trending과 동일한 인기 정책으로 주장하지 않는다.

### M0 — Hybrid 대응 확인이 필요하다

현행 [policy.py](../../../../recommender/src/feelm_recommender/policy.py)는
`BAYESIAN_POPULARITY_ONLY`, `ranking_alpha=0`을 강제하고 `rank()`도 인기만 계산한다.
ALS가 있는 부분은 예상 별점 head다. 따라서 현재 core를 개인화 M0로 두면 P0와 M0가 사실상 같은
순위인데 “개인화가 인기보다 나은가”를 실험하게 된다.

M0 상태는 `MISSING_REPRODUCIBLE_HYBRID_CONFIG`다.
단계2 시작 전에 실제 공식 설정/산출물을 확보하거나, 공식 흐름을 따른 고정 연구 구성 하나를
별도 이름으로 명시해야 한다. 입력 표현을 정했다는 이유로 결합식·가중치를 암묵적으로 만들지 않는다.

| manifest 필수값 | 확인 목적 |
| --- | --- |
| model/objective/transform/regularization | raw·relative·binary와 학습/fold-in의 일치 |
| training users/time, feature/index, code/artifact hash | 평가자 혼입·좌표계/영화 매핑 혼동 방지 |
| content fields/checkpoint/pooling/normalization/missing | 어떤 콘텐츠 신호인지 재현 |
| blend formula/weights, candidate supplier, tie/fallback | 무엇이 점수를 만들고 콘텐츠전용 영화가 어떻게 들어오는지 |
| O/H/E/T/C versions, n grid, score seal, label access | 동일 입력·정답·후보 조건과 개방 순서 |
| metrics/inference, decision purpose, effect/loss margins | 탐색인지 채택인지와 판정 규칙 |

## 8. 단계2로 넘기는 조건

| 구분 | 필요한 조건 | 현재 상태 |
| --- | --- | --- |
| 문서·합성 계산 | 입력 규칙과 수식·미채점 처리 명시 | 이 설계로 점검 가능 |
| 모델 재현 점검 | P0 코드/식 확인, M0 실제 설정·학습/표현·산출물 대응 | P0 정의 확인, M0 대응 미확인 |
| 실데이터 score 생성 | 새 목적의 파일·역할·열·기간 allowlist, O/H/E/T/C와 n 범위·모델 hash 잠금 | 미완료. 새 payload를 열지 않음 |
| 채점·품질 보고 | 점수/목록 봉인, 허용 정답·고정 Q·관측 범위, 추론 설정 잠금 | 미완료 |
| 실제 정책 채택·최종 K | 실제 T/D 통합, 근거 있는 효과/손실 기준과 선택 외 확인자료 | 후속 단계 대상 |

정답이 부족하다고 인기 vs 개인화 질문을 Recall500이나 예상 별점 MAE로 바꾸지 않는다.
이 조건들은 성능 실행/판정에 적용한다. 문서 작성·모델 대응 감사·합성 점검이나
군집 자료 준비를 막는 전역 정지 조건이 아니다.

첫 후속 작업은 M0 설정/산출물 대응 확인과 데이터 역할 manifest 작성이다.
그 결과를 바탕으로 필요한 기본 추천 검증만 실행한다. 분류 방법·최종 K·입력 UI 최적화는
현재 단계의 빈칸을 채우는 수단으로 추가하지 않는다.

## 9. 설계 수식의 합성 점검

연구 데이터 대신 직접 만든 값으로 산술을 확인했다. 모델·제품 코드의 실행 검증은 아니다.
아래 상대 입력 예시는 실제 prior 대신 균등10칸 prior를 사용한다.

| 사례 | 확인 결과 |
| --- | --- |
| 반별점 격자 | 0.5/5.0 유효, 0/3.7/NaN 무효 |
| 사용자A는5점100건, B는0.5점1건의 prior | 두 사용자의 분포를 같은 비중으로 평균해 0.5점과5점 각각0.5 |
| O=[1.0,5.0] | q_input은 각각0.178571…, 0.892857… |
| O=[5.0] 또는 O=[3.0,3.0] | q_input은0.875 또는0.535714…로 동점/단일 입력을 자동 중립 처리하지 않음 |
| [5.0]에1.0 입력 추가 | 기존5.0의 상대값도0.875에서0.892857…로 재계산 |

| Q=[null,null] | 평균·최저·HARM20 모두[0,1] |
| 개인화=[0.8,X], 인기=[0.6,X], X 공통 미채점 | 평균 차이는 X가 상쇄되어0.1 |

독립 검토는 입력/모델 대응 감사, 평가 계약 감사, 최종 문서 검토로 분리했다.
