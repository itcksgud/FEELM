## 2026-09-07 온보딩 도입 목적 반영

사용자는 온보딩 도입의 목적이 사용자 취향 반영과 편의성을 함께 확보하는 것이며, 이를

- 무입력 대비 취향 반영, 상대값으로 처리한 별점 대조 대비 품질 유지·실측 부담 감소를 구분했다.

  측정을 분리했다. UI 비교·새 사용자 연구는 설계 대안이며 실행하거나 제품에 채택하지 않았다.

## 2026-09-07 인기→개인화 전환 K 반영

사용자는 입력이 없으면 인기 기반으로 추천하다가 개인화로 넘어갈 K를 결정해야 한다고
명시했다. F13에 전환 방향, P0/V10에 아직 정하지 않은 K·입력 집계 방법을 분리했다.
기존 공식 스냅샷의 S0 인기 가정은 당시 상태로 보존하고, 현재 연구 기준에는 후속 지시를
반영했다. 일반 인기3편으로 제품의 맞춤2·발견1 역할을 대체하지 않았다.

- §3.3에 고정 개인화 정책·인기 정책의 관측 입력 수별 비교, 슬롯별 실질 이득과 손실,
  최소 K 후보 선택·선택 외 자료 확인을 명시했다. §3.4는 그 K에 도달하는 온보딩 부담을 다룬다.
- K와 온보딩 완료 수를 구분하고, 온보딩 응답·감상 별점·혼합 이력의 정보량을 임의 합산하지
  않았다. skip 이후 감상 평가로 개인화에 도달하는 경로와 전환 후 전체 관측 이력 활용도 유지했다.
- `/root/personalization_switch_k_audit`가 기존 REC003/003B/019C/019D 문서를 읽기 전용으로
  확인했다. 기존 예상 별점 MAE의 K10과 조건부 입력 증가 효과는 서비스 전환 K의 확정 근거가 아니다.
- 후속 설계 검토에서 추천 정책이 변경되면 기존 K의 유효성이 보장되지 않는다는 지적을 반영해,
  입력·정책·역할·후보 버전과 후속 변경 시 전환 기준 재확인을 명시했다. 검토자는 대화 맥락을
  제공받았으며 새 대화의 blind handoff로 기록하지 않는다.

연구 문서만 수정했다. 실제 K를 선택하거나 새 성능 실험·사용자 연구·공식 계약 변경을 수행하지 않았다.

## 2026-09-07 기본 기능 우선으로 범위 축소

사용자는 나열한 문제를 모두 실험하기로 정하지 말고 기본 기능부터 확인하라고 지시했다.

모두 실행하거나 첫 실험의 선행조건으로 삼지 않는다. 정확한 서비스 K 선택도 첫 결과 뒤의 결정이다.

이번 변경은 범위 조정이며 성능 실험이나 제품 계약 변경을 실행하지 않았다.

## 2026-09-07 전체 단계 재설계와 독립 검증 완료

사용자의 요청은 기본 실험 한 개로 범위를 끝내는 것이 아니라, 최종 서비스까지의 전체 단계를
구상하고 결정 순서 자체를 검증하는 것이다. 이에 덧붙여 온 임시 우선순위 대신
experiment-design.md 본문을 단계1–6의 한 흐름으로 다시 작성하고 README를 한 페이지 요약으로 정리했다.
과거 이력은 아래 최신 설계의 실행 순서로 사용하지 않는다.

현재 순서: 입력·평가 기준 → 기본 추천 → K-means·8맛 → 맞춤2·발견1/입력 정책 →
고정 정책의 전환 K → 온보딩·서비스 확인.
필수 연결 점검과 결함이 있을 때의 추가 비교를 구분하고, 평가척도·모델·군집·입력 변경 시
영향받는 단계로만 돌아가는 규칙을 포함했다. 정확한 실험 수나 모델/내부 k 전수 탐색을 예약하지 않았다.
