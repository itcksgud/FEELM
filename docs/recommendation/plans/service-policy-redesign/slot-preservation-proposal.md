# 같은500/100 안에서 최초 슬롯을 보존하는 연구 제안

상태: DRAFT. 합성 검증용이며 공식 후보 정책으로 채택하지 않았다. 실제 사용자 재실험 없음. 2026-09-08.

REC034에서는500개에 있던 T 또는 D가100개 절단에서 사라졌다. 이 문서는 그 경계를 설명하는
대안 하나만 만든다. 공급 비교를 더 실행하거나 후보 수·임계치를 탐색하지 않는다.

## 현재 계약과 변경점

공식 [streaming-contract.md](C:/higher/projects/S15P21E106/docs/api/streaming-contract.md)의 경계는
Redis raw ALS 후보500개, 점수순 topn100개, Spring의 최신 제외·타입별 인터리브,
PostgreSQL20편 세트 버퍼다. Spring은 전달받은100개 밖에서 승격하지 않는다.
제외 후20편이 안 되면 남은 수만 저장하고,0편일 때 기존 실패 계약을 따른다.

제안은 **타입 적격 후보 중 T최대3편·D최대1편을100개 선정 시 먼저 포함**한다.
T3은 D없음→T3 fallback, D1은 최초 맞춤2·발견1에서 나온 수다.20편 전체의 구성 비율은 정하지 않는다.
낮은 점수의 후보가 원래 상위100 일부를 대체하므로 선택집합을 바꾸는 연구 정책 변경이다.
점수·ALS·500크기·100크기·Spring 책임을 바꾸지 않는다는 사실이 공식 채택을 뜻하지 않는다.

## 순서

1. 기존 점수순 raw500과 같은 snapshot에서 계산한 T/D 자격을 입력으로 받는다.
2. 그 순서에서 T앞3편·D앞1편을 확보한다. 타입 미배정 후보는 넘긴다.
3. 확보한 영화와 중복 없이 기존 점수순 적격 후보로 최대100편을 채운다.
4. 선택된 집합을 기존 점수순으로 정렬해 전달한다. 여기에서 T/D를 인터리브하지 않는다.
5. 이후 최신 제외·타입 처리·세트 버퍼는 현재 공식 책임에 남는다.

`scripts/feelm_slot_preservation.py`는1~4의 순수 함수다. ID와 타입만 가진 이미 정렬된 합성 입력을 받는다.
입력의 점수순·타입 snapshot을 실제로 보장하는 통합은 구현하지 않았다. 모델·사용자 데이터·Redis·PG 접근도 없다.

## 합성 반례로 확인할 범위

| 상황 | 확인할 결과 |
| --- | --- |
| D400편 뒤 T100편 | 전달100에 T3·D1 이상 포함. 최신 제외가 없으면 최초2+1 구성 가능 |
| 위100에서 보존한 T3편을 모두 최신 제외 | T0. 원500에 T가 남아 있어도100밖 승격은 불가 |
| T400편 뒤 D100편, 보존한 D1을 최신 제외 | 전달100에 D0. 원500에 다른 D가 남아 있어도 T3 fallback |
| 적격 T3편만 남음 |3편 공급.20편을 강제로 채우지 않음 |
| 적격 후보0편 | 빈 목록. 실제 서비스 실패 응답은 이 함수가 새로 결정하지 않음 |

보장할 수 있는 것은 **입력 raw500에 있는 T최대3·D최대1의 제외 전 포함**이다.
최신 제외 후 최초2+1,20편 버퍼 전체, 추천 품질, 새 입력과 재생성 사이의 일관성을 보장하지 않는다.
최신 제외 후에도500에서 가능한 슬롯을 반드시 공급하려면 제외 반영·추가 조회 또는 보충 경로의 계약 검토가 필요하다.
