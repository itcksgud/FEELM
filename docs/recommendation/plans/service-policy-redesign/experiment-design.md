# 요구사항에서 출발한 맞춤2·발견1 실험 설계

상태: DRAFT_DESIGN — 설계 단계. 실행용 프로토콜·제품 정책 승인이 아니다.
선행 기준: requirements-classification.md의 F01–F11, V01–V09, U01–U08.

결정할 질문은 **“어떤 상태의 사용자에게, 어떤 입력을 받아, 맞춤2편의 선호 품질과
발견1편의 새 맛 자격·취향 연결·선호를 동시에 만족시키는가”**다.
단일 Top3 점수나 후보 Recall500으로 답하지 않는다. 아래 순서대로 의존성을 해결하고
각 묶음에서 한 종류의 선택만 비교한다. 아직 없는 데이터와 미정인 의미를 숫자로 채우지 않는다.

## 1. 서로 다른 슬롯과 데이터 계약

| 항목 | 맞춤2편(T) | 발견1편(D) |
| --- | --- | --- |
| 제품 목적 | 개인 관측 선호로 좋아할 가능성이 높은 두 편 | 새 맛에 속하면서 기존 취향과 연결되고 받아들일 만한 한 편 |
| 자격 | 현행은 새 맛이 아닌 영화. 이 상호배타 제약은 V01의 우선 검토 대상 | 관측 평가의 맛별 count<τ, 미감상·관심없음 제외, 선정방식별 연결성 조건 |
| 선택 점수 | 협업/콘텐츠 개인화 점수 | 개인화 점수에 새 맛 자격을 적용하고 연결 방식/하한 비교 |
| 필수 출력 | 두 영화, type=TASTE, 실제 점수 근거 | 한 영화, type=DISCOVERY, 대표맛, 당시count/τ, 연결근거, 개인 선호 근거 |
| 평가 | 슬롯별 선호 효용·불호, 두 편 중 적합한 영화가 있는지 | 새 맛 자격·연결성·선호를 분리하고 그 교집합 확인 |
| 실제 서비스 결과 | 선택·감상·평가 결과를 슬롯에 연결 | 추천 당시 새 맛 자격과 이후 감상+평가 완료를 연결. 노출만으로 발견 성공 아님 |

입력 데이터는 `onboardingPreferences`, `observedRatings`, `watchRecords`, `dismissals`,
`exposures`, `movieFlavorAssignment`를 구분한다. 각 값의 관측 시점과 출처를 기록한다.
팝콘수는 관측된 유효 평가를 영화 대표맛별로 집계한다. 온보딩은 카운트에 들어가지 않는다.
숨긴 평점이나 미래 감상량을 입력 변환·새 맛 판정·본 영화 제외에 사용하지 않는다.
반별점은0.5 간격 원값을 보존하며 범위0.5~5.0은 연구 가정이다.

사용자 상태는 S0 입력없음, S1 온보딩만(평가0), S2 소수평가, S3 누적평가로 분리한다.
S2/S3 경계 숫자는 이번에 임의 확정하지 않는다. 이력량을 연속값/사전구간으로 보고하고,
특히 ‘모든맛count<τ / 익숙한맛 일부 / 모든맛count≥τ’를 함께 나눈다.
S1의 선호 입력 수와 팝콘수0을 혼동하지 않는다. S3에는 해당 시점까지의 전체 관측평가를
허용한다. S3를 profile30 가능자로 바꾸지 않는다.

## 2. 첫 묶음: 상태·자격 규칙과 후보 공급 검증

F01–F09를 지킬 수 있는지 먼저 확인하는 명세 검증이다. **추천 성능의 승자를 고르는 실험은 아니다.**

### 2.1 먼저 재현할 경우

합성 상태 fixture로 S0/S1, 평가가 한 맛에만 있음, 모든맛이적음, 모든맛이충분함,
선호는높으나경험적음, 경험은많으나저평가, 평가수정/삭제, LINK_CLICKED,
WATCHED_UNRATED, 관심없음, 추가추천, 같은타입후보소진을 만든다.

현행규칙 R0는 `D={f:count(f)<τ}`, `T=나머지`다. 연구대안 R1은 T를 개인선호로 선정하고,
D만 새 맛 자격을 추가하며 최종 두 목록의 영화중복을 제거한다. R2는 저이력 상태에만
명시적 예외를 두고 충분한 상태에는 R0를 유지한다. **R1/R2를 이미 채택된 정책으로 구현하지 않는다.**
τ=1과 API예시인3은 의미가 다른 두 연구 후보로만 비교 표를 작성한다. 예시3을 기본정책으로
간주하지 않는다. 모두0인 S1에서 R0가 T2를 만들 수 없음을 숨기지 않는다.

출력은 규칙×상태별 T/D 자격, 2+1 생성 가능 여부, 원인별 부족, 필요한 제품 결정이다.
이 표로 U01/U02의 의미를 확정할 수 있는 대안을 좁힌다. 품질데이터로 선택하지 못한
제품 의미를 합성 검증 통과만으로 확정하지 않는다.

S0(온보딩·평가 모두 없음)의 인기 TASTE 충원은 API-045와 streaming-contract §6.3에 있는
미확정 가정으로 별도 표시한다. 처리 주체·임계치는 미정이며 이 가정을 S1/저이력 전체에
확대해 역할 공백을 해결한 것으로 처리하지 않는다.

### 2.2 실제 후보 공급에서 확인할 항목

외부8맛 배정의 버전·실물과 허용 관측이력이 확인된 뒤 다음을 추적한다.

`원천 카탈로그 → 후보500 → 기본순위100 → 실제 제외 → T/D별 선택 → 2+1 → 버퍼/추가추천`

각 단계에서 T/D별 후보 수, T2와D1을 채울 수 있는 사용자 비율, 콘텐츠전용 영화의
유입 여부를 기록한다. 다음 실패 원인은 별도 코드로 보존한다.

- 새 맛이 없음 / 새 맛에 유효 영화 없음
- 후보500에서 소실 / Top100에서 소실
- 감상·관심없음 제외 후 소진
- 연결·선호 조건을 만족하지 못함
- TASTE2 부족 / 관측정보 부족 / 역할 규칙 미확정

발견 후보가 절단 과정에서 사라진 것을 제품상 ‘발견 후보가 원래 없음’으로 합치지 않는다.
타입별 공급 검증 뒤에만 V04의 보충/별도 후보 생성 실험을 설계한다. 단순 인기도250+
콘텐츠250를 먼저 고정하지 않는다. 후보 Recall은 이 단계의 원인 진단에만 둔다.

## 3. 두 번째 묶음: 슬롯별 선택 방식의 품질 비교

첫 묶음에서 역할·τ·외부맛배정·허용이력을 동결한 다음 수행한다. 시작 전에 아래 데이터
판정 가능성 조건과 점수식·모델·파라미터·표본을 실행계약에 고정한다.

### 3.1 맞춤2편 비교

- 같은 사용자·같은 관측 시점·같은 입력·같은T자격·같은D선정규칙으로 비교한다.
- 개인화 기준은 공식 ALS+콘텐츠 흐름을 재현 가능한 설정으로 정의한다. ‘ALS+콘텐츠’라는
  이름만으로 가중치가 정해진 것처럼 실행하지 않는다.
- 허용학습 인기도, 협업만, 협업+개인 콘텐츠 중 기존 근거로 줄인 최소 대조를 사용한다.
  입력 변환 비교와 모델 비교를 동시에 바꾸지 않는다. 개인입력 제거/교환은 귀속 대조다.
- T1·T2의 선호 효용과 불호, 두 편 중 적합한 영화 포함 여부를 중심으로 본다.
  D슬롯 및 전체목록 변화도 함께 기록한다. T목록과D목록의 중복 제거 영향은 숨기지 않는다.

### 3.2 발견1편 비교

- 동일 사용자의 맞춤2편을 고정하고 같은D자격/후보예산에서 발견 방식만 바꾼다.
- D0: 현재 개인화 점수 순으로 적격D에서1편. D1: 동일 개인화 점수에 관측한 선호영화와의
  콘텐츠 연결을 반영한1편. 연결을 쓰지 않는 방식/사용자입력교환은 귀속 진단으로 구분한다.
- 연결 후보식은 LIKE 또는 관측입력만으로 양의 선호가 확인된 anchor와의 콘텐츠 유사도다.
  max/평균·음수처리·특징·하한은 비교 전에 하나로 고정하며 결과를 보고 유리한 식을 고르지 않는다.
  anchor가 없으면 부족 상태로 기록한다. 숨긴 높은평가 영화를 anchor로 삼지 않는다.
- D0도 새 맛 자격을 지켜야 한다. 일반인기1편·다른장르1편을 동등한발견정책으로 비교하지 않는다.
- 새 맛 자격 통과, 연결 근거의 타당성, 발견1편 선호/불호, D제공가능률을 별도로 보고한다.
  많이 다른 영화일수록 좋은 발견이라고 점수화하지 않는다.
- 전체2+1의 선호품질과 비용도 확인하되 전체평균이 D실패 또는 T손실을 숨기지 못하게 한다.

### 3.3 먼저 확인해야 하는 정답의 범위

실제 추천된 T2/D1을 채점할 수 있는지를 **성능 실행 전에** 확인한다. 기존target20만으로
대부분의노출이미채점인 과제를 다시 만들지 않는다. T와D의 관측률·평가가능사용자 수를 별도 산출한다.
사용자행을 조용히 제거하지 않고 원 모집단과 제외/미판정 사유를 남긴다.

선정에 사용한 콘텐츠 유사도 상승이나 같은 하한 통과만으로 연결 품질이 개선됐다고
판정하지 않는다. 이는 구현·선정조건 진단이다. 관측한 anchor가 맞는지, 설명한 감독·장르·
줄거리 등 공통 특징이 실제 존재하는지는 별도 사실 검증으로 확인한다. 그 연결이 사용자에게
납득되는지와 좋은 발견인지 여부는 독립적인 판단 자료가 없으면 미판정으로 남긴다.
선정 점수 자체를 정답으로 사용하지 않으며 새 평가 수집을 이번 작업에 포함하지 않는다.

MovieLens가 제공하는 것은 영화 평점이다. 노출·관심없음·감상확인·새로움 느낌·발견완료가
관측된다고 가정하지 않는다. 기존허용 시간자료가 있더라도 새 목적에 맞는 사용자역할·기간·열·
cutoff 이전 전체 관측이력을 명시한 접근계약이 필요하다. 평가용 전체이력 histogram을
모델 입력/맛경험카운트로 전용하지 않는다. 이번 설계 중 raw평점·새라벨은 열지 않는다.

오프라인 선호정답은 정확한반별점과 사전고정한 개인상대 효용을 함께 보고한다. 절대/상대
채점과 입력인코딩은 별개다. 관측된T/D의 효용은 조건부 지표이며 미채점은불호/0점이 아니다.
완전카탈로그 출력에 미채점이 남으면 효용의 가능범위도 보고한다. 0~1효용에서 미채점은
[0,1]이고 두정책에공통노출된항목은 paired차이에서 상쇄할 수 있다. 가능한 미채점값에 따라
정책 우열이 뒤집히면 서비스 품질 결정을 내리지 않는다. 계산식·신뢰구간 구현은 별도 감사한다.

이미평가한영화만모은 풀은 필요한 경우 슬롯 알고리즘 진단으로 명명하며, 전체서비스노출
검증으로 승격하지 않는다. 기존030의 일반개인화귀속을 같은이름의새실험으로 반복하지 않는다.
신규실험은 외부8맛자격·관측경험량·T/D별선택이라는 추가 연결에 답해야 한다.

실제 FR-32 발견 성과는 추천 당시 자격과 이후 감상+평가가 연결되는 서비스 로그가 필요하다.
별도의 사용자평가를 설계한다면 ‘보고싶음/새롭다고느낌’과 실제감상·평가를 분리한다.
현재는 참여자모집·메시지전송·라이브노출·새데이터수집을 수행하거나 승인된것으로 간주하지 않는다.
정답범위가 충분하지 않으면 이 단계는 **실행불가조건을 보고**하고 Recall500으로 목적을 바꾸지 않는다.

## 4. 그 다음에만 비교할 입력·군집

V06 입력 정책은 같은사람·같은T/D판정대상에서 표시카드수·실제응답수·정보량·부담을
구분한다. 온보딩skip은 유지한다. binary와별점 UI를 비교해도 onboarding 기록이 팝콘을
만드는것으로 바꾸지 않는다. S3는 전체누적을 입력하고 신규prefix 실험과 분리한다.

V08은 외부8맛배정을 먼저동결해 내부군집의 추천효과를 비교한다. 추천점수/후보에 군집
가산·제한이없는 대조도 외부대표맛과D자격판정은 유지한다. 외부맛까지없애면 FR-12 비교가 아니다.
외부8종배정 자체를 비교하는 경우에는 별도 묶음으로 다루고 대표영화·해석·배정안정성·
감상카운트/발견이력변화를 평가한다. 새매핑으로D정답을바꾸고 기존정책과같은정답이라 주장하지 않는다.
