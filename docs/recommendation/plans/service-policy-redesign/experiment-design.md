# 추천 정책 실험의 전체 결정 순서

상태: DRAFT — 전체 설계와 검증 순서. 기본 추천의 후속 실행 결과는10절에 기록하며 제품 정책은 미확정이다.
기준: requirements-classification.md의 F01–F13, V01–V10, U01–U08.
현재 공식 문서 조회 기준: S15P21E106 HEAD/origin/develop `43e2884d295cc885c9d2b22958ef2be72ab04669`.
source-manifest.json은 이전 감사의 원문 스냅샷으로 보존한다. 후속 지시와 이번 검토는 review-log.md에 기록한다.

2026-09-08 최신 실행은 [REC041](../../experiments/rec-ev-041/RESULT.md)의 분류2안×발견 정책2안 진단이다.
원별점 ALS를 고정하고 맛은 T/D 자격에 사용했다. 초기 맛별 평균 gate 대신 개별 긍정 관측을 보존하며,
같은 n30·raw500→적격100·관측 입력 제외에서 연결형과 T3 점수 비교형을 실행했다.
발견 제공률은 개선 규칙97.2%→77.1%, 장르KM94.3%→58.9%다. 네 조합 모두3편을 제공했으나
최종 선택 슬롯의 이번 E 정답이0개여서 실제 불호 감소·품질 우위는 미판정이다.
아래 역사적 단계4 제안과 새 실행 계약을 구분한다. 현재 품질 자료가 준비됐다고 선언하지 않는다.

다음 판단 순서는 실제 슬롯의 선호·발견 납득 자료 연결 → 입력량/영화 선정 비교 → 고정 정책의 전환K다.
입력 축은 같은 최대30편의 hash/장르 다양성 우선 ONE 순서와 중첩 n0/5/10/30으로 별도 설계한다.
경험·제외 이력까지 O(n)으로 증가시키는 경우와 알려진 감상 ID 이력 W를 고정하는 경우를 구분한다.
W=30편은 감상 ID30개는 이미 안다는 조건이며 실제 신규 온보딩의 시간 흐름이 아니다.
이번에 선택기·n별 추천은 실행하지 않았다. 품질 자료가 없으면 공급 진단만 가능하며 그 결과로 K를 결정하지 않는다.
맞춤은 평균·낮은 쪽 Q·저선호 포함, 발견은 저선호 노출과 제공/보류를 함께 보고한다.
미관측 Q의[0,1] 식별 범위를 신뢰구간이나 불호0으로 해석하지 않는다. 실제0.5단위 별점과 상대 채점 Q는 별개다.

2026-09-08 입력 비교: [REC035](../../experiments/rec-ev-035/RESULT.md)의 원별점/상대값/이진환산 계산을 마쳤다.
원별점 ALS 기준을 유지한다. 고정 상대값 ALS는 불리했고 이진환산↔원별점 차이는 미확인이며 동등성은 입증하지 않았다.
아래 단계와 과거 기록은 유지하되 최신 실행 판단은 이 결과를 따른다.
후속 [REC036 현재 K-means 준비도 진단](../../experiments/rec-ev-036/RESULT.md)을 완료했다.
전체 배정 재현은PASS,120편의 중심·고정hash·경계 검수에서8맛 설명 준비도는INCONCLUSIVE다.
새 모델 탐색과 사용자 평점 접근은0회다. 현재 버전을 완성된8맛으로 전제한 품질 비교 진입은 보류한다.
사용자 후속 지시에 따라 [REC037 설명 보강 진단](../../experiments/rec-ev-037/RESULT.md)을 먼저 수행했다.
장르/키워드 c-TF-IDF 분리와 고정120편의 줄거리128구절 연결로01/02/04의 설명을 일부 보강했다.
03/05/06과07/08의 내용 구별은 여전히 부족해 현재8맛 준비도INCONCLUSIVE를 유지한다. 새 fit은0회다.
이어 사용자 요청에 따라 [REC038의 8개 구성 비교](../../experiments/rec-ev-038/RESULT.md)를 실제 수행했다.
같은 85,517편에서 6개 새 구성을 두 초기화씩 12회 fit하고 기존 두 기준안과 비교했다.
평가 전 봉인한 설명으로 공통 128편을 블라인드 대조한 결과, 단순 장르 규칙과 장르 K-means를 잠정 후보로 좁혔다.
단순 규칙의 배정 설명 수용은 53편, 장르 K-means는 44편이지만 유일 수용은 각각 21/27편으로 상충한다.
군집+4편 설명 구성의 탐색 결과이며 최종 8맛·추천 품질을 확정하지 않는다. 같은 영화 재채점·추가 모델 탐색은 종료했다.
이 문서의 과거 단계3 두 안과 REC034 공급 결과는 당시 기존 전체 텍스트 K-means를 뜻한다.
새 장르 K-means의 의미·8색 연결·슬롯 품질이 검증됐다는 뜻으로 바꾸지 않는다.

후속 [REC039](../../experiments/rec-ev-039/RESULT.md)는 고정 두 장르 후보의 추론 adapter와 자료 계약이다.
기존171,034배정 일치와16그룹×19장르 구성304행을 계산했다. 새 모델·군집 품질 평가가 아니라 실행 코드 적합성 확인이다.
단계4는 이 새 native 배정과 미지원/형식전용 상태를 직접 읽어 같은 raw500·n30·개별양수 규칙의 공급을 별도 확인해야 한다.
REC039에서는 해당 슬롯 계산을 실행하지 않았으며 이전 공급·품질 수치를 전용하지 않는다.

사용자의 후속 지적에 따라 [REC040 개선 규칙](../../experiments/rec-ev-040/RESULT.md)을 추가 적용했다.
기존8개 장르 묶음을 유지한 binary cosine 규칙 ONE이며 장르 순서·중복 의존을 없애고 정확 동점을 공개한다.
순서 반전 변화는 기존42,504편/새0편, 새 규칙의 동점은14,245편(16.7%)이었다. 배정 변경22,819편은 품질 향상 수가 아니다.
다음 단계4의 비교에는 이 RULE_GENRE_SET과 고정 KM_GENRE를 포함하고 기존 첫 장르 규칙은 원인 대조로 보존한다.
새 규칙의 그룹 크기·구성·삭제 민감도·ARI를 정확도나 우승 근거로 쓰지 않는다. 새 fit·128재채점·slot 실행은 없다.

## 1. 전체 흐름과 결정 순서

목표는 **입력 없을 때는 인기 추천으로 시작하고, 취향 정보가 쌓이면 외부8맛을 활용한 맞춤2·발견1을
제공하며, 온보딩이 그 정보를 적은 부담으로 확보하는지 확인하는 것**이다.
전체 단계를 설계하되 각 쟁점에 별도 실험을 만들지는 않는다. 필수 연결 검증과 결함이 있을 때의
추가 비교를 구분한다. 한 단계의 출력이 다음 단계의 입력이다.

| 단계 | 먼저 정하거나 확인할 것 | 수행할 검증 | 다음 단계로 넘길 결과 |
| --- | --- | --- | --- |
| 단계1. 입력·평가 기준 | 어떤 정보를 모델에 주며 추천 품질을 무엇으로 판단하는가 | 기존 근거 재사용 범위, 누출 방지, 실제 채점 가능성, 재현 설정 확인 | 입력·채점 계약과 인기/개인화 기준 설정 |
| 단계2. 기본 추천 | 보정 평균 별점·ALS 단독을 기준으로 기존 결합의 추가 이득 점검 | 입력이 개인 선호 순위에 반영되는지, 기준 대비 선호·불호와 분할 안정성 비교 | 기본 추천 경로와 남은 결함. 입력량 곡선은 탐색 근거 |
| 단계3. 8맛 분류 준비·내용 비교 | REC038의8구성 비교, REC039 추론 계약, REC040 개선 규칙 ONE | 같은 영화의 단일 배정, 설명 대조 및 전체 장르 규칙의 동작 진단 | 개선 규칙·장르 KM을 다음 비교에 포함. 최종 8맛 및 추천 품질의 승자는 보류 |
| 단계4. 맞춤2·발견1 및 입력 정책 | 두 분류안에 같은 의미의 유형 규칙을 연결하고 실제 입력을 적용 | 저이력 상태·후보 공급·T2/D1 품질과 비용 비교, 입력 정보 손실 | 선택 또는 잠정 보류된 분류안과 유형·후보·입력이 고정된 서비스 후보 |
| 단계5. 개인화 전환 K | 단계4의 고정 정책에서 언제 인기보다 유리해지는가 | 입력량별 비교 → 최소 K 후보 선택 → 선택 외 자료 확인 | 검증 범위와 버전이 붙은 전환 K 또는 미판정 |
| 단계6. 온보딩·서비스 확인 | 필요한 정보를 편하게 얻으며 실제 상태 변화에도 동작하는가 | K 도달 시간·이탈·부담, 수정/삭제·skip·추가추천·교체 통합 | 서비스 채택 근거와 아직 미검증인 사용자 성과 |

**단계1 → 단계2 → 단계3 → 단계4 → 단계5 → 단계6**를 최종 결정의 기준 순서로 사용한다.
단계1 뒤에는 단계3의 분류 실물 확인·배정 점검과 단계4의 규칙 초안 검토를 단계2와 병행할 수 있다.
다만 단계4의 최종 품질 비교는 기본 추천과 두 분류안이 모두 준비되어야 한다.
온보딩 비교 화면 준비는 먼저 할 수 있지만, 최종 K 도달 부담은 단계5 뒤의 고정 정책으로 판단한다.

## 2. 확정 사항과 임시 기준을 구분한다

| 구분 | 적용 |
| --- | --- |
| 사용자·제품 제약 | 외부 맛·색상8종, 영화별 대표 맛 하나, 맞춤2·발견1과 정해진 fallback, 별점0.5~5.0·간격0.5, skip, 온보딩은 팝콘을 만들지 않음, 무입력 인기→개인화 전환 |
| 처음 재현할 기준 | 공식 ALS+콘텐츠 흐름, ADR-0015의 내부 k=8·외부8 매핑, 현행 LIKE/DISLIKE 입력. 성능 최적값으로 선언하지 않음 |
| 기존 근거를 이어 쓸 처리 | 관측 별점의 사용자 상대값 해석. 실제 별점 원값은 보존하고, LIKE/DISLIKE를 숨긴 별점 강도로 복원하지 않음 |
| 이번에 다시 연 연구 선택 | 외부8맛은 유지하되 K-means 자체의 실효성은 TMDB 단순 분류와 비교. 공식 K-means 계약은 이번에 수정하지 않음 |
| 해당 단계에서 정할 사항 | 인기 점수·ALS/콘텐츠 결합 설정(단계1/단계2), 분류 두 안의 실물(단계3), 분류 선택·유형 규칙·저이력 처리·입력 집계(단계4), 전환 K(단계5) |
| 결함이 있을 때만 추가 비교 | 새 모델, raw/상대값 재대조, 내부 k 변경, 군집 가산점, 카드 선정 경쟁, 후보500/100 크기, 점진적 혼합·조건별 K |

임시 연구 설정을 팀 계약으로 승격하지 않는다. 특히 무입력/온보딩만 상태의 역할 공백, TASTE2 부족 처리 같은
제품 의미는 성능 점수가 높다는 이유로 임의 확정하지 않는다.
`k`는 내부 군집 수, `n`은 관측 입력량, `K`는 개인화 전환 기준이다.

## 3. 단계1 — 입력과 평가 기준을 먼저 정한다

구체 수식·입력 레코드·미채점 처리·P0/M0 대응과 실행 조건은 [1단계 설계](stage-1-input-evaluation.md)를 따른다.

“평가 방식”에는 서로 다른 세 가지가 있다. 이를 처음에 구분해야 뒤에서 좋은 모델의 기준이 바뀌지 않는다.

| 대상 | 이번 설계의 기준 |
| --- | --- |
| 사용자가 남기는 값 | 감상 별점은 정확한 반별점. 온보딩 LIKE/DISLIKE는 별도 신호. 모름·미응답·skip은 불호가 아님 |
| 모델에 넣는 값 | 별점 원값을 보존하고 관측된 입력과 학습 사전분포만으로 상대값 계산. 소수 입력·동점 보정과 중복/수정/삭제 의미를 버전으로 남김 |
| 추천을 채점하는 값 | 입력과 분리한 평가값으로 맞춤2의 평균 선호·불호/최저 선호, 발견1의 새 맛 자격·취향 연결·선호를 각각 판단 |

T/D 지표 정의와 미채점 처리는 단계1에서 정하고, 그 자격을 계산하는 제품 규칙은 단계4에서 구체화한다.
선정에 사용한 콘텐츠 유사도나 군집 규칙 통과 자체를 좋은 발견의 정답으로 쓰지 않는다.
연결 설명의 공통 감독·장르·줄거리 사실 검증과 사용자의 납득·선호 판단도 분리한다.

실행 전에 확정할 최소 설정은 사용자·학습/평가 역할·관측 cutoff·후보/제외 규칙, 입력 변환,
인기 점수 정의, ALS 학습/영화 factor·콘텐츠 checkpoint·결합식·seed와 버전이다.
ALS 학습 목표의 척도와 fold-in 입력의 척도·부호·가중치가 맞는지도 확인한다.
인기 기준도 학습 시점의 허용 자료로 계산한다. 실서비스 Trending 집계와 MovieLens 인기 proxy를
같은 데이터라고 부르지 않는다. 기존 설정을 찾거나 한 기준안을 명시하며 모델 순위표를 만들지 않는다.

품질 판단용 최소 효과·불호 허용치·신뢰구간·선택 절차는 결과를 열기 전에 정한다.
이 수치를 과거 실험에서 이유 없이 상속하거나 이번 설계에서 근거 없이 만들어 넣지 않는다.
현재 자료의 채점 가능 범위를 확인한 뒤 실행 계약에 수치와 근거를 채운다.

| [REC003B](../../evidence/REC-EV-003B-cold-start-blend.md) | 예상 별점 오차와 추천 순위 결과가 다를 수 있음 | 별점 MAE의 K10을 서비스 전환 K로 상속 |
| [REC019C](../../evidence/REC-EV-019C-validation-analysis.md)·[REC019D](../../evidence/REC-EV-019D-prefix-ablation.md) | 특정 조건에서 입력 증가와 인기 대비 개인화의 이득 관찰 | 서로 다른 사용자·평가창을 직접 비교하거나 T2/D1 전환 K 확정 |
| [REC027–030](../../evidence/REC-EV-027-030-masked-content-personalization-final-report.md) | 가린 관측 영화에서 구조 콘텐츠의 개인 선호 신호 확인 | 해당 모델을 서비스 ALS+콘텐츠 경로와 동일시, K30을 최적 입력 수로 채택 |
| [REC031 정정](../../experiments/rec-ev-031/POLICY-RETRACTION.md) | 후보 회수 진단과 서비스 품질은 다름 | Recall500으로 인기3편·발견 생략·군집 미사용 결정 |

기존 실험의 일반 개인화 신호를 같은 이름의 새 실험으로 반복하지 않는다.
이번 검증은 **현재 서비스 경로와 기존 실험 사이에 남아 있는 연결**에 한정한다.

## 4. 단계2 — 기본 추천 경로부터 검증한다

최초에는 보정 평균 별점 기준과 기존 ALS+콘텐츠 정책을 비교했다. 후속 단독·분할 반복 결과에 따라
이후 연구의 기본 비교 기준은 ALS 단독으로 두고 콘텐츠의 추가 이득·영화 지원 역할을 구분한다.
별점 기반 입력 경로를 먼저 재현하고, 온보딩의 실제 이진 입력 경로는 단계4에서 연결한다.
이 순서가 별점 UI 채택을 뜻하지 않는다. 후속 수치와 종료 판단은10절에 기록한다.

먼저 입력 변경이 사용자 벡터·순위·제외에 반영되는지 확인한다. 품질 비교가 추가로 필요한 부분만
동일 사용자·후보·누적 입력 순서·분리된 공통 평가대상에서 비교한다. 모델·결합 가중치·카드 정책을
동시에 바꾸지 않는다. 입력량별 곡선을 보더라도 여기서는 개선 방향과 K 후보 구간만 얻는다.

군집 자격을 아직 적용하지 않은 상위2편 평가는 **맞춤 추천용 순위 계산의 진단**이다.
이 결과를 실제 TASTE2·DISCOVERY1 검증이나 최종 서비스 K로 보고하지 않는다.

- 기본 경로가 재현되고 필요한 품질 근거가 있으면 단계4 통합에 넘긴다.
- 개선이 없으면 입력 변환·fold-in·후보 손실 중 원인을 좁힌다. 새 모델 탐색을 자동으로 시작하지 않는다.
- 품질을 채점할 수 없으면 데이터 문제로 남긴다. 코드가 동작한다는 사실은 품질 통과가 아니다.

## 5. 단계3 — 8맛 분류 두 안만 준비한다

최신 논의는 K-means가 이미 유리하다는 전제를 다시 검증하는 것이다. 기존 F12는 이전 합의와
공식 계약의 기록으로 남기고, 이번 연구는 다음 두 안을 비교한다. 공식 계약을 자동 변경하지 않는다.

| 안 | 준비할 것 |
| --- | --- |
| A. TMDB 단순 분류 | 사용할 메타데이터와 외부8맛 대응 규칙 하나. 복수 장르·누락·동률·신규 영화의 단일 배정 규칙 포함 |
| B. K-means 분류 | ADR-0014/0015의 표현·전처리·좌표계에 맞는 k=8 centroid와 외부8맛 매핑 하나 |

같은 영화 범위에서 두 안을 만들고 분류에 평가 정답을 사용하지 않는다. A의 임시 이름/규칙이나
B의 원시 cluster ID를 공식 맛으로 확정하지 않는다. 연구의 384차원 구조/임베딩 산출물을
공식 E5 표현·centroid와 확인 없이 섞지 않는다.
필수 확인은 외부8종·영화별 한 맛, 대표 영화/키워드의 해석, 배정 안정성과 누락 처리다.
TMDB 장르 개수와 외부 맛8개가 저절로 일치한다고 가정하지 않는다.

여기서는 사용 가능한 두 안을 준비한다. K-means의 실루엣이나 A의 간단함만으로 추천 품질의
승자를 정하지 않는다. **실제 선택은 단계4에서 같은 맞춤2·발견1 흐름에 붙여 비교한 뒤 한다.**
표현·메타데이터 활용이 함께 다른 경우 두 분류 정책 전체의 비교이며 K-means 알고리즘만의
인과 효과라고 주장하지 않는다. 최초 비교는 이 두 안으로 닫고 새 분류법·내부 k 전수 탐색은 추가하지 않는다.

## 6. 단계4 — 맞춤2·발견1과 실제 입력을 하나의 정책으로 만든다

### 먼저 결정할 제품 의미

분류된 맛을 쓰더라도 경험량·선호도·거리 중 무엇으로 T/D를 나눌지는 별도 결정이다.
후보 규칙은 아래 상태표에서 의미와 결과를 비교한 뒤 최소한으로 좁힌다.
기존 `count<τ이면 D, 나머지 T`는 미합의 분기다. 이를 정답으로 삼거나 τ=3 예시를 기본값으로 채택하지 않는다.

| 상태/질문 | 반드시 확인할 것 |
| --- | --- |
| 입력 없음 | 인기 시작. 취향 연결 근거가 없는 D의 처리와 실제 출력 구성을 명시 |
| 온보딩만 있음·팝콘0 | 선호는 있으므로 입력 없음과 구분. T2 자격을 어떻게 만들지 명시 |
| 경험은 많으나 저평가 / 경험은 적으나 선호 높음 | 감상량과 좋아함을 같은 기준으로 쓰지 않음 |
| 새 맛 없음 / 적격 영화 없음 / T2 부족 | 발견 부재→T3 계약과 T2 부족의 미정 규칙을 구분 |
| 새 맛 표시와 DISCOVERY 자격 | 팝콘 표시를 바꾼 것이 발견 추천의 품질 개선인지 혼동하지 않음 |
| 입력 수정·삭제로 n이 K 아래로 감소 | 즉시 인기 복귀인지 이전 전환 상태를 유지하는지 단계4에서 원칙을 정함. 정확한 K 값은 단계5의 대상 |

이 표의 제품 의미를 합성 검증 통과만으로 승인하지 않는다. 합의가 필요한 미정 규칙은
대안과 실제 영향이 보이는 상태표를 준비한 뒤 결정한다. 그동안 단계2·단계3의 독립 작업은 진행할 수 있다.

### 실제 추천 경로와 슬롯 품질

고정 후보 정책에 맛별 자격·제외·T2/D1 선정·중복 제거·fallback을 연결한다.
공식 `후보500 → 기본100 → 실제 제외/유형별 선정 → 2+1 → 버퍼20/추가추천`의 단계별 손실을
추적하되 수를 바로 최적화하지 않는다. 500과100은 각각 Redis 산출물이고20은 서비스 버퍼다.
적격 D가 원래 없는 것과 후보 절단으로 사라진 것을 구분하고, 콘텐츠전용 영화의 유입도 확인한다.

T2는 선호·불호, D1은 새 맛 자격·연결 근거·선호·제공 가능률로 평가한다.
문제가 드러난 경우만 선택 방식을 비교한다. T 방식 비교는 D 규칙을, D 방식 비교는 T2를 고정한다.
전체 평균이 어느 한 슬롯의 악화를 숨기지 못하게 한다.
군집 가산점이나 별도 후보 보충도 구체적인 실패 원인에 답할 때만 추가한다.

### 두 분류안 비교의 종료 기준

분류안 선택에서는 같은 사용자·평가 범위·후보 공급·랭킹·유형 규칙의 의미와 사전 입력량 n을
고정한다. 이 n은 최종 전환 K가 아니다. 안마다 유리한 유형 규칙/가중치를 따로 튜닝하지 않는다.
매핑이 달라지면 T/D 자격도 달라질 수 있으므로 실제 자격·출력·판정 가능률을 모두 남긴다.
공통 선호 정답과 독립적인 연결/새로움 판단을 사용하며 각 안의 자격 통과율만으로 우열을 정하지 않는다.

- 실질적 이득·허용 손실·해석/운영 비용·자료 정밀도와 종료 시점을 결과를 보기 전에 정한다.
- K-means가 추가 복잡성을 감수할 이득을 보이면 연구 채택 후보로 삼는다.
- 품질이 실용적으로 비슷하면 운영·설명이 단순한 쪽을 선택한다.
- 품질 판단 근거가 부족하면 우열은 미판정이다. 기본 요건을 충족한 단순안을 잠정 개발 후보로
  둘 수 있으나 성능 승리나 서비스 채택 근거로 보고하지 않는다. 두 안 모두 요건에 실패하면 그 결함을 먼저 고친다.
- 결과가 아쉽다는 이유로 세 번째·네 번째 분류법을 추가하지 않는다. 근거 부족을 더 많은 모델로 해결하지 않는다.

후속 K 확인에서 특정 입력 구간의 손실이 드러나면 해당 적용 범위를 제한하거나 이 두 안의
관련 조건만 재검토한다. 새 방법을 계속 추가하는 이유로 삼지 않는다.

### K를 정하기 전에 입력 정책까지 고정

현행 온보딩은 LIKE/DISLIKE이며 감상 별점과 팝콘을 만들지 않는다. 단계2의 상대 별점 입력을
이진 응답에 그대로 사용할 수 있다고 가정하지 않는다. 실제 응답만으로 개인화 입력을 만들고
입력 영화 중복·수정·삭제 및 전체 관측 이력의 처리를 명시한다. 이후 누적 사용자는 전체 관측
평가를 사용하며 K개만 남기는 입력 제한으로 바꾸지 않는다.

온보딩의 취향+편의성 주장을 평가할 최소 대조는 **현행 이진 응답과 사용자 상대값을 적용한
반별점 응답**이다. 같은 카드 선정·노출 조건에서 정보 손실을 확인하고 단계6에서 실제 부담을 비교한다.
이는 입력 정책 검증 하나이며 카드 선정·UI 대안 전체의 탐색이 아니다. 비교용 별점 온보딩도
감상 기록/팝콘을 만들지 않는다. 제품 입력 형식 변경은 이 설계만으로 채택하지 않는다.

MovieLens의 별점을 이진 응답으로 줄인 비교는 정보 축약의 대리 평가다. 실제 사용자가 같은
응답을 한다는 증거가 아니다. 숨긴 별점으로 이진 입력의 강도를 복원하지 않는다.
같은 응답 수의 정보 비교와 같은 시간의 효율 비교는 별개로 설계한다.

단계4 종료 시 인기 점수·개인화 모델·콘텐츠 표현·분류/맛 매핑·T/D 규칙·입력 처리·후보 공급과
수정/삭제에 따른 전환·역전환 상태 규칙을
한 버전으로 잠근다. 입력 후보 둘을 유지한다면 각각 별도 고정 버전으로 단계5에 넘긴다.
**최종 K는 이 출력이 준비된 뒤에만 고른다.**

## 7. 단계5 — 고정된 최종 정책에서 전환 K를 선택한다

유효 입력량 n마다 계속 인기 정책과 개인화 정책을 비교한다. 두 정책 모두 그 시점에 관측한
제외·맛별 자격·슬롯 규칙을 지킨다. 인기 대조의 후보를 개인화 점수로 먼저 잘라 놓아
이미 개인화된 대조가 되지 않도록 후보 생성까지 명시한다.

온보딩만·감상 별점만·혼합 이력은 경로를 구분한다. 좋아요1건과 별점1건을 같은 정보량으로
임의 합산하지 않는다. 혼합 경로의 집계가 미정이면 해당 경로의 K는 미판정이다.
무응답·모름·skip은 입력 건수에 넣지 않는다. 같은 영화 중복으로 K 도달을 부풀리지 않는다.

비교는 동일 사용자·관측 순서에서 입력을 누적하며 수행하고, 주 비교의 평가대상은 모든 입력과
분리해 공통으로 둔다. 큰 n까지 관측 가능한 사용자만 남긴 효과와 실제 사용자 K 도달률을 따로 보고한다.
미래 입력을 앞선 n의 상대값 변환·감상량·제외에 쓰지 않는다.

선택 기준은 인기 대비 실질적인 T2 품질 개선과 D1을 포함한 사전 손실 기준을 만족하는
최소 n이다. 여러 n의 선택 절차·불확실성·인접 구간 안정성을 결과 전에 정한다.
평균이 한 번 역전되거나 차이가 유의하지 않다는 이유로 우위·동등성을 선언하지 않는다.
선택하지 않은 허용 자료에서 전환 정책 자체를 확인한다. 단순 임계 정책이면 `n<K는 인기,
n≥K는 개인화`를 그대로 적용한다. 이전 전환 상태를 유지하는 정책을 단계4에서 정했다면
그 상태 전이까지 포함해 비교한다. 두 정책을 결과에 따라 사후 교환하지 않는다.

품질 자료가 부족하거나 독립 확인자료가 없으면 각각 미판정 또는 탐색 후보로 남긴다.
기준을 만족하는 n이 없으면 이번 범위에서 K를 찾지 못한 것이며 탐색 상한을 K로 강제하지 않는다.
공통 K에서 특정 상태·슬롯이 실패할 때만 조건별 K나 점진적 혼합을 후속 대안으로 연다.

## 8. 단계6 — 온보딩 가치와 서비스 상태를 최종 확인한다

단계4/단계5에서 고정한 입력 방식과 추천 정책으로, 같은 품질 기준에 도달하는 실제 시간·K 도달률·
중도 이탈·수정·주관적 부담을 비교한다. 현행 온보딩과 상대 별점 대조의 K가 다를 수 있으므로
같은 응답 수의 조작 횟수만 비교하지 않는다. 온보딩이 무입력 인기보다 취향을 반영하고,
상대 별점 대조 대비 품질을 유지하면서 부담을 줄일 때 검증 범위 내 도입 근거가 된다.
온보딩 완료/권장 수는 이 결과로 결정하며 전환 K와 자동으로 같게 두지 않는다.

실사용 비교의 참여자 배정·순서/학습 효과·추론 방식은 연구 전에 정한다.
MovieLens에는 완료시간·이탈·사용자 납득이 없으므로 이 자료만으로 편의성을 입증하지 않는다.
이 문서는 사용자 연구 설계까지 포함하되 모집·메시지 전송·라이브 노출·새 데이터 수집을 수행하지 않는다.

통합 확인에는 skip 후 감상 평가로 전환, 평가/온보딩 수정·삭제, K 아래로 다시 내려간 경우의
전환 처리, LINK_CLICKED·WATCHED_UNRATED 제외, 같은 입력의 결과 안정성, 추가추천2+1,
관심없음 같은 타입 교체/후보 없으면 null, 후보 소진과 fallback을 포함한다.
이때 단계4에서 정한 온보딩 응답 영화의 제외와 역전환 규칙을 검증한다. 아직 미정이면
단계4로 돌아가며 단계6에서 처음 정하거나 검증 중 임의로 바꾸지 않는다.
약한 행동 신호의 가중치 경쟁은 별도 결함이 있을 때만 수행한다.

실제 발견 성과는 추천 당시 자격과 이후 감상+평가가 연결되어야 한다(F11/FR-32).
새로워 보임·클릭·시청의도는 별도 관측이며 발견 완료와 같지 않다.

## 9. 품질 자료와 되돌아갈 단계

### 2026-09-08 사용자 후속 지시: 기본 ALS 입력 표현의 미검증 부분을 먼저 비교

현재 ALS 근거는 raw 학습/raw fold-in뿐이다. 콘텐츠/맛 해석의 상대값 근거를 상대 ALS 근거로 확대하지 않는다.

학습 목적과 같은 척도의 입력을 연결하고, 같은 관측 행·영화·정답과 train-only 수치 규모 보정으로 비교한다.
이진 대리는 상대 강도를 부호로 줄이는 정보 압축 진단이며 실제 UI 응답·누적 입력 과정과 다르다.
새 설계의 독립 검토·실행 계약·코드 검증 이전에 학습하거나 품질 수치를 만들지 않는다.
기존 분류/공급 준비를 폐기하지 않고 이 입력 경로 확인 뒤 재연결한다. K와 실사용 부담은 여전히 그 뒤다.

### 2026-09-08 추가 서비스 조건: 감상 별점 유지·온보딩 입력 연결

변환 목표는 실제 별점과 출처를 분리하고, 같은 영화의 현재 실제 별점이 있으면 이를 우선한다.
