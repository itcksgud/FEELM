# 다음 품질 판단에 필요한 최소 자료와 비교 양식

상태: DRAFT. 실제 모집·노출·응답 수집을 수행하지 않았다. 2026-09-08.

**다음에 알아야 할 것은 “추천3편을 채웠는가”보다 “그 사용자에게 볼 만한2편과 납득할 발견1편인가”다.**
REC033/034의 영화 배정·공급 결과는 이 질문의 정답이 아니다. 기존 MovieLens에서 평점이 없는 추천을
반복 조회하거나 미평가를 불호로 바꾸지 않는다. 먼저 수집할 값과 비교 순서를 고정한다.

## 최소 비교 단위

같은 사용자의 같은 입력 snapshot에서 A/B 두 분류안의 추천을 만든다. 역할 규칙·입력adapter·후보 정책은 같은 버전이다.
개인화와 인기의 전환 K 비교는 여기의 A/B 분류 비교와 섞지 않는다. 온보딩 UI도 한 번에 바꾸지 않는다.
추천을 생성·봉인한 뒤 응답을 받으며, 응답을 보고 같은 요청의 추천을 다시 고르지 않는다.

사용자에게 방법 이름을 숨긴 좌/우 목록을 보여주고, 순서를 균형 있게 배정한다. 같은 영화가 양쪽에 있으면
감상 여부·영화 자체의 시청 의향은 한 번만 받아 두 정책에 연결한다. 같은 영화도 A/B의 맛 배정이나 설명이 다르면
D의 새로움·연결 납득 응답은 정책별로 따로 받는다. 각 방법의 T2는 한 쌍으로 비교하고 D1은 따로 판단한다.
노출되지 않은 후보·미응답·모름을 실패나0점으로 기록하지 않는다. 부족 상태 자체와 응답 누락을 구분한다.

T2가 부족해 완전한 두 목록이 없으면 T2 짝 비교를 수행 불가로 남긴다. 그 사용자를 비교 대상에서 제거하지 않고
공급 실패와 평가 가능 분모를 함께 보고한다. D없음→T3이면 D질문은 해당 없음이며 세 번째 T를 D평가로 대신하지 않는다.
한쪽만 D가 있는 경우도 양쪽 D의 짝 비교로 합치지 않는다. D개별 응답과 공급 상태를 각각 유지한다.

## 실제로 받을 질문

| 대상 | 짧은 질문 | 저장할 값과 의미 |
| --- | --- | --- |
| 감상 경험 | 이 영화를 이미 봤나요? | YES/NO/UNSURE. 추천 제외의 실제 오류와 경험 미확인을 구분 |
| 영화 선호의 사전 대리값 | 지금 이 영화를 보고 싶은가요? | YES/MAYBE/NO/UNSURE. 시청 의향이며 실제 감상 만족도 아님 |
| T2 비교 | 지금 볼 영화 두 편으로는 어느 목록이 더 맞나요? | LEFT/RIGHT/TIE/UNSURE. 개인별 짝 비교 |
| D의 새로움 | 이 영화의 제시된 맛/유형은 아직 경험하지 않은 쪽인가요? | YES/NO/UNSURE. 모델 자격과 별개의 사용자 판단 |
| D의 연결 설명 | 제시된 이유가 본인 취향과의 연결로 납득되나요? | YES/NO/UNSURE. 사실의 정확성과 별개 |
| 연결 사실의 정확성 | 공통 감독/장르/키워드라는 사실이 맞나요? | 자료 검수자가 VERIFIED/INCORRECT/UNVERIFIED 기록. 사용자의 납득을 대신하지 않음 |
| 실제 감상 뒤 | 실제 감상했나요? 감상했다면 별점은? | 감상 확인과0.5~5.0·간격0.5 원별점. 클릭·의향을 감상으로 바꾸지 않음 |

정확한 맛 이름·색상은 검수된 표시 버전을 사용해야 한다. 현재 연구용 SEMANTIC 번호만으로 좋은 설명이라고 판단하지 않는다.
D를 보고 싶다고 답한 것과 FR-32의 감상+평가 완료에 따른 발견 성립은 별도 결과다.
관심없음·클릭·감상 기록·온보딩 응답도 서로 대체하지 않는다.

## 기록의 최소 열

공개 보고에는 집계만 쓴다. 로컬 비교 자료에는 다음 키와 값이 필요하다.

- request_key, participant_key: 이름/이메일을 넣지 않은 연구 식별자.
- input_snapshot_sha256, mapping/policy/adapter/candidate 버전 또는 hash, 추천 생성 시각.
- input_mode(RATING/BINARY/MIXED), 고유 유효 영화 수, skip/미응답 수. 응답수와 노출수 구분.
- 추천된 모든 영화 ID·실제 슬롯 타입·노출 순서·T/D 부족/fallback 사유. 미응답 영화도 행을 유지.
- A/B 짝 연결과 방법을 숨긴 좌우 배정. 같은 영화의 감상 여부·시청 의향은 공유하고 정책별 맛/설명 응답은 분리.
- 위 질문의 응답/UNSURE/미응답, 응답 시각. 실제 감상 뒤 평점은 별도 시점의 필드.
- D 연결 사실의 원천/ID·근거 영화와 자료 검수 상태, 사용자 납득 응답을 각각 저장.

평가 데이터를 실제 서비스 감상/온보딩 이벤트로 자동 기록하지 않는다. 별도의 연구 응답이다.
추천 시점 뒤의 답변을 같은 추천의 입력/제외/맛 경험으로 소급 사용하지 않는다.

## 판정 전에 잠글 것

이 문서는 모집 수나 채택 임계치를 임의 확정하지 않는다. 다음 항목을 입력한 뒤 평가 계약을 봉인해야 한다.

1. 어떤 대상 사용자·입력 상태를 판단하는지와 모집/누락/반복 노출의 처리.
2. T2의 최소 의미 있는 선호 개선과 허용할 D1 손실. “후보를 채움”의 개선으로 이 값을 대신하지 않음.
3. 필요한 정밀도에 따른 표본 수·최대 수집량·종료 시점. 결과를 보며 유리해질 때까지 표본을 늘리지 않음.
4. 주 지표와 T/D별 보조 지표, 동률·UNSURE·미응답 분모, 동일 사용자의 반복 비교에 대한 불확실성 처리.
5. 한 자료로 정책을 고른 경우 별도 확인 자료를 어떻게 확보할지. 탐색 자료를 새 확증으로 부르지 않음.

자료를 받으면 먼저 노출/누락·실제 감상 경험을 감사하고, T2와 D1을 각각 보고한다.
모든 슬롯을 합친 하나의 평균이 D1 손실이나 T2 불호를 숨기지 않게 한다.
필요한 정밀도를 얻지 못하면 미판정이며, 새로운 모델을 추가하는 이유로 삼지 않는다.

## 온보딩의 취향+편의성 주장

현행 LIKE/DISLIKE와 반별점 응답을 비교하려면 같은 카드 선정·노출 조건과 각 입력의 실제 adapter가 먼저 준비돼야 한다.
같은 응답 수의 정보 비교와 같은 시간의 효율 비교를 분리한다. MovieLens 별점을 이진화한 proxy는 실제 응답 부담 자료가 아니다.
편의성에는 시작~종료 시간, 노출/유효응답/skip 수, 중도 이탈, 체감 부담이 필요하다.
온보딩 응답은 감상 평점/팝콘을 만들지 않는다. K가 정해지기 전부터 권장 응답 수나 K 도달 편의성이 검증됐다고 주장하지 않는다.

현재 준비된 것은 이 비교 양식과 데이터 역할이다. 실제 모집·배포·타인 연락·응답 수집은 수행하지 않았다.
