# ALS에서 절대 별점·상대값·이진 선호를 비교하는 설계

상태: SUPERSEDED — 아래 세 모델 우선 실행 계획은 후속 서비스 조건에 따라 [온보딩→별점 ALS 연결 설계](onboarding-rating-bridge.md)로 대체했다. 새 학습·채점은 실행하지 않았다. 2026-09-08.

아래는 당시 연구 설계의 보존본이다. 전체 이진 ALS 학습을 현재 서비스 연결의 필수 단계로 읽지 않는다.

**먼저 세 표현에 맞춰 학습과 신규 사용자 계산을 일치시킨 ALS를 비교한다.**
이는 다음에 먼저 수행할 기본 추천 실험이다. 이미 준비한8맛·공급 결과는 보존하고,
이 입력 경로를 확인하기 전에 최종 통합 정책·K로 넘어가지 않는다.

## 지금까지 빠져 있던 비교

REC032는 원별점으로 ALS를 학습하고 신규 사용자에게도 원별점을 넣었다.
`scripts/rec_ev_032_basic.py`의 train은 `implicitPrefs=False`, `nonnegative=False`이고,
fold_in은 정확한 반별점만 허용한다. 명시적인 사용자/영화 bias나 centering은 없다.
상대값 계산 함수는 별도로 있지만, 해당 ALS의 학습 목표나 fold-in에 적용하지 않았다.
과거 콘텐츠·맛 해석에서의 상대값 근거가 상대값 ALS의 우위를 입증한 것은 아니다.

LIKE/DISLIKE는 사용자가 직접 표현한 선호다. 따라서 이진 응답이라는 이유만으로 콘텐츠 방식만 써야 하거나
`implicitPrefs=True`로 바꿔야 하는 것은 아니다. 관측된 두 범주의 목표를 근사하는 explicit ALS도 연구 후보가 된다.
기존 raw adapter의 타입 차단은 잘못된 숫자 대입을 막는 장치이며 ALS가 이진 선호를 학습할 수 없다는 제약이 아니다.

## 학습값도 바꾸는 이유

ALS는 관측 목표 `t_ui`와 사용자·영화 벡터의 내적이 가까워지도록 학습한다.
학습된 영화 벡터를 고정한 신규 사용자 계산은 아래와 같다.

```text
p = (Y_OᵀY_O + λ·|O_supported|·I)^(-1) Y_Oᵀ t_O
score(i) = pᵀ y_i
```

원별점을 목표로 만든 영화 벡터에 `4.5` 대신 상대값 `0.6` 또는 LIKE의 부호 `+1`을 넣으면
새 입력으로 무엇을 맞추려는지 달라진다. 따라서 그 숫자만 교체한 결과를 세 표현의 공정한 비교로 삼지 않는다.
기존 영화 벡터를 재사용하는 별도 변환/추정 adapter를 설계할 수는 있다. 그때의 질문은
“이 영화 벡터에 어떤 입력 연결이 좋은가”이며 이번 학습 표현 비교와 다르다.

**이번 비교에는 표현별 학습이 필요하다. 모든 서비스 구현에서 반드시 세 모델을 유지해야 한다는 뜻은 아니다.**
정책별 학습은 한 번이고, 평가 사용자가 입력5개에서10개로 늘릴 때마다 영화 모델을 다시 학습하지 않는다.
해당 영화 벡터를 고정하고 사용자 벡터만 다시 계산한다.
미관측 사용자·영화 쌍을0점/싫어요로 채우지 않는다. 이번 explicit ALS는 실제로 관측된 공통 행만 손실에 사용한다.

## 최소 비교: 세 정책

| 정책 | 학습 사용자의 목표 | 신규 평가 사용자가 제공한 입력의 처리 |
| --- | --- | --- |
| ABSOLUTE | 원별점0.5~5.0, 간격0.5 | 현재 입력의 원별점 |
| RELATIVE | 허용된 학습 이력 안의 개인 상대값 | 현재 입력 O(n)만으로 계산한 개인 상대값 |
| BINARY_PROXY | 위 상대값의 양수/음수 부호 | 같은 O(n)에서 만든 LIKE/DISLIKE 대리 부호만 사용 |

학습/평가 사용자·영화·입력 순서·후보·제외·평가 정답은 공통으로 둔다.
먼저 ABSOLUTE↔RELATIVE로 상대 표현 정책의 효과를, RELATIVE↔BINARY_PROXY로 상대 강도를 없앤 영향을 본다.
학습 표현과 신규 입력 표현을 함께 바꾸므로 **신규 입력만 바꾼 인과 효과**라고 해석하지 않는다.
두 범주의 실제 UI 응답은 아직 없으므로 마지막 행은 MovieLens에서 만든 대리 실험이다.

기존 한 개발 분할과 n=5/10/30을 재사용한다. 모델별 한 번 학습해 각 n에서 사용자 계산만 바꾼다.
raw checkpoint는 학습 행·설정·목표·척도가 정확히 일치할 때만 재사용한다.
공통 마스크 때문에 학습 행이 달라지면 ABSOLUTE도 새로 학습한다. 최초 범위는 최대 세 fit이며,
세 입력량마다 재학습하거나 새 분할·군집·콘텐츠 모델을 추가하지 않는다.

## 변환과 동일 입력 조건

상대값은 기존 사용자 동등 학습 prior·수축5의 mid-CDF를 재사용한다.

```text
w(u,r,O) = 2·[N_O(<r) + 0.5·N_O(=r) + 5·G_train(r)]/(|O|+5) - 1
binary_proxy = +1 if w > 0; -1 if w < 0; unresolved-neutral if w == 0
```

이는 평균 차감이나 z-score와 다른 정의다. 이번에 상대값 정의 여러 개를 함께 탐색하지 않는다.
학습 사용자에는 학습 역할로 허용된 기록만 사용하고, 평가 사용자에는 매 n의 O(n)만 사용한다.
입력5개의 상대값에 나중의30개·평가용 전체 이력 H·정답 E를 넣지 않는다.
현재 O(n)의 상대값을 모두 계산한 뒤 factor 지원 여부를 적용한다. 모델마다 지원하는 영화만으로 상대값을 다시 정의하지 않는다.

이진 부호는 상대 선호 강도를 버리는 대리 비교를 위한 한 규칙이다. 실제 사용자가 상대값의 부호대로
LIKE/DISLIKE를 누른다고 가정하지 않는다. 과거 수축10·±0.15를 가져오거나3.5점 같은 새 절대 임계치를 병행하지 않는다.
O(n)이 바뀌면 상대값뿐 아니라 이전 영화의 대리 부호도 바뀔 수 있다. 따라서 각 n은 정보 압축을 비교하는 별도 상태이며,
실제 사용자의 LIKE/DISLIKE 응답이 수정 없이 그대로 누적되는 과정이나 시간에 따른 K 실험으로 해석하지 않는다.

`w==0`은 DISLIKE가 아니며, 실제 이진 입력에 세 번째 숫자0으로 주입하지 않는다.
사전 자료 점검에서는 정답을 열지 않고 학습 행과 각 O(n)의 중립 수·지원 감소만 집계한다.
본 비교는 중립 행을 **세 정책 모두의 학습/사용자 계산에서 동일하게 제외하는 공통 마스크**를 사용한다.
상대값은 제외 전 허용 기록에서 한 번 계산하고 마스크 뒤에 반복 재계산하지 않는다.
이렇게 하면 세 정책이 ALS에 사용하는 영화 ID는 같지만 기존 raw 전체행 실험과 다른 범위일 수 있다.
원래 관측 수 n과 실제 공통 유효 수 n_used, factor 지원 수 n_factor를 각각 보고한다.
중립 제외로 일부 사용자/영화가 미지원이 되거나 유효 입력0이 되면 집계와 fallback에 남기며 사용자를 조용히 탈락시키지 않는다.
결론은 이 공통 마스크 범위의 표현 비교다. 실제 이진 응답 수·온보딩 부담을 측정한 결과가 아니다.

## 숫자 크기와 정규화의 혼동을 통제한다

원별점은0.5~5.0, 상대값은-1~1, 이진 부호는±1이다. λ=0.1이라는 숫자만 같아도
손실과 규제의 상대적 크기가 같다고 보장할 수 없다. Spark의 ALS-WR은 관측 개수로 규제를 조정하지만
서로 다른 목표값의 단위 차이를 자동으로 없애는 것은 아니다.

이번 최소 통제 제안은 **공통 마스크의 학습 목표 RMS를 원별점 RMS에 맞추는 양의 상수 배율**이다.

```text
s_j = sqrt(mean_training_retained(t_j²))
c_j = s_ABSOLUTE / s_j
target_for_ALS = c_j · t_j
```

평균을 빼지 않고 한 정책 전체에 상수 하나만 적용한다. 학습 목표로 계산한 c_j를 고정해 신규 사용자 입력에도 똑같이 쓴다.
개인별 재정규화나 숨긴 원별점 강도 복원은 없다. 이진 정책은 두 범주 모두 같은 크기의 ±c_binary를 쓴다.
DB/입력 packet의 원별점과 enum은 그대로 보존하고 모델 내부 목표값만 변환한다. RMS0 또는 비유한 값이면 실행 실패다.
이는 수치 규모를 맞추는 연구 설정이며 모든 분포의 최적 λ나 완전한 동등성을 보장하지 않는다.
rank32·seed42·λ0.1은 재현 기준으로 두며, 각 정책의 목적함수/유한값·10회 반복의 학습 상태도 기록한다.
학습이 충분하다는 근거가 없으면 알고리즘 최종 우열로 확대하지 않고, 결과를 보고 특정 안만 더 학습하지 않는다.
별도 λ 탐색·bias 모델·implicit ALS·BPR까지 동시에 추가하지 않는다.

## 무엇으로 차이를 판단하는가

세 모델의 raw RMSE·상대값 RMSE·이진 RMSE는 단위가 달라 직접 승패를 매기지 않는다.
모든 추천을 같은 사용자·같은 정답으로 판단한다. 기존 관측 영화 안의 Q 기준에서
상위2편의 평균 선호·낮은 쪽 선호·저선호 포함을 재사용하고, 사용자별 짝 차이와 불확실성을 보고한다.
분모·차이의 단위·평가 가능/미지원 수를 같이 남긴다. 원별점도 보존한다.
Q가 상대 순서라는 평가 목적을 명시하고, 한 표현의 모델 출력값 자체를 정답으로 사용하지 않는다.
기본 추천 성분의 진단이므로 이 상위2편을 최종 T2/D1 서비스 평가라고 부르지 않는다.

이전 실제 추천은 미평점이 많았으므로 우선 기존 관측 영화 안의 부분순서 비교를 사용한다.
새 추천의 만족도·발견 성공률·최종 K는 이 결과만으로 정하지 않는다. 실제 온보딩 응답과 부담도 별도 확인한다.
선택된 정책은 이후 이미 준비한8맛·역할·공급 규칙에 연결하고, 고정한 통합 정책에서 K를 확인한다.

## 실행 전 절차와 이번 문서의 완료 범위

이번 작업은 빠져 있던 비교와 학습 일치 원칙을 결정하는 설계다. 아직 학습/채점하지 않았다.
다음 실행에서는 기존 원천의 hash·학습자 배제·공통 마스크/규모 보정·prior 계산을 명시한 접근 계약을 만든다.
표현/척도 함수와 typed adapter, 중립/0입력/미지원/λ 처리의 합성검사, 평가 비교 수·구간/종료 기준을 먼저 봉인한다.
그 설계·코드의 독립 검토 뒤 최대3개 정책을 학습하고, 세 정책 점수를 모두 봉인한 다음 E/H를 연다.
실행 후에는 다른 검토자가 변환·학습자 배제·점수·짝 차이를 독립 검산한다.
이미 개봉된 개발 자료를 새 확증으로 부르지 않으며 Locked Test/reserve 접근을 이 문서로 허용하지 않는다.
