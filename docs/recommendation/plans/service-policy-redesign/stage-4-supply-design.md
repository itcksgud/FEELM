# 단계4 후보 공급 진단 — 실행 전 초안

상태: DRAFT. 아직 실데이터 실행 계약·코드 검토를 통과하지 않았다. 2026-09-08.

**다음 질문은 “A/B 중 누가 더 좋은 추천인가”에 앞서, 같은 규칙으로 맞춤2·발견1을 실제로 채울 수 있는가다.**
[역할·상태 제안](stage-4-policy-proposal.md)의 규칙 하나를 적용하되 실제 발견 품질은 이 진단으로 결정하지 않는다.
REC033 완료 산출물의 독립 검산 후 두 배정 파일을 고정하고 별도 실행 검토를 받아야 한다.

## 읽을 자료와 읽지 않을 자료

- REC032의 이미 고정된 R0 관측 입력30개, 같은 ALS factor, 학습 prior를 재사용한다. 사용자2,180명 전체를 유지한다.
- REC033의 같은85,517편 A/B 배정, 공통 ID와 원천 메타데이터를 사용한다. 공통 TMDB 장르·감독·키워드 ID로 연결 사실을 계산한다.
- 새 ALS 학습·새 군집·새 n·새 seed·새 후보 크기 탐색은 없다. 두 안에 같은 raw ALS 순위를 적용한다.
- 사용자 평가 E, H histogram, label-extension, raw MovieLens archive, Locked Test/reserve는 읽지 않는다.
- n=30은 이미 준비된 한 관측 상태이며 최종 K도 온보딩 권장량도 아니다. 개인화 강제 진단이라고 표시한다.
- 입력30개 밖의 과거 감상을 알 수 없으므로 경험 기준은 **관측 입력 내 미경험 proxy**다.
  실제 서비스 감상 경험0·새로운 맛·발견 성공률로 부르지 않는다. 입력30개를 전체 사용자 이력으로 해석하지 않는다.

## 고정할 계산

원별점0.5단위30개에서 ALS factor가 있는 영화만 raw explicit fold-in에 사용한다. 기존 rank32·reg0.1과
`reg × n_factor`를 유지한다. 사용자 내 점수 내림차순·movie_id 오름차순이다. factor 없는 영화에는 임의 ALS점수를 주지 않는다.
factor가 없는 영화의 메타데이터상 T/D 자격은 별도 공급 손실로 집계한다. 콘텐츠 결합·보충 모델을 이번에 추가하지 않는다.
ALS 입력이 전혀 없으면 비활성 사유를 남기고 P0나 콘텐츠로 조용히 대체하지 않는다.
fold-in 벡터가0/비유한값이거나 선형계 풀이가 실패하는 경우도 같은 방식으로 비활성 사유를 남긴다.
해당 사용자를 전체2,180명 분모에서 제외하지 않는다. 별도 모델·인기 fallback으로 순위를 섞지 않는다.

맛별 선호는 같은30개 원별점의 상대 weight와 동일 학습 prior로 계산한다. A/B에서 영화 배정만 다르다.
T는 평균weight>0 맛, D proxy는 관측 경험도 긍정도 없는 맛이고 긍정 맛 안에 속하면서 weight>0인 입력 영화와
장르/감독/키워드 ID가 겹치는 영화다. 두 조건을 모두 만족한 입력 영화만 연결 anchor로 사용한다.
미배정과 T/D 어느 쪽도 아닌 영화는 분모에서 숨기지 않는다. 안별 미배정 입력 수와 유효 긍정 anchor 수도 사용자별 감사에 남긴다.

## 후보 단계의 의미부터 구분한다

공식 candidates500은 **제외 전 ALS순위**다. 이 단계에서 이미 입력 영화를 빼면 공식 후보 손실을 재현할 수 없다.
공식 topn100은 type을 가진 점수순 목록이며 Spring이 이후 감상·관심없음 제외와 슬롯 구성을 수행한다.

제안의 T/D는 전체 영화를 둘로 나누는 규칙이 아니므로 둘 다 아닌 후보가 생긴다. 이번 연구의 단일 연결안은
500 안에서 타입 적격 후보만 남긴 뒤 그중 점수순100을 만드는 것이다. 이는 미정 연결 규칙의 연구 제안이며
현재 제품 구현이 정확히 이렇게 동작한다는 뜻이 아니다. 남은 후보가100보다 적으면 그대로 두고 추가 생성하지 않는다.

| 단계 | 남기는 수치 |
| --- | --- |
| 전체 공통 카탈로그 | A미배정, 긍정/관측경험/미경험 맛 수, T/D/어느쪽도아님 영화 수 |
| ALS 지원 영화 | 메타데이터상 적격이지만 factor 없어 점수화할 수 없는 T/D 수 |
| 제외 전 ALS500 | T/D/어느쪽도아님 수, 관측 입력 영화 수 |
| 500 중 타입 적격 | T/D만 남긴 수. 역할이 없는 후보를 T로 재명명하지 않음 |
| 타입 적격 중100 | T/D 수와 잘려나간 적격 D |
| 관측 입력30개 제외 후 | 실제 T/D 공급 수. 실제 서비스 감상/관심없음 이력 전체 제외를 재현했다고 하지 않음 |
| 최초 슬롯 | T2/D1, D없음→T3, T부족, D도T3도부족을 각각 집계 |

전체 ALS 지원 목록에서 같은 제외·타입·슬롯 규칙을 적용한 값도 진단용 상한으로 계산한다.
실제 서비스 후보를 전체로 늘리는 정책은 아니다. 이 상한에서 D가 있고500이나100에서 없으면 후보 절단 손실이다.
전체 메타데이터에도 D가 없는 경우와 ALS 지원에서 소실된 경우를 따로 기록한다.

## 무엇을 결론으로 말할 수 있는가

사용자별 A/B를 짝지어 T2/D1 제공 여부·T부족·D 소진 원인을 집계한다. 사용자마다 나온 영화 목록과
연결 사실은 로컬 감사용으로만 남기고 보고에는 집계만 쓴다. 제외 실패·중복·미배정의 강제 타입 부여는0이어야 한다.
순위·별점·연결 사실을 추천 만족도의 정답처럼 채점하지 않는다. 더 많이 D를 줄 수 있다는 사실만으로 A/B 승자를 정하지 않는다.

실행 전에 입력/출력/hash·코드·합성 테스트·시간/메모리 상한·부분 실행 보존·완료 재사용 계약을 추가로 봉인한다.
종료는 이 한 관측 상태의 A/B 공급 진단1회다. 결과가 나쁘다고 τ·k·n·500/100 크기를 연속 탐색하지 않는다.
이후 품질 비교·이진 랭킹 adapter·전체 감상 경험 자료·실질 효과 기준 중 어떤 결정을 먼저 해야 하는지 정리한다.
