# 자는 동안 진행한 결과와 다음 순서

이 문서는 야간 완료 당시의 요약이다. 사용자 복귀 뒤 진행한 최신 원별점/상대값/이진환산 비교는
[REC035 세 결과 정리](../../experiments/rec-ev-035/RESULT.md)에서 확인한다. 아래 기존 결과는 보존한다.

2026-09-08. 연구 문서·코드만 변경했다. 각 실행 전에 독립 검토하고, 실행 뒤 다른 검토자가 결과를 다시 계산했다.

**기본 ALS 검증 다음으로 두8맛 분류안을 만들고, 맞춤2·발견1을 실제로 구성할 수 있는지까지 확인했다.**
그 과정에서 맛별 평균 때문에 개별 선호 근거가 사라지는 문제를 발견했고, 대안 하나를 검증했다.
이제 같은 공급 실험을 더 늘릴 필요는 없다. 다음은 실제 온보딩 입력 경로와 추천 품질 판단을 연결하는 단계다.

## 무엇이 나왔는가

1. **ALS는 계속 연구의 기준이다.** 학습자와 평가자를 바꾼3회 모두 원별점30개 입력에서 관측 영화 안의 이득이 재현됐다.
   평가자의 평점은 해당 회차 학습에 들어가지 않았다. 이것은 K=30이나 실제 새 추천 품질의 통과가 아니다.
2. **비교할8맛 두 안을 준비했다.** 같은85,517편에 TMDB 장르를8그룹으로 묶는 안과 K-means8 안을 만들었다.
   K-means가 더 좋은지는 아직 모른다. 공식 맛 이름·색상·제품 정책은 바꾸지 않았다.
3. **추천을 구성하는 규칙의 영향이 컸다.** 원안은 한 맛의 평균 선호가0 이하면 그 맛을 맞춤에서 제외했다.
   개별적으로 좋아한 영화가 있어도 평균에서 상쇄되는 경우가 있었다. 대안은 그 개별 양수 근거를 유지했다.

| 같은2,180명·입력30개에서 맞춤2+발견1 구성 | 원안 | 대안 |
| --- | ---: | ---: |
| 장르8그룹 | 2,168명 | 2,171명 |
| K-means8 | 2,026명 | 2,180명 |

기존에 구성되던 사용자가 새로 실패한 경우는0명이었다. **2,180명 전원에게 구성했다는 것은 만족도100%가 아니다.**
추천 영화와 발견의 연결 근거도 바뀌었으므로, 새 추천을 사용자가 더 좋아하는지는 별도로 판단해야 한다.
실제 전체 감상 이력이 아닌 이번 입력 안의 경험만 썼다. 대안 하나로 이번 공급 비교를 종료했다.

## 다음에 쓸 준비도 마쳤다

- 원별점0.5~5.0·간격0.5와 실제 LIKE/DISLIKE를 서로 다른 입력으로 검증한다.
  LIKE의+1을 별점1.0으로 오해해 ALS에 넣는 경로를 차단했다. 삭제·중복·이전 이벤트·혼합 입력도 합성 검증했다.
  실제 이진/혼합 랭킹 모델이 완성된 것은 아니다.
- 같은500/100개에서 T3·D1을 먼저 포함하는 제안과 한계를 합성 검증했다.
  이후 최신 감상 영화를 제외하면 다시 부족할 수 있다. 공식 후보 정책으로 채택하거나 실제 사용자를 재실험하지 않았다.
- 품질 판단 양식을 만들었다. 맞춤2편의 선택과 발견1편의 새로움·설명 납득을 따로 받고,
  부족·T3 fallback·모름·미응답을 숨기지 않는다. 모집·노출·응답 수집은 하지 않았다.

## 이제 어떤 순서로 정하는가

**가장 먼저 정할 것은 실제 온보딩 LIKE/DISLIKE만 있는 사용자의 추천 경로와 비교할 인기 기준이다.**
기존 raw ALS에는 원별점을 넣었다. 실제 이진 응답을 어떻게 반영할지는 별도 경로가 필요하며,
현재 입력 검증 코드가 그 순위 계산까지 대신하지 않는다. 별점과 이진 응답이 섞일 때의 계산도 미정이다.

그 뒤의 순서는 고정한다.

1. 입력 경로와 공통 역할·후보 정책을 연구용 한 버전으로 정한다. 일반 맞춤 부족·제외·입력 삭제 뒤 복귀 원칙도 함께 기록한다.
2. 비교 기준과 자료 수집 범위를 먼저 정하고, 준비된 두 분류안의 실제 맞춤2·발견1 품질을 판단한다. 여기서 단계4 정책을 고정한다.
3. **그 고정판에서** 입력을 늘려가며 인기보다 유리해지는 최소 입력 수 K를 확인한다.30을 그대로 가져오지 않는다.
4. 같은 품질까지 걸리는 시간·이탈·부담으로 온보딩의 편의성을 확인한다. 권장 응답 수와 K는 자동으로 같지 않다.

연구의 인기 P0는 MovieLens 보정 평균 별점이다. 공식 VIEW 기반 Trending과 같지 않으므로,
서비스에서 쓸 인기 대조를 연결하지 않은 채 서비스 전환 K라고 부르지 않는다.
새 추천의 실제 선호 자료·시간 순서의 입력·온보딩 부담 자료가 현재 없어 단계5/6의 실제 실행은 아직 열리지 않았다.
