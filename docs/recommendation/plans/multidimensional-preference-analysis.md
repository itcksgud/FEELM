# MovieLens·TMDB 개인 취향을 여러 방향에서 보는 분석안

상태: DRAFT — 자료 점검과 분석 순서 제안. 2026-09-09. 실행 조건을 봉인한 실험 계약이나 제품 정책이 아니다.

최신 사용자 방향: **특징을 추천 모델에 추가하기 전에 데이터 전반을 탐색하고, 적은 근거와
서로 다른 집단에서도 관계가 유지되는지 먼저 확인한다.** 아래 순서는 이 지시에 맞춰 수정했다.

사용자 질문: 장르뿐 아니라 대중성·국가·배우·감독 등 가능한 취향 경향을 폭넓게 확인할 수 있는가?
Wikipedia/Wikidata를 더하면 무엇을 얻고, 적은 개인 입력으로도 인물 취향을 볼 수 있는가?

**주요 정보 축을 한 번에 정리하고 같은 기준으로 비교할 수 있다. 모든 조합과 모든 사람의
취향을 빠짐없이 증명할 수는 없다.** 각 축의 관측 범위, 입력 안의 반복 근거, 다른 영화에서의
재현, 기존 정보에 대한 추가 설명력을 나눠 판단한다. 이번 작업에서는 메타데이터만 점검했고
새로운 선호 채점·학습·Wikidata 대량 수집은 하지 않았다. REC044 결과·봉인은 그대로 보존했다.

## 1. 볼 수 있는 축과 질문

| 줄거리 의미·분위기 | 키워드가 달라도 비슷한 서사나 분위기를 좋아하는가? | 기존 E5 텍스트 표현 보유. Wikipedia 줄거리 확장 후보. 추출한 분위기는 원천 사실과 모델 추정을 구분해야 함 |
| 명시적 속성 밖의 공동평가 | 장르가 달라도 같은 사람들이 좋아하는 작품군에 개인이 반응하는가? | MovieLens ALS 등 협업 정보. 기존 비교 기준으로 유지하며 이번 자료 점검에서는 재학습하지 않음 |
| 시간에 따른 변화 | 평가 기록 전반부와 후반부에서 개인 취향이 달라지는가? | MovieLens timestamp. 시청 시각이 아니므로 기분·동행·실제 시청 순서를 직접 주장할 수 없음 |

TMDB는 국가·언어·인물·키워드·상영시간·평가 수 등의 검색/필터를 지원한다.
[TMDB 영화 검색 조건](https://developer.themoviedb.org/reference/discover-movie).
TMDB popularity는 조회·투표·관심목록 등 여러 활동이 포함된 값이며 관객 수나 평균 평점과 다르다.
[공식 정의](https://developer.themoviedb.org/docs/popularity-and-trending).

## 2. 배우·감독은 실제로 얼마나 연결되는가

평가 사용자2,180명, 입력 O30, 검증 E191,932쌍에서 **별점 값을 열지 않고 ID만** 비교했다.
REC027 정규화 정보가 REC044 카탈로그85,517편을 모두 포함한다.

| 정보 | 입력과 같은 값이 E에 존재 | 그 값이 입력의 서로 다른 영화2편 이상에 존재 |
| --- | ---: | ---: |
| 감독 | 15,777쌍 / 8.22% | 2,800쌍 / 1.46% |
| 배우 상위5명 | 60,512쌍 / 31.53% | 11,527쌍 / 6.01% |
| 제작국가 | 182,271쌍 / 94.97% | 177,415쌍 / 92.44% |

분모는 사용자별 관측 평가쌍이다. 고유 영화 비율, 전체 미평가 후보의 적용률, 선호 정확도가 아니다.
‘입력2편 이상’은 희소성을 보여주기 위한 진단이며 서비스 K나 최소 채택 횟수로 확정하지 않는다.
같은 영화 안에서 중복된 인물은 한 번만 센다. 미국처럼 큰 제작국가 범주의 높은 중복은 효과의 증거가 아니다.

감독의 E누락은23쌍, 배우는250쌍으로 작다. 따라서 이번 인물 정보의 제약은 메타데이터 부재보다
개인 입력에서 동일 인물이 반복되는 사례의 부족이다. 한 편을 좋아했다는 이유로 그 인물의 팬이라고
단정하지 않는다. 적은 근거의 개인 효과는0 또는 공통 사전값 쪽으로 줄이고, 근거가 쌓일수록 더 반영하는
방식을 후보로 둘 수 있다. 추정값은 실제0.5단위 감상 별점과 구분한다.

인물 축은 전체 사용자 평균과 실제 인물 연결이 있는 조건의 효과를 함께 보고한다.
감독·배우 효과가 장르·국가·시리즈에 의해 설명되는지도 공동모델과 정보 제거 대조로 확인해야 한다.
전체 출연진으로 넓히는 결정은 적용률뿐 아니라 조연·단역 연결의 유용성도 함께 확인한 뒤 판단한다.

재현: `py -3.12 -B -X utf8 scripts/audit_preference_feature_support.py`

[입력 해시와 원 집계](multidimensional-feature-support.json). 별도 에이전트의 직접 집계와 루트의
재현 스크립트 결과가 일치했다. 원자료·사용자별 목록을 새로 Git에 넣지 않는다.

## 3. 기존 실험이 확인한 것과 아직 모르는 것

REC044는 장르와 키워드의 별도 진단을 했고 장르2.04%/키워드0.55%의 MSE 감소를 확인했다.
그 결과로 국가·배우·감독의 개별 추가 기여를 주장할 수 없다.

REC027~030에서는 여러 정보를 합친 구조 표현에 개인화 신호가 있다는 결과가 있었다.
실제 구조는 아래 네 블록이다.

`GENRE / CONTEXT(원어·10년 단위 연대·30분 단위 상영시간) / PEOPLE(감독·상위5배우) / KEYWORD`

**기존 최종 보고서의 ‘국가’ 포함 요약은 실제 변환 계약과 다르다.** 제작국가는 별도
domain-projection에 보유하여 KR 구간을 나누는 데 썼고, 그 모델의 취향 특징에는 넣지 않았다.
따라서 국가별 개인 취향을 이미 검증한 것으로 해석하지 않는다. 과거 봉인된 파일을 수정하는 대신
이번 자료 점검에서 정정 근거를 남긴다.

## 4. Wikipedia·Wikidata가 더할 수 있는 것

Wikipedia 본문과 Wikidata 구조 정보를 구분한다. 추가 수집의 목적은 TMDB의 인물·장르 정보를
그대로 복제하는 것이 아니라 **새로운 설명 축이나 누락 정보**를 얻는 것이다.

- Wikidata 후보: 원작/각색 관계, 시리즈 관계, 주요 주제, 이야기 배경 장소·시대, 수상/후보 정보.
  이런 속성이 존재하지만 영화별 채움률은 별도로 측정해야 한다.
- Wikipedia 후보: 더 긴 줄거리나 작품 해설의 제한된 부분. 제목/동명이작·리메이크·언어판 매칭과
  문서 길이 차이를 확인한다. Wikipedia 전체 본문을 영화 고유의 내용 특징으로 바로 넣지 않는다.
- TMDB external_ids는 Wikidata ID를 지원한다. 채워진 ID로 연결하고, 미연결을 수작업 추측으로
  덮지 않는다. IMDb ID와 개봉연도 등을 이용한 검증도 가능하지만 커버리지는 아직 미측정이다.
- 흥행·비평·수상·평점 문장을 섞으면 내용 선호와 대중 평가를 분리하기 어렵다. 줄거리/주제와
  외부 평가 정보를 다른 블록으로 다루고, 수상/흥행은 해당 시점 이후의 정보라는 경계를 남긴다.
- Wiki도 사용자에게 노출됐거나 좋아한 영화의 정답을 추가로 제공하는 것은 아니다.
  연관 메타데이터가 늘어나는 것과 개인별 평점 근거가 늘어나는 것은 다르다.

공식 근거: [Wikidata 영화 속성](https://www.wikidata.org/wiki/Wikidata:WikiProject_Movies/Properties),
[TMDB external IDs](https://developer.themoviedb.org/reference/movie-external-ids),
[Wikidata 접근 방법](https://www.wikidata.org/wiki/Wikidata:Data_access),
[MediaWiki 문서 텍스트 접근](https://www.mediawiki.org/wiki/API:Get_the_contents_of_a_page).
실제 대량 수집이나 새 임베딩 학습은 이번에 실행하지 않았다.

## 5. 넓게 보되 끝이 있게 비교하는 순서

1. **전체 자료 구조와 분포부터 확인한다.** 보유한 모든 종류의 필드, 연결키, 중복·결측·수집일,
   영화 수·평가 수·평가자 수를 나란히 정리한다. 국가·장르·연대·평가자 수 등에 따라 자료가
   어디에 몰렸는지 보고 원별점 분포와 영화 평균·개인 별점 습관을 감안한 편차를 함께 본다.
   평점 외 필드가 있는 것과 개인별 관계를 확인할 표본이 있는 것을 구분한다. 기존 정규화 자료뿐
   아니라 원응답에만 있는 필드의 전수 커버리지도 확인한다. 이 단계는 추천 모델 순위표가 아니다.
2. **정보끼리 겹치는 관계를 확인한다.** 국가×장르, 국가×언어, 감독×장르/시리즈,
   개봉연도×평가자 수처럼 결합 분포를 본다. 예를 들어 일본 제작 선호처럼 보이는 차이가
   애니메이션 구성비를 맞춰도 남는지 비교한다. 영화 평가량·시리즈 반복·인물 겹침 때문에
   생긴 차이를 독립된 취향 성과로 여러 번 세지 않는다. 관측 구성비와 높은 별점은 분리한다.
3. **근거가 줄어도 유지되는지 확인한다.** (a) 사용자 총 입력 편수, (b) 해당 속성의 입력 내
   반복 편수, (c) 그 속성을 공유한 독립 사용자 수, (d) 검증 영화 수를 각각 다룬다. 같은 사용자의
   입력을 여러 번 줄여 보는 경우 숨긴 평가집합은 고정하고, 입력 선정에 따라 결과가 얼마나 바뀌는지도
   기록한다. 적은 자료에서 방향·효과 크기·불확실성·적용 범위를 함께 보고, 가장 좋아 보이는
   한 번의 추출만 선택하지 않는다. 분석용 입력 구간은 서비스 온보딩 K 결정과 별개다.
4. **집단을 바꿔도 유지되는지 확인한다.** 서로 다른 학습/평가 사용자 분할, 허용된 범위의
   활동량·취향 집중도별 사용자 집단, 평가자 수가 많은/적은 영화, 국가·언어·장르·개봉연대별
   영화 집단에서 같은 분석을 반복한다. 각 집단에서 모두 유의해야 한다고 기계적으로 요구하지 않고
   표본 크기에 따른 구간 폭과 실제 방향 차이를 구분한다. 한 집단에서만 남으면 조건부 관계로
   기록한다. 사용자 국적/연령/성별 집단은 현재 자료로 구성하지 않는다.
5. **관계의 사용 범위를 판정한 뒤 모델 실험으로 간다.** 여러 조건에서 안정적 / 충분한 반복
   근거가 있을 때만 유효 / 특정 집단에 한정 / 기존 정보로 설명됨 / 표본 부족으로 판단 불가 /
   미확인으로 정리한다. 추천 모델에 넣을 정보와 사용 조건은 그 뒤 결정한다. 살아남은 정보에 대해
   공통 효과와 개인 효과를 구분한 공동모델·정보 제거 대조, ALS 및 취향/발견 추천의 추가 이득을
   비교한다. Wiki는 분포 점검에서 드러난 정보 공백이나 새 질문에 맞춰 보강한다.

넓게 탐색한 뒤 같은 자료만으로 독립 확인까지 끝냈다고 주장하지 않는다. 데이터 종류 전체를
파악하는 것과 최종 확인용 평점까지 미리 열어 보는 것을 구분한다. 개발 자료에서 분포와 가설을
탐색하고, 비교·그룹·표본·반복 추출·다중비교 보정·중단 기준은 실행 전 독립 검토로 고정한다.
최종 확인에는 사전에 분리해 둔 허용 자료를 사용한다. 이미 반복 사용한 REC043/044 자료의
집단별 재분석은 탐색적 안정성 점검으로 표시한다.

첫 산출물은 **각 정보별 보유량·편중·중복 관계·개인 근거 수·집단별 안정성·사용 가능 조건을
나란히 보여주는 표**다. 새 ALS 학습이나 8개 맛 재분류를 첫 단계로 삼지 않는다.

이 문서는 순서 제안이다. 실제 비교 개수·모델·정규화·수축/튜닝 범위·표본·지표·통계 family는
아직 사전 고정하지 않았고 새 실험을 시작하지 않았다. 기존 봉인의 금지 자료와 locked/reserve
범위를 임의로 열지 않는다. 전체 데이터를 더 많이 볼 수 있다는 이유로 공식8맛이나 서비스 정책을 바꾸지 않는다.

## 6. 이 자료로 직접 알 수 없는 것

MovieLens32M에는 사용자 인구통계가 없다. 사용자 국적/성별/연령별 경향을 분석할 근거로
삼을 수 없다. 평점 기록 시각은 실제 시청 시각·동행자·기분을 제공하지 않는다.
미평가가 미노출인지, 아직 안 봤는지, 싫어서 피했는지도 구분되지 않는다.
따라서 현재 질문의 ‘경향’은 관측 평점에서의 조건부 관계와 추가 설명력을 뜻하며 인과적 이유는 아니다.
[MovieLens32M 공식 설명](https://files.grouplens.org/datasets/movielens/ml-32m-README.html).

Jira·GitLab·GitHub 게시, 새 의존성 설치, API/DB/추천 정책 변경은 이 점검에서 수행하지 않았다.
