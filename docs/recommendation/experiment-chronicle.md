## 출발점 — 추천 모델을 만들려고 시작한 작업이 아니다

서비스 개발 중 막힌 두 가지 문제에 답하려고 시작했다. 모델 순위표를 만드는 것이 목적이 아니었기
때문에, 모든 실험의 판정은 “수치가 올랐는가”가 아니라 **“이 수치로 무엇을 주장할 수 있는가”**로 내렸다.

### 문제 1 — MovieLens에는 한국 영화도, 최신 영화도 없다시피 하다

평점의 `78.73%`가 유명 외국 영화 proxy에 몰려 있고 한국 제작 영화는 `0.33%`뿐이다. TMDB 한국-origin
후보 `11,680`편 중 MovieLens와 연결되는 영화는 `1,056`편(1.21%)이고, 그중 평점 1,000개 이상은
`16`편이다. 한국-origin 평점은 전체 `32,000,204`개 중 `90,885`개(0.28%)다. 데이터 수록 이후 영화에는
상호작용이 아예 없다.

### 문제 2 — 출시 전에는 추천–시청–평가 순환을 만들 수 없다

실제 사용자 만족을 직접 정답으로 쓸 수 없다. 그래서 MovieLens를 대리 실험 환경으로 쓰되, 그 대리성이
어디서 깨지는지를 매 실험마다 명시적으로 기록하는 방식을 택했다.

## 읽는 법 — 판정은 다섯 가지 상태로만 쓴다

“좋아졌다 / 나빠졌다”가 아니라 **결과를 보기 전에 잠근 Gate** 기준으로 상태를 찍는다. 결과를 본 뒤에
Gate나 손실 예산을 바꾸지 않는 것이 이 기록의 유일한 규칙이다.

| 판정 | 뜻 |
| --- | --- |
| `PASS` | 사전에 잠근 Gate를 그대로 통과했다. 그래도 champion 승인과는 별개다. |
| `FAIL` | Gate를 넘지 못했다. 예산을 사후에 늘리지 않고 실패로 남긴다. |
| `INCONCLUSIVE` | 안전선은 넘지 않았지만 최소 유의미 효과(SESOI)에 못 미쳤다. 근거로 쓰지 않는다. |
| `POST-HOC PASS` | 같은 표본을 재사용해 통과했다. 새 표본 확인 전에는 증거로 승격하지 않는다. |
| `SKIPPED` | 선행 실험 결과가 사전 조건을 성립시키지 않아 실행하지 않았다. 숨긴 결과가 아니다. |

각 실험은 아래 네 칸으로 적는다.

```text
질문 → 설계 → 결과 → 이 결과가 강제한 다음 수
```

## 단계 1 — 모델을 만들기 전에 라벨부터 의심했다

“4점 이상 = 좋아함”이라는 흔한 전제와 전역 시간 분할이 실제로 성립하는지부터 확인했다. 둘 다 성립하지
않았고, 이 두 결과가 이후 모든 실험의 평가 설계를 결정했다.

### `REC-EV-001` — 공통 4점 기준은 사람마다 다른 뜻이다 · `OBSERVED`

- **질문** — 모든 사용자에게 `rating >= 4`를 “좋아함”으로 쓸 수 있는가.
- **설계** — Train 사용자 `170,491`명을 평균 별점 4분위로 나누고 사용자별 raw 4+ 비율 분포를 봤다.
- **결과** — 하위 4분위 중앙값 `33.3%`, 상위 4분위 `79.8%`. P10~P90 범위도 각각 `16.6%~46.8%`,
  `69.7%~92.4%`였다. raw 4+가 한 번도 없는 사용자 `230`명, 전부인 사용자 `1,015`명.
- **다음 수** — 공통 threshold를 주 지표에서 내리고 **사용자별 Train ECDF 상대 효용**을 채택. raw 4+는
  민감도 분석으로만 남긴다.

### `REC-EV-001` — 전역 미래 평가는 cold-start fallback이 지배한다 · `OBSERVED`

- **질문** — 전역 시간 분할 하나로 개인화 모델의 능력을 판단할 수 있는가.
- **결과** — Train에 사용자와 영화가 모두 있는 row 비율이 Validation `15.03%`, Test `9.78%`. 나머지는
  fallback이 답한다.
- **다음 수** — 전역 split은 제품 대표 평가로 유지하되, **warm-only 진단**을 별도 파이프라인으로 항상
  나란히 산출한다.

## 단계 2 — 예상 별점은 좋아졌는데 추천 순위는 그대로였다

여기서 프로젝트의 방향이 한 번 꺾인다. 별점 예측과 Top-N 순위를 하나의 성과로 묶어 말할 수 없다는 것이
서로 다른 실험에서 반복 재현됐다.

### `REC-EV-002` / `EXP-20260829-001` — ALS는 warm 별점을 잘 맞혔지만 11.74%에만 답할 수 있었다 · `채택 안 함`

- **설계** — 보정 ALS(rank 32, reg 0.1, seed 42) 대 regularized Bias + isotonic. 전체 `25,600,163`행
  학습 `91.27`초.
- **결과** — warm MAE는 ALS `0.6268` < Bias `0.6530`. 그러나 ALS가 직접 예측할 수 있는 행은
  `187,799 / 1,600,010 = 11.74%`였고, fallback을 합친 전체 MAE는 `0.7345`였다.
- **다음 수** — 정확도와 **서비스 coverage를 분리해 보고**한다. Bias를 fallback 기준선으로 유지.

### `REC-EV-002` — 같은 ALS가 순위에서는 단순 인기도에 졌다 · `채택 안 함`

- **설계** — positive 1편 + uniform 미평가 99편 후보, warm 사용자 `3,553`명.
- **결과** — NDCG@10: Popularity `0.4727`, Bias `0.4106`, ALS `0.2595`. positive의 중앙 순위는 ALS 9위,
  Popularity 4위.
- **다음 수** — 결과를 숨기지 않고 Popularity를 **강한 기준선**으로 고정. 이후 모든 순위 실험은 이
  기준선을 이겨야 한다.

### `REC-EV-002` — isotonic은 calibration을 개선하지만 MAE를 항상 개선하지 않는다 · `OBSERVED`

- **결과** — warm ALS는 MAE `0.6351 → 0.6268`, ECE `0.0939 → 0.0204`로 함께 개선됐다. 전체 Bias는
  ECE `0.0534 → 0.0185`로 개선됐지만 MAE는 `0.7339 → 0.7379`로 소폭 악화됐다.
- **다음 수** — 보정 모델은 ECE와 MAE를 함께 보고 선택한다. 숫자 UI 노출 근거로 ECE만 쓰지 않는다.

### `REC-EV-003` / `EXP-20260829-002` — cold-start 평가는 대상 사용자를 item factor에서도 빼야 한다 · `REPRODUCED`

- **질문** — 이력을 K개로 자르기만 하면 신규 사용자를 흉내 낼 수 있는가.
- **결과** — 없다. 평가 대상 `3,014`명의 Train `1,954,040`행을 빼고 남은 `23,646,123`행으로 item factor를
  재학습해야 성능이 낙관되지 않는다. 재학습 `146.34`초.
- **다음 수** — 이후 모든 cold / Fold-in 실험은 **cohort-excluded factor**만 유효한 근거로 인정.

### `REC-EV-003B` / `EXP-20260829-003` — K10은 별점 Gate를 통과했지만 순위 가중치는 전 구간 0이었다 · `별점 PASS · 순위 효과 없음`

- **설계** — 선택 구간에서 α를 정하고 미래 구간에서만 평가. cohort 3,014명, 미래 `167,194`행. 사전 잠금
  Gate는 “3% 이상 실질 개선”.
- **결과** — K10 macro MAE `-3.95%` (`-0.0298 [-0.0348, -0.0244]`)로 첫 Gate 통과. K1은 `1.66%`로
  통계적으로는 유의미하지만 실질 Gate 미달.
  반면 Popularity ↔ Fold-in **순위 α는 K1·K3·K5·K10·K20 전부 0**이었고, 선택에 쓰지 않은 1,323명에서도
  α=0의 NDCG `0.4571`이 그대로 유지됐다.
- **다음 수** — “입력을 받았다”는 사실이 순위 개인화의 근거가 아님을 확정. Fold-in 순위 가중치 0을
  유지하고, 콘텐츠 Hybrid 전까지 개인 순위 개선을 주장하지 않는다.

### `REC-EV-003C` — 0.5점 격자를 정수 척도로 옮기는 변환은 calibration이 아니다 · `clamp/round 기각 · affine 보류`

- **결과** — 실제값의 `45.17%`가 half-star였고 `1.83%`는 제품 최솟값 1점보다 낮았다. K10 round는 ECE를
  `0.0260 → 0.2165`로 악화시켰다. affine은 단조·가역이고 범위를 맞추지만 interior anchor를 이동시키며
  paired 제품 label이 없었다.
- **다음 수** — 척도 정렬은 실제 제품 별점의 paired artifact가 생긴 뒤로 미룬다. 관련 제품 결정은
  fail-closed로 둔다.

## 단계 3 — 후보를 전체 카탈로그로 바꾸자 결론이 여러 개 뒤집혔다

sampled 후보에서 얻은 좋은 숫자들이 `50,977`편 전수 후보에서 그대로 남지 않았다. 이 단계는 대부분
“미승인”으로 끝나지만, 실패를 지운 것이 아니라 경계를 정한 결과다.

### `REC-EV-004` — Validation에서 지킨 1% 탐험 손실 예산을 Test가 지키지 못했다 · `FAIL`

- **결과** — Validation 손실 `0.69%`로 예산 안이던 후보가 held-out Test에서 NDCG@10 `0.3779 → 0.3719`,
  상대 손실 `1.59%`. paired CI `[-0.0083, -0.0038]`.
- **다음 수** — 예산을 3%로 **사후에 늘리지 않는다.** 탐험 champion·가중치·2+1 구성 모두 미승인 유지.

### `REC-EV-004B` — sampled NDCG 0.3779와 full-catalog NDCG 0.009382는 같은 숫자가 아니다 · `척도 경계 확정`

- **설계** — Train-known `50,977`편 전수를 positive 주입 없이 scan. Validation·Test 합계 `510,789,540`회
  점수 계산, Validation `51.547`초 / Test `35.651`초, peak RSS 약 `1.77 GB`.
- **결과** — Popularity candidate recall@500 `0.3080`, NDCG@10 `0.009382`. Explore 5%는 `0.005113`,
  paired CI `[-0.006604, -0.002002]`. Explore의 list/pair genre coverage는 `0.90185 / 0.803722`.
- **다음 수** — **후보 생성 recall**과 **Top-10 순위 relevance**를 영구히 분리해 본다. 이후 모든 순위
  결론은 full-catalog에서만 낸다.

### `REC-EV-005` / `EXP-20260829-005` — 파티 추천의 Balanced 집계는 Average를 이기지 못했다 · `champion = null`

- **설계** — 2·3·4인 × 유사 / 중간 / 상이 취향 각 30개, 합성 Test party `270`개.
- **결과** — 평균 효용 `-0.0013 [-0.0037, 0.0007]`, 최저 효용 `+0.0005 [-0.0035, 0.0045]`, 격차
  `-0.0042 [-0.0116, 0.0024]` — 세 CI가 모두 0을 포함. 4인 Test 평가 가능 coverage는 `0.69~1.02%`였다.
- **다음 수** — 공개 API·UI 미승인. 실제 파티 노출과 구성원별 사후 평가 로그가 생기기 전에는 재실험하지
  않는다.

### `REC-EV-006` — 점수에 기여했다고 해서 순위를 바꾼 이유는 아니다 · `reason UI 미승인`

- **결과** — 추천 위치 `40,000`개에서 novelty는 기여도가 100% 양수였지만 제거해도 위치가 바뀐 비율은
  `24.31%`. diversity는 양의 기여 `78.86%` 중 위치 효과 `59.98%`.
- **다음 수** — 설명 문구는 active feature · 양의 기여 · **rank effect** · provenance 버전 네 조건을 모두
  요구하고 나머지는 typed `BLOCKED`로 남긴다.

### `REC-EV-007` / `EXP-20260829-004` — 실제 HTTP 경로와 Fold-in 코어 지연은 같은 경로가 아니다 · `local 후보값만 채택`

- **결과** — 실제 Uvicorn Popularity-only 최악 p95는 후보 100개 `4.1012 ms`, 1000개 `30.6875 ms`. 비활성
  Fold-in 코어는 `2.1281 ms`였지만 현재 성공 경로가 실행하지 않는 코드다.
- **다음 수** — timeout 750 ms · freshness 3000 ms는 **local 후보**로만 두고 운영 SLA 확정은 배포
  topology 부하 시험 뒤로 미룬다.

### `REC-EV-011` — full-catalog에서는 K10 하나만 0을 확실히 넘었다 · `offline 후보로만 유지`

- **결과** — α가 K1/3/5/10/20 = `0.2 / 0.2 / 0.1 / 0.2 / 0.3`으로 잠겼고, paired NDCG CI가 명확히 0 위인
  조건은 K10 `[0.000253, 0.002783]`뿐이었다. K5는 하한 0.000016의 경계였다.
- **기록** — 첫 42,299편 run은 후보 universe 계약 위반으로 **폐기**했다. 수정된 50,977편 protocol은 두 번의
  독립 실행에서 canonical hash가 각각 일치했다.

## 단계 4 — 평가 자체를 다시 설계하고, 실행 전에 세 번 막혔다

“숨긴 영화가 추천 500개 안에 있는가”를 버리고, 서비스가 실제로 보여주는 **상위 2편**의 안전성을 1순위에
놓는 Top-2 Gate로 갈아탔다. 그리고 실제 실행 전에 누출 · 의미 충돌 · 계산량 문제가 차례로 걸렸다.

### Top-2 v4 평가 설계 — 안전 → 놓침 → 품질 순서의 사전 잠금 Gate · `protocol 확정`

- **설계** — 사용자의 전체 평점 중 고정 해시로 20편을 평가판으로 떼고, 남은 것에서 K편만 모델에 준다. 두
  정책이 같은 20편을 각각 정렬해 **상위 2편만** 채점한다. 정답이 좋은 영화만 골라 평가판을 만들지 않으며,
  20개 seed를 반복해 우연히 쉬운 20편을 뽑은 영향을 줄인다.
- **지표** — `Harm@2`(상위 2편에 BAD 포함) → `Miss@2` → `BothGood@2` → `SafeHit@2` → `NDCG@2`의
  lexicographic 순서. 개인화 후보는 Harm이 기준선보다 `0.5%p` 이상 나빠지지 않으면서 Miss를 최소 `1%p`

  | 0 | 20,271 | 19,864 | 97.99% |
  | 5 | 18,242 | 17,922 | 98.25% |

  바꾸는 결함은 없었다.
- **다음 수** — 019E 라우팅을 채택하지 않는다. 남은 선택지는 **목표 도메인 증거**를 직접 확보하거나, 별도
  가설을 새로 사전등록하는 것이다.

## 단계 6 — 입력을 바꿔도, 콘텐츠를 옮겨 심어도 한국·최신 구간은 열리지 않았다

여기서는 목표 구간(한국 제작 영화, 2020~2023년 영화)에 직접 겨눈 네 갈래를 순서대로 시도했다. 모두 “목표
구간 신호 없음”으로 끝났고, 그 실패가 다음 단계의 질문 자체를 바꿨다.

### `REC-EV-022A` / `022B` — 사용자별 별점 습관을 percentile로 보정하고 K를 0~30까지 훑었다 · `후보 6개 조합 확정`

- **설계** — 고정 4점 기준 대신 프로필 내 midrank percentile을 shrinkage해 비교했다.

  ```text
  q_K(r) = (프로필에서 r보다 낮은 별점 수 + 0.5 × 같은 별점 수 + 5 × 전체 Train 사전분포의 mid-CDF)
           / (K + 5)
  ```

  `BINARY_SIGN`은 사용자 중앙보다 위인지 아래인지만, `PERCENTILE_MAGNITUDE`는 중앙에서 떨어진 크기까지,
  `ORDINAL_RANK`는 프로필 안의 순서만 쓴다.
- **결과** — 별도 확인 집합에서 `K = {6, 8, 14} × {BINARY_SIGN, PERCENTILE_MAGNITUDE}` 여섯 조합이 살아남았다.
- **경계** — K=30까지 plateau를 확인하지 못했으므로 “K=14가 최적” 또는 “더 많은 입력은 무의미”라고 말할 수
  없다. 이건 성능 순위가 아니라 후속 비교에 남긴 정보량 구간이다.

### `REC-EV-023A~F` — 구조 신호는 남았지만 목표 구간으로 옮겨가지 않았다 · `NO_ROBUST_TARGET_SIGNAL`

- **결과** — masked pseudo-cold에서 TMDB 구조 신호는 유지됐으나 E5 · RRF · feature-only LightFM의 증분
  근거는 없었다. 한국 제작 `319`명, 2020~2023 `686`명 각각에서 robust한 목표 신호가 나오지 않았다.
- **다음 수** — “콘텐츠 표현을 조합하면 해결된다”는 가설을 접고, 입력 쪽을 건드려 본다.

### `REC-EV-024A` / `024B` — 한국·최신 영화를 입력에 강제로 두 편 넣어도 부족했다 · `NO_SUFFICIENT_INPUT_REMEDY`

- **결과** — 입력 구성만 바꿔서는 모델의 목표 구간 한계를 해결하지 못했다.
- **다음 수** — 입력이 아니라 **콘텐츠 표현과 협업 표현 사이의 간극**을 직접 다루기로 한다.

### `REC-EV-025` / `026` — E5 벡터를 협업 공간으로 옮겨 심는 마지막 시도 · `CONFIRMATORY_STOPPED_UNTIL_NEW_TARGET_EVIDENCE`

- **설계** — 384차원 E5를 다섯 BPR seed의 128차원 item-factor 공간에 각각 ridge 정렬했다. mapper는 비한국
  또는 2020년 이전 source item으로만 학습하고 target·control은 mapper 선택에서 제외. 사용자별 profile
  14편 · target 4편 · control 4편의 4개 panel.
- **결과** — 한국 전이 `181`명(target 136편, control 1,853편) · 최근 전이 `445`명(target 774편, control
  2,570편), 공동 max-T family `312` contrasts, bootstrap `4,000`회. mapper validation cosine은
  `0.04053 / 0.03970`으로 다섯 seed 모두 0을 넘었다.
  한국 target 평균은 양수였지만 동시추론 정밀도가 부족했고, 최근 target은 사전 margin에 미달했다.
- **다음 수** — 목표 구간 확증을 **중단**한다. 대신 “애초에 콘텐츠 표현에 사용자별 신호가 있기는 한가”라는,
  한 단계 더 앞선 질문으로 되돌아갔다.

## 단계 7 — 질문을 되돌리자 처음으로 깨끗한 PASS가 나왔다

“한국 영화를 잘 추천하는가”를 잠시 내려놓고, **콘텐츠 profile에 사용자별 신호가 존재하는가**만 분리해
물었다. 핵심은 대조군이다 — 내 profile(OWN)과 남의 profile(SHUFFLE)을 같은 후보에서 비교하면, 영화 자체가
쉬워서 생긴 점수를 개인화로 착각할 수 없다.

| 시스템 | 사용 정보 | 묻는 질문 |
| --- | --- | --- |
| `OWN` | 해당 사용자의 profile | 콘텐츠 표현에 사용자별 선호 신호가 있는가 |
| `SHUFFLE` | 같은 outer의 다른 사용자 profile | 결과가 영화 자체의 쉬운 순위만 반영하는가 |
| `RANDOM` | 후보 중 두 편의 분석적 기댓값 | 복잡한 방법이 무작위보다 나은가 |

### `REC-EV-028` — LightFM의 높은 점수는 개인화가 아니었다 · `ITEM BIAS FOUND`

- **결과** — 사용자 profile을 **다른 사용자 것으로 바꿔도** 이점이 남았다. 따라서 그 차이를 개인화 성능으로
  귀속하지 않고 global item bias 가능성으로 분리했다.
- **다음 수** — OWN / SHUFFLE / RANDOM 세 시스템을 같은 사용자·같은 가린 후보에서 비교하는 귀속 설계를
  확정했다.

### `REC-EV-029` — 사용자 지표는 재현됐지만 영화 동일가중 구간에서 걸렸다 · `DIRECT_PROFILE_PERSONALIZATION_NOT_REPLICATED`

- **결과** — selection winner는 `STRUCTURED_DIRECT + PERCENTILE_MAGNITUDE + K=30 + Top2`. 사용자 지표는
  재현됐지만 48-family 영화 동시 신뢰구간이 불충분해 **실패로 남겼다.**
- **다음 수** — 실패를 덮지 않고, 이전에 한 번도 열지 않은 future 사용자 구간과 더 좁게 사전등록한 10개
  primary 지표로 다시 실행했다.

### `REC-EV-030` — 한 번도 열지 않은 3,345명에서 사전등록 Gate 10개 전부 통과 · `REC_EV_030_FINAL_RESULT_AUDIT_PASS`

- **설계** — profile 평점을 읽고 일곱 outer의 OWN / SHUFFLE 순위를 **모두 봉인한 뒤에만** 가린 후보의 평점을
  열었다. primary 사용자 `3,345`명 · 고유 영화 `24,167`편 · 후보 발생 `265,620`건 · 사용자-영화 중복 `0`건 ·
  profile 평점 `417,300`개 · 가린 후보 라벨 `268,136`개. OWN/SHUFFLE 활성률 각각 100%.
- **사용자 동일가중 절대값**:

  | 시스템 | HARM20 ↓ | TOP2_MIN_Q ↑ | TOP2_MEAN_Q ↑ |
  | --- | ---: | ---: | ---: |
  | **OWN** | **0.2525** | **0.4017** | **0.5418** |
  | SHUFFLE | 0.3388 | 0.3386 | 0.4847 |
  | RANDOM | 0.3816 | 0.3148 | 0.4641 |

  OWN은 무작위보다 하위 20% 영화를 상위 2편에 넣을 확률을 `12.92%p` 낮췄고, **다른 사용자의 profile보다도**
  `8.63%p` 낮췄다. RANDOM과의 차이만 컸다면 “콘텐츠가 인기작을 잘 고른다”로도 설명될 수 있었다. SHUFFLE보다
  낮은 HARM20이 나왔기 때문에 사용자별 신호로 귀속할 수 있었다.
- **사전등록 동시 신뢰구간** (5,000회 shared-multiplier bootstrap):

  | 집계 | 비교 | 지표 | 차이 | 동시 95% 구간 |
  | --- | --- | --- | ---: | ---: |
  | 사용자 | OWN 대 RANDOM | HARM20 감소 | +0.1292 | [0.1188, 0.1395] |
  | 사용자 | OWN 대 RANDOM | MIN_Q 증가 | +0.0869 | [0.0808, 0.0929] |
  | 사용자 | OWN 대 RANDOM | MEAN_Q 증가 | +0.0777 | [0.0730, 0.0824] |
  | 사용자 | OWN 대 SHUFFLE | HARM20 감소 | +0.0863 | [0.0718, 0.1008] |
  | 사용자 | OWN 대 SHUFFLE | MIN_Q 증가 | +0.0631 | [0.0552, 0.0711] |
  | 사용자 | OWN 대 SHUFFLE | MEAN_Q 증가 | +0.0571 | [0.0507, 0.0636] |
  | 영화 | OWN 대 RANDOM | utility 증가 | +0.0704 | [0.0378, 0.1030] |
  | 영화 | OWN 대 RANDOM | low-risk 감소 | +0.0779 | [0.0520, 0.1038] |
  | 영화 | OWN 대 SHUFFLE | utility 증가 | +0.0638 | [0.0217, 0.1058] |
  | 영화 | OWN 대 SHUFFLE | low-risk 감소 | +0.0638 | [0.0259, 0.1017] |

  사전 조건 10개가 모두 통과했다. 별도 작업이 metric artifact에서 사용자 3,345명과 영화 24,167편을 다시
  집계하고 저장된 5,000회 bootstrap 배열로 critical과 구간을 재계산해 같은 판정을 확인했다.
- **경계** — 이것은 **MovieLens 사용자가 이미 평가한 영화를 가린 대리 과제**의 결과다. 실제 한국 사용자
  성능도, 수록 이후 신작 성능도 아니다. 표본 안의 KR 247명과 RECENT 382명은 descriptive-only로만 기록했다.
- **다음 수** — 콘텐츠 후보 생성과 후속 모델 개발의 근거로는 쓰되, 제품 champion 승인으로는 쓰지 않는다.

## 단계 8 — 남은 하나는 오프라인으로 풀 수 없다

MovieLens 안에서 할 수 있는 것은 여기까지다. 목표 도메인 증거는 사람에게 직접 물어야 얻어진다.

### `REC-EV-021V` — 인프라는 준비됐고 실제 평가자는 아직 0명이다 · `INSUFFICIENT_TARGET_DOMAIN_EVIDENCE`

- **사전등록** — 한국 거주 `100`명, K10, mapped positive / negative 각 2개 이상, recent-Korean-low-pop
  target과 세 control stratum 각 12개, `4 × 12` blind pool, B0 / B7 / B8 / B9 비교, paired NDCG@10과
  Top-2 harm Gate, license · consent · PII · budget Gate를 결과 전에 모두 잠갔다.
- **현재** — 4명 synthetic fixture에서 `192`개 judgment 파이프라인만 검증했다(`PASS_INFRASTRUCTURE_READY`).
  실제 100명 · 4,000 judgment · target positive 300건은 미수집이다.
- **다음 수** — catalog / license · consent · privacy · budget · 모집 · frozen ranking이 승인되기 전에는
  상태를 바꾸지 않는다.
