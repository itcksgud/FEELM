# FEELM 개인 실험실

이 디렉터리는 팀 확정 명세와 분리된 개인 프로토타입 공간이다. 실험 결과가 좋다는 이유만으로
팀 저장소의 요구사항, API, DB 또는 아키텍처가 변경되지는 않는다.

## 진행 방식

1. 한 번에 가설 하나만 코드로 만든다.
2. 실제 서비스 연결보다 재현 가능한 입력과 측정을 먼저 만든다.
3. 효과가 없거나 설명하기 어려우면 부담 없이 폐기한다.
4. 채택 후보만 `문제, 데모, 비교 수치, 통합 비용` 네 가지로 정리해 팀에 제안한다.

각 실험은 긴 기획서 대신 다음만 남긴다.

- 코드와 실행 방법
- 기준선 또는 비교 대상
- 테스트와 대표 입력
- 결과 및 `KEEP / REVISE / DROP` 판단

## 우선순위

| 순서 | 실험 | 먼저 확인할 것 |
| --- | --- | --- |
| 1 | 파티 추천 점수 | 평균만 쓸 때보다 한 명의 낮은 만족도를 보호하는가 |
| 2 | 예상 별점 | 모델 점수를 1~5점으로 보여줘도 실제 평가와 보정되는가 |
| 3 | 탐험 추천 거리 | 취향 연결점을 유지하면서 어느 정도 변칙을 줄 수 있는가 |
| 4 | OTT 비교 | OTT별 집계보다 실제 영화 목록이 선택에 도움이 되는가 |
| 5 | Spark Scale-out | 어느 데이터 크기부터 Worker 추가가 이득인가 |

현재 첫 실험은 [`party_ranking.py`](./party_ranking.py)이다.

## 실험 1 현재 결과

- 입력 `4.5, 4.0, 3.5, 4.0`은 적합도 `74점`이다.
- 평균이 같은 `4.0, 4.0, 4.0, 4.0`과 `5.0, 5.0, 3.0, 3.0`을 비교하면 취향 차이가
  큰 두 번째 후보의 점수가 더 낮다.
- 최저 예상 별점이 기준보다 낮으면 점수는 계산하되 기본 후보가 아닌 fallback으로 표시한다.
- 현재 판단: **KEEP AS PROTOTYPE** — 실제 개인 예상 별점을 연결한 뒤 가중치와 3.0 하한을
  다시 검증한다.
