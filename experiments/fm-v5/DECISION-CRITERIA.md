# FM-v5 Jira 기준 의사결정 규칙

상태: `INPUT_VERIFIED_IMPLEMENTATION_PENDING_INDEPENDENT_REVIEW`(입력 검증 완료, 구현과 독립 검토 대기)

이 문서는 2026-09-19 Jira `S15P21E106-623` 갱신 뒤 FM-v4를 대체한 의사결정 계약이다. 완료된 실험 결과가 아니다. 고정된 621 자료가 존재하고 해시가 일치하며 실행 설정이 완전하고 독립 사전 검토가 진행 승인 판정을 내리기 전에는 학습하거나 검증 정답에 접근할 수 없다.

## 1. 기준 입력과 즉시 중단 조건

Jira가 지정한 S15P21E106-621 자원 승인 10% 실행은 새로 뽑은 분할이 아니라 `ml32m-zero-n-readiness-10pct-v2`이다.

- 분할·후보 초기화값: `621`
- 사용자: 학습 `15,000`, 검증 `3,000`, 최종 시험 `2,000`
- 에피소드: `161,057`, SHA-256 `58d0d3f81d324823704b11523e89ade5bddbe9c86a84085f2b9ba5c6a38e826f`
- 후보: `2,000,000`, SHA-256 `d1fa052649a8bca9132a3ddd52b544626bfdd807106a398eb8d0f2220a808cae`
- 분포 보고서 SHA-256: `1a2c8c2872cea9b3972edce5f9bb2f7e560ee0611081817fbece4b653398b7c9`
- 620 계약 SHA-256: `974b03945a86c5db93605a52f57d32755213a492288a1fbd4abda3652678f5ba`

이 v2 입력 전달본은 2026-09-20에 수신해 검증했다. 체크섬 32개가 모두 통과했고 학습·검증 내보내기는 에피소드 143,926행과 후보 1,800,000행이며 최종 시험은 전달되지 않았다. 그러나 v2는 사용자마다 관측 양성 판단이 정확히 1개뿐이고 관측 음성은 없으며 Python `random.Random`으로 뽑은 `UNKNOWN_SAMPLED` 후보 99개를 사용한다. 따라서 현재 의사결정 계약의 NDCG@2를 계산할 수 없고, 표본 확률과 중요도 가중치를 선언한 620의 `SHA256_THRESHOLD_V1` 정책과도 다르다.

완료된 GBT는 이후의 `ten-percent-input-v7`, 분할 초기화값 `622`, 정답을 보지 않고 뽑은 여러 대상, 시점 기준 카탈로그, `SHA256_THRESHOLD_V1`을 사용했다. v2와 에피소드·후보 digest가 다르다. 최초 전달본에는 v7 manifest와 결과는 있었지만 바이트가 같은 v7 학습·검증 행과 이를 만든 정확한 소스 묶음은 없었다. 당시 Jira는 621과 정확한 digest만 언급했고 v7 또는 초기화값 622는 언급하지 않았다.

어느 입력도 공통 FM 의사결정 입력으로 몰래 승격할 수 없다. 이후 사용자가 바이트 동일 v7 학습·검증 전달본을 제공했으므로 이번 회차는 GBT와 비교 가능한 경로를 선택한다.

1. **선택한 GBT 비교 경로:** v7 학습·검증 에피소드, 후보·판단, 투영한 분포 보고서, 역할별 카탈로그, 정확한 소스 파일 7개와 체크섬을 수신해 독립 검증했다. 검증 자료가 이미 열렸고 실제 저이력 집단이 희소하므로 최대 `K_POLICY_STATUS=CANDIDATE`까지만 가능하다.
2. **향후 완전 검증 경로:** 보지 않은 확인 사용자, 충분한 관측 판단, 충분한 실제 저이력 셀을 갖춘 새 620 준수 공통 입력으로 GBT·기준선·FM을 함께 실행해야 `VALIDATED` 주장을 새로 만들 수 있다. 이는 Jira/621 계보 수정이 필요하며 이번 실행 범위가 아니다.

사용자 600명의 `ml32m-zero-n-readiness-v1`과 수신한 v2 입력은 점검·계보 감사 자료로만 남긴다. 10% 모집단은 MovieLens 전체 모집단도 아니다. 전체 데이터 FM 주장을 하려면 새 전체 모집단 manifest, 역할, 에피소드, 후보, 분포 보고서, 자원 판정과 digest를 실행 전에 고정해야 한다.

모든 기준선·FM 프로필·초기화값·제거 실험은 같은 역할, 에피소드, 후보, 판단, 카탈로그, 제외 규칙, 분포 digest를 사용해야 한다. 불일치하거나 필수 셀이 없으면 전체 실행을 실패시킨다. 행을 몰래 버리지 않는다. 최종 시험은 `S15P21E106-625`를 위해 봉인한다.

## 2. 필수 비교

같은 후보 집합에서 다음 항목을 모두 비교하지 않으면 검증 행렬은 완전하지 않다.

1. 인기도 기준선
2. 콘텐츠 기준선
3. 기존 집계 FM
4. 공통 집계 비상호작용 기준선
5. 희소 이력 FM
6. 희소 이력+콘텐츠 FM

기존 집계, 공통 집계, 새 희소 모델은 서로 다른 프로필 ID·버전·정렬 스키마·digest를 유지한다. 기존 벡터를 희소 FM 입력이라고 이름만 바꾸지 않으며, 차원을 맞추기 위해 GBT의 조밀한 245차원 벡터를 FM에 강제로 넣지 않는다.

필수 제거 실험은 선형 대 상호작용, 인기도 대 개인화, 양성 대 음성 이력, 후보-이력 관계 제거, 검증된 각 콘텐츠 묶음 제거다. TMDB/KOBIS 필드는 S15P21E106-624가 검증한 고정 시점 자료에서만 사용할 수 있다. 없거나 검증되지 않은 묶음은 비활성화하고 누락으로 보고하며 현재 API 값으로 메우지 않는다.

희소 스키마는 장르·감독·배우·핵심어마다 후보와 양성·음성 이력 값을 서로 다른 이름공간에 둔다. 후보 ID, 선언한 교차항과 상호작용은 학습 자료로 만든 고정 어휘, 명시적 미등록 값 버킷, 가중치, 정규화, 정렬 이름 해시, 프로필 digest를 사용한다. 사용자 ID 임베딩은 필수가 아니다. 선택한 모든 프로필은 숨은 사용자·영화 ID 조회 없이 이력이 없는 사용자와 보지 못한 영화를 점수화할 수 있어야 한다.

학습한 보조 점수는 학습 행에서는 학습 전용 교차검증 예측이어야 하고 이후 역할에서는 엄격한 시점 기준이어야 한다. manifest에는 학습 역할, 시간 절단점, 원천 행 digest, 폴드 배정, 모델 결과 ID, 특징 digest를 기록한다. 계보 누락, 미래 입력, 이름공간 충돌, 선언되지 않은 미등록 값 동작, 행 실패가 하나라도 있으면 전체 실행을 실패시킨다.

## 3. 이력 보기와 보고 셀

`K_history`는 모델에 노출한 엄격히 이전 사건 수다. 순위 절단점은 `@L`로 써 두 개를 혼동하지 않는다. 대상 사건이 자기 이력에 들어가면 안 되며 임의의 `K_history`를 지원해야 한다. 모든 보고서는 다음을 포함한다.

- 이력 구간: `0`, `1`, `2`, `3-4`, `5-9`, `10-19`, `20-29`, `30-49`, `50+`.
- 전체 이력 수와 모델이 지원하는 이력 수를 별도로 보고한다.
- 같은 사용자·대상·예측 시각·후보·정답·카탈로그에서 이력 앞부분만 바꾸는 `NESTED_HISTORY`; 부트스트랩 단위는 사용자-대상이다.
- 서로 다른 사용자를 비교하는 `LOW_HISTORY_COHORT`; 사용자 내부 개선으로 표현하지 않으며 부트스트랩 단위는 사용자다.
- 역할×이력 필수 셀의 사용자가 100명 미만이면 `INSUFFICIENT_SAMPLE`로 쓰며 효과 0이나 통과로 해석하지 않는다.

`K_history=0`은 별도 초기 사용자 경로다. 이력이 없을 때 개인화 FM이 실패해도 집계 평균으로 숨기거나 대체하지 않는다.

## 4. 후보 정답, 지표, 불확실성

후보 판단은 `POSITIVE_OBSERVED`, `NEGATIVE_OBSERVED`, `UNKNOWN_SAMPLED`를 구분한다. 미관측 후보를 음성 정답으로 바꾸지 않는다. 후보 모집단·제외·표본 확률·중요도 가중치·모든 digest는 620의 `SHA256_THRESHOLD_V1` 계약을 따른다.

주 지표는 후보 재현율, NDCG, 낮은 평점 노출, 다양성, 모델 지원률이다. 선택 지표는 사용자 평균 NDCG@2이며 @4·@6·@10을 필수 보조 보기로 둔다. MSE와 MAE는 평점이 관측되고 비교 모델 둘 다 행을 지원하는 경우에만 계산하는 보조 지표다. 모든 지표는 정규 사용자별 기여도에서 다시 만들며 분자·분모·제외·사용자 수·대상 수·고유 영화 수를 기록한다.

짝지은 불확실성은 PCG64 초기화값 `339`로 사용자 묶음 부트스트랩 10,000회를 사용한다. 모든 정책 비교에 같은 추출을 사용한다. 각 표는 점 차이, 95% 구간, 짝지은 악화 사용자 비율, 세 모델 초기화값의 결과, 각 모델의 원시 평균과 분모를 보고한다. 모델 초기화값은 `621`, `1621`, `2621`이며 분할·후보 초기화값은 `621`이다.

모델 적합 전과 완료 결과에서 역할·이력 보기마다 학습 고정 구간 PSI, 범주형 최대 백분율점 차이, 밑이 2인 Jensen-Shannon 거리를 보고한다. 경고 임계값은 PSI `0.10`, 최대 백분율점 차이 `0.05`, JSD `0.10`이다. 자연스러운 시간 변화가 임계값을 넘으면 `DISTRIBUTION_SHIFT`, 구성·digest 불일치나 누수 또는 필수 셀 누락이면 `BLOCKED`다. 보고서는 활동량, 전체·지원 이력, 양성·음성 비율, 대상 관련성과 학습 지원, 연도·시간·범주 구성, TMDB/KOBIS/모델 적용 범위, 후보 수, 특징 적용 범위, 이름공간 미등록 값 비율, 이력 셀별 유효 가중치를 포함한다. 재가중은 새 manifest를 가진 새 학습·검증 실행에서만 허용하고 최종 시험 개봉 뒤에는 하지 않는다.

## 5. K별 정책 후보

같은 후보와 제외 규칙에서 다음 정책을 비교한다.

- `BASE_POPULARITY`와 `BASE_CONTENT`
- `FM_ONLY`
- 임계값 `T in {5,10,20}`의 즉시 전환: `K_history<T`에서는 기준선, 그 이상은 FM
- 같은 임계값의 점진 혼합: `K_history>0`에서 `fm_weight=min(1,K_history/T)`, `score=(1-fm_weight)*baseline_score+fm_weight*fm_score`; `K_history=0`의 가중치는 항상 0

혼합 전에 모든 구성 점수를 학습 자료로 같은 연속 평점 척도에 보정한다. 낮은 K 기준선, 선택 FM 프로필, 임계값, 혼합 형태는 학습과 검증만으로 정한 뒤 고정한다. 가중치·임계값·후보·특징 결정에 최종 시험을 사용할 수 없다.

## 6. 정확한 의사결정 규칙

임계값 T부터 시작하는 이력 구간은 검증에서 다음을 모두 만족할 때만 안정 FM 구간이다.

1. 같은 후보 집합, digest, 누수, 분포, 정규 기여도 검사가 통과한다.
2. T 이상에서 지원해야 하는 모든 `NESTED_HISTORY` 셀의 사용자가 100명 이상이다.
3. 세 초기화값을 합친 희소 FM의 인기도·콘텐츠 대비 NDCG@2 차이 95% 신뢰구간 하한이 모두 0보다 크다.
4. 세 모델 초기화값의 NDCG@2 점 차이가 두 기준선 모두에 대해 양수다.
5. 합친 짝지은 악화 사용자 비율이 50% 미만이다.
6. 낮은 평점 노출 차이의 95% 신뢰구간 상한이 `+0.02` 이하다.
7. 같은 후보 재현율과 지원률이 변하지 않는다. 정규화 다양성 차이의 점추정이 0 이상이고 95% 신뢰구간 하한이 `-0.02` 이상이다.
8. T 이상 `LOW_HISTORY_COHORT` 집계가 NDCG 점 방향을 뒤집지 않는다.

임계값은 `5`, `10`, `20` 순서로 검사하고 모든 규칙을 만족하는 가장 작은 값을 선택한다. 즉시 전환이 없으면 같은 규칙으로 점진 혼합을 검사한다. 여러 혼합이 통과하면 NDCG@2 신뢰구간 하한이 가장 높은 것, 낮은 평점 노출이 더 낮은 것, 다양성이 더 높은 것, 임계값이 더 작은 것 순으로 고른다. 결과를 본 뒤 만든 하위집단으로 이 규칙을 대체하지 않는다.

상태 상수의 뜻은 다음과 같이 고정한다.

- `K_POLICY_STATUS=NOT_SUPPORTED`: 안정 구간 규칙을 만족한 정책이 없거나 안전 조건이 실패함.
- `K_POLICY_STATUS=CANDIDATE`: 검증에서 정책을 골랐지만 필수 셀 부족, 초기화값 재현 미완료, 또는 불확실성 구간이 주장을 확립하지 못함.
- `K_POLICY_STATUS=VALIDATED`: 같은 후보 정책이 검증의 모든 안정 구간·안전·초기화값·재현성 규칙을 만족함. 서비스 채택을 뜻하지는 않음.
- `TRANSITION_THRESHOLD_STATUS=NOT_EVALUATED`: 필수 정책 또는 계약 검사를 완료하지 못함.
- `TRANSITION_THRESHOLD_STATUS=VALIDATION_REQUIRED`: 임계값을 제안했지만 위의 완전한 검증 근거가 없음.
- `TRANSITION_THRESHOLD_STATUS=VALIDATED`: 선택 임계값이 전체 검증 규칙을 만족함.

상호작용 기제에는 별도 `FM_INTERACTION_STATUS`를 둔다. 선택한 상호작용 프로필이 정확히 대응하는 선형 제거 모델도 NDCG@2 우월성과 안전 규칙에 따라 이길 때만 `VALIDATED`다. 그렇지 않아도 K별 정책은 선형 희소 모델을 선택할 수 있으나 FM 상호작용을 검증했다고 주장할 수 없다.

## 7. 실행 승인 조건

전체 실행 전에 독립 검토자는 기준 자료 해시, 정확한 비교 행렬, 특징·프로필 해시, 임의 이력 처리, 후보 판단, 정규 지표, 세 초기화값, 분포 검사, K별 정책 구현, 최종 시험 방화벽, 자원 제한, 실패 실행 불변 보존을 확인해야 한다. 진행 승인 뒤 수정하면 새 설정 digest를 만들고 다시 검토해야 한다. 완료·실패 실행을 덮어쓰거나 재사용하지 않는다.

완료된 모든 적합은 목적함수·손실 곡선, 선택 반복, 요인 차원, 학습률, 정규화, 조기 종료 사유, 수렴 상태, 경과 시간, 최대 메모리, CPU/GPU 사용, 출력 크기, 실행 환경 이미지 ID, 소스·설정·모델·결과 digest와 한 명령 검증 기록을 남긴다. 수렴하지 않았거나 자원 제한으로 종료된 적합은 약한 점수가 아니라 실패한 시도다.
